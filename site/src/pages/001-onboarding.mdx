# Welcome to VibeLang

VibeLang is a language for building reliable TypeScript in the AI era, built on [Effect](https://effect.website). It gives Effect a simple, readable syntax. The compiler turns it into ordinary Effect code that your team can read and ship, and `.ts` files, npm packages and the rest of the TypeScript ecosystem stay one import away.

Here is one program twice: a typed error, a service, a fallback and the layer that provides the service. First in Effect TypeScript, then in VibeLang.

:::code-group

```vibe [VibeLang]
interface User { id: string; name: string }

error UserNotFound { id: string }

service Users {
  static readonly key = "app/Users"
  find(id: string): User!UserNotFound
}

effect function greet(id: string) {
  const users = try Users
  const user = users.find(id) catch () => ({ name: "guest" })
  return `Hello, ${user.name}`
}

const UsersLive = Layer.succeed(Users, {
  find: effect (id: string) => ({ id, name: "Ada" })
})

effect function main() {
  provide UsersLive {
    try Console.log(try greet("ada"))
  }
}
// Output: Hello, Ada
```

```ts [Effect]
import { Console, Context, Data, Effect, Layer } from "effect"

interface User { id: string; name: string }

class UserNotFound extends Data.TaggedError("UserNotFound")<{ readonly id: string }> {}

class Users extends Context.Service<Users, {
  find(id: string): Effect.Effect<User, UserNotFound>
}>()("app/Users") {}

const greet = (id: string) => Effect.gen(function* () {
  const users = yield* Users
  const user = yield* users.find(id).pipe(Effect.orElseSucceed(() => ({ name: "guest" })))
  return `Hello, ${user.name}`
})

const UsersLive = Layer.succeed(Users, {
  find: (id: string) => Effect.succeed({ id, name: "Ada" })
})

const main = Effect.gen(function* () {
  yield* Console.log(yield* greet("ada"))
}).pipe(Effect.provide(UsersLive))
```

:::

Both programs print `Hello, Ada`, and both run on Effect. `error` declares the tagged error class, `service` declares the dependency, `effect function` returns an Effect, `try` runs one, `catch` handles the declared failure, and `provide` supplies the layer. The compiler infers the type of `greet` as `string!!Users`, which is `Effect<string, never, Users>`: it returns a `string`, has no expected failure, and needs the `Users` service. TypeScript code that imports `greet` sees that Effect type.

VibeLang is v0. The language will change in major, breaking ways, and it is not ready for production use.

## Why a language

A TypeScript signature names what a function returns. It does not say what the function can fail with or what it depends on. Effect puts all three in one type the compiler checks, `Effect<Success, Error, Requirements>`, and adds retries, timeouts, concurrency, resource cleanup and tracing around it.

Effect is a library, so it builds each of those from TypeScript's existing tools. Generators and `yield*` sequence steps. `pipe` composes operators. Classes declare errors and services. The result reads like a second language written in library calls.

VibeLang gives each Effect idea its own syntax and compiles it to the Effect program you would write by hand. `try` runs an Effect, `throw` fails with a typed error, `catch` handles it, `service` declares a dependency, and `fork` starts a fiber. [Why VibeLang?](/getting-started/002-why-effect) makes the full case, and answers Effect's own argument against a language.

## TypeScript stays one step away

Interop rests on two facts.

1. **The output is ordinary Effect code.** The compiler is a fork of the TypeScript 7 compiler. It checks `.vibe` and `.ts` files in one program, with TypeScript's type system, and emits JavaScript plus a `.d.vibe.ts` declaration beside each `.vibe` file. TypeScript imports a VibeLang module and sees ordinary Effect functions. [VibeLang for Effect users](/vibelang-features/114-vibelang-for-effect-users) covers the rules.
2. **A `.ts` file can sit beside any `.vibe` file.** Plain and `async` functions are TypeScript's. Code that needs a Node or browser global, or that throws, lives in a `.ts` file, and Effect code calls it through Effect's own adapters: `Effect.try` for a call that may throw, `tryPromise` for a Promise, and `callback` for a callback API.

Based on [Effect's Creating Effects](https://effect.website/docs/v4/getting-started/creating-effects#trypromise), this adapter wraps an `async` function from a `.ts` file:

```vibe
import { fetchTodo } from "./todos.ts" // (id: number, signal: AbortSignal) => Promise<string>

error TodoFailed { cause: unknown }

effect function getTodo(id: number) {
  return try tryPromise({ try: (signal) => fetchTodo(id, signal), catch: (cause) => new TodoFailed({ cause }) })
}
// (id: number) => string!TodoFailed

effect function todoOrFallback(id: number) {
  return retry(getTodo(id), Schedule.recurs(2)) catch () => "Todo unavailable"
}
```

The `tryPromise` callback captures `id` and passes the cancellation signal to `fetchTodo`.

## Effect's features, in VibeLang syntax

Effect's functions and modules are in scope without imports. The common features have their own syntax:

| Effect feature | VibeLang |
| --- | --- |
| Effect types | `User!NotFound!Users`: returns `User`, fails with `NotFound`, needs `Users` |
| Effect functions | `effect function load(id) { const user = try find(id); ... }` |
| Typed errors | `error NotFound { id: string }`, `throw new NotFound({ id })`, `x catch () => fallback` |
| Dependency injection | `service Users { ... }`, `provide UsersLive { ... }` |
| Structured concurrency | `fork work()`, `join f`, `try.all [a(), b()]`, `for concurrent(8) (const id of ids) { ... }` |
| Retries and timeouts | `try (work() \|> retry(%, policy) \|> timeout(%, "1 second"))` |
| Resource safety | `try scoped(effect { const conn = try acquireRelease(connect(), close); ... })`, `try ensuring(work, cleanup)` |
| Tracing | `try withSpan(effect { ... }, "checkout")` |
| Streams | producers `effect function* rows() { yield row }`, `for try (const row of rows()) { ... }` |
| Schema validation | `schema User { id: string; role: "admin" \| "member" }` |
| Pattern matching | `match (e) { when NotFound: ...; }` |

Configuration and Effect's HTTP, SQL, CLI and AI packages keep their library APIs. Run them with `try`. The [cheat sheet](/vibelang-features/115-cheat-sheet) puts every VibeLang form beside the Effect code it replaces.

## Try it

You need Node 22.22.3 or later. Bun is optional, at 1.4 or later.

```sh
npm create vibelang@latest my-app
cd my-app
npm run start
```

With Bun:

```sh
bun create vibelang@latest my-app
cd my-app
bun run start
```

Then open the folder in VS Code or Cursor and install the editor extension that ships with the compiler:

```sh
code --install-extension node_modules/vibelang/editor/vibelang.vsix
```

[Getting Started](/013-getting-started) walks through the starter. [Installation](/getting-started/004-installation) covers platforms, editors and existing projects.
