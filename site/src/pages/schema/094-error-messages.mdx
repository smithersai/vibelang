# Error Messages

Schema error messages work as in Effect. A `SchemaError` combines a readable message with a structured issue, including paths into nested values. Customize a message at the node that fails, so users get an explanation that fits that field. Plain builders follow the [call rules](/schema/085-introduction#configuring-compiler-prerequisites).

## Understanding default validation messages

```vibe
const Package = Schema.Struct({
  label: Schema.String,
  pieces: Schema.Finite
})

effect function explainPackage(input: unknown) {
  return effect {
    try Schema.decodeUnknownEffect(Package)(input, { errors: "all" })
    return "Accepted"
  } catch (error) => error.message
}
// { label: 7, pieces: "several" } reports both expected types and their paths.
```

```text
Expected string
  at ["label"]
Expected number
  at ["pieces"]
Accepted
```

A base-type mismatch reports the expected type, an absent required field `Missing key`; a nested mismatch adds a key or index path. `errors: "all"` collects independent issues instead of stopping at the first. Checks run only after their underlying type is accepted.

## Identifying schemas in error output

```vibe
const Tracking = Schema.String.annotate({ identifier: "TrackingReference" })
const Count = Schema.Finite.annotate({ expected: "a finite package count" })
const LabeledPackage = Schema.Struct({ tracking: Tracking, count: Count }).annotate({
  identifier: "LabeledPackage"
})
```

```text
Expected TrackingReference
  at ["tracking"]
Expected a finite package count
  at ["count"]
Expected number
  at ["count"]
```

An identifier replaces a generic expected-value description with a stable domain name. `expected` supplies readable text for the annotated node or check. `Count` annotates the finite-number check: `NaN` reports `Expected a finite package count`, while a string reports `Expected number` before that check runs. `title` is documentation metadata and leaves the default validation message unchanged.

Naming the whole struct changes only the struct's own errors; an invalid nested tracking value still reports the tracking schema's own identity.

## Customizing messages for checks and conversions

```vibe
const WholeCount = Schema.String.annotate({
  message: "Enter the count as text"
}).pipe(
  Schema.decodeTo(
    Schema.Int.annotate({ message: "Use a whole package count" }),
    {
      decode: SchemaGetter.transformEffect(effect (text) => {
        if (text.trim() === "" || !Number.isFinite(Number(text))) {
          throw new SchemaIssue.InvalidValue({ message: "Count is not numeric" })
        }
        return Number(text)
      }),
      encode: SchemaGetter.transform((count) => String(count))
    }
  )
)
const TrackingText = Schema.String.check(
  Schema.isMinLength(4, { message: "Reference needs at least four characters" }),
  Schema.isMaxLength(24, { message: "Reference is too long" })
)
```

```text
Enter the count as text
Count is not numeric
Use a whole package count
Reference needs at least four characters
```

The conversion has three failure sites, each with its own message: the encoded string, the conversion function, and the decoded integer check. For checks, pass a message to the check constructor; `.annotate({ message })` after several checks targets only the last check, not every earlier failure.

## Assigning messages to scalar and compound values

```vibe
const Contact = Schema.String.annotate({ message: "Contact must be text" })
const Delivery = Schema.Union([
  Schema.Literal("collect"), Schema.Literal("courier")
]).annotate({ message: "Choose collection or courier" })
const Orders = Schema.Struct({
  contacts: Schema.Array(Contact).check(
    Schema.isMinLength(1, { message: "Add a delivery contact" })
  ),
  delivery: Delivery
})

effect function explainOrders(input: unknown) {
  return effect {
    try Schema.decodeUnknownEffect(Orders)(input, { errors: "all" })
    return "Accepted"
  } catch (error) => error.message
}
```

```text
Add a delivery contact
  at ["contacts"]
Choose collection or courier
  at ["delivery"]
Contact must be text
  at ["contacts"][0]
```

A scalar message replaces a mismatch at that scalar. A union message summarizes failure of all alternatives, and a collection check explains a failure of the collection's size. Nested failures keep their own messages and paths; a message on an outer node does not replace every inner issue.

## Explaining missing fields

```vibe
const Dispatch = Schema.Struct({
  tracking: Schema.String.annotateKey({
    messageMissingKey: "Supply a tracking reference"
  })
})
const Coordinates = Schema.Tuple([
  Schema.Finite.annotateKey({ messageMissingKey: "Supply longitude" }),
  Schema.Finite.annotateKey({ messageMissingKey: "Supply latitude" })
])

effect function readCoordinates(input: unknown) {
  return try Schema.decodeUnknownEffect(Coordinates)(input, { errors: "all" })
}
```

```text
Supply a tracking reference
  at ["tracking"]
Supply longitude
  at [0]
Supply latitude
  at [1]
```

`messageMissingKey` belongs to a field or tuple position and explains absence; a present but wrong value still uses its value schema's message. This lets a form give different instructions for a missing answer and an invalid one.
