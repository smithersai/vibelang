# Managing Services

A service is a named capability a program uses without passing an implementation through every function. `service` declares its key and members' contracts; looking up its implementation with `try` adds the identifier to the `R` channel.


The transitional `static readonly default = implementation` form keeps its `EK4855` migration warning. `vibelang --fix` can rename the field and its value/type reads before the canonical static-member rules apply.

## Declaring typed service keys

```vibe
service Sequence {
  next(): number!!
}

service Reporter {
  write(message: string): void!!
}

effect function stringify(value: unknown) {
  return try Effect.try(() => JSON.stringify(value))
}
// Output: ticket-17
```

Export a service with `export service Counter { readonly value: number }`, or declare it and write `export { Counter as default }`. `export default service Counter { }` reports `EK0905`; an ordinary expression whose variable is named `service` can still follow `export default`.

Separate service method and property signatures with `;`, a newline, or `,`, as in a TypeScript interface. A trailing comma is allowed.

A service has no superclass or type parameters, and every instance member is abstract. Methods and properties declare the service's shape as in a TypeScript `interface`; `readonly` value members are allowed. Write intended types; a default factory does not infer missing member types. Its only static members are `static readonly key` and `defaultValue`; keep layers and helpers in ordinary declarations beside it. Two members on one line with no separator are `EK0908`, whose quick fix inserts `;`. Value members are mutable unless declared `readonly`. When `--fix` converts a `Context.Service` class, it preserves the shape's `readonly` properties. Other static fields, methods, accessors and initialization blocks report `EK0902`. An instance method body, a value initializer, or an accessor is `EK0902`; declare the member's contract and implement it in a layer.

Service contracts also work with `noUnusedLocals` and `noUnusedParameters`. Their bodyless signatures describe an implementation; unused checks still apply to actual private implementation members.

Service methods and properties accept semicolons, commas or line breaks between members. Formatting accepts these separators and preserves the member types and comments, including commas inside tuple, generic and function types.


Bodyless properties and methods use interface syntax. Class-only modifiers such as `public`, `private`, `protected`, `abstract`, `declare`, `accessor`, `override`, `async` and `effect`, private names such as `#count`, and definite assignment assertions such as `count!: number` are `EK0902`. `readonly` belongs only on a property, not a method. The editor quick fix and `vibelang --fix` remove a modifier or assertion while retaining comments and the written contract; a private name needs an explicit public name.

`Users.Shape` names the written member object directly, so service contracts can refer to their own or another service's `.Shape`. A service cannot declare type parameters or capture an enclosing type parameter in a member contract (`EK3005`): different specializations would share one runtime key. Use a concrete contract or a member-local generic method independent of outer parameters. An unused argument does not capture a type parameter: `Phantom<T>` is allowed when `interface Phantom<U> { n: number }` never uses `U`. A foreign callable's written `@throws` contract also counts when checking captures. Conditional branches count too: `U extends string ? T : number` captures an enclosing `T` even when `U` belongs to the member.

A service declaration takes no `extends` or `implements` clause (`EK0904`): its identity is its key. Compose shapes with types instead, such as `find: Base.Shape["find"]`.

A service method may declare a plain return type, such as `lookup(): number`, or an Effect return type, such as `lookup(): number!!`, as a `Context.Service` shape can. An omitted member type follows TypeScript, as in an interface: under `noImplicitAny`, `read()` is `TS7010` and an untyped property is `TS7008`; with the option off they are `any`. Explicit `read(): any` is valid under strict checking. VibeLang adds no diagnostic of its own and infers no Effect contract; fix `TS7010` by writing the intended return type.

At module or namespace scope, `Users.Shape` names a service's implementation type. A function or block cannot declare that companion namespace: write `Context.Service.Shape<typeof Users>` for a local service instead. The editor offers this replacement, and `vibelang --fix` migrates a local `Users.Shape` annotation. Within the service's own instance member type, `Users.Shape` remains a type-only self-reference. A member-local type parameter named `Users` shadows that service name, as in TypeScript.

Copying a service value into a `const` or an object property keeps the same service identity. The restrictions on `new`, `extends` and `instanceof` apply through those aliases and through parentheses too.

A `service` body cannot contain constructors or index signatures, such as `[name: string]: Value`; each reports `EK0902`. Declare named properties and methods instead. For a dictionary implementation, declare its type separately and use an explicit `Context.Service` class, as below.

Construct signatures directly in a service body, such as `new(): T!!` and `new<T>(value: T): T!!` are `EK0902`: declare a named factory method or a property whose value is a constructor instead. A method literally named `new` can use a quoted name, `"new"(): T!!`.

A call signature directly in a service body, such as `(value: string): string`, is `EK0902`: declare a named method, or a property whose type is a function, such as `format: (value: string) => string`.

A service needs its body, even an empty one: `service Users` alone is `EK0906`. A service creates a run-time key, so it cannot be ambient: `declare service Users { … }`, or a service inside a `declare namespace` or `declare module`, is `EK0907`. Two members on one line need a separator, `;` or a line break: `a: number b: string` is `EK0908`, and its quick fix inserts `;`.

The `EK0908` repair inserts `;` before the following member's comments and JSDoc, retaining its `@throws` contract.

Services are nominal: the compiler derives the key from package, module path, and declaration name, so two services with identical members are different dependencies. To keep a key, such as one a `Context.Service` class wrote before migrating, write it in the body: `static readonly key = "app/Users"`. A `key` that is not `static readonly` with a quoted string literal is `EK0901`. A type annotation is allowed, as in `static readonly key: string = "app/Users"`; a template literal or computed initializer is not. An `abstract class` is an ordinary TypeScript class; one written as a service draws `EK4854`, whose fix, which `vibelang --fix` applies, writes the `service` declaration with its members and key. Implement one with an object literal or a class that `implements` its `.Shape`; don't construct, extend, or use `instanceof` on it.

When migrating, preserve every original explicit key; deriving a new key can break providers across package boundaries or persisted identities.

An explicit string-literal key keeps its value, including `""`. It is used for runtime lookup, the emitted key type, and duplicate-key checks; an empty literal does not request a derived key.

Derived keys require a module-scope declaration in a package whose `package.json` has a string `name`. A local or block-scoped service, or one outside a named package, reports `EK0903` when it omits `static readonly key`. The editor quick fix and `vibelang --fix` insert an explicit key while preserving the declaration's current runtime identity. A namespace at module scope can still derive its services' keys.

The special `key` and `defaultValue` property headers allow only `static readonly`, without `public`, `private`, `protected`, `declare`, optional `?` or definite `!` markers. `defaultValue` also needs an initializer. Malformed headers report `EK0902`; invalid key literals or a missing `readonly` on `key` use the key-validation diagnostic instead.

A `defaultValue` initializer has ordinary class-field context, even when its service is declared inside an effect function. A `try` expression there is `EK0501`. Compute an effectful input before the service declaration, then capture the resulting value in its `() => Shape` default factory.

A service's shape may have properties named `key` or `defaultValue`. They are ordinary implementation members and can coexist with the service's `static readonly key` and `static readonly defaultValue`. Read them from the implementation returned by `try Effect.service(ServiceName)`.

Service members form an object type, so a written `this` type there gets TypeScript's `TS2526` rather than referring to a service instance. For recursive members, name the implementation type; a separately declared interface can use its ordinary polymorphic `this` type and become a service's shape. Ordinary classes keep their `this` types.

## Declaring a service of any shape

```vibe
interface SearchApi {
  find(query: string): string!!
}

class Search extends Context.Service<Search, SearchApi>()("app/Search") {}
class Prefix extends Context.Service<Prefix, string>()("app/Prefix") {}

effect function lookup(query: string) {
  const prefix = try Prefix
  const search = try Search
  return `${prefix}${try search.find(query)}`
}
// Output: > hit:vibe
```

Use Effect's `Context.Service` class for a service whose implementation has any type: an interface declared elsewhere, a primitive such as `string`, or a function type. `class Search extends Context.Service<Search, SearchApi>()("app/Search") {}` declares a key with an explicit identity. Its body can hold static members, such as `static readonly layer = Layer.succeed(Search, impl)`; declare implementation members in `SearchApi`. Read the implementation with `const search = try Search`, then run an Effect-returning member with `try search.find(q)`; `try Prefix` returns the string implementation. The type `Search` is the service's identifier, so type an implementation `SearchApi` or `Context.Service.Shape<typeof Search>`.

## Requesting and supplying implementations

```vibe
effect function nextLabel() {
  const sequence = try Sequence
  return `ticket-${try sequence.next()}`
}
// string!!Sequence

effect function fixedLabel() {
  return try provideService(nextLabel(), Sequence, {
    next: effect () => 17
  })
}
// string!!

effect function readImplementation() {
  const sequence = try Sequence
  return try sequence.next()
}
// number!!Sequence
// Output: ticket-17
// Output: ticket-23 23
```

A service can declare `static readonly defaultValue = () => implementation` to supply an implementation without a provider. It compiles to a `Context.Reference`. The returned implementation is checked against the service shape, as with `Layer.succeed`. For `Layer.succeed`, the compiler reports a shape mismatch as a TypeScript error, an excess member failure as `EK9201`, and an undeclared call-time requirement as `EK3101`. Support for the new `defaultValue` form arrives with the compiler's VIP implementation.

A reference has `Flags.Shape` for its implementation and `typeof Flags` for its key value, but no `Flags` identifier type. Writing `let value: Flags` reports `TS2749`, as for Effect's `Context.Reference`; references do not appear in `R`. An import type such as `import("./flags.vibe").Flags` reports `TS2694`; use `typeof import("./flags.vibe").Flags` for the key value.

`try Sequence` looks up the implementation, to capture it or read value members; `try sequence.next()` runs its Effect-returning method. Supply every requirement before running the program.

```vibe
service Settings {
  baseUrl: string
}

effect function endpoint(path: string) {
  const settings = try Settings
  return `${settings.baseUrl}/${path}`
}
// string!!Settings
// Output: https://example.test/tickets
```

Read value members from the implementation, as `settings.baseUrl` after `const settings = try Settings`. Looking up a service adds it to `R` whatever its members return, including when a `catch` handles a member's typed failure or a pipe transforms its Effect: `const path = try Path.Path; path.join(a, b)` returns a plain string and still requires Effect's `Path` service. Wrap a synchronous member call that may throw with `Effect.try` and run it with `try`; wrap a Promise with `tryPromise` and run it with `try`. A member that is itself an Effect value runs with `try`, as in `try terminal.readLine`.

`provideService` removes the dependency only within its program. Nested overrides are local, a captured implementation stays the same object across later overrides or pauses, and forked fibers inherit the context present when they start.

## Service identifiers and shapes

```vibe
type SequenceImplementation = Sequence.Shape
type SameImplementation = Context.Service.Shape<typeof Sequence>
```

A service has two types, as an Effect `Context.Key` has, because it is Effect's own `Context.Service` class. As a type, `Sequence` is the service's identifier, which carries its key, so neither another service with the same members nor a structural type such as `{ next(): number!! }` can stand for it in `R`. `Sequence.Shape`, which Effect spells `Context.Service.Shape<typeof Sequence>`, is the members alone, the type of an implementation. `Layer.succeed`, `Layer.effect`, `provideService`, `provide Sequence = …`, and a `defaultValue` factory check an implementation against the shape, and `implements Sequence.Shape` in a `.vibe` file checks a class against it.

`try Sequence` returns the implementation typed as the shape, as `yield* Sequence` does. The same lookup works for imported keys and inside exported `effect` functions. Type a parameter or a default implementation `Sequence.Shape`; a parameter typed `Sequence` takes the identifier, as in Effect TypeScript. A TypeScript class implements the emitted service with `implements Context.Service.Shape<typeof Sequence>`. The emitted declarations also export `Sequence.Shape`, so TypeScript callers can use that name directly. The key and public alias share a private named member type, preserving recursive shapes and their `readonly` members.

Providers infer and check the implementation from the key argument, so most layers don't need either name. At a TypeScript boundary, the shape describes the emitted implementation's Effect-returning methods.

## Combining multiple dependencies

```vibe
effect function announceTicket() {
  const label = try nextLabel()
  const reporter = try Reporter
  try reporter.write(`Created ${label}`)
  return label
}
// string!!(Sequence | Reporter)

const SequenceTest = Layer.succeed(Sequence, {
  effect next() { return 17 }
})
const ReporterTest = Layer.succeed(Reporter, {
  effect write(_message) {}
})

effect function testAnnouncement() {
  provide Layer.merge(SequenceTest, ReporterTest) { return try announceTicket() }
}
// Output: "ticket-17"
```

A union in `R` needs both capabilities. Layers supply the group together; `Layer.merge` combines independent layers, and `Layer.provide` feeds one layer's outputs into another's construction requirements. Inputs no argument provides stay requirements of the resulting layer, reported as missing where a runner or contract needs them satisfied. For a small local override, nest direct service provision.

```vibe
const testContext = Context.add(
  Context.make(Sequence, { next: effect () => 17 }),
  Reporter,
  { write: effect (_message) => {} }
)

effect function testWithContext() {
  return try Effect.provide(announceTicket(), testContext)
}
// Output: ticket-17
```

A `Context` holds existing implementations; a `Layer` describes how to build them. A `provide` block takes layers and `Key = value` entries, or a single `Context`. `testWithContext` passes its `Context` to `Effect.provide` directly, which works too. `provide` is a statement, not an expression: return the value from inside its block. Keep resource-owning implementations within the lifetime that created them.

## Requesting optional services

```vibe
effect function optionalAnnouncement(message: string) {
  const reporter = try serviceOption(Reporter)
  if (Option.isNone(reporter)) return false
  try reporter.value.write(message)
  return true
}
// boolean!!
// Output: false
// Output: hello
// Output: true
```

`serviceOption` returns `None` when an application service is absent and `Some(implementation)` when present, without adding the service to `R`. Calling a found implementation still carries the method errors and call-time requirements the service declares.

## Handling dependencies between services

```vibe
service ReportSettings {
  prefix: string
}

const ReporterLive = Layer.effect(Reporter, effect {
  const settings = try ReportSettings
  return {
    effect write(message) {
      try Console.log(`${settings.prefix}: ${message}`)
    }
  }
})
// Layer<Reporter, never, ReportSettings>
// Output: audit: ready
```

Capture construction dependencies in the layer factory: `try reporter.write(...)` then requires only `Reporter`, because the implementation retains `settings`. Looking up `try ReportSettings` inside `write` would add a call-time requirement, which its declared `R = never` rejects.

## Coming from Effect

`service` declarations replace hand-written `Context.Service` declarations in `.vibe` files. A `Context.Service` class there draws EK4831, whose quick fix writes the `service` declaration, keeping the class's key as `static readonly key`, when its members are written in the class's type argument ([TypeScript-style Effect code](/getting-started/012-devtools#typescript-style-effect-code)). Support for the new forms arrives with the compiler's VIP implementation. `try ServiceName` replaces yielding the key in a TypeScript generator to get its implementation; `try implementation.method()` runs an Effect-returning method.

Service members follow TypeScript interface typing. Omitting a method's return type gives `TS7010` under `noImplicitAny`; an untyped property gives `TS7008`. With that option disabled both are `any`, and an explicit `read(): any` works under strict checking. Write the intended type; no Effect return is required.
