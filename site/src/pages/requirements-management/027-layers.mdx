# Managing Layers

A `Layer<Out, E, In>` is a recipe for building services: what it produces (`Out`), how construction can fail (`E`), and what dependencies it needs to build (`In`). Build your application's layer graph once around `main` so services share one managed lifetime and clean up together on shutdown.

## The service graph we will wire

```vibe
service Settings {
  prefix: string
}
service Printer {
  print(text: string): void!!
}
service Reports {
  render(title: string): string!!
}

effect function report(title: string) {
  const reports = try Reports
  return try reports.render(title)
}
// Inferred: string!!Reports
// Run in an effect function: provide Reports = { render: effect (title) => `report/${title}` } { try Console.log(try report("Inventory")) }
// Output: report/Inventory
```

Here `Printer` depends on `Settings`, and `Reports` depends on both `Settings` and `Printer`.

## Building layers without leaking dependencies

Capture dependencies inside `Layer.effect(Service, effect { ... })` so callers of `Printer` never have to know `Printer` uses `Settings`:

```vibe
const PrinterLive = Layer.effect(Printer, effect {
  const settings = try Settings
  return {
    effect print(text) {
      try Console.log(`${settings.prefix}: ${text}`)
    }
  }
})
// Inferred: Layer<Printer, never, Settings>
// Run in an effect function: provide Settings = { prefix: "test" } { provide PrinterLive { const printer = try Printer; try printer.print("ready") } }
// Output: test: ready
```

Choose the layer constructor that matches your setup work:

| Constructor | Use when |
| --- | --- |
| `Layer.succeed(S, impl)` | Pure object or constant implementation |
| `Layer.sync(S, () => impl)` | Synchronous non-throwing factory |
| `Layer.effect(S, effect { ... })` | Setup runs Effects, reads other services, or acquires scoped resources via `acquireRelease` / `addFinalizer` |

`Layer.effect` supplies its own construction `Scope`, so resources acquired during layer setup stay open for the lifetime of the layer and close automatically when the `provide` block exits.

```vibe
const SettingsLive = Layer.succeed(Settings, {
  prefix: "reports"
})
// Layer<Settings, never, never>

const ReportsLive = Layer.effect(Reports, effect {
  const settings = try Settings
  const printer = try Printer
  return {
    effect render(title) {
      try printer.print("Rendering report")
      return `${settings.prefix}/${title}`
    }
  }
})
// Layer<Reports, never, Settings | Printer>
// Run in an effect function: provide SettingsLive { provide PrinterLive { provide ReportsLive { try Console.log(try report("Inventory")) } } }
// Output: reports: Rendering report
// Output: reports/Inventory
```

## Merging vs. wiring layers

This is the single rule to remember when composing layers:

- **`Layer.merge` / `Layer.mergeAll`** combines **independent** layers side by side. It does **not** feed one layer's output into another's input (doing so triggers warning `EK4807`).
- **`Layer.provide(consumer, dep)`** feeds `dep`'s outputs into `consumer`'s inputs and exposes only `consumer`'s outputs.
- **`Layer.provideMerge(consumer, dep)`** feeds `dep` into `consumer` and exposes **both** outputs.

```vibe
// expect-warning: EK4807
const Merged = Layer.merge(SettingsLive, PrinterLive)
// Layer<Settings | Printer, never, Settings>  (PrinterLive still needs Settings!)

const Many = Layer.mergeAll(SettingsLive, PrinterLive, ReportsLive)
// Layer<Settings | Printer | Reports, never, Settings | Printer>
// Run in an effect function: provide SettingsLive { provide PrinterLive { provide Merged { const printer = try Printer; try printer.print("merged") }; provide Many { try Console.log(try report("many")) } } }
// Output: reports: merged
// Output: reports: Rendering report
// Output: reports/many
```

Wire the dependency edges explicitly with `Layer.provide` and `Layer.provideMerge`:

```vibe
const PrinterReady = Layer.provide(PrinterLive, SettingsLive)
// Layer<Printer, never, never>

const PrinterAndSettings = Layer.provideMerge(PrinterLive, SettingsLive)
// Layer<Printer | Settings, never, never>

const ReportsReady = Layer.provide(ReportsLive, PrinterAndSettings)
// Layer<Reports, never, never>

const AppLive = ReportsLive |> Layer.provideMerge(%, PrinterAndSettings)
// Layer<Reports | Printer | Settings, never, never>
// Run in an effect function:
//   provide PrinterReady {
//     const printer = try Printer
//     try printer.print("ready")
//   }
//   provide PrinterAndSettings { try Console.log((try Settings).prefix) }
//   provide ReportsReady { try Console.log(try report("wired")) }
//   provide AppLive { try Console.log(try report("app")) }
// Output: reports: ready
// Output: reports
// Output: reports: Rendering report
// Output: reports/wired
// Output: reports: Rendering report
// Output: reports/app
```

Any requirement left unsatisfied stays in `In` until a runner or contract flags it (`EK9211` / `EK9202`). Reuse the same layer reference across branches when you want Effect to memoize and build it only once ([Layer Memoization](/requirements-management/028-layer-memoization)).

## Providing layers with `provide`

```vibe
effect function main() {
  provide AppLive {
    const first = try report("Inventory")
    const second = try report("Forecast")
    return [first, second]
  }
}
// Inferred: string[]!!

effect function withBuiltContext() {
  return try scoped(effect {
    const context = try Layer.build(AppLive)
    provide context { return try report("Inventory") }
  })
}
// Run in an effect function:
//   {
//     const jsonValue = try main()
//     try Console.log(try Effect.try(() => JSON.stringify(jsonValue)))
//   }
//   try Console.log(try withBuiltContext())
// Output: reports: Rendering report
// Output: reports: Rendering report
// Output: ["reports/Inventory","reports/Forecast"]
// Output: reports: Rendering report
// Output: reports/Inventory
```

`provide AppLive { ... }` is a statement inside effect code (`EK1201` outside):

- It builds `AppLive` once, shares its implementations across the block, and releases its resources when the block finishes.
- `return`, `break`, and `continue` inside `provide` target the enclosing function or loop normally.
- It accepts comma-separated layers and `Service = value` bindings on one line (`EK1202` for line breaks around the comma — use `Layer.mergeAll(...)` for multiline composition), or a single `Context`.
- For long-running layer-only apps (like an HTTP server), use `Layer.launch(AppLive)`. For multiple entry points sharing one service graph, use [ManagedRuntime](/036-runtime).

## Observing and recovering layer startup failures

```vibe
error InitializationFailed

const ReportsUnavailable = Layer.effect(Reports, effect {
  throw new InitializationFailed()
})

const ReportsFallback = Layer.succeed(Reports, {
  effect render(title) { return `Offline report: ${title}` }
})

const ObservedReports = ReportsUnavailable
  |> Layer.tap(%, () => Console.log("Reports initialized"))
  |> Layer.tapError(%, (error) => Console.log(`Reports initialization failed: ${error._tag}`))

const ResilientReports = Layer.catch(ObservedReports, () => ReportsFallback)
// Run in an effect function: provide ResilientReports { try Console.log(try report("Inventory")) }
// Output: Reports initialization failed: InitializationFailed
// Output: Offline report: Inventory
```

`Layer.catch` recovers **construction** failures with a fallback layer (not failures from later service method calls). If a larger graph fails partway through initialization, already-acquired layers still release cleanly.

## Swapping layers in tests

Separate the raw factory (`BannerWithoutDependencies`) from its production wiring (`BannerLive`) so tests can either swap a single dependency or replace the service outright:

```vibe
service Banner {
  text(title: string): string!!
}

effect function makeBanner(): Banner.Shape!!Settings {
  const settings = try Settings
  return { text: effect (title) => `${settings.prefix}: ${title}` }
}

const BannerWithoutDependencies = Layer.effect(Banner, makeBanner())
const BannerLive = Layer.provide(BannerWithoutDependencies, SettingsLive)
// Run in an effect function:
//   provide BannerLive {
//     const banner = try Banner
//     try Console.log(try banner.text("Orders"))
//   }
// Output: reports: Orders
```

```vibe
// expect-warning: EK4808
const SettingsTest = Layer.succeed(Settings, { prefix: "test" })
const BannerWithTestSettings = Layer.provide(BannerWithoutDependencies, SettingsTest)
const BannerTest = Layer.succeed(Banner, {
  effect text(title) { return `fixture/${title}` }
})

effect function testBannerDependency() {
  provide BannerWithTestSettings {
    return try (try Banner).text("Orders")
  }
}

effect function testBannerDirectly() {
  provide BannerTest {
    return try (try Banner).text("Orders")
  }
}

effect function testBannerWithInlineSettings() {
  provide Settings = { prefix: "inline" } {
    provide BannerWithoutDependencies {
      const banner = try Banner
      return try banner.text("Orders")
    }
  }
}
// Run in an effect function:
//   {
//     const jsonValue = [try testBannerDependency(), try testBannerDirectly(), try testBannerWithInlineSettings()]
//     try Console.log(try Effect.try(() => JSON.stringify(jsonValue)))
//   }
// Output: ["test: Orders","fixture/Orders","inline: Orders"]
```

Notice the nested `provide` in `testBannerWithInlineSettings`: providers in a single comma list supply the block in parallel and do not feed one another's construction inputs, so put construction dependencies in an outer `provide` block (or compose with `Layer.provide`).

## Coming from Effect

- `provide AppLive { ... }` replaces `try Effect.provide(effect { ... }, AppLive)` (direct `try Effect.provide(...)` draws advisory `EK4836`).
- Legacy `layer Live: Service { ... }` (`EK2121`), `wire(A, B)`, and `with Live { ... }` forms are retired — use `Layer.succeed`, `Layer.effect`, `Layer.provideMerge`, and `provide`.
