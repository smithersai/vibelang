## Overview

VibeLang is a language for building reliable TypeScript in the AI era, built on [Effect](https://effect.website). It gives Effect a simple, readable syntax. The compiler turns it into ordinary Effect code that your team can read and ship, and `.ts` files, npm packages and the rest of the TypeScript ecosystem stay one import away.

### One program, twice

:::code-group

```vibe [VibeLang]
interface User { id: string; name: string }

error UserNotFound { id: string }

service Users {
  static readonly key = "app/Users"
  find(id: string): User!UserNotFound
}

effect function greet(id: string) {
  const users = try Users
  const user = users.find(id) catch () => ({ name: "guest" })
  return `Hello, ${user.name}`
}

const UsersLive = Layer.succeed(Users, {
  find: effect (id: string) => ({ id, name: "Ada" })
})

effect function main() {
  provide UsersLive {
    try Console.log(try greet("ada"))   // Hello, Ada
  }
}
```

```ts [Effect]
import { Console, Context, Data, Effect, Layer } from "effect"

interface User { id: string; name: string }

class UserNotFound extends Data.TaggedError("UserNotFound")<{ readonly id: string }> {}

class Users extends Context.Service<Users, {
  find(id: string): Effect.Effect<User, UserNotFound>
}>()("app/Users") {}

const greet = (id: string) => Effect.gen(function* () {
  const users = yield* Users
  const user = yield* users.find(id).pipe(Effect.orElseSucceed(() => ({ name: "guest" })))
  return `Hello, ${user.name}`
})

const UsersLive = Layer.succeed(Users, {
  find: (id: string) => Effect.succeed({ id, name: "Ada" })
})

const main = Effect.gen(function* () {
  yield* Console.log(yield* greet("ada"))
}).pipe(Effect.provide(UsersLive))
```

:::

Both programs print `Hello, Ada`, and both run on Effect. `error` declares the tagged error class, `service` declares the dependency, `effect function` returns an Effect, `try` runs one, `catch` handles the declared failure, and `provide` supplies the layer. The compiler infers the type of `greet` as `string!!Users`, which is `Effect<string, never, Users>`. [Welcome](/001-onboarding) walks through this program, and [Why VibeLang?](/getting-started/002-why-effect) makes the case, including Effect's own argument against a language.

### TypeScript stays one step away

The compiler is a fork of the TypeScript 7 compiler. It checks `.vibe` and `.ts` files in one program and emits JavaScript plus a `.d.vibe.ts` declaration beside each `.vibe` file, so TypeScript imports VibeLang functions as ordinary Effect functions. A `.ts` file can sit beside any `.vibe` file. Based on [Effect's Creating Effects](https://effect.website/docs/v4/getting-started/creating-effects#trypromise), this adapter wraps an `async` function from a `.ts` file:

```vibe
import { fetchTodo } from "./todos.ts" // (id: number, signal: AbortSignal) => Promise<string>

error TodoFailed { cause: unknown }

effect function getTodo(id: number) {
  return try tryPromise({ try: (signal) => fetchTodo(id, signal), catch: (cause) => new TodoFailed({ cause }) })
}
// (id: number) => string!TodoFailed

effect function todoOrFallback(id: number) {
  return retry(getTodo(id), Schedule.recurs(2)) catch () => "Todo unavailable"
}
```

### Effect, with syntax

Effect's functions and modules are in scope without imports. `error`, `service`, `provide`, `try.all`, `fork`, `for concurrent`, `schema`, `data` and `match` give the common features their own syntax, and every other Effect API keeps its library form. The [cheat sheet](/vibelang-features/115-cheat-sheet) puts every form beside the Effect code it replaces.

## Where to go next

- **Start:** [Welcome](/001-onboarding), then [Getting Started](/013-getting-started) for the starter project. You need Node 22.22.3 or later. Bun is optional, at 1.4 or later.
- **Coming from Effect:** the [cheat sheet](/vibelang-features/115-cheat-sheet) shows every change, and [VibeLang for Effect users](/vibelang-features/114-vibelang-for-effect-users) explains the rules.
- **Set up a project or editor:** [Set up VibeLang](/setup) covers new and existing projects, Vite, React, Vue, Svelte, VS Code, Neovim and Zed.

VibeLang is in early alpha. The language will change in major, breaking ways, and it is not ready for production use. The release rehearsal creates, starts and tests a starter with npm and Bun on Linux x64. The other five binaries are cross-built.

Version 0.0.11 provides native packages for macOS, Linux and Windows on arm64 and x64.
