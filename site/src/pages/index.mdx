## Overview

VibeLang is [Effect](https://effect.website) as its own language, written in TypeScript syntax. Effect puts what a function returns, what can fail, and what it depends on into one type, `Effect<Success, Error, Requirements>`, and the compiler checks it. As a library, Effect builds every feature out of generators, `yield*`, `pipe`, and classes. VibeLang gives each Effect idea its own syntax, and its compiler builds the same Effect program you would have written by hand.

### Effect functions

:::code-group

```vibe [VibeLang]
interface User { id: string; name: string }

error UserNotFound { id: string }

service Users {
  find(id: string): User!UserNotFound
}

effect nameOf(id: string) {
  const users = try Users
  const user = try users.find(id)
  return user.name
}

effect greet(id: string) {
  const name = nameOf(id) catch "guest"
  return `Hello, ${name}`
}
// (id: string) => string!!Users
```

```ts [Effect]
import { Context, Data, Effect } from "effect"

interface User { id: string; name: string }
class UserNotFound extends Data.TaggedError("UserNotFound")<{ id: string }> {}
class Users extends Context.Service<Users, {
  find(id: string): Effect.Effect<User, UserNotFound>
}>()("app/Users") {}

function greet(id: string) {
  return Effect.gen(function* () {
    const users = yield* Users
    const name = yield* users.find(id).pipe(
      Effect.map((user) => user.name),
      Effect.orElseSucceed(() => "guest")
    )
    return `Hello, ${name}`
  })
}
```

:::

An `effect` function returns an Effect, as an `async` function returns a Promise. The comment under `greet` is the type your editor shows: `string!!Users` is exactly `Effect<string, never, Users>`, so `greet` gives a `string`, cannot fail, and needs the `Users` service. The compiler infers it from the body, and TypeScript code that imports `greet` sees the same Effect type.

`try` runs an Effect and gives its value, `throw` fails with a typed error, `catch` handles it, `service` declares a dependency, and `fork` starts a fiber. Every form is exact sugar for the Effect code beside it.

### Retries, timeouts, and concurrency

:::code-group

```vibe [VibeLang]
error ApiError { status: number }

service Users {
  name(id: string): string!ApiError
}

effect nameOf(id: string) {
  const users = try Users
  const attempt = users.name(id)
    |> retry(%, Schedule.exponential("100 millis"))
    |> timeout(%, "2 seconds")
  return attempt catch "unknown"
}

export effect names(ids: ReadonlyArray<string>) {
  const all = try forEach(ids, nameOf, { concurrency: 8 })
  try log(`Loaded ${all.length} names`)
  return all
}
```

```ts [Effect]
import { Context, Effect, Schedule, Schema } from "effect"

class ApiError extends Schema.TaggedError<ApiError>()("ApiError", {
  status: Schema.Number
}) {}

class Users extends Context.Service<Users, {
  name(id: string): Effect.Effect<string, ApiError>
}>()("app/Users") {}

const nameOf = Effect.fn("nameOf")(function* (id: string) {
  const users = yield* Users
  return yield* users.name(id).pipe(
    Effect.retry(Schedule.exponential("100 millis")),
    Effect.timeout("2 seconds"),
    Effect.orElseSucceed(() => "unknown")
  )
})

export const names = Effect.fn("names")(function* (ids: ReadonlyArray<string>) {
  const all = yield* Effect.forEach(ids, nameOf, { concurrency: 8 })
  yield* Effect.log(`Loaded ${all.length} names`)
  return all
})
```

:::

Both versions describe the same program. A call returns its Effect without running it, so the pipe operator `|>` passes the Effect `users.name(id)` to `retry` and `timeout`, which can run it again. `catch "unknown"` runs the result and removes every failure, including the timeout, so `nameOf` gives `string!!Users`. `forEach` with `{ concurrency: 8 }` loads up to eight names at once.

### Hello, VibeLang

Create a project from the starter. You need Node 26 or later. Bun is optional. If you use Bun, use Bun 1.4 or later.

```bash
npm create vibelang@latest my-app
cd my-app
npm run start
```

The starter's two source files:

:::code-group

```vibe [src/greeting.vibe]
export error EmptyName

export effect greeting(name: string) {
  if (name.length === 0) throw new EmptyName()
  return `Hello, ${name}!`
}
```

```vibe [src/main.vibe]
import * as NodeRuntime from "@effect/platform-node/NodeRuntime"
import { EmptyName, greeting } from "./greeting.vibe"

service Greeter {
  greet(name: string): string!EmptyName
}

const GreeterLive = Layer.succeed(Greeter, {
  greet: (name: string) => greeting(name)
})

export effect main() {
  provide GreeterLive {
    const greeter = try Greeter
    try Console.log(try greeter.greet("VibeLang"))
    const recovered = greeter.greet("") catch (error) => `Recovered from ${error._tag}`
    try Console.log(recovered)
  }
}

NodeRuntime.runMain(main())
```

:::

`npm run start` compiles the project, and the module runs `main` with Node's runner, which prints:

```text
Hello, VibeLang!
Recovered from EmptyName
```

### TypeScript stays one step away

VibeLang's compiler is TypeScript's compiler, extended. It checks `.vibe` and `.ts` files together and emits JavaScript and declarations, so npm packages, your `.ts` files, and Effect libraries compatible with the supported Effect version work unchanged. TypeScript code calls VibeLang's `effect` functions as ordinary Effect functions.

Plain and `async` functions in a `.vibe` file are TypeScript's, and a `.ts` file can sit beside any `.vibe` file. Effect's own functions adapt the rest: `tryPromise` wraps a Promise, `Effect.try` wraps a call that may throw, and `callback` wraps a callback API. Based on [Effect’s Creating Effects](https://effect.website/docs/v3/getting-started/creating-effects#trypromise), this adapter wraps an `async` function from a `.ts` file:

```vibe
import { fetchTodo } from "./todos.ts" // (id: number, signal: AbortSignal) => Promise<string>

error TodoFailed { cause: unknown }

effect getTodo(id: number) {
  return try tryPromise({ try: (signal) => fetchTodo(id, signal), catch: (cause) => new TodoFailed({ cause }) })
}
// (id: number) => string!TodoFailed

effect todoOrFallback(id: number) {
  return retry(getTodo(id), Schedule.recurs(2)) catch "Todo unavailable"
}
```

## Features

Everything Effect does is reachable from VibeLang: Effect's functions and modules are in scope, so use its APIs directly. The common features have their own syntax:

| Effect feature | VibeLang |
| --- | --- |
| Effect types | `User!NotFound!Users`: returns `User`, fails with `NotFound`, needs `Users` |
| Effect functions | `effect load(id) { const user = try find(id); ... }` |
| Typed errors | `error NotFound { id: string }`, `throw new NotFound({ id })`, `x catch fallback` |
| Dependency injection | `service Users { ... }`, `provide UsersLive { ... }` |
| Structured concurrency | `fork work()`, `join f`, `try.all [a(), b()]`, `for concurrent(8) (const id of ids) { ... }` |
| Retries and timeouts | `work() \|> retry(%, policy) \|> timeout(%, "1 second")` |
| Resource safety | `try scoped(effect { const conn = try acquireRelease(connect(), close); ... })`, `ensuring` |
| Tracing | `try withSpan(effect { ... }, "checkout")` |
| Streams | producers `effect function* rows() { yield row }`, `for try (const row of rows()) { ... }` |
| Schema validation | `schema User { id: string; role: "admin" \| "member" }` |
| Pattern matching | `match (e) { when NotFound: ...; }` |

Streams, configuration, and Effect's HTTP, SQL, CLI, and AI packages need no syntax of their own: call them as you would in TypeScript. The [cheat sheet](/vibelang-features/115-cheat-sheet) puts every VibeLang form beside the Effect code it replaces.

## Built for coding agents

When coding agents write a growing share of your code, the hard part moves from writing code to trusting it.

- **The compiler checks what agents write.** Every function's type lists what it can fail with and what it needs, and code that breaks a declared type does not compile.
{/* token-headline:start */}

- **People can review what agents write.** [8.9% fewer tokens across the 47 cheat-sheet pairs](/vibelang-features/117-token-counts); VibeLang is longer in 17 pairs.

{/* token-headline:end */}
- **Agents write less.** Fewer tokens per program means less to generate and less context to read back.
