# Coding agents

`npx vibelang agents init` configures a repository's coding agents for `.vibe` and `.vibex` files—installing the VibeLang skill, `AGENTS.md` instructions, LSP config where supported, and a post-edit check that feeds compiler errors back to the agent. Run it in an existing project directory with `package.json` (a missing target path errors without creating the directory).

<figure className="vibe-video"><video controls preload="metadata" playsInline poster="/videos/agent-loop.jpg"><source src="/videos/agent-loop.mp4" type="video/mp4" /></video><figcaption>The compiler reports a discarded Effect, and the agent runs it with try</figcaption></figure>

In a new starter, Effect's `floatingEffect` rule reports the discarded Effect as `EK3801`; the example adds `try` to run it and verifies the printed greeting.

## 1. Set up the repository

Install `vibelang` ([Add VibeLang to an existing project](/setup/existing-project)), then run from the repository root:

```sh
npx vibelang agents init
```

Commit the written files so every clone gets the same setup. After upgrading `vibelang`, rerun `init` to refresh its files and its `AGENTS.md` section while preserving your own hooks and settings.

## 2. Trust the repository

Claude Code and Codex run repository code only after trust is granted:

- **Claude Code:** Loads the LSP plugin once you trust the folder. For non-interactive `claude -p`, pass `--plugin-dir .claude/skills/vibelang-lsp "…"`.
- **Codex:** Runs the hook after you trust the project and approve the hook in `/hooks`. Vetted automation can pass `codex exec --dangerously-bypass-hook-trust`.

## What each agent gets

| Agent | Skill | Instructions | Language server | After each edit |
| --- | --- | --- | --- | --- |
| Claude Code | `.claude/skills/vibelang/` | `AGENTS.md`, or `CLAUDE.md` when the repository has one | `.claude/skills/vibelang-lsp/` plugin | `PostToolUse` hook in `.claude/settings.json` |
| Codex | `.agents/skills/vibelang/` | `AGENTS.md` | None (Codex has no LSP client) | `PostToolUse` hook on `apply_patch` in `.codex/hooks.json` |
| opencode | `.agents/skills/vibelang/` | `AGENTS.md` | `lsp.vibelang` in `opencode.json` | `.opencode/plugins/vibelang.js` plugin |
| Cursor | `.agents/skills/vibelang/` | `AGENTS.md` | [VibeLang extension](/setup/vscode) | Loads Claude Code's `.claude/settings.json` hooks |
| VS Code with Copilot | `.agents/skills/vibelang/` | `AGENTS.md` | [VibeLang extension](/setup/vscode) | Loads Claude Code's `.claude/settings.json` hooks |

`init` does not install the editor extension; see [VS Code and Cursor](/setup/vscode).

## The check after each edit

Hooks and the opencode plugin run `npx vibelang agents check` on edited `.vibe` and `.vibex` files. You can run it directly:

```sh
npx vibelang agents check src/profile.vibe
```

It finds the nearest enclosing config (`vibe.config.json`, `tsconfig.json`, `jsconfig.json`, then alternate `tsconfig*.json` such as `tsconfig.test.json` selecting the first project that includes the file) and prints diagnostics for those files:

```text
src/profile.vibe(6,10): error TS2322: Type 'string' is not assignable to type 'number'.
vibelang: 1 error left in the files you edited. Fix it before you finish.
```

Behavior:

- **Exit codes:** `agents check` exits `1` on any project error (including errors in other files, summarized on one line), missing explicit paths, files without an enclosing config (even alongside passing files; add a config or run `vibelang --noEmit <file>`), or an incomplete compiler run (non-zero exit, signal, or spawn failure—never reported as `no errors`, with stderr included). Hooks skip deleted files, return project errors or incomplete checks to the agent with exit status `2`, and pass warnings or Effect lint suggestions (with codes and explanations) as context.
- **Project-wide diagnostics:** Locationless diagnostics (such as `TS18003` when no inputs match) keep their code, message, and continuation lines without counting as errors in edited files.
- **Linting:** Generated instructions also recommend `vibelang lint` (or `vibelang lint --project <config>`), which runs the compiler's Effect language-service rules without emitting files.

## In a workspace

When `vibelang` is installed in a workspace package rather than the root, run `init` from that package and pass the root:

```sh
cd packages/core && npx vibelang agents init ../..
```

Generated commands prefix the package (`npx --no --prefix packages/core -- vibelang agents hook`). Paths containing spaces, quotes, or shell punctuation are handled across hooks, LSP commands, and the opencode plugin. Rerun `init` to refresh an existing setup.
