# Foldkit

[Foldkit](https://github.com/foldkit/foldkit) is a UI framework for Effect in the Elm architecture: a Model schema, Messages, an `update` function, Commands for side effects, and a `view`. Write the app in VibeLang; a TypeScript entry file mounts it with Foldkit's runtime. These pages use `foldkit` 0.169.0, `effect` 4.1.1 and VibeLang 0.0.11.

The complete app, a counter, a todo list and an HTTP command, is [`examples/foldkit-app`](https://github.com/smithersai/vibelang/tree/main/examples/foldkit-app). One Vitest suite runs against its VibeLang version and its Effect TypeScript original, so each pair below has the same tested behavior.

## Install

```sh
mkdir my-app && cd my-app
bun init -y
bun add effect@4.1.1 @effect/platform-browser@4.1.1 foldkit@0.169.0 vibelang-runtime@0.0.11
bun add -d vibelang@0.0.11 vibelang-vite@0.0.11 vite@8.3.4 vitest@5.0.5 happy-dom@20.14.6
```

`bun install` warns `incorrect peer dependency "effect@4.1.1"`: Foldkit 0.169.0 pins its `effect` and `@effect/platform-browser` peers to exactly 4.0.0. The example's tests and production build pass on 4.1.1.

## Configure

Copy `tsconfig.json`, `vite.config.ts`, `index.html`, `src/entry.ts` and `test/setup.ts` from the example. Foldkit's functions are plain TypeScript. Run `vibelang` to write adjacent `.d.vibe.ts` declarations, even with `--noEmit`; [configure TypeScript tools to read them](/setup/vibelang-cli#let-typescript-tools-read-vibe-modules).

```json
{
  "compilerOptions": {
    "module": "ESNext",
    "moduleResolution": "Bundler",
    "lib": ["ES2022", "DOM", "DOM.Iterable"],
    "strict": true,
    "noEmit": true,
    "allowImportingTsExtensions": true,
    "rewriteRelativeImportExtensions": true
  },
  "include": ["src", "test"]
}
```

Vitest needs `environment: "happy-dom"`, `server: { deps: { inline: ["foldkit"] } }` and Foldkit's `setup()` from `foldkit/test/vitest` in a setup file. The app's entry stays TypeScript and imports the `.vibe` module:

```ts
// TypeScript (.ts)
import { Runtime } from "foldkit"
import { Message, Model, init, update, view } from "./main.vibe"

Runtime.run(Runtime.makeApplication({ Model, init, update, view, container: document.getElementById("root"), devTools: { Message } }))
```

## The model

A `schema` declaration is the schema and its type at once; `Runtime.makeApplication({ Model })` takes it as the schema.

:::code-group

```vibe [VibeLang]
export schema Todo { readonly id: number; readonly text: string; readonly done: boolean }

export schema Model {
  readonly count: number
  readonly draft: string
  readonly todos: ReadonlyArray<Todo>
  readonly quote: string
}
```

```ts [Effect]
import { Schema } from "effect"

export const Todo = Schema.Struct({ id: Schema.Number, text: Schema.String, done: Schema.Boolean })
export type Todo = typeof Todo.Type

export const Model = Schema.Struct({
  count: Schema.Number,
  draft: Schema.String,
  todos: Schema.Array(Todo),
  quote: Schema.String
})
export type Model = typeof Model.Type
```

:::

## A command's work

An effect function runs each operation with `try`. A `catch` expression provides a fallback on typed failure.

:::code-group

```vibe [VibeLang]
schema Quote { readonly text: string }

effect function loadQuote(url: string) {
  const response = try HttpClient.get(url)
  const quote = try Schema.decodeUnknownEffect(Quote)(try response.json)
  return quote.text
}

export effect function quoteOrFallback(url: string) {
  return loadQuote(url) catch () => "Could not load a quote"
}
```

```ts [Effect]
import { Effect, Schema } from "effect"
import { HttpClient } from "effect/http"

const Quote = Schema.Struct({ text: Schema.String })

export const quoteOrFallback = (url: string) =>
  Effect.gen(function* () {
    const response = yield* HttpClient.get(url)
    const quote = yield* Schema.decodeUnknownEffect(Quote)(yield* response.json)
    return quote.text
  }).pipe(Effect.catch(() => Effect.succeed("Could not load a quote")))
```

:::

`response.json` holds an Effect value. Run it with `try response.json` to read the body, then run the Schema decoder with `try`.

In the app, the command returns a Message, and `provide` supplies Foldkit's HTTP layer inside it:

:::code-group

```vibe [VibeLang]
// fragment
export const FetchQuote = Command.define("FetchQuote", {
  args: {},
  messages: [Message.SucceededFetchQuote, Message.FailedFetchQuote],
  execute: effect () => {
    provide Http.layer {
      return try fetchQuote()
    }
  }
})
```

```ts [Effect]
// fragment
export const FetchQuote = Command.define("FetchQuote", {
  args: {},
  messages: [Message.SucceededFetchQuote, Message.FailedFetchQuote],
  execute: () => Effect.provide(fetchQuote(), Http.layer)
})
```

:::

## update and view are plain functions

Foldkit's runtime calls `update` and `view` as plain functions. Declare them with `function` and leave off `effect`. A return annotation can check their result shape. It does not decide the function's kind.

:::code-group

```vibe [VibeLang]
// fragment
export function update(model: Model, message: Message): Update.Return<Model, Message> {
  return Message.match<Update.Return<Model, Message>>(message, {
    ClickedIncrement: () => ({ model: { ...model, count: model.count + 1 } }),
    ClickedFetchQuote: () => ({ model: { ...model, quote: "Loading..." }, commands: [FetchQuote({})] })
  })
}
```

```ts [Effect]
// fragment
export const update = (model: Model, message: Message) =>
  Message.match<Update.Return<Model, Message>>(message, {
    ClickedIncrement: () => ({ model: { ...model, count: model.count + 1 } }),
    ClickedFetchQuote: () => ({ model: { ...model, quote: "Loading..." }, commands: [FetchQuote({})] })
  })
```

:::

`defineMessageUnion`, `Message.match`, `Command.define`, `Http.layer`, the `h` builder, and `story` tests are Foldkit's own API and read the same in both versions. The excerpts above trim the example's other messages.

### Decoding a date with typed failures

`CalendarDateFromIsoString` uses `effect` callbacks, with `throw` for a typed `SchemaIssue.InvalidValue` failure and direct returns replacing `Effect.succeed`.

[Before: `packages/foldkit/src/calendar/calendarDate.ts`](https://github.com/foldkit/foldkit/blob/b702a5efbb74bebc056b798b414ddb923a82fbd5/packages/foldkit/src/calendar/calendarDate.ts#L211-L237) · [After: `packages/foldkit/src/calendar/calendarDate.vibe`](https://github.com/smithersai/foldkit/blob/64a3e6edd7df91fafd655c9d2d5789c1523388ae/packages/foldkit/src/calendar/calendarDate.vibe#L209-L235)

:::code-group

```vibe [VibeLang]
// fragment
export const CalendarDateFromIsoString = Schema.String.pipe(
  Schema.decodeTo(
    CalendarDate,
    SchemaTransformation.transformEffect({
      decode: effect input => {
        const match = input.match(isoPattern)
        if (match === null) {
          throw new SchemaIssue.InvalidValue({
            message: `Expected ISO date (YYYY-MM-DD), got ${
              JSON.stringify(input)
            }`,
          })
        }
        const [, yearString, monthString, dayString] = match
        return {
          year: Number(yearString),
          month: Number(monthString),
          day: Number(dayString),
        }
      },
      encode: effect ({ year, month, day }) =>
        `${String(year).padStart(4, '0')}-${String(month).padStart(2, '0')}-${
          String(day).padStart(2, '0')
        }`,
    }),
  ),
)
```

```ts [Effect]
// fragment
export const CalendarDateFromIsoString = Schema.String.pipe(
  Schema.decodeTo(
    CalendarDate,
    SchemaTransformation.transformEffect({

          year: Number(yearString),
          month: Number(monthString),
          day: Number(dayString),

        Effect.succeed(
          `${String(year).padStart(4, '0')}-${String(month).padStart(2, '0')}-${String(day).padStart(2, '0')}`,
```

### Running a subscription stream

The subscription pipeline uses `Stream` methods and `effect` callbacks, with `try` running message delivery and the scoped fork.

[Before: `packages/foldkit/src/runtime/subscriptionFibers.ts`](https://github.com/foldkit/foldkit/blob/b702a5efbb74bebc056b798b414ddb923a82fbd5/packages/foldkit/src/runtime/subscriptionFibers.ts#L128-L146) · [After: `packages/foldkit/src/runtime/subscriptionFibers.vibe`](https://github.com/smithersai/foldkit/blob/64a3e6edd7df91fafd655c9d2d5789c1523388ae/packages/foldkit/src/runtime/subscriptionFibers.vibe#L111-L136)

:::code-group

```vibe [VibeLang]
// fragment
    const consume: void!never!Services = Stream.concat(
      Stream.make(initDependencies),
      modelChangesStream,
    )
      .changesWith(equivalence)
      .switchMap(dependencies =>
        dependenciesToStream(
          dependencies,
          (): ReturnType<typeof modelToDependencies> =>
            Ref.getUnsafe(latestDependenciesRef),
        )
      )
      .runForEach(effect (message) => {
        /* eslint-disable-next-line @typescript-eslint/consistent-type-assertions */
        try enqueueMessageEffect(message as Message)
      })

    const runSubscription = effect (): void!! => {
      try Effect.catchCause(
        provideAllResources(consume),
        effect (cause) => {
          try crashWith(cause, Option.none())
        },
      )
    }
    try forkIn(runtimeScope, () => runSubscription())
```

```ts [Effect]
// fragment
          yield* Effect.forkIn(runtimeScope)(
            Stream.concat(
              Stream.make(initDependencies),
              modelChangesStream,
            ).pipe(
              Stream.changesWith(equivalence),
              Stream.switchMap(dependencies =>
                dependenciesToStream(dependencies, () =>
                  Ref.getUnsafe(latestDependenciesRef),
                ),
              ),
              Stream.runForEach(message =>
                /* eslint-disable-next-line @typescript-eslint/consistent-type-assertions */
                enqueueMessageEffect(message as Message),
              ),
              provideAllResources,
              Effect.catchCause(cause => crashWith(cause, Option.none())),
            ),
          )
```
