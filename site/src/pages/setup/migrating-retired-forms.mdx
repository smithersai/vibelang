# Migrating retired forms

`vibelang --fix` rewrites each retired or legacy form to its VIP form or to the Effect TypeScript it means. The [specification](https://vibelang.sh/spec/007-tooling#compiler-and-tooling-requirements) states, for each form, its diagnostic and the rewrite it produces, and one rule for all of them: a rewrite that can't preserve types, behavior and declaration output refuses at that site. This page describes how the rewrites work. It is not normative: where it and the specification differ, the specification and the compiler's tests decide.

## General migration rules

**Migration** rewrites toward the VIP form or native Effect TypeScript and preserves evaluation order, captures, the call-versus-run phase, coldness, error and environment channels, and public declarations. It never edits a test or a fixture: a test that bundles `.vibe` passes unchanged, or its modules stay `.ts`. A default plan leaves Effect type-only users in TypeScript. A legacy `try make()` of a removed plain wrapper loses its `try`, whatever the result's shape. An old call whose behavior it can't preserve keeps a `.ts` boundary, with an explicit refusal. It never invents `asEffect()`, never turns `Match.withReturnType<T>()` into an unchecked `as T`, and writes `try Effect.forkChild(program, options)` for the legacy `fork(program, options)`. Prelude cleanup keeps an explicit Effect import where removing it would change the declaration. A tool cache for type-directed compilation is reusable only while its source, declarations, configuration, versions and project are unchanged. A missing validation outcome is unverified: a later stage never inherits an earlier stage's exit. The migrate flow pairs a callback with its original callee, argument position and occurrence, separately from its enclosing function. A callback returning a cold `Effect.gen` program may become an `effect` callback with the same void completion. An `effect { … }` block remains a program returned by its plain factory; a dropped return value or call-time work moved into an `effect` function still fails verification.

The API check supports `exports` that point at generated declaration sidecars through `rootDirs`. A sidecar must match the selected project's emitted declaration and have one source owner; changed or ambiguous mirrors keep the batch under review.

## Provider construction order

When converting `Effect.provide` with an inline cold block, the repair captures that program before constructing its provider. The resulting `provide` block preserves construction and execution order. A redundant `try` and `catch` around a nested program keeps the entire operand inside the recovery boundary.

## Pure request pipelines

The repair recognizes pure `HttpClientRequest` setter pipelines and keeps each setter's request argument first. It converts stable arguments only; an argument that can observe interleaved construction keeps the original pipeline with an explicit refusal.

## Stored program callbacks

Generator repairs distinguish comments from comment-looking literal contents. URL strings such as `"https://example.test"`, template text and regex literals do not prevent a preserving conversion; actual comments still have to survive the edit.

A converted generator returned from an array's `map` callback remains a stored program. The repair writes its checked program type explicitly, so the array can be passed to a later program consumer without an inferred-effect warning.

## Generator parameter bindings

An `Effect.fn` generator binds its parameters when its program runs. The
converter keeps supported destructuring and pattern defaults inside that cold program,
including repeated executions. A plain factory that binds its parameters
before returning `Effect.gen` keeps its original timing.

The repair refuses a binding whose lexical scope would change, and a
destructured parameter combined with rest. Copying the rest array with a spread
would add an observable iterator access. Those cases keep their native generator. A keyword conversion must preserve
their binding behavior and public parameter labels.

## Catch pipelines

`vibelang --fix` keeps sequential catch stages as programs. Each later handler
can recover failures from the earlier handler's fallback. Capturing the program
before its recovery block preserves construction timing. If a grouped `try`
contains another `try`, the repair keeps the whole operand inside recovery.

## Synchronous throws

For `EK0401`, `vibelang --fix` moves an existing `throw` instruction into a TypeScript `module` helper, keeping its operand in its original scope and evaluation position. The same repair covers throw expressions and plain parameter defaults. Supported tracked synchronous calls move their invocation into TypeScript while keeping the receiver, method getter order, argument order and return type. A plain throwing `catch` handler uses `catch effect` and `die` to retain the native exception as a defect.

A plain factory returning an Effect can use `die` only when it is internal and every use immediately runs its result. A factory with an escaping native exception is refused when it is exported, escapes, or returns a stored result; changing a call-time exception into a later defect would change behavior. Generic, overloaded, type predicate, optional and spread calls, suspension operands, direct `eval` and unsupported comment placements also refuse at their own sites. Converting a throw to an Effect return refuses native iterator or resource cleanup to preserve cleanup-error precedence. Inline `Effect.suspend` callbacks can return `die` at throw statements or tail throw expressions, preserving their native defects. Non-tail expressions and throwing callback defaults stay refused. These repairs keep the synchronous declaration API; they do not turn a published plain function into an effect function.

A call that may throw inside a plain callback that Effect runs in the fiber keeps its timing too: an `Effect.catchTag`, `Effect.catchTags` or `Effect.tapError` handler, an `Effect.matchEffect` member, an `Effect.onExit` or `Effect.acquireRelease` finalizer, or an `Effect.suspend` thunk. `vibelang --fix` wraps the callback's body as `try { … } catch (thrown) { return die(thrown) }`, so the program fails with the same defect. The `Eager` variants, such as `Effect.flatMapEager`, can call their callback while the program is built, so their calls stay refused.

A factory such as `chunk => Effect.succeed(decoder.decode(chunk, { stream: true }))` decodes at the call. Moving that argument into an effect body changes its state and exception timing. Migration verification rejects that delay. Keep the TypeScript boundary when a native rewrite cannot preserve it; callbacks deliberately supplied to `Effect.sync` or `Effect.try` remain deferred. See [creating effects](/getting-started/005-creating-effects) for the no-throw rules.

If a plain Effect-returning factory's own native `try`/`catch` intercepts a `throw`, `--fix` can use the TypeScript helper inside that `try`. The existing `catch` still receives the same value and keeps its error mapping, evaluation order and native cleanup. This also applies to exported factories. A throw in the catch body or a nested function does not qualify.

Calls whose callee or receiver is a type parameter, indexed type, conditional type, union or intersection remain refused. A generic TypeScript boundary can otherwise change an inferred return type, such as `number`, into a deferred `ReturnType<…>`. The refusal keeps the original site and declaration API.

Native `module name { … }` bodies keep the original TypeScript spelling of their imports and re-exports, including `./leaf.js`, when a dependency migrates. They follow the project's TypeScript extension options. Imports at the containing `.vibe` file's top level continue to follow the existing migration extension policy.

Generator migration carries nested `.pipe` repairs through the surrounding pipeline, including calls in its receiver and stage callbacks. Custom stages retain their original construction order and each nested program keeps its execution boundary.

## Stale `.ts` specifiers

The migration ships before enforcement: `vibelang --fix` repairs stale relative `.ts` names in the selected project's own VibeLang sources. `node scripts/migrate-stale-specifiers.mjs` repairs the repository corpus, including foreign importers, without renaming modules or applying other language migrations. Native TypeScript implementations stay native. Emitted JavaScript and declarations do not mask an available VibeLang source. The repair honors `rootDirs` and `moduleSuffixes`, so a migrated `user.native.vibe` is found through the same configured suffixes and native matches still win. With `rewriteRelativeImportExtensions`, the repair names `.vibe` or `.vibex`; a type-only project allowing source extensions can also use those names. Otherwise it names the actual runtime output, `.js` (or `.jsx` for a JSX-preserving target). The migrate flow uses the same project policy for newly renamed modules. An unresolved name without a migrated sibling stays unresolved. Run the repair before upgrading to the resolver that rejects stale native extensions.

## Trailing blocks

The repair is selected from the pinned legacy source, compiler and options, preserving the actual old program or callback kind and argument position; the callee's parameter type alone cannot decide it. If kind, placement or body preservation is unproved, refuse with an explanation. Comments stay in the source, though their printed placement and equivalent arrow layout can differ. A comment between the call and its block has no place in the rewrite, so the codemod leaves that site to the author; a block after an Effect dual that `0.0.10` placed elsewhere first uses its versioned compatibility repair, retaining a native call error or transitional `EK1023` for a type-correct appended call with changed meaning, without duplicate `EK1101` (VIP-34).

## The retired global `Effect` alias

Its quick fix keeps existing parentheses and written default slots, keeps required imports when globals are disabled, and is refused where it cannot keep the `Effect` namespace binding.

## Ordinary mutable-marker migration

The redundant `mutable` marker on an ordinary interface or object-type property or index signature is removed by `vibelang --fix`, including `--fix-migration-only`. Written `readonly`, comments, declarations and behavior are preserved. A plain `error` payload with a legacy `mutable` marker becomes an explicit compatibility class using the existing runtime error factory, retaining tagged matching. The project gate refuses conversions that introduce an error. Schema fields, schema errors, schema tuples and `data` bodies use their separate rules.

After the preserving codemods ship and all migration repositories have zero remaining accepted uses, these ordinary member and plain-error payload markers are rejected with `EK3410`. A method or identifier named `mutable` keeps its TypeScript meaning. This specifies the retirement target; it does not claim the held rejection implementation or consumer migration is complete.

## Legacy data receiver methods

Legacy Effect data receiver methods migrate to the resolved module’s data-first function: `Option.some(1).map(f)` becomes `Option.map(Option.some(1), f)`. The preserving codemod runs under `--fix` and `--fix --fix-migration-only` before rejection. It keeps receiver and argument evaluation once and in order, import evaluation, comments and exact public declaration output. It refuses a shadowed module without a safely reusable namespace binding, an alias whose import elision or deferred evaluation cannot be preserved, explicit type arguments, trailing blocks or changed declarations. Native/own methods, namespace calls, computed access and optional chains are not rewritten by this migration.

## Legacy prelude shorthand

For a legacy bare prelude `Scope` type, `vibelang --fix` writes `Scope.Scope`; `--fix-migration-only` and `--fix-vip-only` apply this migration too. It selects the resolved implicit binding and preserves comments, the declaration API and emitted JavaScript. A written import, local or ambient type, or type parameter named `Scope` keeps its TypeScript meaning. Prelude cleanup retains the qualified namespace type.

`--fix`, including `--fix-vip-only` and `--fix-migration-only`, expands the retired same-named module-export shorthand using the resolved binding: `Option<A>` becomes `Option.Option<A>`, and `FileSystem.of(impl)` becomes `FileSystem.FileSystem.of(impl)`. VIP-14 supplies module namespaces; a local type, an ambient type, an already qualified export and a namespace's own member keep their meaning. Prelude import cleanup retains these explicit export names. The migration preserves the emitted declaration and the runtime lookup.

## Legacy fork, try-statement and wire migration

The transitional bare `fork { ... }` spelling migrates with `vibelang --fix` to `fork effect { ... }` (VIP-2 and VIP-17). The insertion preserves the cold body, lexical captures, return value, Exit and declaration output; explicit Effect operands are unchanged. Retire the old spelling only after migration consumers have no remaining uses.

A retired statement reports `EK0503`; a typed catch clause also reports warning `EK2112`. These diagnostics do not prevent a preserving migration. The fixed program must compile without errors.

The `try statements` codemod migrates old Effect statement catches and finalizers to explicit Effects, `catch effect`, and native cleanup combinators under VIP-5. It keeps structural tag matching, handler order and the old successful finalizer input `Exit.void`. It refuses unsupported outward jumps, observed `do` completion and any rewrite that changes the declaration's [API identity](https://vibelang.sh/spec/001-functions#api-identity).

The `wire compositions` codemod replaces the retired resolved `wire` intrinsic under VIP-24 with explicit `Layer.provideMerge` composition. It evaluates each supplied layer once in source order and preserves the dependency order of the old graph. Opaque, duplicate or cyclic graphs, spreads and rewrites that change the declaration's [API identity](https://vibelang.sh/spec/001-functions#api-identity) require manual migration. An unrelated local function named `wire` keeps its TypeScript meaning.

After preserving migration, a bare `fork { … }` is `EK1707` and the resolved retired `wire` intrinsic is `EK2401`. The held enforcement changes still require landed codemods and zero remaining uses in every migration repository. The spec does not wait for those code receipts.

## Empty legacy trust wrappers

The resolved `trusted(f, [])` runtime wrapper is retired with `EK0407`. Its preserving `vibelang --fix` migration captures `f` at the original declaration and replaces private direct synchronous calls in explicit Effect bodies with an identity-mapped `Effect.try` and `Effect.orDie` bridge. Preserve the callee read, forwarding function, argument order, coldness, exact defect value and declaration output. Refuse escaping function values, changed exported `Trusted` types, lost comments or reordered Effect operands. A reviewed `.ts` helper with `@throws {never}` is another replacement. Listed-failure wrappers are outside this migration. `EK0407` is reported now: run `vibelang --fix`, and replace by hand each wrapper it leaves, whose `EK0407` carries a note that `--fix` cannot rewrite it.

VIP-4 recorded the same migration:

Migrate a private wrapper whose only uses are direct synchronous calls in explicit Effect bodies by capturing `f` at the original declaration and using the identity-mapped `Effect.try` / `Effect.orDie` bridge at each invocation. Preserve the original callee read, forwarding function, argument order, coldness, exact defect value and public declaration output. Refuse automatic migration when function values escape, an exported `Trusted` type would change, comments would be lost, or Effect operands cannot stay in order. A reviewed TypeScript helper with `@throws {never}` is another replacement. Calls with listed failure classes are outside this retirement.


## Legacy entry-dispatch migration

The legacy entry input is a module marked by a side-effect import of `vibelang/platform/node`, `vibelang/platform/bun` or `vibelang/platform/browser`. These compiler-only markers report `EK2601`, including in a module without `main`. A function named `main` alone remains ordinary source and gets no entry diagnostic ([VIP-26](https://vibelang.sh/vips/0026-top-level-and-main#decision)).

An eligible startup is an exported, non-default, zero-parameter function declaration `main` with a body, without a checker-resolved top-level runner call under the pinned legacy compiler and options. If the marked module has no eligible startup, `vibelang --fix` removes the inert marker and keeps any explicit runner unchanged.

The legacy compiler started an eligible `main` only when the host started its module, never when another module imported it. A runner call written into the module also runs on import, and no admitted source can test which module the host started: ESM cannot read `import.meta.main`, and the retired dispatcher is not a migration target. So `vibelang --fix` refuses every eligible startup. It keeps the marker, reports the file and line as not fixed, exits nonzero, and names what to write where your program starts:

```text
vibelang --fix: main.vibe:1: EK2601 not fixed: the legacy compiler started main only when the host started this module, and no admitted source can test that, so a runner here would also start main on import; where the program starts, write `import * as NodeRuntime from "@effect/platform-node/NodeRuntime"` and `NodeRuntime.runMain(main())`, then delete the marker
```

The named runner and layers are the ones the legacy compiler selected. The `node` and `bun` markers select `NodeRuntime.runMain`; `browser` selects `BrowserRuntime.runMain`. A layer appears only when the legacy compiler provided it to `main`, with experimental layers in their original nesting order; `bun` names `BunServices.layer` when it was selected. The runner receives `main()` for a legacy Effect function and `Effect.sync(main)` otherwise, so `main` keeps its callable kind and public declaration. When the runner's package is not installed, the refusal says so instead.

If the module is only ever started, never imported, write the named imports and runner call in it and delete the marker. Otherwise, write them in a separate entry file that imports `main`. A remaining marker still reports `EK2601`, and current compilation emits no implicit startup.

If an older unmarked application relied on automatic startup, add a written runner to its application entry file, as in [Create a project](/getting-started/004-installation). Unmarked exports are not legacy entry migration inputs, so `vibelang --fix` leaves them unrun. The normative [entry migration](https://vibelang.sh/spec/007-tooling#legacy-entry-dispatch-migration) states the target forms and refusal rule.

VIP-26 recorded the refusal this way:

The retired side-effect imports `vibelang/platform/node`, `vibelang/platform/bun` and `vibelang/platform/browser` report `EK2601`, naming `vibelang --fix`. The [entry migration](https://vibelang.sh/spec/007-tooling#legacy-entry-dispatch-migration) preserves the pinned legacy startup, including entry-only execution, layers and public types, or refuses with a file, line and reason and a nonzero exit. A refused marker remains an error; no implicit startup is retained and no ordinary `main` binding is rejected.

## Retired continuation forms

`vibelang --fix` rewrites only proved local service-shaped uses whose declarations and `Exit` are preserved. It explicitly refuses continuation-dependent uses and unproved selection rewrites. As for every relic, ship the preserving migration and migrate consumers before enforcing rejection.


## The VIP-1 function-kind and `try` migration

The VIP-1 migration preserves each call's original run phase. When it removes a known legacy wrapper, it removes the `try` that ran that wrapper, even when the success data is an `error` or `schema error` instance, another Effect, or an object with an `asEffect` member. Keeping that `try` would fail with data or run a previously unrun program. A call whose written or native contract already returned the intended Effect keeps its `try`, including an error returned for intentional execution. Use the original resolved callable and migration provenance, not the final value's shape or annotation alone; refuse the repair when that provenance cannot be established ([VIP-34](https://vibelang.sh/vips/0034-compiler-and-tooling#decision), amended).

Only `--fix-vip-only` runs the VIP-1/VIP-2 function-kind and `try` passes, reading input as source for the release before VIP-1. Ordinary `--fix` and `--fix-migration-only` do not run those passes: ordinary `--fix` never removes a valid `try` from current source merely because its callee is unannotated. In current source, `try make()` intentionally runs the result whenever it passes the [operand test](https://vibelang.sh/spec/002-running#operand-test).

A value that fails that operand test, such as `Option.some(1)` or `Result.succeed(2)`, keeps `EK0502`: the migration inserts no conversion and unwraps nothing, whatever methods the value has ([VIP-5](https://vibelang.sh/vips/0005-try-runs-effects#decision), amended). Removing the run of a proven legacy wrapper is a separate repair.

The VIP-1 migration writes `try` before each call that ran where it stood before VIP-1 and keeps that call's run phase; source whose old meaning it can't establish is not reinterpreted. It refuses such a call instead, names its file and line, and exits nonzero. When it refused any, it sets `"vibe": { "severities": { "EK4802": "error" } }` in the project's config with a comment that says why, so all inferred Effect argument sites that report `EK4802` in the project fail to compile; the owner removes the setting once a run refuses none.

Schema-error class upgrades preserve the declaration's own tag matcher. A legacy schema-error family with a child tagged `"Child"` does not match the base pattern `when E:`; the class upgrade keeps that result as well as declaration output.

A plain catch handler returns its result as data, including an error or an `Effect` value. Automatic `--fix` preserves this behavior and its `EK0508` advisory. Select the editor action to run the returned `Effect` only when that is the intended behavior.

Preserving call repairs use ordinary native arrow functions to defer method arguments until after receiver access. Their inferred return types retain the original argument's type without a legacy `infer _` annotation.

An implicit prelude `Effect.gen` repair preserves the native generator's synchronous exceptions as defects. Unknown foreign calls use an explicit defect bridge; a proven `@throws {never}` call needs none. Constructor exceptions receive the same bridge when a generator is repaired, including imported object members and local constructor aliases. In a written effect body, synchronous foreign constructors and tagged templates can also receive an automatic bridge when the whole invocation fits inside its thunk. Suspension operands, narrowed property captures, direct `eval` and named failure contracts require a manual boundary at these sites. Direct `eval` includes a parenthesized callee such as `(eval)(code)`.

A declined automatic repair retains its source bytes. Module-export qualification elsewhere in the same file still proceeds, and the refusal report refers to the original source location. Native JavaScript generators retain their return values.

When a legacy migration adds an `effect` marker to a function, it also converts service receiver calls in that body before replacing written `infer` channels. This preserves the service requirement and the failures of dependent method calls.

An alias repair in a class `implements` clause changes only the type spelling. Independent `EK0402` callable throws errors remain, just as they do with a written `Effect.Effect<…>` type.

Migration setup excludes generated declaration sidecars, including `x.vibe.platform.d.ts` and `x.vibex.platform.d.ts`, from Oxlint, ESLint, dprint and formatters that read `.prettierignore`. Authored `.platform.ts` implementations remain checked. Rerun setup to update an existing migration's configuration.

When the migrate flow receives a host-global diagnostic such as `globalThis.Response` after `vibelang --fix` qualifies `new Response(...)`, it checks the original TypeScript spelling before extracting the platform code. Both companion-file and module-body extraction recognize a bare constructor; a local binding with the same name stays local.

The migration's canonical API comparison uses freshly emitted declarations for native `module` bodies. Existing compatibility copies can spell imports differently; they do not replace the current emit. Handwritten neighbouring declarations remain checked.

In Vite+ projects, these generated-output exclusions also go in `vite.config.ts` under `fmt.ignorePatterns` and `lint.ignorePatterns`. Existing rules, test settings and authored implementation checks stay in place. Setup reports a warning when those sections are computed and require an explicit edit.

## Callback completion values

The global `callback` is `Effect.callback`, including in a direct call. Removing a legacy `: infer _` annotation from its registration callback keeps this native API and preserves the written resume argument. Complete it with `resume(succeed(value))`, `resume(fail(error))` or `resume(exit)`. Return a cleanup Effect, such as `sync(cleanup)`, for interruption.

Code using the older `resume(value)`, `resume.fail(error)`, `resume.exit(exit)`, explicit input arguments or cleanup functions can keep the legacy adapter with `import { callback } from "vibelang-runtime"` while migrating. That import keeps the adapter's existing type and behavior.

A bare `: infer _` return annotation on a plain callback has no TypeScript meaning. `vibelang --fix` removes it for native `callback` and `Effect.callback` registration functions too; native completion still passes an Effect to `resume`, such as `resume(Effect.succeed(value))`.

## Legacy return-slot inference

For a plain function that returns an `Effect`, the legacy return-slot repair infers
channels from the returned program. A retired placeholder does not become a
requirement of a generic call or its handler. The repair keeps real errors and
service requirements introduced by callbacks, and keeps the function's own type
parameters when they describe those channels.
