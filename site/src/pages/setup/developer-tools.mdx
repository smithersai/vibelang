# Developer tools after migration

The `vibelang` package ships TypeScript declarations for every public JavaScript entry (`vibelang/eslint`, `vibelang/oxlint`, `vibelang/knip`, `vibelang/prettier`, `vibelang/format`, `vibelang/ast-grep`, `vibelang/metro`, `vibelang/babel`), so strict tool configs work under `bundler` or `node16` module resolution without a local `.d.ts` shim. Preload `vibelang/register` in Node and `vibelang/bun` in Bun.

- **Package identity:** Effect packages keep their identity when linked as `effect` from a numbered or content-addressed store. Foreign `Effect` values and `Context.Reference` keys stay valid operands of `try` regardless of physical directory name.
- **Format and lint scripts:** Setup extends existing scripts rather than letting a green command skip `.vibe` files.
- **Compilation roots:** An included source outside the compilation root reports that boundary directly. Widen the root or give the external package its own `package.json` and `tsconfig.json` instead of editing a valid `include`.

## Build entry points

Write an explicit runner such as `Effect.runSync(main())` at the application entry; bundlers execute that call, whereas exporting or importing `main` does not start it. To select a custom compiler, set `VIBELANG_BINARY` to its native executable (selecting the JavaScript launcher errors before starting). Source-loader diagnostics—including multiline excerpts that resemble bundled library URLs—keep source details and omit compiler file lists.

### Bundler behavior

| Bundler / feature | Behavior |
| --- | --- |
| Rolldown & `tsdown` | `vibelang-unplugin/rolldown` excludes `.d.vibe.ts` sidecars from entries and expanded globs while preserving array order and named aliases; pick the `.vibe` source for a single entry. Programmatic builds default the compiler root to Rolldown's `cwd` (`project` is relative to it; explicit `root` selects another project without moving relative bundle entries). |
| Vite | `import.meta.glob` (eager and lazy overloads), `import.meta.env`, and `import.meta.hot` work with `"types": ["vite/client"]` in `compilerOptions`. Existing `import.meta.hot.accept` handlers keep updates in-page and preserve state; ordinary `.ts` HMR is unchanged. With `allowJs`, edits to JS dependencies recheck VibeLang importers (including type-only imports) and restore HMR when fixed. |
| esbuild | Applies project JSX settings when preserving JSX and keeps original source filenames (including Unicode, spaces, and literal `%`) in mapped Node stack traces. Absolute and relative imports of a `.vibe`/`.vibex` module load one copy; default exports through a TypeScript barrel share objects, classes, symbols, and closure state. |
| `Bun.build` | Relative entries resolve from the process working directory; plugin `root` and `project` select compiler config without changing that directory. |
| Watch recovery | Creating a missing relative source (including directory indexes and emitted `.js` specifiers) triggers a rebuild. Rollup keeps watching sources, type-only dependencies, and config after error recovery; Vite and Rolldown also recover when files appear in newly created nested directories. Set `VIBELANG_UNPLUGIN_DEBUG=1` to log candidates, directory watches, and change acknowledgements. |
| `.vibex` & filenames | Explicit `.vibex` imports (including queries and `.js`/`.jsx` rewrites) work through `vibelang-unplugin`; ordinary `.ts` keeps priority on shared stems. Imports preserve Unicode, spaces, and literal `%`: `./créé.vibe` vs `./cr%C3%A9%C3%A9.js`, `./value.vibe` vs `./value.js`, and `percent%20.vibe` vs `percent%2520.js` (including under Vite `base`) stay distinct with original source-map locations. |
| Downstream plugins | Compiled `.vibe` JS imports `.ts` dependencies by emitted name (`./dep.js`). In Rollup, Rolldown, Vite, esbuild, webpack, and Rspack, plugins after `vibelang-unplugin` still resolve the written source name (`./dep.ts`, `./dep.tsx`, `./dep.mts`), so externalize/replace plugins keep working. Bun plugins cannot pass resolution on, so later Bun plugins see `./dep.js`. |

### Entry rewiring during migration

- Batched migration updates renamed sources in owned `.ts`/`.js` `*.config.*` files (`tsdown`/`tsup` `entry` arrays and maps, `rolldown` `input`, Vite `build.lib.entry`), even when a package only inventories `src`. Protected test configs and fixtures stay untouched; resumed batches retain earlier edits, and reverting restores original entries.
- Setup installs `vibelang-unplugin/rolldown` in static `tsdown` configs and local config factories, reusing an in-scope import or adding a fresh alias if shadowed (default, namespace, or named).
- Removing an old loader wrapper from a shell probe while keeping sibling TypeScript/VibeLang launches refreshes the retained helper in the same pass; replaying setup is idempotent.

## Runners with no VibeLang loader

Node on a package `bin`, `bun file` from a directory whose `bunfig.toml` lacks `vibelang/bun`, and Playwright's Babel cannot read `.vibe`. Compiles and tests pass, then the tool fails at run time. Setup wires every runner it can; batched migration keeps modules reached by bare runners as TypeScript, listing them under `deferred` in `plan.json` and `bareRunners` in `setup.json`:

```ts
// packages/pkg/package.json: "bin": { "pkg": "./src/cli/bin.ts" }
// Node runs bin.ts, so bin.ts and each module it imports at run time stay .ts.

// A fixture's package.json: "dev": "bun run ../../tools/src/e2e/Cli.ts"
// No bunfig in the fixture, so Cli.ts and what it imports stay .ts.
```

Where a script already has a loader (`node --import vibelang/register src/x.ts`), reached modules can migrate while `src/x.ts` keeps its name. To migrate deferred modules, wire their runner or change the entry in an earlier commit. An existing `.vibe` module reached by a bare runner triggers a setup warning. Other bundlers such as vinext are not followed.

**Child Node processes:** Starting a parent with `--import vibelang/register` does not preload child Node processes. Setup adapts `spawn`, `spawnSync`, `execFile`, and `execFileSync` calls with typed source entries to pass `vibelang/register` resolved from the parent package (including across a different `cwd`), preserving options and `execFile` callback order. Built JavaScript entries proven via direct, unmodified `node:path` `join`/`resolve` calls need no loader—setup preserves those bytes (including scripts run under `vm.Script`) and removes unnecessary earlier helpers on repeat runs.

## Paths to converted files

Renaming `X.ts` to `X.vibe` updates imports, not paths held as data, which fail only at run time. A source-mode extension check must cover both extensions on the same path (for example, `import.meta.url.endsWith(".ts") || import.meta.url.endsWith(".vibe")`); unrelated `".vibe"` strings, comments, or checks on another path do not qualify, and qualification must preserve source/bundle entries and child-process loaders.

Batched migration rewrites resolvable static paths; `verify` fails the batch for remaining references under `pathReferences.refusals` in `verify.json` (by module, file, and line as `path-to-converted-file`):

```ts
// Each of these fails the batch while Local.ts is now Local.vibe.
import.meta.resolve(`./Local${moduleExtension(import.meta.url)}`)
spawn("bun", ["src/Local.ts"])
export default { include: ["src/**/*.ts"], test: /\.tsx?$/ }

// In a module that became .vibe, this silently takes its other branch.
const fromSource = import.meta.url.endsWith(".ts")
```

Revert the module to TypeScript or update the caller in an earlier commit. Unprovable dynamic paths (``import(`./${name}`)``) are recorded under `pathReferences.reports` without failing the batch; comments, remote URLs, prose, assertions, generated outputs, and unrenamed files stay clean.

- **Vite SSR entries:** Literal `ssr.serverEntry` / `ssr.clientEntry` URLs (such as `/src/entry.server.ts`) in owned Vite configs with the default root follow renames and preserve slash/quoting for exact revert. Explicit roots or object spreads require manual wiring.
- **Build output (`distList.refusals`):** `verify` builds from clean output before and after each batch and fails if an entry glob (`src/**/*.ts`) drops a converted module from `dist`. If no build script exists, it records the skip.
- **Published pack load (`packLoad.refusals`):** After other checks pass, `verify` packs each touched published package, installs the tarball in an empty directory, and imports every `exports` specifier under Node and Bun. Regressions—uninstallable dependencies (`file:`), unloadable specifiers (`export * from "./x.vibe"`), lost export names, or added/removed specifiers—fail the batch.

## Prettier and Oxfmt

Setup and record split large formatter file lists into bounded argument chunks, log each command and exit status, and fail after attempting all chunks if any chunk fails.

- **Prettier (`vibelang/prettier`):** Add `"vibelang/prettier"` to Prettier's `plugins` (or pass `--plugin vibelang/prettier`). It handles `.vibe` and `.vibex` through the shipped dprint process plugin—the same formatter used by `vibelang format --write`, the language server, and `vibelang-format --write`/`--check`. Only `singleQuote` and `printWidth` affect output; syntax errors in unsaved input are reported.
- **dprint and `vibelang-format`:** Include `**/*.{vibe,vibex}` in dprint configs. `vibelang-format` discovers `.vibe`, `.vibex`, and `// @vibe`-marked `.ts`/`.mts`/`.cts`/`.tsx` files while leaving unmarked TypeScript unchanged. `.vibex` and marked `.tsx` use TSX mode (including in the language server). dprint 0.64.3 ships with the compiler; the pinned TypeScript Wasm plugin downloads and caches on first use.
- **Editor buffers (`vibelang/format`):** `formatSource(text, filePath)` formats the supplied buffer even if ignored or under `node_modules`, using the full path for repository style and honoring unsaved `// @vibe` directives (and `.tsx` JSX). File-scanning commands still honor ignore rules.
- **Type assertions:** The formatter keeps comparisons after Effect type assertions (`value as number!! < limit`) without parsing `<` as a type argument list.

`vibelang-format` reads the nearest formatter configuration from the file's directory up to the repository root:

| Formatter config | Settings read | Defaults when omitted |
| --- | --- | --- |
| `.oxfmtrc.json`, `.oxfmtrc.jsonc` | Quote style, width | Double quotes, width 100 |
| `.prettierrc`, `.prettierrc.json`, `package.json#prettier` | `singleQuote`, `printWidth` | Double quotes, width 80 |
| `dprint.json` | `typescript.quoteStyle`, `lineWidth`, global `indentWidth`/`useTabs`/`newLineKind`, all `typescript` options | Double quotes, width 120, `semicolons: "asi"` |
| None | — | Double quotes, width 120 |

Other Prettier config formats (`.prettierrc.yaml`, `prettier.config.js`) stop `vibelang-format` with an error naming the file: format through Prettier with `vibelang/prettier` instead. Tooling setup leaves YAML/unsupported Prettier configs unchanged with a warning, updates JSON/JSONC dprint configs preserving comments (warning on invalid data), and preserves checksum-pinned dprint plugin lists by running `vibelang-format` afterward (older unpinned setup output is not yet recognized as pinned).

**Oxfmt:** Oxfmt's [unsupported features](https://oxc.rs/docs/guide/usage/formatter/unsupported-features.html) exclude Prettier plugins, and its [CLI source](https://github.com/oxc-project/oxc/blob/main/apps/oxfmt/src/cli/command.rs) has no external formatter option (internal N-API callbacks are not a plugin API). Migration appends `vibelang-format --check` or `--write` to Oxfmt and Vite+ format scripts and Vite+ staged hooks; raw `oxfmt file.vibe` remains unsupported.

## ESLint a repository runs itself

<figure className="vibe-video"><video controls preload="metadata" playsInline poster="/videos/eco-lint-eslint.jpg"><source src="/videos/eco-lint-eslint.mp4" type="video/mp4" /></video><figcaption>ESLint rules on .vibe files</figcaption></figure>

The recording runs ESLint on a published-package project; diagnostic paths are relative to that project.

Repository ESLint configs target `*.ts`, so `eslint src` skips `.vibe` files. Setup writes `.vibelang/eslint-vibe.mjs` and wraps each `eslint.config.*` export in `withVibe`:

```js
import { withVibe } from "../../.vibelang/eslint-vibe.mjs"

export default withVibe(tseslint.config({ files: ["src/**/*.ts"], rules }))
```

`withVibe` adds matching `.vibe` globs to every `files`/`ignores` block targeting TypeScript, parses them with `vibelang/eslint`, disables type-aware rules (since `vibelang -p` type-checks them), and configures `eslint-plugin-import` for `.vibe`. CLI TypeScript globs in scripts gain `.vibe` companions and `--no-error-on-unmatched-pattern`. Non-ESM shapes (`module.exports`) produce a setup warning; test fixtures stay unchanged.

Lint parser semantics:

- **`effect { ... }` blocks:** Treated as Effect values, not callbacks, so callback-arity rules inspect written functions (`effect (cause) => ...`) rather than mistaking a block passed to `Effect.catchCause` for a handler. Captured names, locals, and control flow inside the block keep normal checks.
- **`for concurrent`:** Retains the written limit expression (`8` in `for concurrent(8)` has `Numeric` token kind), iteration bindings, lexical scopes, and `no-unreachable` control flow; compiler-generated cache and loop-head names are marked synthetic.
- **`module` bodies:** Retain stock parser JSDoc type nodes and source ranges.
- **Plain `error` payloads:** Keep fields (including a field named `constructor`), written methods, and getters for ordinary rule checks.
- **Throw expressions:** An unparenthesized `throw` before a comma reports `EK1010`; write `[(throw error), value]`.

## Knip a package installs itself

Knip reads configuration only from its working directory. Setup adds `knip.config.ts` with the `vibelang/knip` compiler to each package that installs Knip or defines a `knip` key in `package.json`. A `--config` naming a JSON file cannot register a compiler, so use a JavaScript/TypeScript config instead.

`export default value` keeps its named binding, so duplicate-export, unused-export, and JSDoc tag findings match TypeScript.

For Knip releases whose compiled-output mapper searches only built-in extensions when mapping `dist/main.js` back to `src/main.vibe`, setup writes a versioned patch under `patches/` and registers it in pnpm's or Bun's `patchedDependencies` (adding `.vibe` and `.vibex` while keeping TypeScript precedence; kept on repeat runs; skipped if Knip already supports it). Setup preserves authored patches and warns when a patch needs updating, Knip is not installed, the mapper layout is unsupported, or the package manager cannot persist patches. Run the repository's normal install command to apply the patch before running Knip.

## Oxlint

<figure className="vibe-video"><video controls preload="metadata" playsInline poster="/videos/eco-lint-oxlint.jpg"><source src="/videos/eco-lint-oxlint.mp4" type="video/mp4" /></video><figcaption>Oxlint on .vibe files</figcaption></figure>

Oxlint's [JS plugin API](https://oxc.rs/docs/guide/usage/linter/js-plugins.html#api-support) excludes custom parsers, and its [partial loader](https://github.com/oxc-project/oxc/blob/main/crates/oxc_linter/src/loader/partial_loader/mod.rs) only handles Vue, Astro, and Svelte script regions.

Migration keeps upstream `oxlint`—with no patch, fork, or extra binary—and adds two passes per `oxlint` invocation (including subshells such as `(oxlint --disable-nested-config)`), preserving `-c`/`--config`, `--deny-warnings`, and `--max-warnings 0`, and adding `--no-error-on-unmatched-pattern` to the native call so `.vibe`-only directories still reach ESLint:

1. **ESLint pass (`vibelang/eslint`):** Runs repository JS plugins and ESLint-carried rules over `**/*.{vibe,vibex}` (`.ts` -> `.vibe`, `.tsx` -> `.vibex`). JSX tags count as references for ESLint and Knip, and React/Solid rules inspect source JSX.
2. **Native pass (`node .vibelang/oxlint.mjs --vibe-native`):** Runs Oxlint's remaining native rules on projected TypeScript.

Key integration details:

- **Migrated local JS plugins:** Setup preloads `vibelang/register` separately for Oxlint and each generated ESLint command (preserving `NODE_OPTIONS` and project `--import`/`--require` resolution for native linting and `--print-config`), including direct `oxlint`, `vp lint`, and `vp check` steps in GitHub workflows.
- **Script runners & adapter:** Setup follows local JS/TS runners launched by package scripts (and their relative imports), extending extension filters to `.vibe`/`.vibex` (`.tsx`-only adds `.vibex`; repairs older `.vibe`-only filters), excluding `.d.vibe.ts`/`.d.vibex.ts`, and warning on unsupported filter shapes. File-list runners invoke `.vibelang/oxlint.mjs`: missing explicit files exit `2` (including with `--vibe-native`), unmatched globs keep empty-selection policy, `--fix` applies ESLint source fixes only, and `--help`/`--version`/`--print-config`/`--init` run without parsing inputs (`--vibe-native --print-config` prints the native projection config). Configs (including `oxlint.config.ts` and `-c` via `--print-config`, rules, options, severities, and extensionless directory overrides such as `packages/gui/**`) are reread per run; JSON output merges passes with original `.vibe` filenames and lines.
- **Rule & directive fidelity:** `oxlint-disable`/`-line`/`-next-line`/`-enable` and ESLint directives keep scope (reason-only directives follow the installed Oxlint release; `typescript/`, `typescript-eslint/`, and `@typescript-eslint/` map to the same rule; parsed comments are adapted without modifying source files, strings, or locations; unused directives stay quiet). The ESLint pass exposes Oxlint `start`/`end` offsets (so `SAFETY:` rules match TypeScript), includes `oxc/no-accumulating-spread`, fails on undefined enabled JS plugin rules, and uses typescript-eslint's recommended fallback only when default correctness is on and installed Oxlint cannot resolve rules. Effect language-service rules stay in `vibelang lint` (VIP-38).
- **Language-aware lint mappings:** `no-unused-vars` counts `typeof` reads (including erased `declare const` symbol brands); record patterns expose generated type checks, keep written extractor bindings (`Number(let value)`), and report runtime `typeof` only for written operators (including guards and computed keys); `match` arm exits stay inside `match`, avoiding false `no-unreachable` in `do` expressions.

### Native rules on the projected TypeScript

For each module, the native pass generates virtual TypeScript via stdin:

```sh
vibelang --ts-projection src/app.vibe < src/app.vibe
```

It prints one JSON object (`text`, `extension`, `mappings`, `diagnostics`) and exits `2` on usage errors, like `--estree`. Forms left for annotations in checking take their value reading here. Helper types import from `vibelang/prelude` (shipped with `vibelang`; requires `vibelang`, `vibelang-runtime`, and pinned `effect`, with no content mapper). Keep the virtual file inside the source project so relative imports resolve; the projection is for inspection and checking, not execution. Re-exported members (named, namespace, and type-only) keep native checks.

`vibelang/oxlint` writes `x.vibe` as `x.ts` and `x.vibex` as `x.tsx` into a temporary directory mirroring relative paths with the root config—so `overrides`, `ignorePatterns`, `.gitignore`, and `typeAware` match TypeScript—and maps reports back to source positions:

| Report | Result |
| --- | --- |
| Starts on source text | Reported at the source position |
| Starts on text the projection generated, such as `require-yield` on a lowered `function*` | Dropped |
| `no-unused-vars` on an `effect` import, which declarations keep | Dropped, as in `vibelang/eslint` |
| `no-unsafe-declaration-merging` where the source does not write both an `interface` and a `class` of that name, such as a `service` | Dropped |
| `no-unexpected-multiline` on the `(` of a `try (x)` at a line's start, and `no-unused-expressions` on the value of a `match` arm | Dropped |
| A module the projection leaves unparsable | A `vibelang(unprojected)` warning on that module, because it got no rules |

Each rule runs once: the native pass turns off ESLint-carried rules (including in overrides), leaves JS plugins to ESLint, keeps type-aware TypeScript rules (avoiding parser-service requirements before JS plugins run), skips `--fix`, and leaves `reportUnusedDisableDirectives` off.

## ast-grep

`vibelang-ast-grep [output]` compiles all parsers declared in `editors/tree-sitter-vibelang/tree-sitter.json` into one shared library (`vibelang.dylib` on macOS, `vibelang.so` elsewhere; `--help` prints usage, other flags exit `2`). The npm package includes the manifest and grammar `src` directories; a C compiler is required, and legacy flat-parser packages remain supported.

- **Config & rules:** Migration registers `VibeLang` (`tree_sitter_vibe`, `vibe`)—and `VibeLangJSX` (`vibex`) when the JSX grammar is present—in each `sgconfig.yml` pointing to the generated library beside it. TypeScript/TSX rules (matched case-insensitively) get copies with matching selectors and unique IDs (JSX-only kinds on JSX, TS-only on plain, `.ts` -> `.vibe`, `.tsx` -> `.vibex` preserving directory scope, JSX tag identifiers visible, sidecars excluded from TS rules).
- **Rebuilds & versions:** The library is gitignored and rebuilt by `postinstall` (same extensionless path on Linux/macOS; WSL on Windows). ast-grep 0.50+ requires `--custom-languages allow` or project trust ([custom language loading](https://ast-grep.github.io/advanced/custom-language.html)); earlier versions load directly, and existing pinned versions are kept.

## Bun runtime preload

Use Bun `1.4.2` or newer for `vibelang/bun` (older releases have plugin-resolution and Unicode-scanner defects). Public and internal runtime entries preserve helper values even if Bun captures a CommonJS bridge early or an earlier module import fails.

- **`.ts` fallback:** `vibelang/bun` resolves a missing relative, absolute, or `tsconfig.json` `paths` `.ts` import to its sibling `.vibe` source, preserving inherited `paths` and substitution order. Existing native files keep priority (including files with `#!`, quoted CommonJS such as `exports.default`, or `.exports`/`.module` property reads like `ctx.exports.program`). Compiler `.ts` import rules are unchanged, and the CLI entry itself must exist.
- **Computed dynamic imports:** Use a relative or absolute path (`const name = "./src/feature.vibe"; await import(name)`). Computed bare aliases like `import(alias)` where `alias` is `"@/feature.ts"` are not rewritten to `.vibe`; use a literal alias import instead. Bun can invoke runtime resolver hooks for computed `.ts` aliases, whereas for computed extensionless bare aliases Bun does not invoke runtime resolver hooks ([Bun runtime limitation](https://github.com/oven-sh/bun/issues/40579)).

## Bundlers inside unchanged tests

### Preloaded bundler adapters

| Entry point | How to load | Notes |
| --- | --- | --- |
| `vibelang-unplugin/rolldown/register` | `node --import`, or Bun 1.4.1+ `--preload` / both `bunfig.toml` preload arrays | Includes runtime loader; supports Rolldown build/watch for literal ESM bundler imports. Load before importing bundler; preserves options, explicit plugins, literal entry paths, and filename assertions. |
| `vibelang-unplugin/esbuild/register` | Same as above | Same as above for esbuild `build`/`context` (`buildSync` does not support plugins). Computed imports, CJS, and older Bun need the explicit plugin. |
| `vibelang-unplugin/bun/register` | Both top-level and `[test]` preload in `bunfig.toml` | Configures `Bun.build` and runtime imports without editing test code (each child Bun process needs its own preload). Resolves missing literal `.ts` entries and relative/absolute/`paths` `.ts` imports (rereading inherited aliases per build) to `.vibe`, keeping existing native files, in-memory entries, and external imports untouched. ### Private emitted routes (`#vibelang/emitted/…`)

When tests call unconfigured esbuild, Rolldown's API, or Vite's bundled config loader directly, runtime register hooks do not configure those bundlers:

- **Private packages (`.vibelang/js/`):** After conversion, migration emits JavaScript even for private packages without public exports and routes native TypeScript runtime imports through exact private `imports` entries. Bare `node entry.ts` and unconfigured test esbuild calls read `.vibelang/js/`, while source-aware tools and type checkers use source/declarations. Missing output is reported in the emit receipt; revert restores source paths. Setup still wires `vibelang-unplugin/esbuild` into ordinary build scripts (reporting unsupported shapes by file and line while leaving tests untouched; mixing native and emitted copies of a shared module can still load two instances).
- **Condition routing:** Exact `#vibelang/emitted/…` entries map `vibelang-source` (added to compiler `customConditions` for cold builds), `types`, and `default` (emitted JS for Node, Rolldown, and Vite). Compiled JS and declarations rewrite routes back to relative outputs (`./user.js`), preventing leaks into published packages and keeping one module copy. Wildcard routes follow Node private-import matching (exact > longest prefix > longest key; `*` matches at least one character and replaces every `*`, such as `./src/*/*.vibe`).
- **Safety & formatting:** Setup records selections in `setup.json`'s `wired.emittedImports.modules` without adding a build step or touching tests, fixtures, type-only imports, or `exports`. After emission or restoration, migration formats packing manifests and `.vibelang/pack-policy.json` before recording loader fingerprints (stopping with exit status and log path on formatter failure). For published packages, setup requires byte-identical declarations before and after (resolving conditional exports in TypeScript's order); leaked routes or changed declarations restore edits and report every affected file and module.
- **Conservative fallback (`runtimeRouting`):** Unrelated native runtime exports keep written source paths; package-wide emitted routing triggers only when computed or unresolved imports are reachable from a migrated source or public native runtime entry (ignoring unused private fixtures and dev scripts). The `runtimeRouting` receipt names the opaque source behind a fallback and lists ignored opaque sources.

### Migration verification and snapshots

- **Transitive discovery:** Setup follows relative imports in sources and tests (such as `../other/src/module.vibe`) as well as manifest dependencies without modifying test files.
- **Original reports & receipts:** Verification requires each checked package's original compiler report and current `setup.json` receipts. Missing reports or disappeared receipts fail as unverified (older green receipts cannot substitute); unambiguous legacy snapshots remain readable.
- **Solution-style projects:** Each referenced project keeps a distinct bounded identity for declarations and logs (e.g., `config/build.json` vs `config__build.json`); ambiguous legacy output directories require fresh setup.
- **Frozen declaration snapshots:** Snapshots preserve each project's effective `types`, `typeRoots`, inherited options, module-resolution settings, and auto-selected type packages (resolved from the recorded config directory; triple-slash references keep source file origin; an explicit empty `types` stays empty; installed dependency declarations stay pinned). Relative cross-package imports (such as `../../packages/gateway/src/RuntimeBridge.js`) resolve to that workspace module; out-of-package files belonging to no package need their own declaration or a recorded reason. Omitted `rootDir` uses one consistent config-dir or common-source layout recorded in `outputLayout` (ambiguous ownership stops recording). Shipped copies match identical originals while preserving handwritten snapshot identity so edits stay visible. Duplicate installed copies of a package version merge only if byte-identical with equivalent dependency closures and load order; a workspace package loaded as source on one side and declaration on the other pairs when ambient blocks and reached local declarations print identically. Missing declarations (such as `TS7056`) mark each reaching export unavailable by name without treating the package as identical.
- **One-pass `rootDir` & fixtures:** With an explicit `rootDir`, one-pass migration retains dependencies whose sidecars are unchanged and reverts changed ones (missing evidence never counts as unchanged). Temporary build fixtures proven to stay inside a fresh `mkdtemp`/`mkdtempSync` directory keep their original source kind.
- **API identity probes:** If TypeScript cannot finish a probe, the error names the package entry, exported binding, type-vs-value comparison, and generated assertion; shared helper errors keep their own location.

## Metro, Babel and the React Compiler

Single-file tools (Metro, Babel, Oxc) cannot parse `.vibe`. Three entry points pass compiled JavaScript and remap AST/source-map positions back to `.vibe` lines:

| Entry point | Usage |
| --- | --- |
| `vibelang/metro` | Wrap `metro.config.cjs` with `withVibeLang(config)`. Resolves `.vibe`/`.vibex` and `module` declarations before the app's Babel transformer. See [React Native and Metro](/setup/react-native). |
| `vibelang/babel` | Babel preset (listed last) for tools running Babel directly, such as `babel-jest` or React Compiler coverage tests. |
| `vibelang/emit` | `toolArguments(filename, text, options)` adapts `transform(filename, text, options)` APIs such as `oxc-transform-react`. |

The React Compiler sees JavaScript and produces identical diagnostics and output on `.vibe` and `.ts` twins. Tooling setup wraps `metro.config` in `withVibeLang`, adds `vibelang/babel` to Babel presets, adds `.vibe` to `@vitejs/plugin-react` `include` when the React Compiler is enabled (its default `/\.[tj]sx?$/` skips `.vibe`), and under pnpm or Bun writes `patches/oxc-transform-react@<version>.patch` + `patchedDependencies` (warning under npm or Yarn). Metro and Babel are optional peer dependencies.

## Failed toolchain migrations

- **`EK1101` trailing blocks:** Accepts JavaScript whitespace between call and block (nonbreaking spaces, thin spaces, BOM); an intervening comment requires a manual edit.
- **`Option.match`:** Preserves qualified callback payload types, record annotations, Effect-inferred types, contextual result types (including literal and local symbols) when ignoring the `Some` payload, and the original argument (including `arguments.length`).
- **Retired `select` (`EK4607`):** References, hover, rename, and call hierarchy still follow written identifiers, including bindings in empty arms and defaults before later cases.

## Published packages

Package publishing excludes `*.d.vibe.ts` and `*.d.vibex.ts` sidecars from package tarballs: publish ordinary `.js` and `.d.ts` files and point published `types` conditions at `.d.ts`. Verification compares pack file lists against the upstream baseline (sidecars, missing files, and unexpected additions fail; a migrated `.vibe` source may replace a deliberately published `.ts` twin; tests, fixtures, and manifests stay intact).

## Last resort: keep TypeScript file names

Use the compiler, plugins, and editor integrations above with `.vibe` and `.vibex` files whenever possible. Only if you cannot rename `.ts` files, consider the experimental [TypeScript shim](/setup/typescript-shim). Stock readers can accept marked files with different meaning; read its limitations first.
