# Other editors

Any LSP-capable editor can run `node_modules/.bin/vibelang --lsp --stdio` over `.vibe`, `.vibex`, `.ts`, and `.tsx` files selected by `vibe.config.json`, `tsconfig.json`, or `jsconfig.json` (checked in that order). The server uses LSP 3.17 pull diagnostics (`textDocument/diagnostic`), falling back to `publishDiagnostics` on open, change, and save for push-only clients such as Claude Code.

## 1. Check the server

From the project directory, run:

```sh
npx vibelang --version
```

Expected output: `VibeLang 0.0.13 (TypeScript 7.1.0-dev)`.

## 2. Configure the LSP client

| Setting | Value |
| --- | --- |
| Command | `node_modules/.bin/vibelang --lsp --stdio` (or its absolute path) |
| Files | `*.vibe`, `*.vibex` (add `*.ts`, `*.tsx` to serve TypeScript too) |
| Root marker | `vibe.config.json`, `tsconfig.json`, or `jsconfig.json` |
| Language id | `vibe`, `vibex` (`typescript`, `typescriptreact` for TypeScript) |

If the server handles `.ts` files, disable your other TypeScript server for the project to avoid duplicate diagnostics. JetBrains IDEs can attach through the LSP4IJ plugin.

## 3. Highlight .vibe files on GitHub

Add to `.gitattributes`:

```text
*.vibe linguist-language=TypeScript
```

## Language server behavior

- **Inline `module` declarations (VIP-40):** Diagnostics stay on the containing `.vibe` document (no virtual editor documents). Rename, Find References (including across large native TypeScript libraries without stalling, honoring the client's declaration filter), and Organize Imports span module bodies and identifier specifiers (`from text`, escaped `from \u0074ext`). Renaming a merged symbol updates specifiers too, while an independent `import type { M }` stays separate from `module M`. Other bindings stay renameable even if a `module` declaration is missing its name.
- **Patterns, parameters, and matchers:** `is` bindings in `while`, `do…while`, and `for` heads keep identity across short-circuiting (`||`, `&&`, `?:`) for references and rename. Parameter declarations and destructuring sources (including contextual names such as `source`) stay linked even when defaults contain `do { }` or returning `match` arms. Signature help supports qualified/computed extractor matchers (`Matchers.pick(let item)`, `Matchers["pick"](let item)`), regex extractors, and unresolved matcher names.
- **Schemas and types:** Definition, type-definition, hover, references, and rename follow written type bindings—including type-only/namespace imports and mapped generics (`Array<number>`, `ReadonlyMap<string, number>`)—while ordinary `Schema` values keep their own definitions. Legacy `infer _` placeholders decline rename (ordinary generic parameters and conditional `infer` bindings remain renameable).
- **Formatting and retired forms:** Same-line `schema`, `error`, `schema error`, and `data` declarations preserve both declarations, docs, and written schema type aliases when formatted. Retired `service class` (`EK0909`) and `layer` (`EK2121`) declarations are always errors regardless of warning settings.
