# VibeLang in .ts files

The `vibelang-typescript` package is an experimental implementation of [open VIP-42](https://github.com/smithersai/vibelang/blob/main/docs/design/vips/0042-vibelang-in-ts-files-open.md). It is included in the VibeLang 0.0.12 release. Prefer [the regular integration](/setup/existing-project) when you can use `.vibe` files.

The compiler recognizes VibeLang in a `.ts` file whose first line is `// @vibe`. The replacement package runs it under the name `typescript`, so existing `tsc` scripts can reach it. Files without the directive stay TypeScript.

This is the last option. Use it only when you can't name files `.vibe`. The [`vibelang` CLI](/setup/vibelang-cli), [Vite and Vitest](/setup/vite) and the other plugins in [Set up VibeLang](/setup) keep every stock TypeScript tool working. Here each tool that reads a `// @vibe` file with stock TypeScript or its own parser fails.

## Install

```sh
npm install --save-dev --save-exact typescript@npm:vibelang-typescript@7.1.12
npm install --save-exact effect@4.1.1 vibelang-runtime@0.0.12
```

The package targets TypeScript 7.1. Move a TypeScript 5 or 6 project to that compiler version first, including its configuration migrations.

In a monorepo, install it at the root and replace every other `typescript` with the root's `overrides`:

```json
{
  "devDependencies": { "typescript": "npm:vibelang-typescript@7.1.12" },
  "overrides": { "typescript": "$typescript" }
}
```

pnpm takes `overrides: { typescript: npm:vibelang-typescript@7.1.12 }` in `pnpm-workspace.yaml`.

## Source checkout preview

Use Go, Bun and Node with the [contributor setup](https://github.com/smithersai/vibelang/blob/main/CONTRIBUTING.md). From the repository root:

```sh
export VIBELANG_CHECKOUT="$PWD"
(cd docs/tools && bun install --frozen-lockfile)
(cd packages/runtime && bun install --frozen-lockfile && bun run build)
sh scripts/build-vibelang.sh
node packages/compiler/bin/vibelang --version
```

In the same shell, switch to your target project's directory. Install Effect and the built runtime from this checkout before checking marked files:

```sh
npm install --save-exact effect@4.1.1 "$VIBELANG_CHECKOUT/packages/runtime"
node "$VIBELANG_CHECKOUT/packages/compiler/bin/vibelang" --noEmit
```

Pass the project's normal compiler options to the launcher. This route uses the checkout's compiler and runtime together.

## Write a file

The first line is exactly `// @vibe`. Only a `#!` line can come before it.

```ts
// @vibe
error Empty

effect function greet(name: string) {
  if (name === "") throw new Empty()
  return `hello ${name}`
}

export effect function main() {
  const who = greet("") catch () => "nobody"
  return try greet(who)
}
```

A `.ts`, `.mts` or `.cts` file with the line follows every `.vibe` rule, and a `.tsx` file every `.vibex` rule, including `EK` diagnostics. Plain TypeScript files import it as they import any `.ts` file. Three things stay as they are in TypeScript:

| In a `// @vibe` file | Because |
| --- | --- |
| Import paths follow your `tsconfig.json`, such as `./plain.js`, or `./plain.ts` with `allowImportingTsExtensions` | The file is a `.ts` file |
| No `module` declarations: `module text { }` is `TS1540`. Put the code in a plain `.ts` file and import it | TypeScript gives that syntax another meaning |
| No declaration sidecar | Sidecars exist for `.vibe` names |

## Tool compatibility

| Tool | With the shim |
| --- | --- |
| `tsc`, `tsc --watch`, `tsc -b` | Checks and emits both kinds of file |
| An editor that starts `tsc --lsp --stdio` from the project | Diagnostics, hover and formatting in both kinds of file, including marked `.mts`, `.cts` and `.tsx` files. In VS Code set `"js/ts.tsdk.path": "node_modules/typescript/lib"` and accept the workspace version |
| Vite and Vitest | Add [`vibelang-vite`](/setup/vite): one line in the config |
| webpack, Rspack, Rollup, Rolldown, esbuild | Add [`vibelang-unplugin`](https://www.npmjs.com/package/vibelang-unplugin#configure): one line in the config |
| Node.js | `node --import vibelang/register src/main.ts` |
| `bun build`, Bun's test runner, Metro | Not supported: use `.vibe` files |
| `tsx`, `ts-node`, Node.js without `vibelang/register` | Stops with a syntax error |
| A stock TypeScript, such as one a dependency installs | Stops with `TS1434` and other syntax errors. Your `tsc` stays VibeLang, unless the project also installs a stock `typescript` under another name: both then claim the `tsc` command |
| Prettier, ESLint, Oxlint, Knip | Stops with a syntax error: ignore `// @vibe` files, and use `vibelang format` and `vibelang lint` |
| Anything that imports TypeScript's JavaScript API | Fails: the package exports only `version`. This includes `vue-tsc`, `svelte-check` and `ngc` |

Bundlers need a plugin because esbuild and Oxc parse `.ts` files themselves, so there is no TypeScript for this package to replace there. A file that uses no VibeLang syntax can pass through these tools, and it means there what it means in VibeLang, except that `vibelang` always reads it as a module.

## Return to stock TypeScript

Rewrite the VibeLang forms before passing a marked file to stock TypeScript. A file that retains that syntax reports parse errors such as `TS1434`.
