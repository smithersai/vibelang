# Known limitations

VibeLang is in early alpha.

- Platforms: [macOS arm64/x64, Linux arm64/x64; Windows via WSL](/getting-started/004-installation#prerequisites). Native Windows binaries are not available yet.
- Effect: [`effect@4.1.0` exactly](/setup/existing-project); other versions are unsupported.
- Stock TypeScript: `tsc`, `vue-tsc`, and `svelte-check` report TS2307 for `.vibe` imports; [build with `vibelang`](/setup/vibelang-cli#2-replace-tsc-in-the-scripts). `vibelang-ts-mapper`, a TypeScript 7.1 content mapper that lets stock TypeScript check `.vibe` files, is experimental and unpublished. It is tested with `typescript@7.1.0-beta`, which runs it only under `tsc --runExternalCode`.
- Editors: [VS Code and Cursor use the bundled VSIX](/setup/vscode). VS Code Marketplace and Open VSX publishing are not ready.
- Stability: [v0: breaking changes expected](/setup/release-notes). Read release notes before upgrading.

Calls through `any` can hide an Effect and its failure and service channels.
EK4409 warns when an effectful body returns such a call. It also warns when a
function with an Effect contract requiring a primitive success value returns a local `const` call whose initializer
is known to be effectful, even if the containing function compiles to plain
JavaScript internally. The warning does not track arbitrary `any` values through
mutable assignments, containers, foreign APIs, or intermediate local values.
A hidden Effect can still be returned as an ordinary, unrun value. Keep the
callee's callable type, such as `() => number!NotFound!`, instead of erasing it.

The experimental TypeScript mapper keeps an exported function’s written Effect contract, such as `number!!`, even when its body is pure. Its projected type has no `$plain` member.

Support for the new forms and adjacent `.d.vibe.ts` declarations arrives with the compiler's VIP implementation.
