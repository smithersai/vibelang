# Fibers

A fiber is a running computation with a result and a lifetime. Effect's lightweight fibers overlap waiting work, inspect completion, and cancel safely. They give concurrency on the runtime's scheduler, not parallel CPU execution of JavaScript.

A parsed `fork` or `join` runs only inside an `effect` function or `effect { ... }` block. A plain nested function, a class field, a static block or a parameter default is outside that code and reports `EK1701`. A discarded operator statement receives that placement error alone, including in a static block nested in effect code. Ordinary discarded Effect calls retain their lint diagnostic. Ordinary helper calls such as `join(parts)` in plain code keep their TypeScript meaning. For previously accepted operators in plain code, `vibelang --fix` writes a cold API call and preserves the enclosing function's plain behavior; mark the function `effect` yourself when you intend to run the operation there.

An `effect` function or producer expression cannot name itself `fork` or `join` (`EK1702`). A declaration uses its enclosing context: `export effect function fork() { return 1 }` is allowed in plain code, while a declaration named `fork` or `join` inside effect code is rejected. Method and property names remain ordinary names, so `{ effect join() { return 1 } }` is allowed.

## Forking and awaiting

```vibe
effect function buildDashboard() {
  const chart = fork effect {
    try sleep("30 millis")
    return "chart"
  }
  try Console.log("preparing dashboard frame")
  return join chart
}
// string!!
// Output: preparing dashboard frame
// Output: chart
```

`fork` starts a child fiber and returns its handle, here a `Fiber.Fiber<string>`, without waiting for its result: the parent continues while the child waits. `join` waits for the child and returns its value or propagates its failure.

`join fiber` calls `Fiber.join` directly. It evaluates the operand once and does not inspect marker properties or enumerate the handle.

`fork loadChart()` starts the Effect returned by `loadChart()`. To fork several statements, write `fork effect { ... }`. An existing Effect value is also a valid operand: after `const job = loadChart()`, write `fork job`. An operand that is not an Effect, such as a plain function's result, is `EK1703`. A bare object, such as `fork { value: 1 }`, is an object operand and receives the same error; it never becomes a callback body. Parentheses and `satisfies` wrappers keep that single operand diagnostic; errors in written calls inside the operand are still reported. `join` takes a fiber: `join chart` waits for the fiber's result. A plain `fork` is owned by the current fiber, which interrupts unfinished children when it ends. `await` waits for Promises inside async functions. Awaiting a fiber there is the `EK4609` lint warning; keep the native `async` context with `await runPromise(Fiber.join(fiber))`. Awaiting a `Deferred` is `EK4610`, with `await runPromise(Deferred.await(deferred))` as its repair. In effect code, every `await` reports only the fixed placement error `EK0102`, including Promise, Effect and ordinary-value operands; async advisory settings cannot change or disable that error. Write `join fiber` or `try Deferred.await(d)` instead.

Returning a handle from an Effect helper, passing it to another function, storing it in a collection or capturing it in a closure does not transfer ownership. Finishing that helper or a loop iteration does not interrupt the child; the current parent fiber owns it until the parent ends.

An operand that is not assignable to `Fiber.Fiber<any, any>` reports `EK1704`. An object with only a `~effect/Fiber` marker or an incomplete fiber shape is rejected; complete structural fiber types remain valid. TypeScript still reports independent errors inside the operand, including wrong call arguments, assignments and `satisfies` checks.

When `join` receives a `Deferred`, `Promise` or `Effect`, its diagnostic shows an executable alternative: `try Deferred.await(value)`, `try Effect.tryPromise(() => value)` or `try value`. Calling an Effect factory constructs its program; `try` runs it. An incomplete marker does not establish a valid `Effect` or `Deferred` operation.

A collection of fibers is not itself a fiber: `join [first, second]` and `join { first, second }` report `EK1704`. For previously accepted collection joins, `vibelang --fix` writes an explicit compatibility helper that preserves operand evaluation, collection reads, result shape and interruption of the remaining fibers after a failure. It does not replace that cleanup policy with a different collection operation.

With `strictNullChecks` disabled, `null` and `undefined` pass the operand's TypeScript assignability check; `void` remains invalid.

A misplaced `fork` or `join` operator reports `EK1701`. Independent TypeScript errors in their operands, including wrong arguments and generic constraints, retain their own diagnostics.

`any` and `never` follow TypeScript's operand assignability for `join`. A value typed `unknown` must first be narrowed to a fiber.

`fork` and `join` follow the unary precedence of `await`. Their operands can use any unary form, including type assertions and parenthesized expressions, and may start on the following line. A following member or call belongs to the operand; group the completed operation first when reading its result, as in `(join child).length`. Inside Effect code and its parameter lists, these words begin operators regardless of the next token. Outside Effect code they remain ordinary identifiers; give an ordinary helper another name when calling it from Effect code. Parenthesize either operator on the left of exponentiation: `(join child) ** 2`. They may appear directly on its right: `2 ** join child`.

An `effect` function or producer expression cannot be named `fork` or `join` (`EK1702`): its own name uses its body's Effect context. For example, `const item = effect function fork() { return 1 }` is rejected. `vibelang --fix` moves the name into a local constant in a plain arrow, as in `const item = (() => { const fork = effect function() { return 1 }; return fork })()`, preserving the callable name and self-references. Use `--fix` for self-references or contextual types; the editor offers the simpler repairs. The fixer leaves edits that add type errors unapplied. Top-level declarations such as `effect function fork() { return 1 }` and method names such as `effect join() { return 1 }` remain valid.

The native `await` warnings apply to values typed as a single `Fiber` or `Deferred`. Arrays, tuples and objects containing handles remain ordinary JavaScript values; awaiting a container does not run its contents. A marker property alone does not make an object a handle. The editor's native `await` quick fixes insert the Promise bridge with imports that remain valid when local names shadow `Fiber`, `Deferred` or `runPromise`. The operand is evaluated once. A handle union that cannot be passed to one generic bridge call keeps its warning without an automatic edit. This includes a generic parameter constrained to such a union.

## Awaiting completion as data

```vibe
effect function inspectChild() {
  const child = fork effect { throw "render failed" }
  const outcome = try Fiber.await(child)
  if (Exit.isFailure(outcome)) {
    try Console.log("renderer stopped", Cause.squash(outcome.cause))
  }
  return outcome
}
// Output: renderer stopped render failed
// Output: true
```

`Fiber.await` succeeds with an `Exit`, which also represents defects and interruption, so it doesn't rethrow the child's failure into the caller. Use `join child` to propagate failure and `try Fiber.await(child)` when the caller decides what the outcome means.

Fiber operators compose with other unary expressions. `join fork task` starts the Effect `task` and waits for its result; `! join child` negates the child's completed value.

## Handling asynchronous interruption

```vibe
effect function stopWorker() {
  const started = try Deferred.make<void>()
  const worker = fork ensuring(
    effect {
      try Deferred.succeed(started, undefined)
      try sleep("1 minute")
    },
    Console.log("worker finalizer")
  )
  try Deferred.await(started)
  try Fiber.interrupt(worker)
  try Console.log("worker has terminated")
}
// Output: worker finalizer
// Output: worker has terminated
```

The child completes `started` from inside `ensuring`, after its cleanup is registered. The parent awaits that `Deferred` before interrupting; a startup delay or `yieldNow` cannot prove that cleanup is ready.

Cancellation needs no hand-written polling loop: Effect delivers it at runtime boundaries, defers it in uninterruptible regions, and runs cleanup before `Fiber.interrupt` returns. A long plain JavaScript calculation still holds the host thread until it returns or reaches an Effect operation.

To continue during cleanup, fork the interruption (`const stopping = fork Fiber.interrupt(worker)`) and `join stopping` before its owner exits. When cleanup ordering matters, avoid immediate unsafe runtime methods.

## Protecting work from interruption

Interruption blocks require an `effect` function or `effect { }` block. Plain and `async` functions, `class` field and `enum` member initializers, `static` blocks and parameter defaults report `EK2201`; a plain callback nested in effect code is still plain. `vibelang --fix` removes the ignored keyword and preserves the ordinary JavaScript block the old compiler emitted.

```vibe
effect function saveReport() {
  uninterruptible {
    try Console.log("saving; an interruption waits until the block ends")
    restore {
      try sleep("1 second")
    }
    try Console.log("saved")
  }
}

effect function pollStatus(cancelled: boolean) {
  interruptible {
    try sleep("1 second")
  }
  if (cancelled) try interrupt
}
// Output: saving; an interruption waits until the block ends
// Output: saved
// Output: true
```

- `uninterruptible` (`Effect.uninterruptibleMask`) runs its block without interruption: an interruption that arrives waits until the block ends.
- `restore` inside it brings back the fiber's previous interruptibility, so long waits stay cancellable. A `restore` in an `effect` function, arrow, method, producer or block nested in the mask, or anywhere in a `for concurrent` head or body, is `EK2202`: those run as their own Effects, outside the mask. A `do` expression runs in place, so its `restore` is inside the mask.
- `interruptible` (`Effect.interruptible`) makes its code interruptible even inside an uninterruptible region.
- `try interrupt` (`Effect.interrupt`) interrupts the running fiber. `try yieldNow` (`Effect.yieldNow`) yields to the scheduler. Both names are native Effect values, so omit parentheses; for a chosen priority, use `try Effect.yieldNowWith(priority)`.

The opening `{` must be on the same line as `uninterruptible`, `restore` or `interruptible`. With a line break before `{`, the word is an ordinary identifier and the following block is a separate statement.

An `uninterruptible` block protects a child after it enters the block. If another fiber must wait for that point before interrupting it, signal with a `Deferred` from inside the block; a sleep does not prove the child has started.

Statements in these blocks stay code of the enclosing function, so `return` returns from it. Run Effects inside each block with `try`. To pass an Effect value instead, use `Effect.uninterruptible(saveRows())` or `Effect.interruptible(program)`. The bare names are reserved for blocks, so calls and stored function values use the `Effect.` qualifier.

## Combining results

```vibe
effect function title() {
  return "Inventory"
}

effect function rowCount() {
  try sleep("20 millis")
  return 18
}

effect function combine() {
  const [name, count] = try.all [title(), rowCount()]
  return `${name}: ${count}`
}
// string!!
// Output: Inventory: 18
```

`try.all [...]`, like `Promise.all`, waits for all and keeps the input array's order. Its operands start in order with unbounded concurrency. `rowCount()` returns its Effect unrun, and `try.all` starts it in its fiber. For an object of Effects, use `try all({ name: title(), count: rowCount() }, { concurrency: "unbounded" })` to keep the object shape. If one fails, `try.all` interrupts the rest and propagates the failure, as `all` fails fast. For an expected-failure fallback, use `program catch () => fallback`; defects and interruption still propagate.

`try.allSettled [...]` returns an `Exit` for each element and never fails. Each `Exit` represents success, failure, defect, or interruption, keeping every outcome as data, mixed causes included.

For fibers you already hold, join each handle or use `try all([Fiber.join(titleFiber), Fiber.join(rowsFiber)])`. In a `try.all` operation, pass `Fiber.join(fiber)` or `Deferred.await(ready)` as the element, not the fiber or deferred handle itself. Pass an existing array of Effects directly, as `try.all jobs`; a plain function must be called to get its Effect first.

## Racing events

```vibe
effect function nextEvent(jobs: Queue.Queue<string>, shutdown: Deferred.Deferred<void>) {
  return try.race [
    effect { return `job: ${try Queue.take(jobs)}` },
    effect {
      try Deferred.await(shutdown)
      return "shutdown"
    },
    effect {
      try sleep("30 seconds")
      return "idle"
    }
  ]
}
// string!!
// Output: job: build
// Output: shutdown
// Output: idle
```

`try.race [...]` (`Promise.race`, `Effect.raceAllFirst`) starts each element in its own fiber, returns the first to finish, success or failure, and interrupts the rest; of elements ready at once, the first written wins. An `effect { ... }` element builds an Effect whose statements run in its fiber, and `return` supplies its value. `try.any [...]` (`Effect.raceAll`) returns the first success instead and fails only when every element fails. To poll without waiting, test `try Queue.poll(jobs)` with an `if`.

## Running a loop body concurrently

```vibe
effect function fetchPage(id: string) {
  try sleep("5 millis")
  return `page ${id}`
}

effect function printAll(ids: ReadonlyArray<string>) {
  for concurrent(8) (const id of ids) {
    if (id === "") continue
    try Console.log(try fetchPage(id))
  }
}
// Output: page a
// Output: page b
```

`for concurrent` runs its body for each item and ends when all finish; `for concurrent(8)` runs at most eight at once, and `for concurrent (...)` sets no limit. Whether an item gets its own fiber is `Effect.forEach`'s choice: a limit above 1 forks one fiber per item, and `for concurrent(1)` runs the items in order on the enclosing fiber. A failure interrupts the items still running and fails the loop. `continue` ends one item. A labeled `continue` naming the `for concurrent` itself also ends the current item. A labeled `continue` targeting a loop outside `for concurrent` is an error (`EK1905`); use an unlabeled `continue` at the item level to end the current item. Labels on loops inside the item keep their ordinary meaning. Because the body runs in `Effect.forEach`'s callback, a `break` that would leave the loop (`EK1903`) and a `return` (`EK1904`) are errors; throw to stop every item. For results, use `forEach`.

Line breaks and multiline comments may separate `concurrent` from its optional limit or loop head.

An omitted limit always means unbounded concurrency, even when a local binding is named `undefined`.

The formatter preserves nested `try` expressions in the concurrency limit and iterable expression.

A written `for concurrent(limit())` limit is evaluated once, before the iterable expression, in both the native compiler and TypeScript mapper.

## Supervising child lifetimes

```vibe
effect function request() {
  try ensuring(scoped(effect {
    const started = try Deferred.make<void>()
    const progress = fork.scoped ensuring(
      effect {
        try Deferred.succeed(started, undefined)
        try sleep("1 minute")
      },
      Console.log("progress reporter stopped")
    )
    try Deferred.await(started)
  }), Console.log("request finishing"))
}
// Output: progress reporter stopped
// Output: request finishing
```

A plain `fork` belongs to the parent fiber. A nested block, including a `provide` block, doesn't create a fiber owner. A child can be joined after `provide` ends and retains the services that block supplied. Use `fork.scoped` when work must end with a specific scope. Here `scoped` closes that scope, interrupts the reporter, and waits for cleanup before the outer finalizer runs.

Forked fibers inherit the current services and tracing context.

A service declared inside a function or block needs an explicit `static readonly key`. Its `static readonly defaultValue` initializer keeps the class-field context, so ordinary helpers named `fork` or `join` remain ordinary calls there.

## Selecting scoped or detached lifetimes

```vibe
effect function inCallerScope(owner: Scope.Scope) {
  const started = try Deferred.make<void>()
  const background = fork.in(owner) effect {
    try Deferred.succeed(started, undefined)
    try sleep("1 minute")
  }
  try Deferred.await(started)
  // Closing owner interrupts background.
  return background
}

effect function detachedExample() {
  const independent = fork.detached sleep("50 millis")
  join independent
}
// Output: true
// Output: detached finished
```

`fork.in(owner)` attaches the child to a scope you hold; it lives until that scope closes. `fork.detached` ties the child to nothing: it survives its parent and needs an explicit shutdown strategy (the example joins it to stay bounded). `fork.scoped` attaches the child to the caller's scope and leaves `Scope` in the caller's requirements until a scope is supplied.

Start a fiber that must outlive its parent with `fork.scoped work()` for the caller's scope, `fork.in(owner) work()` for a scope the caller holds, or `fork.detached work()` and a shutdown strategy. To bound a `join`, race its Effect: `try.race [Fiber.join(child), effect { try sleep("5 seconds"); throw new Late() }]`.

## Understanding execution scheduling

```vibe
effect function waitForReady() {
  const ready = try Deferred.make<void>()
  const worker = fork effect {
    try Console.log("worker initialized")
    try Deferred.succeed(ready, undefined)
    try sleep("20 millis")
  }
  try Deferred.await(ready)
  try Console.log("initialization is complete")
  join worker
}
// Output: worker initialized
// Output: initialization is complete
```

Forking schedules a child; it doesn't prove the child reached a particular statement. `try yieldNow` lets other work run but guarantees no readiness, and sleeping for an estimated startup time leaves a race. When ordering matters, use a `Deferred`: `try Deferred.await(ready)` waits until the child completes it.

Parenthesize an execution expression before exponentiation: `(join fiber) ** 2`. A bare `join fiber ** 2` or `fork program ** 2` reports `EK0510`. For a numeric `join` result, the editor action and `vibelang --fix` write `(join fiber) ** 2`.

For an old bare `fork { ... }` body, run `vibelang --fix` to write `fork effect { ... }`. The `fork blocks` codemod also handles adjacent `fork{}` and a line break after `fork`, preserving the cold body, captures and return value.
