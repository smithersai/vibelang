# Basic Concurrency

Effect functions return Effect values without running them. Inside an effect function, use `try` to run an Effect. Effect's concurrency combinators overlap work, limit concurrency, and control cancellation; pass the work as Effect values so the combinator starts each operation at the right time.

Running a completed Effect with `try` can continue in the same fiber turn. It adds no Promise job: Effect's scheduler decides when other fibers run, including through its cooperative work budget. Use `try yieldNow` to request a cooperative yield; one yield does not promise a global order for unrelated fibers.

## Sequential, bounded, and unbounded work

<figure className="vibe-video"><video controls preload="metadata" playsInline poster="/videos/concurrent.jpg"><source src="/videos/concurrent.mp4" type="video/mp4" /></video><figcaption>try all runs calls together</figcaption></figure>

```vibe
effect function task(id: number) {
  try Console.log("starting", id)
  try sleep("40 millis")
  return id * 2
}

effect function runTasks() {
  const sequential = try all([task(1), task(2)])
  const bounded = try forEach([1, 2, 3, 4], (id) => task(id), {
    concurrency: 2
  })
  const unbounded = try.all [task(5), task(6), task(7)]
  return { sequential, bounded, unbounded }
}

effect function stringify(value: unknown) {
  return try Effect.try(() => JSON.stringify(value))
}
// Output: starting 1
// Output: starting 2
// Output: starting 1
// Output: starting 2
// Output: starting 3
// Output: starting 4
// Output: starting 5
// Output: starting 6
// Output: starting 7
// Output: {"sequential":[2,4],"bounded":[2,4,6,8],"unbounded":[10,12,14]}
```

A destructuring head keeps native `for…of` binding inference. A default may supply a missing property of a fresh object literal, as in `for concurrent (const { n = 1 } of [{}]) { … }`. A named or explicitly typed `{}[]` still has no `n` property and reports `TS2339`, as in TypeScript.

A non-iterable `for concurrent` operand reports `EK1901`; pass an `Iterable`, or use `for try` to consume a Stream. `any`, `never`, readonly arrays, sets and strings follow ordinary assignability, including a `Stream` that also implements `Iterable`. Independent type errors in an iterable operand or the loop body retain their TypeScript diagnostics. An iterable union keeps every possible element type: `number[] | Set<string>` gives `number | string` in the loop head, as a native `for...of` loop does.

An item from `any` keeps type `any`; identifier heads use ordinary TypeScript declarations and narrowing, just like pattern heads.

With `noUnusedLocals`, an unused named head reports `TS6133`, as in native `for...of`; prefix an intentionally unused head with `_`. `vibelang --fix` makes that rename when the source has no other use of the head name; an RHS capture or shadowed use needs a manual rename that preserves its scope.

`all` runs Effects sequentially by default; a positive integer limit bounds active operations. On Effect `4.1.1`, numeric limits below `1` still run every item sequentially. `for concurrent(n)` passes the limit unchanged to Effect, including fractional and non-finite values, without adding a range check or rounding. `try.all [...]` is the project's `Effect.all` with unbounded concurrency, like `Promise.all`. Its operands start in order, and one that fails before it suspends stops later ones from starting. Results keep the written order however the work finishes. Whitespace, comments and line breaks may separate `try`, the dot and the operation name. Parentheses let you access the result's properties: `(try.all [task(1), task(2)]).length` is `2`. For a constrained service or resource, set a finite limit with `forEach` or `for concurrent(n)`.

A concurrency limit bounds running work, not iterable pulling. In pinned Effect, `for concurrent(1)` pulls incrementally and an item failure does not call the iterator's `return()`. The parallel branch, including an omitted limit or `"unbounded"`, first materializes a non-array iterable; an endless one cannot finish that step. An existing array is reused by reference and its custom iterator is not called in that branch. Use a Stream with `for try` for ordered Stream consumption. See the [runtime witness](https://vibelang.sh/spec/008-runtime#iterable-lifecycle).

A `return` cannot leave a `for concurrent` item, including its head binding initialization, computed member names and class heritage. These positions report `EK1904`. A nested method or function keeps its own returns. Use `continue` to finish one item. The same jump restrictions apply at every concurrency limit, including `1`. A labeled `continue` naming the concurrent loop itself, including any label in a chain, also finishes that item, including from a `do` expression; nested loops keep their own jump targets.

A label cannot be repeated inside the statement it labels. Reusing an enclosing label in a `for concurrent` body reports `TS1114`; a nested function has its own label scope.

A label named by `continue` in a `for concurrent` body counts as used for `allowUnusedLabels`. In a chain, each label is checked separately.

A written `for concurrent(limit())` limit is evaluated once, before the iterable expression, in both the native compiler and TypeScript mapper. The traversal calls the project's `Effect.forEach`, so item fibers and surrounding `fork` operations share the same Effect instance even when the runtime has a separate installation.

Group a comma expression used as a limit with extra parentheses: `for concurrent((record(), 4)) (...)`. A bare comma list in the limit reports `TS1005`; `vibelang --fix` adds the parentheses while preserving evaluation order.

A written concurrency limit must be assignable to Effect's `Types.Concurrency` (`number | "unbounded"`). Other types, including explicit `undefined` and `null`, report `EK1907`. Omitting the limit runs unbounded. Ordinary TypeScript assignability still admits `any` and `never`. If an unchecked written limit evaluates to `undefined` or `null`, Effect receives that value unchanged and runs items sequentially. The `"unbounded"` sentinel also works through a variable, parameter, type alias or generic constrained to `Types.Concurrency`.

## Interrupting computations

```vibe
effect function cancelWork() {
  const worker = fork effect {
    try sleep("1 minute")
    return "finished"
  }
  try Fiber.interrupt(worker)
  return try Fiber.await(worker)
}
// Output: true
```

`Fiber.interrupt` requests cancellation and waits for termination, finalizers included; `Fiber.await` then returns an `Exit` describing the interruption instead of propagating it. `try interrupt` interrupts the current fiber. Interruption is outside the expected error channel, so ordinary `catch` doesn't handle it.

## Attaching interruption cleanup

```vibe
effect function cancelWithCleanup() {
  const started = try Deferred.make<void>()
  const worker = fork onInterrupt(
    ensuring(effect {
      try Deferred.succeed(started, undefined)
      try sleep("1 minute")
    }, Console.log("released worker resources")),
    () => Console.log("worker cancelled")
  )
  try Deferred.await(started)
  try Fiber.interrupt(worker)
}
// Output: released worker resources
// Output: worker cancelled
// Output: interrupt returned
```

The child signals `started` after both cleanup handlers are installed, and the parent awaits that `Deferred` before interrupting. Sleeping for an estimated startup time leaves a race: an interrupted child that never started has no cleanup to run.

`ensuring` runs cleanup on every exit; `onInterrupt` adds work only for cancellation. Cleanup runs before the interrupting caller resumes. For acquired resources, `acquireRelease` inside `scoped(effect { ... })` registers release as part of acquisition, not in a later statement.

## Propagating cancellation across concurrent work

```vibe
effect function cancelBatch() {
  for concurrent (const id of [1, 2, 3]) {
    try ensuring(effect {
      if (id === 2) {
        try sleep("10 millis")
        try interrupt
      }
      try sleep("1 second")
    }, Console.log("branch finished"))
  }
}
// Output: branch finished
// Output: branch finished
// Output: branch finished
// Output: true
```

The tokens in `for concurrent` use ordinary whitespace: a line break or multiline comment may separate `concurrent` from its limit or loop head.

Omitting the limit means unbounded concurrency. Local bindings, including a binding named `undefined`, do not change that default.

The body's braces keep a separate scope from its `const` or `let` head binding, so a local declaration may reuse that binding's name.

Above a limit of 1, `for concurrent` runs each item in its own fiber. At a limit of 1 or below, items run in order on the enclosing fiber. An interrupted branch stops the loop and interrupts its active siblings; so does an expected failure in the default concurrent traversal, cancelling work whose result is no longer needed. The parent waits for branch cleanup. A cause that holds a defect passes through ordinary `catch` with its failures re-raised as defects, as `Effect.catch` does. A cause with no expected failure, such as a lone interruption, never reaches the handler.

The right-hand operand sees uninitialized loop-head bindings, as in JavaScript's `for…of`; a closure created there keeps those bindings rather than an outer or per-item binding. This also holds for an empty iterable and after an item reassigns a `let` head; calling the saved closure still encounters a `ReferenceError`. If an older program used an outer binding there and now fails type checking, `vibelang --fix` renames the item binding and its uses, keeping the RHS reference attached to the live outer binding. Outward `return` is rejected in both head binding initialization and the body (`EK1904`), including a `return` in a default's `do`. A `do` return in the concurrency-limit or iterable expression still targets the enclosing function. A labeled `break` from a `do` in the limit or iterable can leave an enclosing labeled block. The block keeps its own jump target when a declaration precedes the loop; an item-ending labeled `continue` must name the loop itself.

## Racing under different winner rules

<figure className="vibe-video"><video controls preload="metadata" playsInline poster="/videos/race.jpg"><source src="/videos/race.mp4" type="video/mp4" /></video><figcaption>try race: the first answer wins, the losers are cancelled</figcaption></figure>

```vibe
effect function answer(label: string, delay: Duration.Input) {
  try sleep(delay)
  return label
}

effect function raceExamples() {
  const firstSuccess = try race(
    effect { throw "unavailable" },
    answer("replica", "20 millis")
  )
  const anySuccess = try.any [
    answer("west", "40 millis"),
    answer("east", "10 millis"),
    answer("central", "30 millis")
  ]
  const firstCompletion = try.race [
    answer("primary", "10 millis"),
    answer("backup", "50 millis")
  ]
  return { firstSuccess, anySuccess, firstCompletion }
}
// Output: {"firstSuccess":"replica","anySuccess":"east","firstCompletion":"primary"}
```

The `try` operations (TC39 await operations proposal) keep the same-named `Promise` methods' choice of result, with two differences: the Effects that lose are interrupted, and an empty `try.race` or `try.any` never completes, where `Promise.any([])` rejects. `try.any` (`Effect.raceAll`) waits for a success, so an early failure doesn't defeat a branch that can still succeed; if none succeeds, it fails with the collected failure reasons. `try.race` (`Effect.raceAllFirst`) takes the earliest completion, failure included. Both interrupt and clean up the losers before returning. A named Effect function keeps Effect's meaning: `race`, like `Effect.race`, waits for a success.

## Inspecting the winner

```vibe
effect function inspectRace() {
  const winners: number[] = []
  const outcome = try result(raceFirst(
    effect { throw "primary offline" },
    effect {
      try sleep("1 second")
      return "backup response"
    },
    { onWinner: ({ index }) => { winners.push(index) } }
  ))
  if (Result.isFailure(outcome)) {
    try Console.log("first completion failed", outcome.failure)
  }
  return { outcome, winners }
}
// Output: first completion failed primary offline
// Output: true
// Output: [0]
```

The synchronous `onWinner` callback observes the winning fiber and its index: zero for the first branch, one for the second. It doesn't replace the winning result and can't run an Effect. `Effect.result` captures expected failures as data; `Effect.exit` also captures defects and interruption.

## Coming from Effect

`Effect.all([task(1), task(2)], { concurrency: "unbounded" })` becomes `try.all [task(1), task(2)]`, and `Effect.raceFirst(a, b)` becomes `try.race [a, b]`. Each element is an Effect value, so `task(1)` returns its Effect unrun and `try.all` starts it in its own fiber. Use `effect { ... }` for a branch that needs several statements.

An operand that is not an array of Effects reports `EK1801`. TypeScript still reports independent errors inside its calls, literals and `satisfies` checks. A literal's `satisfies` check uses its written target type.

For `try.allSettled`, explicit array-literal elements keep their tuple positions and use the native `Effect.exit` argument checks. A literal without spreads wraps each element directly at runtime, adding no `.map` call for the source array. A named operand uses `xs.map(Effect.exit)` and produces an array. For a heterogeneous named tuple, write its known positions explicitly, `try.allSettled [xs[0], xs[1]]`. For an array whose element type is a union of different Effects, first widen it to one Effect type, such as `ReadonlyArray<Effect.Effect<number | string>>`; indexing that union array does not narrow each position. A literal spread contributes an array rest, even when its source is a fixed-length tuple. It is built once before its `.map(Effect.exit)` call. Use `try.allSettled []` when there are no tasks: mapping a named empty tuple or `never[]` inherits TypeScript's `unknown` service requirement. For code that relied on the earlier contract, `vibelang --fix` preserves it with an explicit import of the existing `$tryAllSettled` helper, including the former empty-collection service requirement.

`try.all`, `try.race`, `try.any` and `try.allSettled` require arrays or tuples of Effects (`EK1801`). The check uses TypeScript assignability to `ReadonlyArray<Effect.Effect<any, any, any>>`, so `any`, arrays or tuples with `any` elements, and `never` pass; `unknown` does not. For an object, use `try all({ user: load() }, { concurrency: "unbounded" })`; the `try.all` quick fix writes this form. The removed spellings `await.all`, `await.race`, `await.any` and `await.allSettled` report `EK1802`, including inside native `async` functions, arrows and methods. In effect code, `vibelang --fix` rewrites them to these operations. An async callable retains its JavaScript context: construct the corresponding Effect operation and wait with `await Effect.runPromise(...)`. The fixer does not insert effect-only `try` syntax into that body.

Each operation runs its elements on separate fibers. Provide their service requirements around the combined `Effect`.

Both a braced body and a single statement support the same head patterns and `is` bindings in the TypeScript projection.

The head of `for concurrent` must declare its item with `const` or `let`. A `var`, `using`, `await using`, or assignment head reports `EK1906`, including with `--noCheck`. To assign an existing variable, declare a fresh item and assign inside the body: `for concurrent (const item of items) { current = item }`.
