# The Effect Type

`Effect<A, E, R>` is the contract of a computation: its success value, expected errors, and required services. VibeLang infers it for every effect function, even one that only calculates a value.

## Success, failure, and services

```vibe
error MissingRate {
  currency: string
}

service Rates {
  lookup(currency: string): number!MissingRate
}

effect convert(amount: number, currency: string) {
  const rates = try Rates
  return amount * (try rates.lookup(currency))
}
// number!MissingRate!Rates
// Output: 60
```

`A` is `number`, `E` is `MissingRate`, and `R` is `Rates`. A service method states its complete contract because it has no body to infer from; running its Effect also adds the service itself to the caller's requirements.

| Channel | Meaning of special types |
| --- | --- |
| `A` | `void` returns no useful value; `never` never succeeds. |
| `E` | `never` has no expected failure; defects and interruption remain possible. |
| `R` | `never` needs no additional services. |

Errors and services from several Effects run with `try` accumulate as unions. Catching a failure removes it from `E`; providing a service removes it from `R`. Write a full annotation, such as `number!!Rates`, to have the compiler check a promise. `Effect<number, never, Rates>` is accepted too, and means the same.

Inferred errors and services are unions: running the same Effect more than once does not add another copy of its error or service types. Chains of repeated calls do not need written contracts to keep inference bounded.

## Write a contract

```vibe
effect rateOf(currency: string): number!MissingRate!Rates {
  const rates = try Rates
  return try rates.lookup(currency)
}

effect safeRate(currency: string): number!!Rates {
  const rates = try Rates
  return try orDie(rates.lookup(currency))
}

effect anyRate(currency: string) {
  const rates = try Rates
  return try rates.lookup(currency)
}
// Inferred: number!MissingRate!Rates
// Output: 2
```

`.vibe` code writes `Effect<A, E, R>` as `Result!Error!Dependencies`. An empty slot is `never`: `number!MissingRate!` cannot need a service, and `number!!` neither fails nor needs one. An omitted dependencies slot is `never` everywhere. `anyRate` omits the whole return annotation, so all three channels are inferred. A union belongs to its slot: `string!MissingRate | Offline!Rates` fails with either error. Parenthesize a function type, a conditional type, or an object type after a `!`; an object type's `{` would start the function's body.

Hovers show contracts this way, and declaration files keep `Effect.Effect<A, E, R>` for TypeScript callers. `Effect<A, E, R>` is accepted anywhere a type is.

## Check selected channels

```vibe
effect rate(currency: string): Effect<number, MissingRate, Rates> {
  const rates = try Rates
  return try rates.lookup(currency)
}
// Checks number, MissingRate, and Rates.

effect rateOrDie(currency: string): Effect<number, never, Rates> {
  const rates = try Rates
  return try orDie(rates.lookup(currency))
}
// Checks number, never, and Rates.

effect label(currency: string): Effect<string, MissingRate, Rates> {
  const rates = try Rates
  return (try rates.lookup(currency)).toFixed(2)
}
// Checks string, MissingRate, and Rates.

effect checkedConversion(amount: number, currency: string) {
  return try convert(amount, currency)
}
// Infers number, MissingRate, and Rates.
// Output: 60
```

A return annotation checks the complete Effect type. Leave it out to infer all three channels from the body. A type argument left out of `Effect<…>` is `never`, as in TypeScript: `Effect<number>` is `number!!`, a promise that the function cannot fail and needs nothing. `number!MissingRate` also needs no services.

The `effect` keyword decides the function's kind. Plain functions and `async` functions keep TypeScript's meaning, regardless of their return annotations. A plain callback can return an Effect without running it, so `xs.map((x) => work(x))` builds an array of Effects. A callback that must run Effects uses `effect`, as in `forEach(xs, effect (x) => { return try work(x) })`.

Recursion is as stack-safe as it is with `Effect.gen`. `effect sumTo(n: number): number!! { return n === 0 ? 0 : n + (try sumTo(n - 1)) }` runs each recursive Effect with `try`; `try sumTo(100000)` succeeds. Plain JavaScript recursion retains JavaScript's stack limit. Recursion through a synchronous callback recurses as JavaScript does: past roughly 10,000 calls on Node it fails with a `RangeError` defect.

The shorthand has the same meaning in parameter types, aliases, service members, and return annotations. A callback parameter type means what TypeScript means: `(n: number) => string` is a plain callback, and one returning an Effect is `(n: number) => string!E!R`, with `E` and `R` declared as the function's type parameters.

## Description and execution

```vibe
const conversion = convert(30, "EUR")

effect displayedPrice() {
  const amount = try conversion
  return amount.toFixed(2)
}
// Output: 60.00
```

Creating `conversion` does no work. `try conversion` runs the computation within the current effect function and returns its success value. `try` starts no new fiber; runners start execution at the application edge.

An Effect value such as `Clock.currentTimeMillis` is a description; `try Clock.currentTimeMillis` reads the clock inside an effect function. Effect-returning library functions build Effects that run with `try`.

`Config` descriptors and Context keys are Effect values that run with `try`. Returning an Effect leaves it unrun; `new` only constructs an instance. Use `throw error` to fail with an error instance.

## Extract inferred channel types

```vibe
// convert.vibe
export effect double(amount: number) {
  return amount * 2
}
// number!!
// Output: 60
```

```ts
// TypeScript (.ts)
// inspect.ts: imports the emitted VibeLang module
import { Effect } from "effect"
import { double } from "./convert.js"

type Contract = ReturnType<typeof double>
type Value = Effect.Success<Contract>    // number
type Failure = Effect.Error<Contract>    // never
type Services = Effect.Services<Contract> // never
```

TypeScript consumers see exported VibeLang functions as returning ordinary Effects. `Effect.Success`, `Effect.Error`, and `Effect.Services` extract the channels from those inferred return types without executing the program.

## Coming from Effect

`Effect<A, E, R>` is global in `.vibe` files. Written with its type arguments, as `Effect.Effect<A, E, R>`, it draws EK4833, whose quick fix writes `A!E!R` ([TypeScript-style Effect code](/getting-started/012-devtools#typescript-style-effect-code)). A call returns an Effect; `try` gives `A`. Keep the Effect value to compose or store it.
