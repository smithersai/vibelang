# Path

`Path` is Effect's platform-specific path service, in place of `node:path`. Use it to join, split, normalize, and convert paths without hard-coding host separators or importing a native path module.

## Requesting the path service

```vibe
import * as NodePath from "@effect/platform-node/NodePath"

effect function pathSeparator() {
  const path = try Path.Path
  return path.sep
}
// Output: /
```

`try Path.Path` gets the implementation from the current environment. Its `sep` property is a value, and `path.join(...)` calls one of its methods. The module's own exports, such as `Path.layer`, keep their meaning, and the key itself is `Path.Path`.

## Manipulating paths portably

```vibe
import * as NodePath from "@effect/platform-node/NodePath"

effect function describeReport() {
  const path = try Path.Path
  const joined = path.join("reports", "weekly.txt")
  const normalized = path.normalize("reports/./draft/../weekly.txt")
  const parsed = path.parse(joined)
  return {
    joined,
    normalized,
    base: path.basename(joined),
    directory: path.dirname(joined),
    extension: path.extname(joined),
    absolute: path.isAbsolute(joined),
    rebuilt: path.format(parsed)
  }
}
// Output: {"joined":"reports/weekly.txt","normalized":"reports/weekly.txt","base":"weekly.txt","directory":"reports","extension":".txt","absolute":false,"rebuilt":"reports/weekly.txt"}
```

Most `Path` methods are plain synchronous TypeScript functions. Getting the service with `try Path.Path` adds `Path` to R even when a member returns a string. Call non-throwing methods directly. Wrap a synchronous call that may throw with `Effect.try` before running it in effect code.

| Operation | Result |
| --- | --- |
| `basename`, `dirname`, `extname` | File name, directory, or extension |
| `join`, `normalize` | A combined or simplified path |
| `parse`, `format` | Structured path components or their string form |
| `isAbsolute` | Whether a path has an absolute root |
| `relative`, `resolve` | A relative relationship or an absolute resolution |
| `sep` | The implementation's separator |
| `toNamespacedPath` | A Windows namespace path where applicable |
| `toFileUrl`, `fromFileUrl` | Effectful file-URL conversion |

```vibe
import * as NodePath from "@effect/platform-node/NodePath"

effect function asFileUrl(file: string) {
  const path = try Path.Path
  const absolute = path.resolve(file)
  const url = try path.toFileUrl(absolute)
  return try path.fromFileUrl(url)
}
// Output: /reports/weekly.txt
```

URL conversions return Effects, run with `try`, and report `BadArgument` on invalid input. Path string operations are lexical: normalizing or resolving a path doesn't check that a file exists. Use FileSystem when file-system state matters.

## Supplying a platform path implementation

```vibe
// main.vibe
import * as NodeRuntime from "@effect/platform-node/NodeRuntime"
import * as NodePath from "@effect/platform-node/NodePath"

effect function main() {
  const path = try Path.Path
  try Console.log(path.join("reports", "weekly.txt"))
}

NodeRuntime.runMain(Effect.provide(main(), NodePath.layer))
// Output: reports/weekly.txt
```

`NodePath.layer` supplies host path behavior; `NodeServices.layer` supplies it as part of the whole Node service bundle, and `BunServices.layer` supplies Bun's. The module's `Path.layer` supplies the built-in POSIX implementation, for programs that use POSIX paths on purpose, deterministic tests included: `provide Path.layer { ... }` inside `main` wins over the bundle.

## Coming from Effect

Use `try Path.Path` to get the service. Call synchronous methods directly, and run Effect-returning methods with `try`. Read value properties from the implementation, as in `path.sep`.
