# Matching

Matching turns an outcome into one value or selects the next computation. Use typed matching for domain failures, and cause matching when a boundary also needs defects and interruptions.


## Folding success and failure into values

```vibe
error InvalidCount

effect itemCount(raw: number) {
  if (raw < 0) throw new InvalidCount()
  return raw
}

effect countLabel(raw: number) {
  return try Effect.match(itemCount(raw), {
    onFailure: () => "Count unavailable",
    onSuccess: (count) => `${count} items`
  })
}
// string!!
```

```text
3 items
Count unavailable
```

`Effect.match` applies synchronous value callbacks, which are plain functions and can't perform Effect operations, such as one that only formats text. A cause without an expected failure propagates. A cause with a defect propagates too, its expected failures as defects. From an expected failure beside an interruption, Effect selects the failure and discards the interruption, as ordinary catch does.

## Choosing effectful branches

```vibe
effect reportCount(raw: number) {
  return try matchEffect(itemCount(raw), {
    onFailure: effect () => {
      try Console.log("Invalid count received")
      return "Count unavailable"
    },
    onSuccess: effect (count) => {
      try Console.log("Count accepted")
      return `${count} items`
    }
  })
}
```

```text
Count accepted
3 items
Invalid count received
Count unavailable
```

`matchEffect` accepts callbacks returning Effects that can pause, fail, or use services. Only the selected branch runs; its errors and requirements join the result's contract. Use a catch expression with an effect handler when recovery needs several statements.

## Matching complete failure causes

```vibe
effect outcomeLabel() {
  return try matchCause(die(new Error("index invariant")), {
    onFailure: (cause) => Cause.hasDies(cause) ? "Index defect" : "Index stopped",
    onSuccess: () => "Index ready"
  })
}

effect reportOutcome() {
  return try matchCauseEffect(die(new Error("index invariant")), {
    onFailure: effect (cause) => {
      try Console.log("Index stopped", JSON.stringify(cause.reasons.map((reason) => reason._tag)))
      return "Unavailable"
    },
    onSuccess: () => succeed("Ready")
  })
}
```

```text
Index defect
Index stopped ["Die"]
Unavailable
```

`matchCause` passes the full cause to a synchronous failure callback; `matchCauseEffect` allows Effect operations in both callbacks. Both can consume cancellation and mixed causes, so use them where the boundary's policy calls for that.

## Discarding failures or all causes

```vibe
effect ignoreRejectedCount() {
  try ignore(itemCount(-2))
}
// void!!

effect discardBoundaryOutcome() {
  try ignoreCause(die(new Error("isolated task failed")))
}
// Output:
```

`ignore` discards the success value and typed failures; causes without an expected failure propagate, and so do causes with a defect, but an expected failure beside an interruption is consumed with it. `ignoreCause` consumes the full failure cause, even one with no expected failure; use it only where losing both diagnostics and cancellation is deliberate.
