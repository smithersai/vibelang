# VIP-7: `match` is TC39 pattern matching, plus a compile-time exhaustiveness check

**Status:** accepted by Will, 2026-10-28.

## Decision

```ts
match (e) {
  when NotFound: guest;                // NotFound's Symbol.customMatcher decides, as TC39 says
  when Option.Some(let v): v;
  when DbError and if (retryable): retry();
  default: fallback;
}
```

- `match`, `when`, `is`, patterns, guards, `and`/`or`/`not` and `default` are exactly the TC39 pattern-matching proposal, pinned to a dated snapshot. We move to a newer snapshot deliberately, never automatically.
- The full proposal is implemented, not today's subset (D207): regular-expression and relational patterns and `async match` included.
- One addition: a `match` with no `default` over a finite union that misses a case is a compile error. The check only reports errors; it never changes what runs.
- Class arms use the class's `Symbol.customMatcher`. VibeLang's `error` classes get a matcher that tests `_tag`, so `when NotFound:` matches across copies of a package.
- **Condition: no run-time patching of Effect.** Until Effect ships custom matchers for `Option`, `Exit`, `Result` and its tagged errors, the compiler keeps today's fixed checks for them (D208). We propose the matchers upstream.
- **Amended 2026-10-29: what the exhaustiveness check covers.** Literal unions, `boolean`, `data` unions, `error` unions and enums. A guarded arm covers nothing. Sent to Will on Telegram 2026-10-29 11:28 under his standing rule 'assume I accept'; no objection by 12:00.

- **Amended 2026-10-30: class patterns on ordinary classes test `instanceof`.** The pinned draft's inherited `Function.prototype` matcher reads a `[[ConstructedBy]]` internal slot that only an engine can record, so compiled JavaScript can't emulate it for classes and objects from untouched `.ts` or `.js` code. - **Amended 2026-10-29: which subjects are checked, and which arms cover a case.** The subject's type is normalized into union members (`boolean` to `true | false`, an enum to its members, a `data` type to its variants, `Option` to `None | Some`, `Exit` and `Result` to `Success | Failure`). The check applies when every member is a literal, `null`, `undefined`, an enum member, a `data` variant, an `error` or `schema error` instance, one of those six cases or a retained Effect error; any other member turns it off. Only unguarded arms cover; a bare binding covers everything; an object pattern covers variant `V` when it has `_tag: "V"` and its other properties are bare keys or `let` bindings of required fields; `or` covers the union; `and`, `not`, regex, relational, array, built-in and user-matcher patterns cover nothing. Decided by the agent on 2026-10-29 under Will's rule "when I state a principle, the agent derives the concrete rule and acts; I can override later" (decided detail 78).
- **Amended 2026-10-30: lexical cell identity.** Alternatives of one `or` share the cell of a name bound with the same keyword. A later alternative may replace a cell initialized by a failed earlier alternative; saved closures observe the replacement. Source `const` assignments remain forbidden; ordinary TDZ and duplicate-initialization rules outside that authorized replacement remain.
- **Amended 2026-10-30: loop-head binding lifetimes.** Lexical `is` bindings in `while`/`do…while` shadow outer names in a loop-head scope and never leak outside the loop. Every complete condition evaluation, including after `continue`, starts with fresh uninitialized cells. A successful condition and its following body share those cells, including later `let` writes seen by closures; short-circuiting can leave a binding in TDZ even when the condition is true. The initial `do` body uses uninitialized head cells; closures captured there retain those cells permanently in TDZ. Later conditions never rebind the initial cells. Nested source scopes and ordinary `if` block scope retain their existing rules.
- **Amended 2026-10-30: the other binding homes, and use before assignment.** In `for (init; test; update)`, an `init` binding belongs to the loop head as a `let` or `const` declared in `init` would, copied into each iteration when it is `let`; a `test` or `update` binding is a fresh cell in each iteration environment. A `for…in`, `for…of`, `for await`, `for concurrent` or `for try` head expression's binding is copied into each iteration. A concise arrow body's binding belongs to the arrow body, and a field initializer's binding to that initializer. `is` and `match` bindings take part in TypeScript's definite-assignment and use-before-declaration checks (`TS2454`, `TS2448`); a read those checks can't see throws `ReferenceError` while the cell is uninitialized.

- **Amended 2026-10-30: leaving a `match`.** However a `match` or `is` test ends, its cached iterators close before control goes on, as at the end of a `for…of` body: a value, a `return`, a `break` or a `continue` closes and goes on, and an error from closing replaces it. A pending throw with a closing error gives the draft's `AggregateError`. The draft's `FinishMatch` appends every abrupt completion to its errors, which turns `return 7` into `throw 7`; VibeLang reads that step as "a throw completion", as the draft's notes intend. In effect code a failed `try`, or a `throw`, abandons the generator, so nothing closes. A no-match error is `new TypeError()`. A `return` in an `async match` is a syntax error, as in TC39's `async do`. Decided by the agent on 2026-10-30 under Will's rule "when I state a principle, the agent derives the concrete rule and acts; I can override later".
- **Amended 2026-10-30: `_tag` exhaustiveness counts literal cases.** `EK4701` counts the literal cases of `switch (s._tag)` per normalized member. A pattern testing a shared literal covers each member's matching case even when TypeScript does not narrow the whole subject because every member has the same `_tag` type. A generated error's bare or one-binding pattern likewise covers each member's matching tag case, including a plain object with that tag; any other tag cases on that member remain. A member is tagged when its `_tag` is a literal type: a string, number, bigint, boolean, enum, `null` or `undefined` literal, a `unique symbol`, or a union of those. Each literal is a case, and an optional `_tag` has the case `undefined`, so `{ _tag?: "A" } | { _tag: "B" }` is checked and the absent tag is left, as `tsc` leaves it. Any other `_tag` type turns the check off. Members that share a tag are covered one at a time: an object pattern covers a member only when every other property it tests is required on that member, as `"x" in s` narrows. Decided by the agent on 2026-10-30 under Will's rule "when I state a principle, the agent derives the concrete rule and acts; I can override later". This replaces "exactly one string literal type" in the amendment above.

- **Amended 2026-10-30: negation follows actual recognition.** `not P` uses only the TypeScript false-branch narrowing of `P`'s actual recognition test. Use `!(s instanceof C)` only for a dispatch path whose positive test is `s instanceof C`. Own matchers and predicates negate their invocation; an arbitrary `boolean` result narrows neither branch. Primitive/built-in adapters, retained Effect guards and generated tagged-error patterns likewise complement their actual tests. This adds no exhaustiveness coverage for negation.


Negation complements the actual recognition test for every dispatch path: literals use their equality test, ordinary classes their `instanceof` test, primitive/built-in adapters their specified tests, retained Effect patterns their module guards, generated tagged errors their tag tests, and own matchers or predicates their invocation. Only the false-branch narrowing established by that TypeScript test applies. An arbitrary `boolean`-returning matcher establishes no narrowing on either branch. This typing rule adds no exhaustiveness coverage for `not`.

```ts
import { Effect, Exit } from "effect"

const complementMatcher: unique symbol = Symbol.for("Symbol.customMatcher")
class OnlyNumbers {
  readonly kind = "instance"
  static [complementMatcher](s: unknown, _hint: { matchType: "boolean" }): boolean {
    return typeof s === "number"
  }
}
function matcherComplement(s: OnlyNumbers | number) {
  if (!OnlyNumbers[complementMatcher](s, { matchType: "boolean" })) return s
  return "number"
}
function rejectedComplement(s: OnlyNumbers | number) {
  if (!OnlyNumbers[complementMatcher](s, { matchType: "boolean" })) {
    // @ts-expect-error TS2365: a boolean-returning matcher establishes no narrowing
    return s + 1
  }
  return 0
}
class Plain { readonly kind = "plain" }
function ordinaryComplement(s: Plain | number) {
  if (!(s instanceof Plain)) return s + 1
  return 0
}
const instance = new OnlyNumbers()
const matcherExit = Effect.runSyncExit(Effect.sync(() => [
  matcherComplement(instance) === instance,
  matcherComplement(7),
  ordinaryComplement(new Plain()),
  ordinaryComplement(7)
]))
console.log(matcherExit) // Success([true, "number", 0, 8])
```

- **Amended 2026-10-30: async results and default flow use TypeScript's actual tests.** For arm-type union `U`, `async match` has type `Promise<Awaited<U>>`, with native async-return adoption and TypeScript's Promise-like/thenable checks. A returned Promise is adopted rather than nested. A default arm follows TypeScript control flow after the preceding ordered pattern and guard tests fail, including cached reads and source mutations. This is independent of exhaustiveness coverage: a predicate can narrow its false branch without covering a case, and a failed guard does not establish that its positive predicate failed. Do not subtract a coverage set instead of analyzing those tests.

function classifyDefault(s: string | number) {
  if (isText(s)) return s.length
  return s.toFixed(0)
}
function guardedDefault(s: string | number) {
  if (isText(s) && false) return 0
  // @ts-expect-error the failed guard leaves both string and number possible

}

## Meaning in Effect TS terms

`match` is plain JavaScript, not an Effect: TC39's semantics, with the arms tested in order and the subject evaluated once. It compiles to ordered tests on the subject, with no Effect involved.
