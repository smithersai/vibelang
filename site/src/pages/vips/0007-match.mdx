# VIP-7: `match` is TC39 pattern matching, plus a compile-time exhaustiveness check

**Status:** accepted by Will, 2026-10-28.

## Decision

```ts
match (e) {
  when NotFound: guest;                // NotFound's Symbol.customMatcher decides, as TC39 says
  when Option.Some(let v): v;
  when DbError and if (retryable): retry();
  default: fallback;
}
```

- `match`, `when`, `is`, patterns, guards, `and`/`or`/`not` and `default` are exactly the TC39 pattern-matching proposal, pinned to a dated snapshot. We move to a newer snapshot deliberately, never automatically.
- The full proposal is implemented, not today's subset (D207): regular-expression and relational patterns and `async match` included.
- One addition: a `match` with no `default` over a finite union that misses a case is a compile error. The check only reports errors; it never changes what runs.
- Class arms use the class's `Symbol.customMatcher`. VibeLang's `error` classes get a matcher that tests `_tag`, so `when NotFound:` matches across copies of a package.
- **Condition: no run-time patching of Effect.** Until Effect ships custom matchers for `Option`, `Exit`, `Result` and its tagged errors, the compiler keeps today's fixed checks for them (D208). We propose the matchers upstream.

- **Amended 2026-10-30: lexical cell identity.** Alternatives of one `or` share the cell of a name bound with the same keyword. - **Amended 2026-10-30: loop-head binding lifetimes.** Lexical `is` bindings in `while`/`do…while` shadow outer names in a loop-head scope and never leak outside the loop. Every complete condition evaluation, including after `continue`, starts with fresh uninitialized cells. - **Amended 2026-10-30: the other binding homes, and use before assignment.** In `for (init; test; update)`, an `init` binding belongs to the loop head as a `let` or `const` declared in `init` would, copied into each iteration when it is `let`; a `test` or `update` binding is a fresh cell in each iteration environment. A `for…in`, `for…of`, `for await`, `for concurrent` or `for try` head expression's binding is copied into each iteration. A concise arrow body's binding belongs to the arrow body, and a field initializer's binding to that initializer; an `enum` member initializer has no home, so a binding there is `EK0705`. `is` and `match` bindings take part in TypeScript's definite-assignment and use-before-declaration checks (`TS2454`, `TS2448`); a read those checks can't see throws `ReferenceError` while the cell is uninitialized.

An `if` head still belongs to the home that contains the `if` statement. The nearest enclosing block would reinitialize one cell once per iteration, and braces would change the Exit. ### Binding homes and redeclarations

The following rules specify binding homes under the adopted proposal.

Two top-level patterns that bind one name in the same lexical home are a redeclaration, as two `let` declarations are, and report what such a `let` reports: `TS2451` beside another lexical declaration, `TS2300` beside a parameter.

The statement body of `if`, `else`, `for`, `for…in`, `for…of`, `for await`, `for concurrent`, `for try`, `while`, `do…while` or a labeled statement, when it is not a Block, is the home of the bindings inside it, exactly as if it were wrapped in braces, and it is fresh each time the body runs, so braces around a body never change a result. An `if` head is outside its own body: `if (!(x is { id: let id })) return; use(id)` in a block reads `id` after the `if`, and the head of an `else if` belongs to the `else` body's home.

A binding in a `for concurrent` limit belongs to the nearest home that encloses the loop, because the limit runs before the head environment exists; it is one cell, not copied into items.

An `is` test in formal-parameter initialization is `EK0705` if a `let` or `const` pattern binding would need the parameter environment as its lexical home. This includes direct defaults, defaults nested in parameter destructuring, and evaluated computed binding keys. The same holds for a catch clause's parameter, whose environment is distinct from the catch Block. The pinned explainer leaves that scope unfinished, so no parameter-home binding is invented or moved into the body.

## Meaning in Effect TS terms

`match` is plain JavaScript, not an Effect: TC39's semantics, with the arms tested in order and the subject evaluated once. It compiles to ordered tests on the subject, with no Effect involved.

### Detail 67

**Class patterns on ordinary classes test `instanceof`** (resolves Astra round-15 M1; VIP-7, VIP-31). ### Detail 78

**Exhaustiveness: which subjects are checked, and which arms cover a case** (NW 42 and 46; Opus M2 and m4; r16-004, r16-006; amends detail 10). Two rules, one algorithm for every finite subject:
    - **Subjects.** Normalize the subject's declared type into a union of members, expanding `boolean` to `true | false`, an enum to its members, a `data` type to its variants, `Option.Option<A>` to `None | Some`, `Exit.Exit<A, E>` and `Result.Result<A, E>` to `Success | Failure`. `EK4701` applies when every member is a literal type, `true`, `false`, `null`, `undefined`, an enum member, a `data` variant, an `error` or `schema error` instance, one of those six `Option`/`Exit`/`Result` cases, or a retained Effect error from detail 53. Any other member (`string`, `number`, an object type, a class from `.ts`, `unknown`, `any`) turns the check off for that `match`, which keeps TC39's run-time `TypeError`.
    - **Coverage.** Only an unguarded arm covers anything (detail 10). A literal, `null` or `undefined` pattern covers that member; an enum member pattern covers that member. A bare binding (`let x`) covers every member. A class pattern covers its class's members as chapter 004 already says (`when NotFound:` and `when NotFound(let e):` cover `NotFound`; `when NotFound():` covers nothing); the fixed patterns `Option.Some(let v)`, `Option.None`, `Exit.Success(…)`, `Exit.Failure(…)`, `Result.Success(…)`, `Result.Failure(…)` and a retained error's bare or one-binding extractor cover their case when every argument pattern is a bare `let` binding. An object pattern covers `data` variant `V` (or an object member with literal `_tag` `"V"`) when it has `_tag: "V"` and every other property is a bare key or a `let` binding of a field `V` declares as required. `or` covers the union of its alternatives. `and`, `not`, regex, relational, array, built-in matcher and user-matcher patterns cover nothing, so those arms need a `default`.
    ```vibe
    match (o) { when Option.Some(let v): v; when Option.None: 0; }          // ok: Option<number> checked and covered
    match (r) { when NotFound: 1; when undefined: 2; }                       // ok: NotFound | undefined
    match (d) { when { _tag: "Sent", let tracking }: 1; }                    // EK4701: Waiting not covered
    match (d) { when { _tag: "Sent" } or { _tag: "Waiting" }: 1; }          // ok
    match (n) { when 1: "a"; }                                               // n: number: no check
    match (b) { when true and if (flag): 1; when false: 0; }                 // EK4701: guarded arm covers nothing
    ```
    Effect TS: `Match.exhaustive`, and TypeScript's `never` check after a `switch` over the same members. Decided by the agent from principle 8 (more forms can be proved later without breaking code; an unchecked subject stays TC39's), principle 2 (normalize as TypeScript narrows unions; D209 checked the same member kinds) and the four reviewers' recommendations; 2026-10-29.

    **Bare fixed-case coverage (Loop r3 Opus OPUS-6).** An unguarded bare retained case pattern with no extractor list covers its whole case: `Option.Some`, `Option.None`, `Exit.Success`, `Exit.Failure`, `Result.Success`, `Result.Failure`. Details 86/92 already make these retained guards. Apply extraction/length constraints only when a list is written; no list is not an empty list. Guarded or payload-constrained coverage and arity lint stay unchanged. For example, `match (o) { when Option.Some: 1; when Option.None: 0; }` exhausts `Option<number>`. Effect TS: `if (Option.isSome(o)) return 1; if (Option.isNone(o)) return 0; const exhaustive: never = o`, with the retained subject test. The equivalent Exit/Result pairs also leave `never` under native strict checking in `native-loop-r3/`. Decided by the agent from VIP-7/details 86/92 and principle 4 (coverage follows the retained guard), 2026-10-31. Clarifies 78; no new number or compiler-conformance claim.

### Detail 79

**Static typing of `match`** (NW 45; Opus M1; r16-004, r16-006; VIP-7 amendment). Patterns type as the TypeScript counterpart the spec shows for them, so every rule below is what `tsc --strict` gives that counterpart.
    - **Result.** A `match` expression has the union of its arm types; a `throw` arm contributes `never`.
