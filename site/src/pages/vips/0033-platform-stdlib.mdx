# VIP-33: the platform standard library

**Status:** accepted, 2026-10-29: Will's 10-26 rulings, re-presented against VIP-1 to VIP-32 and recorded under his standing approval of recommendations.

Before its first release, VibeLang ships no quick fixes or codemods of its own. TypeScript's built-in code fixes remain available.

## Decision

```ts
import { NodeServices } from "@effect/platform-node"   // a platform package: imported, not in scope
effect function readConfig(path: string) {
  const fs = try FileSystem.FileSystem             // Effect's platform service, injected by a layer
  return try fs.readFileString(path)
}
effect function main() {
  provide NodeServices.layer { try readConfig("app.json") }   // VIP-12; the platform layer is chosen at the edge
}
```

**Amended 2026-11-03 (VIP-40):** The restrictions below apply to VibeLang code. A named top-level `module` body follows the rules of a sibling `.ts` file; VIP-40 supersedes VIP-25.

1. **Platform access only through injected Effect services** (`FileSystem`, `Path`, `ChildProcess`, `HttpClient`, …), each provided by a per-platform layer. Outside a TypeScript `module` body, a `.vibe` file has no `node:*` value imports and no Node globals (`process`, `Buffer`). Code that needs them lives in a `.ts` file or a named top-level `module` body ([VIP-40](/vips/0040-module-declarations), which supersedes VIP-25).
   - **Amended 2026-10-29: no exception inside `Effect.try` / `tryPromise` arrows.** A platform call there, such as `tryPromise(() => fetch(url))`, is the same error as anywhere in `.vibe`. Move the body into a sibling `.ts` module, or use the Effect service (`HttpClient` for `fetch`). Recorded under Will's standing approval of recommendations.
2. **What Effect lacks goes under `Experimental.X`**, named after the Effect module it extends, and is written so it can be proposed upstream. No per-project wrappers, and nothing that Effect already provides.
   The additions include `Experimental.Dns` (Effect's `effect/net/Dns` service extended only with TXT queries sent directly to a supplied authority) and `Experimental.Encoding.decodeBase64Lenient` (pure `Result`, no service or layer). Node DNS queries only the supplied server for TXT; Worker DNS uses TCP with recursion disabled and requires AA, or fails typed `Unsupported` when the host lacks that transport. NS/A discovery and all existing DNS members and records remain Effect's; the Worker adapter uses recursive DoH only for discovery. Effect already supplies strict `Base64` and `Base64Url`; only Node-compatible leniency is added. See [Experimental platform APIs](https://github.com/smithersai/vibelang/blob/main/docs/user/src/vibelang-features/118-experimental-platform-apis.md) for layers and guarantees.

3. **Subpath namespaces are in scope** (`HttpClient`, `FileSystem`, `Path`, `ChildProcess`, … from Effect's subpath packages), with VIP-14's precedence rules.
4. Old VibeLang's alias `Path.join(…)` → `Path.Path.join(…)` (D311) was a service shorthand, which VIP-10 denied. You write `(try Path.Path).join(…)`.
5. Old VibeLang's provisional D312, under which the entry provided NodeServices for `main`, is gone (VIP-26).

- **Clarified 2026-11-11: `Experimental` is in scope with no import.** Rule 2's `Experimental` is in scope in every `.vibe` and `.vibex` file, as Effect's modules are: bare `Experimental` is `vibelang-runtime`'s `Experimental` namespace, and emitted code imports it as `import { Experimental } from "vibelang-runtime"`. A local value declaration or an import named `Experimental` shadows it, as with any global; a local type alias or interface of that name keeps its type meaning without hiding the namespace. It is VibeLang's own module, not Effect's, so `vibe.effectModules: false` and `vibe.effectGlobals: false` leave it in scope. This is the rule that the built-in VIPs cite as "in scope with no import, as VIP-33 rules", and that [Experimental platform APIs](https://github.com/smithersai/vibelang/blob/main/docs/user/src/vibelang-features/118-experimental-platform-apis.md) already documents.
- **Clarified 2026-11-11: rule 3's examples.** Of the names rule 3 lists, `HttpClient` (`effect/http`) and `ChildProcess` (`effect/process`) are subpath namespaces. `FileSystem` and `Path` are root modules of `effect`, in scope by VIP-14, as [The platform standard library](https://github.com/smithersai/vibelang/blob/main/docs/design/src/005-services.md#the-platform-standard-library) says; it also lists the 23 subpaths whose namespaces rule 3 puts in scope.

*Corrected 2026-11-02: the Decision example imports `NodeServices` from `@effect/platform-node`, a platform package that is not in scope (VIP-14), and provides it inside `effect function main()`, because `provide` belongs in effect code (VIP-12); chapter 5 shows the same program (found by the round-6 review).*

*Corrected 2026-10-29: the module `FileSystem` is a namespace, and the service key it exports is `FileSystem.FileSystem` (likewise `Path.Path`); in effect 4.1.1, `yield*` of the namespace is a defect.*

- **Amended 2026-10-29: the banned globals.** A reference in any `.vibe` code to a Node global (`process`, `Buffer`, `global`, `__dirname`, `__filename`, `require`, `module`, `exports`, `setImmediate`, `clearImmediate`), a web I/O or host-state global (`fetch`, `XMLHttpRequest`, `WebSocket`, `EventSource`, `localStorage`, `sessionStorage`, `indexedDB`, `caches`, `navigator`, `location`, `document`, `window`, `self`, `Worker`, `SharedWorker`, `BroadcastChannel`, `postMessage`, `alert`, `confirm`, `prompt`, `crypto`, `performance`), `console` or a timer (`setTimeout`, `setInterval`, `clearTimeout`, `clearInterval`, `queueMicrotask`) is a compile error with guidance to use an Effect service or move the code to a `.ts` file. ECMAScript library globals (including `Intl`) and web data utilities with no I/O (`URL`, `URLSearchParams`, `TextEncoder`, `TextDecoder`, `structuredClone`, `atob`, `btoa`, `AbortController`) stay allowed. Decided by the agent on 2026-10-29 under Will's rule "when I state a principle, the agent derives the concrete rule and acts; I can override later" (decided detail 56).
- **Amended 2026-10-29: the banned globals are derived, not listed.** A value reference in `.vibe` code is `EK4402` when the symbol it resolves to is declared in `lib.dom*.d.ts`, `lib.webworker*.d.ts`, `lib.scripthost.d.ts` or `@types/node`, not in `lib.es*.d.ts` or `lib.decorators*.d.ts`, and is not on the allowlist. A local binding, an import or an Effect module in scope shadows the global first. The allowlist is closed: the web data utilities above plus `AbortSignal`, which Effect passes to `Effect.tryPromise` callbacks; `AbortSignal.timeout` stays banned. The set is generated into `docs/design/inventory/platform-globals.json`. This replaces the enumerated list above, whose names retain the same diagnostic guidance. Decided by the agent on 2026-10-29 under Will's rule "when I state a principle, the agent derives the concrete rule and acts; I can override later" (decided detail 101).
- **Amended 2026-10-29: `globalThis` and `import()`.** `globalThis` may appear in `.vibe` code only as the object of a statically named member access. A banned platform member is `EK4402`; `eval` and `Function` follow [VIP-1](/vips/0001-effect-and-async-functions), including its `Function` exemptions for the right operand of `instanceof` and a statically named `prototype` access. Every other use of `globalThis` is `EK0107`. `import(expr)` with a computed specifier stays unchecked; a string-literal `data:` or `blob:` specifier is `EK0107`. Decided by the agent on 2026-10-29 under Will's rule "when I state a principle, the agent derives the concrete rule and acts; I can override later" (decided detail 73 and 74).
- **Amended 2026-10-29: bare `Worker`.** Bare `Worker` is Effect's `effect/workers` namespace, as `Headers`, `Response` and `Event` are Effect's; the banned `Worker` entry covers the host binding only (`globalThis.Worker`, `self.Worker`). Decided by the agent on 2026-10-29 under Will's rule "when I state a principle, the agent derives the concrete rule and acts; I can override later" (decided detail 76).
- **Amended 2026-11-09 (Will): `import.meta` follows TypeScript.** This supersedes the earlier restriction to `import.meta.url` (decided detail 90). VibeLang imposes no additional restriction on `import.meta` syntax. Members are checked against the program's `ImportMeta` declarations: `vite/client` supplies `glob`, `env` and `hot`; `@types/node` supplies Node metadata such as `dirname`. An undeclared member receives TypeScript's ordinary diagnostic, not `EK4402`. Aliases, destructuring, computed access, arguments, spreads and `import.meta.url` retain TypeScript's behavior. Will: "Vibelang should allow it if it's using vite. Same as ts" and "The question in fact is not actually relevant to vibelang in same way it's not a concern of typescript".
- **Clarified 2026-11-10 (Will): the `import.meta` amendment is final.** A member of `import.meta` is allowed in `.vibe` code exactly when the `ImportMeta` type in scope declares it, as in TypeScript: `vite/client` declares `glob`, `env` and `hot`, and `@types/node` declares `dirname` and `filename`. An undeclared member is TypeScript's own error, and `EK4402` never reports a declared member. [VIP-54](/vips/0054-consistent-platform-code-open) is a separate design and does not change this rule while it is open. Will: "Vibelang should allow it if it's using vite. Same as ts" and "The question in fact is not actually relevant to vibelang in same way it's not a concern of typescript".
- **Amended 2026-10-30: one rule for platform members.** `EK4402` asks one question of a statically named value, an identifier, `.name`, `?.name`, a literal key or a destructured property: does the symbol it resolves to reach the platform, by doing I/O, starting a timer, or reading or changing host state? That is a banned global, or a member of an allowlisted global that reaches the host: `AbortSignal.timeout`, `URL.createObjectURL` and `URL.revokeObjectURL`. An alias keeps the symbol, and a key that is not statically known stays unchecked. A name that resolves to nothing is `TS2304`. `docs/design/inventory/platform-globals.json` records the banned globals, the allowlist and every allowlisted member, classified, and a test fails when one is unclassified. Decided by the agent on 2026-10-30 under Will's rule "when I state a principle, the agent derives the concrete rule and acts; I can override later"; `URL.createObjectURL` and `URL.revokeObjectURL` follow from this VIP's "All web apis and all node.js apis should be wrapped and effectful", and no `.vibe` file in the repository uses them.
- **Amended 2026-11-07: members of an injected page.** A banned global read as a member is `EK4402` only through a host receiver, a chain of member reads rooted at a global binding (`globalThis`, `window`, `self`). A member of a value the code was given, such as the page `Experimental.Window`'s `current` injects, a parameter or an import, is that value's member, so a component test builds `new page.KeyboardEvent(...)` and replaces `page.Element.prototype.scrollIntoView` through the injected page. `current` is typed as the DOM library types `window`, `Window & typeof globalThis`, exported as `Experimental.Window.Page`. The change accepts programs that were `EK4402` and rejects none that compiled. Decided by the agent on 2026-11-07 under Will's rules "Platform should always be dependency injected" and "when I state a principle, the agent derives the concrete rule and acts; I can override later".

## Will's words (2026-10-26)

> "All web apis and all node.js apis should be wrapped and effectful. In fact, a lot of this is ALREADY wrapped and effectful. Platform should always be dependency injected. Effect has a platform package. If it doesn't support something we should extend it to support it."

> "Make sure you do NOT implement anything that is already in effect."

> "make Effect namespace global and every namespace below Effect global and if we were forced to add something because Effect doesn't already have a namespace for it it should be under Experimental."

> "Node.js should only even be available via dependency injection or via escaping to normal typescript"
