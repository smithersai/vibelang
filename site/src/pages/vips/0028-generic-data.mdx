# VIP-28: generic `data` unions

**Status:** accepted, 2026-10-29, under Will's standing approval of recommendations ("assume I accept now. I will interrupt you if I need to").

## Decision

```ts
data Outcome<A, E> { Ok { value: A }; Err { error: E } }

// exactly Effect TS's generic TaggedEnum pattern
type Outcome<A, E> = Data.TaggedEnum<{ Ok: { value: A }; Err: { error: E } }>
interface OutcomeDefinition extends Data.TaggedEnum.WithGenerics<2> {
  readonly taggedEnum: Outcome<this["A"], this["B"]>
}
const Outcome = Data.taggedEnum<OutcomeDefinition>()
```

- A `data` declaration (VIP-16) may have up to 4 type parameters, which is the limit of Effect's own `WithGenerics`. More is a compile error that names the limit.
- **Ambiguity: none.**
- **Amended 2026-10-29: a hygienic helper.** The generated generic-data helper (`XDefinition` in the example) gets a fresh name; it is not a reserved user-visible name. Sent to Will on Telegram 2026-10-29 12:28 under his standing rule 'assume I accept'; no objection by 13:00.
- **Amended 2026-10-29: no constraints.** A constraint on a generic `data` type parameter (`<A extends string>`) is a compile error, since this VIP doesn't add them (EK2126 keeps that part). Sent to Will on Telegram 2026-10-29 12:28 under his standing rule 'assume I accept'; no objection by 13:00.
- **Amended 2026-10-29: no defaults.** A default on a generic `data` type parameter (`data Box<A = string>`) is a compile error, as a constraint is. Write the default on a separate `type` alias. Decided by the agent on 2026-10-29 under Will's rule "when I state a principle, the agent derives the concrete rule and acts; I can override later" (decided detail 63).
- **Amended 2026-10-29: the helper's name.** The helper for `data Outcome<A>` is named `$Outcome$Definition`; if the module already declares that name, the compiler appends `$2`, `$3`, … and takes the first free name. Decided by the agent on 2026-10-29 under Will's rule "when I state a principle, the agent derives the concrete rule and acts; I can override later" (decided detail 83).

### Detail 27

### Detail 63

(NW 26; VIP-28) A default on a generic `data` type parameter is a compile error, as a constraint is (decided detail 27): VIP-28 adds neither. Write the default on a separate `type` alias.
    ```vibe
    data Box<A = string> { Value { value: A } }   // error
    data Box<A> { Value { value: A } }
    type StrBox = Box<string>                     // ok
    ```
    Effect TS: `type Box<A> = Data.TaggedEnum<{ Value: { value: A } }>`. Decided by the agent from decided detail 27's precedent and principle 8 (allowing it on the alias later breaks no code); 2026-10-29.

### Detail 83

**Generic-`data` helper name in `.d.vibe.ts`** (NW 49; Opus m8; r16-001; refines detail 26). The helper for `data Outcome<A>` is named `$Outcome$Definition`. If the module already declares that name, the compiler appends `$2`, `$3`, … and takes the first free name, as `tsc` picks the first free name for its own emitted helpers. The name is therefore the same on every build of the same source and still never collides with a user name.
    ```ts
    // outcome.d.vibe.ts
    declare interface $Outcome$Definition extends Data.TaggedEnum.WithGenerics<1> { … }
    ```
    Effect TS: a `WithGenerics<1>` interface under any name. Decided by the agent from principle 2 (deterministic emit, as `tsc`'s) and detail 26 (hygienic); 2026-10-29.
