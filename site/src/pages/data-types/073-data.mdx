# Data

A `data` declaration declares a tagged union: Effect's own `Data.TaggedEnum` type and the `Data.taggedEnum` constructors, under one name, which `match` takes apart. The rest of `Data` works in VibeLang exactly as in Effect: use it for classes and errors with Effect's equality and hashing. Generated `data` builders and type references always use Effect's `Data`; a local value or type parameter named `Data` keeps its ordinary source meaning without capturing them.

## Declaring tagged unions with data

```vibe
data Delivery {
  Waiting
  Sent { tracking: string }
  Rejected { reason: string; note?: string }
}

const sent = Delivery.Sent({ tracking: "parcel-8" })

function describe(delivery: Delivery) {
  return match (delivery) {
    when { _tag: "Waiting" }: "Waiting for dispatch";
    when { _tag: "Sent", let tracking }: `Tracking: ${tracking}`;
    when { _tag: "Rejected", let reason }: `Rejected: ${reason}`;
  }
}
```

```text
Waiting for dispatch
Tracking: parcel-8
Rejected: address missing
true
```

A variant without fields is a bare name. A variant with fields lists them in braces as an `error` does, `name: Type` or `name?: Type`, and they are readonly. A new line, `;` or `,` separates variants and fields. The current compiler still reports a comma as `EK1013`. `Delivery.Sent({ tracking })` and `Delivery.Waiting()` build values: plain records with a `_tag`, which compare and hash by their fields.

Two variants or two fields on one line need a separator. `data D { A B }` and `data D { A { x: number y: string } }` report `EK1605`; insert `;` or a line break. The editor offers a quick fix that inserts `;` after the first member and keeps comments in place. Missing separators inside an ordinary nested TypeScript type keep the native TypeScript diagnostic.

A variant cannot be named `$is` or `$match` (`EK1602`), including in generic data: Effect reserves those properties for helpers. Rename it and its references, for example to a fresh `Is` or `Match`.

`when { _tag: "Sent", let tracking }` tests the variant and binds `tracking`, and `delivery is { _tag: "Sent" }` tests it in a condition. `match` is exhaustive: without a `default` arm, a match that leaves out a variant is a compile error (`EK4701`). A finite generic constraint on these variants is checked over its possible cases. An open type such as `unknown` turns off `EK4701`; unmatched values retain the runtime `TypeError`. See [Pattern matching with match and is](/vibelang-features/116-match-and-is#data-variants).

Support for the new object patterns arrives with the compiler's VIP implementation.

The specification assigns `EK1603` to `export default data D { … }`. Declare the name, then write `export { D as default }`. This keeps the type and constructors under that name.

## Generic data types

```vibe
data LoadState<A, E> {
  Idle
  Loaded { value: A }
  Failed { error: E }
}

const loaded = LoadState.Loaded({ value: ["one", "two"] })
const failed = LoadState.Failed({ error: "offline" })
const idle = LoadState.Idle()

function count(state: LoadState<ReadonlyArray<string>, string>) {
  return match (state) {
    when { _tag: "Loaded", let value }: value.length;
    default: 0;
  }
}
```

```text
[{"value":["one","two"],"_tag":"Loaded"},{"error":"offline","_tag":"Failed"},{"_tag":"Idle"}]
2 0
```

A data type takes up to four unconstrained type parameters without defaults, which the constructors infer from their arguments. A default such as `data Box<A = string>` reports `EK2803`; put defaults on a separate type alias. `vibelang --fix` expands the declaration to equivalent Effect TypeScript while preserving its defaults. A recursive data type, such as `data Tree<A> { Leaf { value: A }; Node { left: Tree<A>; right: Tree<A> } }`, works too.

## What data declares

`data Delivery { ... }` declares what Effect's documentation writes for a tagged union, so TypeScript code that imports `Delivery` gets Effect's types, `Delivery.$is` and `Delivery.$match`:

```ts [Effect]
import { Data } from "effect"

type Delivery = Data.TaggedEnum<{
  Waiting: {}
  Sent: { tracking: string }
  Rejected: { reason: string; note?: string }
}>
const Delivery = Data.taggedEnum<Delivery>()
```

A declaration file declares what TypeScript declares for that counterpart: the type first, each variant's fields as written (`Data.TaggedEnum` makes every field `readonly` in the type either way), then the constant with the type TypeScript infers for it, `Data.TaggedEnum.Constructor<{ readonly _tag: "Waiting" } | …>`. Write `readonly` on a field where your TypeScript wrote it, or wrapped the payload in `Readonly<{ … }>`. Generic declarations use `Data.TaggedEnum.GenericConstructor`, keeping the same callable contract when imported from their declaration files: generic variants, including aliases and destructured constructors, can be called directly in effect code. A generic data type passes its type parameters through the interface `Data.TaggedEnum.WithGenerics` describes, named `$LoadState$Definition`, or `$LoadState$Definition$2` and so on when the module already declares that name, which `export data` exports with the type and the constructors. A user declaration such as `LoadStateDefinition` remains independent; the generated helper chooses another name. If you imported an older generated helper such as `LoadStateDefinition`, run `vibelang --fix` to update the imported type while keeping your local alias and re-exported name. Qualified namespace references and `import(...)` type references are updated too; this migration also runs with `--fix-migration-only`.

```ts [Effect]
import { Data } from "effect"

type LoadState<A, E> = Data.TaggedEnum<{
  Idle: {}
  Loaded: { readonly value: A }
  Failed: { readonly error: E }
}>
interface $LoadState$Definition extends Data.TaggedEnum.WithGenerics<2> {
  readonly taggedEnum: LoadState<this["A"], this["B"]>
}
const LoadState = Data.taggedEnum<$LoadState$Definition>()
```

## Creating values with structural equality

```vibe
const first = { route: "inbox", filters: { unread: true } }
const second = { route: "inbox", filters: { unread: true } }
Equal.equals(first, second) // true
Equal.equals(["inbox", 5] as const, ["inbox", 5] as const) // true
Equal.equals([2, 4, 6], [2, 4, 6]) // true

function makeRoute(name: string) {
  return { _tag: "Route" as const, name }
}
Equal.equals(makeRoute("inbox"), makeRoute("inbox")) // true
```

```text
true true true true
```

In Effect 4, plain records, tuples, arrays, maps, and sets already compare structurally, nested values included, without a `Data` wrapper. Treat compared data as immutable: equality and hashing cache information about objects.

## Building ordinary and tagged classes

```vibe
class Label extends Data.Class<{ text: string }> {
  get upper() { return this.text.toUpperCase() }
}

class Archived extends Data.TaggedClass("Archived")<{
  documentId: string
}> {}

const label = new Label({ text: "pending" })
label.upper // "PENDING"
Equal.equals(label, new Label({ text: "pending" })) // true
new Archived({ documentId: "doc-3" })._tag // "Archived"
```

```text
PENDING true Archived
```

`Class` supplies a constructor taking a field object, plus equality and hashing; `TaggedClass` adds a fixed `_tag` for narrowing union members. These concrete data classes are separate from services declared with `service`.

## Writing a tagged union out with Data.TaggedEnum

Effect's long form works in a `.vibe` file too, with the same `$is` and `$match`:

```vibe
type Delivery = Data.TaggedEnum<{
  Waiting: {}
  Sent: { tracking: string }
  Rejected: { reason: string }
}>

const Delivery = Data.taggedEnum<Delivery>()
const sent = Delivery.Sent({ tracking: "parcel-8" })
const waiting = Delivery.Waiting()
const rejected = Delivery.Rejected({ reason: "address missing" })
const isSent = Delivery.$is("Sent")
isSent(sent) // true

const describe = Delivery.$match({
  Waiting: () => "Waiting for dispatch",
  Sent: ({ tracking }) => `Tracking: ${tracking}`,
  Rejected: ({ reason }) => `Rejected: ${reason}`
})
describe(sent) // "Tracking: parcel-8"
```

```text
true
Waiting for dispatch
Tracking: parcel-8
Rejected: address missing
```

`TaggedEnum` describes the union as a map from tags to payloads. `taggedEnum` creates constructors that insert `_tag`, a `$is` guard factory, and a `$match` helper requiring a case per variant. Match callbacks compute values synchronously; for service work, use `match` inside an effect function, whose arms can run Effects with `try`.

## Writing generic union cases out

```vibe
type LoadState<A, E> = Data.TaggedEnum<{
  Idle: {}
  Ready: { value: A }
  Failed: { error: E }
}>

interface LoadStateDefinition extends Data.TaggedEnum.WithGenerics<2> {
  taggedEnum: LoadState<this["A"], this["B"]>
}

const LoadState = Data.taggedEnum<LoadStateDefinition>()
const loaded = LoadState.Ready({ value: ["one", "two"] })
const failed = LoadState.Failed({ error: "offline" })
const idle = LoadState.Idle()
```

```text
[{"value":["one","two"],"_tag":"Ready"},{"error":"offline","_tag":"Failed"},{"_tag":"Idle"}]
```

`WithGenerics<2>` gives the definition two type parameters, `A` and `B`; the constructors infer payload types per call. Keep the generic definition in a type or interface; it is not a generic service class.

## Errors

| Code | Cause | Fix |
| --- | --- | --- |
| EK2122 | A `data` declaration without variants, which the specification allows as `data Empty {}`; the current compiler still rejects it | Write a variant until the compiler accepts it |
| `TS2300` | A variant or field declared twice | Rename one, or remove the duplicate |
| EK2124 | A variant named `$is` or `$match`, a field named `_tag` | Rename it: the constructors object has its own `$is` and `$match`, and the constructor sets `_tag` |
| EK2125 | A variant member that is not a field: a method, a signature, a field without a type, or a `mutable` field | Write `name: Type` or `name?: Type` |
| `EK2801` | More than four type parameters | Use at most four type parameters |
| `EK2126` | A constrained type parameter | Remove the constraint |
| `EK2803` | A default on a generic `data` parameter | Put the default on a type alias, or run `vibelang --fix` |
| EK2127 | `Delivery.Snet`, a name that is not one of the data type's variants | Use one of the variants the message lists |

## Defining ordinary and tagged errors

```vibe
class InvalidDocument extends Data.Error<{
  message: string
  line: number
}> {}

error DocumentMissing {
  id: string
}

effect function requireDocument(id: string) {
  if (id === "") throw new DocumentMissing({ id })
  return { id }
}
// { id: string }!DocumentMissing

effect function documentOrDraft(id: string) {
  return requireDocument(id) catch (error) => match (error) {
    when DocumentMissing: ({ id: "draft" });
  }
}
```

```text
3
[{"id":"doc-3"},{"id":"draft"}]
DocumentMissing
```

`Data.Error` creates a native error with extra fields. An `error` declaration creates Effect's `Data.TaggedError` class, which fills in `_tag`; `throw` inside an effect function raises it as an expected failure. Use `Schema.TaggedError` when the error needs a schema for serialization.

## Preserving native error causes

```vibe
error DocumentDecodeError {
  cause: unknown
}

effect function decodeDocument(text: string) {
  return try Effect.try({
    try: () => JSON.parse(text),
    catch: (cause) => new DocumentDecodeError({ cause })
  })
}
// any!DocumentDecodeError
```

```text
{"id":3}
DocumentDecodeError true
```

A `cause` field keeps the original exception through native error-cause support; it is not Effect's `Cause`, which describes a whole execution failure. Keep the original error for diagnosis, and keep document contents and credentials out of diagnostic fields.

## Coming from Effect

Raise a data error with `throw new DocumentMissing({ id })`; ordinary error propagation needs no generator yield or `Effect.fail`.

An exported `data` declaration may use the contextual name `as`. Its declaration file writes `export declare type as = …` so TypeScript consumers can import both its constructor and its type.

A variant’s fields are readonly, as in `Data.TaggedEnum`; a nested object or array keeps its written TypeScript mutability. Nested index signatures are writable unless written `readonly`. To keep an older compiler’s implicit nested readonly API, run `vibelang --fix --fix-migration-only`; it writes the nested `readonly` modifiers without changing explicit `mutable` members.
