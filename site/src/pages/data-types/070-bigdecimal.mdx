# BigDecimal

`BigDecimal` represents arbitrary-precision base-10 numbers as an integer coefficient and a decimal scale. Use it for monetary amounts, rates, and decimal inputs where IEEE 754 binary floating point introduces rounding error.

| Constructor / Operation | Behavior |
| --- | --- |
| `make(value, scale)` / `fromBigInt(n)` | Exact construction (`value × 10^-scale`; scale 0 for `fromBigInt`) |
| `fromString(s)` / `fromNumber(n)` | Safe parsing returning `Option.Option<BigDecimal>` |
| `fromStringUnsafe(s)` / `fromNumberUnsafe(n)` | Throws on invalid text or non-finite numbers |
| `sum`, `subtract`, `multiply` | Exact decimal arithmetic |
| `divide`, `remainder` | Return `Option` (`None` on zero divisor); `*Unsafe` throws |

## Representing decimal values

```vibe
const unitPrice = BigDecimal.make(875n, 2)
const bulkPrice = BigDecimal.make(875n, -1)
BigDecimal.format(unitPrice) // "8.75"
BigDecimal.format(bulkPrice) // "8750"
// Run in an effect function:
//   try Console.log(BigDecimal.format(unitPrice))
//   try Console.log(BigDecimal.format(bulkPrice))
```

```text
8.75
8750
```

Each value stores `coefficient × 10^-scale`: a positive scale places digits after the decimal point, while a negative scale appends integer zeros. Precision scales with memory rather than JavaScript's 53-bit significand.

## Constructing decimals

```vibe
const whole = BigDecimal.fromBigInt(42n)
const parsed = BigDecimal.fromString("18.625")
const invalid = BigDecimal.fromString("eighteen")
const fromNumber = BigDecimal.fromNumber(2.5)

Option.isSome(parsed) // true
Option.isNone(invalid) // true
BigDecimal.format(whole) // "42"
// Run in an effect function: try Console.log(Option.isSome(parsed), Option.isNone(invalid), BigDecimal.format(whole), Option.isSome(fromNumber))
```

```text
true true 42 true
```

`fromString` and `fromNumber` return `Option`, keeping malformed inputs as data. Parse external decimal values from strings rather than numbers, since converting a `number` cannot recover precision already lost to binary rounding.

## Safe and unsafe constructors

```vibe
error InvalidPrice {
  input: string
}

effect function parsePrice(input: string) {
  return match (BigDecimal.fromString(input)) {
    when Option.Some(let price): price;
    when Option.None: throw new InvalidPrice({ input });
  }
}
// BigDecimal.BigDecimal!InvalidPrice

const fixedRate = BigDecimal.fromNumberUnsafe(1.25)
// Run in an effect function:
//   try Console.log(BigDecimal.format(try parsePrice("18.625")), BigDecimal.format(fixedRate))
//   try Console.log(parsePrice("invalid") catch (error) => `${error._tag} ${error.input}`)
```

```text
18.625 1.25
InvalidPrice invalid
```

Use `fromStringUnsafe` and `fromNumberUnsafe` only for known-valid literals or constants. For external input, call the safe constructor and raise a domain error on `None`.

## Performing arithmetic

```vibe
const price = BigDecimal.make(875n, 2)
const quantity = BigDecimal.fromBigInt(4n)
const subtotal = BigDecimal.multiply(price, quantity)
const discount = BigDecimal.make(250n, 2)
const total = BigDecimal.subtract(subtotal, discount)

BigDecimal.format(total) // "32.5"
BigDecimal.format(BigDecimal.sum(total, discount)) // "35"
BigDecimal.divide(total, quantity) // Some containing 8.125
BigDecimal.remainder(total, quantity) // Some containing 0.5
BigDecimal.sign(BigDecimal.negate(total)) // -1
BigDecimal.format(BigDecimal.abs(BigDecimal.negate(total))) // "32.5"
// Run in an effect function: try Console.log(try Effect.try(() => JSON.stringify([BigDecimal.format(total), BigDecimal.format(BigDecimal.sum(total, discount)), Option.getOrNull(Option.map(BigDecimal.divide(total, quantity), BigDecimal.format)), Option.getOrNull(Option.map(BigDecimal.remainder(total, quantity), BigDecimal.format)), BigDecimal.sign(BigDecimal.negate(total)), BigDecimal.format(BigDecimal.abs(BigDecimal.negate(total)))])))
```

```text
["32.5","35","8.125","0.5",-1,"32.5"]
```

`sum`, `subtract`, and `multiply` return new immutable decimals; `divide` and `remainder` return `None` when the divisor is zero (`divideUnsafe` and `remainderUnsafe` throw). Nonterminating quotients are truncated according to Effect's division precision policy.

## Comparing values

```vibe
const amount = BigDecimal.make(325n, 1)
const limit = BigDecimal.fromBigInt(40n)
BigDecimal.isLessThan(amount, limit) // true
BigDecimal.isLessThanOrEqualTo(amount, amount) // true
BigDecimal.isGreaterThan(limit, amount) // true
BigDecimal.isGreaterThanOrEqualTo(limit, limit) // true
BigDecimal.min(amount, limit) // amount
BigDecimal.max(amount, limit) // limit
BigDecimal.between(amount, {
  minimum: BigDecimal.fromBigInt(0n), maximum: limit
}) // true
BigDecimal.isZero(amount) // false
BigDecimal.isPositive(amount) // true
BigDecimal.isNegative(amount) // false
BigDecimal.isInteger(amount) // false
// Run in an effect function: try Console.log(try Effect.try(() => JSON.stringify([BigDecimal.isLessThan(amount, limit), BigDecimal.isLessThanOrEqualTo(amount, amount), BigDecimal.isGreaterThan(limit, amount), BigDecimal.isGreaterThanOrEqualTo(limit, limit), BigDecimal.format(BigDecimal.min(amount, limit)), BigDecimal.format(BigDecimal.max(amount, limit)), BigDecimal.between(amount, { minimum: BigDecimal.fromBigInt(0n), maximum: limit }), BigDecimal.isZero(amount), BigDecimal.isPositive(amount), BigDecimal.isNegative(amount), BigDecimal.isInteger(amount)])))
```

```text
[true,true,true,true,"32.5","40",true,false,true,false,false]
```

Always compare `BigDecimal` values with module comparators instead of converting to `number`. `between` uses inclusive bounds, and sign or integer predicates inspect the numerical value independent of stored scale.

## Normalization and equality

```vibe
const padded = BigDecimal.make(87500n, 4)
const compact = BigDecimal.normalize(padded)
BigDecimal.equals(padded, BigDecimal.make(875n, 2)) // true
BigDecimal.format(compact) // "8.75"
BigDecimal.toExponential(compact) // "8.75e+0"
// Run in an effect function: try Console.log(BigDecimal.equals(padded, BigDecimal.make(875n, 2)), BigDecimal.format(compact), BigDecimal.toExponential(compact))
```

```text
true 8.75 8.75e+0
```

`BigDecimal.equals` compares numerical value regardless of trailing zeros, so normalization is unnecessary before equality checks. Call `BigDecimal.normalize` when you need a canonical compact representation.
