# Exit

`Exit` works in VibeLang exactly as in Effect. Use `Exit.Exit<A, E>` to inspect a success or an entire failure cause, defects and interruption included. A plain call that returns an Exit returns data; `try outcome` runs its recorded outcome.

## Representing full outcomes

```vibe
error ExportRejected {
  reason: string
}

effect function inspectExport() {
  const outcome = try exit(effect {
    throw new ExportRejected({ reason: "empty selection" })
  })
  if (Exit.isFailure(outcome)) return outcome.cause.reasons.length
  return 0
}
// Run in an effect function: try Console.log(try inspectExport())
```

```text
1
```

An exit is `Success` with `.value` or `Failure` with `.cause`. `try exit(program)` runs an Effect and succeeds with its outcome, which the caller inspects without re-raising the failure.

## Creating success and cause-based failure exits

```vibe
function sampleOutcomes() {
  const successful = Exit.succeed(12)
  const failed = Exit.failCause(
    Cause.combine(Cause.fail("write rejected"), Cause.die(new Error("release failed")))
  )
  return { successful, failed }
}

function constantSuccess() {
  return Exit.succeed(12)
}
// Exit.Exit<number>
// Run in an effect function:
//   const outcomes = sampleOutcomes()
//   try Console.log(Exit.isSuccess(outcomes.successful), Exit.isFailure(outcomes.failed), Exit.isSuccess(constantSuccess()))
//   if (Exit.isFailure(outcomes.failed)) {
//     const tags = outcomes.failed.cause.reasons.map((reason) => reason._tag)
//     try Console.log(try Effect.try(() => JSON.stringify(tags)))
//   }
```

```text
true true true
["Fail","Die"]
```

`Exit.succeed` and `Exit.failCause` build exit data, even at a module's top level: `Exit.succeed(12)` is a success exit holding `12`, and `Exit.failCause(cause)` a failure exit holding the cause. Neither raises a failure.

## Matching exit variants

```vibe
function describe<A, E>(outcome: Exit.Exit<A, E>) {
  return match (outcome) {
    when Exit.Success(let value): `Completed: ${String(value)}`;
    when Exit.Failure(let cause): Cause.pretty(cause);
  }
}
// Run in an effect function:
//   try Console.log(describe(Exit.succeed(12)))
//   try Console.log(describe(Exit.failCause(Cause.empty)) === "")
```

```text
Completed: 12
true
```

`Exit.Success(let value)` binds the success value and `Exit.Failure(let cause)` the complete cause. The exhaustiveness check covers `Exit`. Without a `default`, handle both `Exit.Success` and `Exit.Failure`. Arms are ordinary expressions and can run Effects with `try` inside an effect function; `Exit.match(outcome, { onSuccess, onFailure })` also works when the callbacks compute values synchronously. To test one variant, write `outcome is Exit.Failure`.

## Relating exits to results

```vibe
function asResult<A, E>(outcome: Exit.Exit<A, E>) {
  if (Exit.isSuccess(outcome)) return Result.succeed(outcome.value)
  return Result.fail(outcome.cause)
}
// Result.Result<A, Cause.Cause<E>>
// Run in an effect function:
//   try Console.log(try Effect.try(() => Result.getOrThrow(asResult(Exit.succeed(12)))))
//   const failed = asResult(Exit.failCause(Cause.combine(Cause.fail("rejected"), Cause.die("broken"))))
//   if (Result.isFailure(failed)) try Console.log(try Effect.try(() => JSON.stringify(failed.failure.reasons.map((reason) => reason._tag))))
```

```text
12
["Fail","Die"]
```

An exit carries roughly the information of `Result.Result<A, Cause.Cause<E>>`; a `Result.Result<A, E>` cannot express the defect and interruption reasons. Keep the full cause when you move an outcome into another data structure.

## Relating exits to effects

```vibe
effect function replay<A, E>(outcome: Exit.Exit<A, E>) {
  return try outcome
}
// A!E
// Run in an effect function:
//   try Console.log(try replay(Exit.succeed(12)))
//   const failed = try exit(replay(Exit.failCause(Cause.combine(Cause.fail("rejected"), Cause.die("broken")))))
//   if (Exit.isFailure(failed)) try Console.log(try Effect.try(() => JSON.stringify(failed.cause.reasons.map((reason) => reason._tag))))
```

```text
12
["Fail","Die"]
```

`try outcome` runs a held exit's constant outcome: success returns the stored value and failure propagates the stored cause, without repeating the original work. So taking an exit with `try exit(program)` and running it later with `try` separates inspection from propagation. `try onExit(program, (outcome) => cleanup(outcome))` runs cleanup with the program's own exit.

## Coming from Effect

`const outcome = Exit.succeed(value)` still builds an exit object; `try outcome` propagates it, and `try exit(work())` captures a program's outcome. Exit extends Effect, and its constructors return data.

For an old `finally (exit) { ... }` clause in effect code, use native `Effect.onExit`. It passes cleanup the program's own exit: on success an `Exit.Success` holding the program's value, and on failure the original cause. The old clause received `Exit.void` on success instead. To keep that contract, convert the exit cleanup receives, not the program, so the program still returns its value:

```vibe
effect function cleanup(outcome: Exit.Exit<unknown, unknown>) {
  try Console.log(outcome._tag, Exit.isSuccess(outcome) ? outcome.value : "failed")
}
```

```text
Success 12
Success undefined
result 12 12
```

The first call is native `Effect.onExit`; the second gives cleanup `Exit.void` on success, as the old clause did. Wrapping the whole program in `Effect.asVoid` would also give cleanup `Exit.void`, but the program would then return `undefined` instead of its value.
