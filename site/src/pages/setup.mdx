# Set up Vibe

Vibe (published on npm as `vibelang`) is a fork of TypeScript for Effect programs. Follow these steps in order; if a command's output differs from what is shown, stop and report the command and output. Vibe is v0: expect breaking changes and do not use it in production.

<figure className="vibe-video"><video controls preload="metadata" playsInline poster="/videos/ecosystem.jpg"><source src="/videos/ecosystem.mp4" type="video/mp4" /></video><figcaption>VibeLang with your TypeScript tools</figcaption></figure>

## 1. Check the tools

- **Node:** run `node --version` and require Node `22.22.3` (`22.x`) or Node `24.11.1` or later.
- **Bun (optional):** run `bun --version` and require `1.4.2` or later (needed to [run sources with Bun](/setup/vibelang-cli#run-sources-with-bun)).
- **Registry:** run `npm view vibelang@0.0.15 version` and expect `0.0.15`. `E404` means the configured registry lacks that version — report the registry and error before continuing.

Version 0.0.15 publishes native packages for macOS, Linux, and Windows on arm64 and x64 (rehearsed end-to-end with npm and Bun on Linux x64).

## 4. Verify the setup

```sh
npx vibelang --version
npx vibelang --noEmit
```

Expect `VibeLang 0.0.15 (TypeScript 7.1.0-dev)` from the first command and empty output (exit 0) from the second. Then run the project's `build` and `test` scripts (both must exit 0) and report the pages followed and command outputs.

## Framework setup

Complete [Add VibeLang to an existing project](/setup/existing-project) first. Keep a `tsconfig.json` that includes `.vibe`, `.ts`, and `.tsx` files; the bundler requires it. Run `npx vibelang --noEmit` separately for whole-program checking.

### Next.js with webpack

<figure className="vibe-video"><video controls preload="metadata" playsInline poster="/videos/webpack.jpg"><source src="/videos/webpack.mp4" type="video/mp4" /></video><figcaption>vibelang-unplugin in webpack</figcaption></figure>

Install `vibelang-unplugin@0.0.15` as a dev dependency. Next's Turbopack does not run webpack plugins, so use `--webpack`. In `next.config.mjs`:

```js
import vibelang from "vibelang-unplugin/webpack"

export default {
  typescript: { ignoreBuildErrors: true },
  webpack(config) {
    config.plugins.push(vibelang())
    return config
  }
}
```

Next's stock TypeScript checker reads only compiler-emitted `x.d.vibe.ts` declarations (with `allowArbitraryExtensions`). Because `ignoreBuildErrors` bypasses that entire checker (including ordinary TypeScript errors), run `vibelang --noEmit` in `package.json`:

```json
{
  "scripts": {
    "dev": "next dev --webpack",
    "check": "vibelang --noEmit",
    "build": "vibelang --noEmit && next build --webpack"
  }
}
```

Keep Next's generated type includes in `tsconfig.json`, and run `npm run check` during development to catch errors in files outside the bundle. In components, run imported Effects (e.g. `Effect.runPromise` in async server components with layers provided) before rendering — never pass an Effect object directly to React.

### Astro with Vite

Install `vibelang-vite@0.0.15` as a dev dependency. In `astro.config.mjs`:

```js
import { defineConfig } from "astro/config"
import vibelang from "vibelang-vite"

export default defineConfig({ vite: { plugins: [vibelang()] } })
```

Ensure `tsconfig.json` includes `src` or `src/**/*.vibe`. Run Effects in `.astro` frontmatter before rendering (use `await Effect.runPromise(...)` for async Effects):

```astro
---
import { Effect } from "effect"
import { greet } from "../lib/greeter.vibe"
const message = Effect.runSync(greet("Astro"))
---
<h1>{message}</h1>
```

Run `npx vibelang --noEmit` and `npx astro build`; Astro's own checker does not gain `.vibe` support from `vibelang-vite`.

## Last resort: keep TypeScript file names

If a project cannot use `.vibe` or `.vibex` extensions with the CLI, bundler plugins, framework setup, and editor integrations above, consider the experimental [TypeScript shim](/setup/typescript-shim). Read its stock-tool limitations first.
