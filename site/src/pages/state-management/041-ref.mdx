# Ref

A `Ref` holds shared mutable state behind atomic operations. Use it when several functions or fibers update one value; keep the stored value immutable so every change goes through the reference.

## Creating a shared reference

```vibe
effect makeCounter() {
  return try Ref.make(0)
}
// Ref.Ref<number>!!

effect countLocally() {
  const counter = try makeCounter()
  try Ref.update(counter, (n) => n + 1)
  return try Ref.get(counter)
}
// Output: [1,1]
```

`makeCounter()` returns an Effect that creates a reference when run with `try`. Each run creates an independent counter; to share one, pass the same reference to each caller. Reads and writes run as Effects even when they complete without waiting.

## Reading and atomically updating state

```vibe
effect allocateIds() {
  const nextId = try Ref.make(100)
  const first = try Ref.modify(nextId, (n) => [n, n + 1] as const)
  const second = try Ref.getAndUpdate(nextId, (n) => n + 1)
  const current = try Ref.get(nextId)
  try Ref.set(nextId, 500)
  return { first, second, current }
}
// Returns { first: 100, second: 101, current: 102 }.
// Output: {"first":100,"second":101,"current":102}
```

`modify` returns the tuple's first element and stores its second in one atomic operation. `getAndUpdate` returns the old value; `updateAndGet` returns the new one. A `get` followed by a `set` is two operations and doesn't protect a read-modify-write sequence from other fibers.

## Coordinating concurrent updates

```vibe
effect countCompleted() {
  const completed = try Ref.make(0)
  for concurrent(4) (const delay of [10, 20, 30, 40]) {
    try sleep(`${delay} millis`)
    try Ref.update(completed, (n) => n + 1)
  }
  return try Ref.get(completed) // 4
}
// Output: 4
```

Each update uses the latest value, so no increment is lost. A `Ref.update` callback computes its replacement synchronously, without running Effects; when the update must wait or call a service, use `SynchronizedRef.updateEffect`. For arrays and objects, return a replacement instead of mutating the previous value in place.

## Supplying state as a service

```vibe
service RequestCount {
  increment(): void!!
  read(): number!!
}

const RequestCountLive = Layer.effect(RequestCount, effect {
  const count = try Ref.make(0)
  return {
    increment: () => Ref.update(count, (n) => n + 1),
    read: () => Ref.get(count)
  }
})

effect handleRequests() {
  provide RequestCountLive {
    const requests = try RequestCount
    try requests.increment()
    try requests.increment()
    return try requests.read()
  }
}
// Output: [2,2]
```

The layer allocates one reference when built. Every call inside this `provide` shares it; a separate `provide` builds a fresh counter. Keeping the reference behind service methods also stops callers from resetting it arbitrarily.

## Sharing references across fibers

```vibe
effect collectNames() {
  return try scoped(effect {
    const names = try Ref.make<ReadonlyArray<string>>([])
    const west = fork.scoped effect {
      try sleep("20 millis")
      try Ref.update(names, (old) => [...old, "west"])
    }
    const east = fork Ref.update(names, (old) => [...old, "east"])
    join west
    join east
    return try Ref.get(names)
  })
}
// Output: ["east","west"]
```

Both closures capture the same reference: forking shares the handle instead of cloning its current value. Joining the fibers makes their updates finish before the final read; the order of updates depends on execution timing.

## Coming from Effect

`Ref.make`, `Ref.get`, and updates return Effect values. Run them with `try` inside effect functions or Effect blocks. Callbacks that only construct an existing Effect can remain plain arrows.
