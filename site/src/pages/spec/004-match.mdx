# Pattern matching

Source: [VIP-7](/vips/0007-match).

## Syntax and meaning

```vibe [VibeLang]
// compiler-gap: pending VIP-7
effect function label(d: { _tag: "Sent"; tracking: string } | { _tag: "Waiting" }) {
  const tracking = "outer"
  return match (d) {
    when { _tag: "Sent", let tracking }: try Effect.succeed(tracking);
    default: tracking;
  }
}
```

```ts [Effect]
import { Effect } from "effect"

function label(d: { _tag: "Sent"; tracking: string } | { _tag: "Waiting" }) {
  return Effect.gen(function* () {
    const tracking = "outer"
    const subject = d
    if (subject._tag === "Sent" && "tracking" in subject) {
      const tracking = subject.tracking
      return yield* Effect.succeed(tracking)
    }
    return tracking
  })
}
```

`match`, `when`, `is`, patterns, guards, `and`, `or`, `not` and `default` follow the vendored TC39 snapshot: commit `ba73ffe42f30f0cf56ece28bebdc28f955f2a52e`, dated `2025-10-03`, with the reconciliations listed there. VibeLang moves to a newer snapshot deliberately, never automatically. The full proposal is in the language, including regular-expression patterns, relational patterns and `async match`, with the class adaptations below.

The first `label` counterpart uses a short object test because its subject type guarantees an object with `_tag`. For an arbitrary subject, the pinned algorithm first rejects non-objects (functions are objects too), then checks property presence before reading it; the short form is not a general lowering.

[MatchExpression](/spec/900-appendices#matchexpression) is a primary expression. Its arm grammar is [MatchBody](/spec/900-appendices#matchbody), [MatchArm](/spec/900-appendices#matcharm) and [ArmBody](/spec/900-appendices#armbody): the pinned draft with VIP-7's `when` prefix and VIP-5's `throw` arm body. At least one arm is required; `default` appears at most once, last; guards belong to `MatchPattern` (`P and if (condition)`). Separate arms with `;`, including the final arm; a missing separator is `EK0701` (quick fix: insert `;`). A newline alone is not a separator. The reconciliations are: relational patterns use the draft specification; regex patterns accept both literals and `RegExp` values; `async match` uses the explainer's Promise-producing sketch; custom matchers receive `(subject, { matchType })`, with `matchType` either `"boolean"` or `"extractor"`; the `RegExp.prototype` matcher uses the draft specification, emulated without modifying globals; built-in and primitive constructor tests are in [Class patterns](/spec/004-match#class-patterns).

Invalid `match`/`is` grammar and pattern-specific early errors use `EK0707` when no more specific diagnostic is assigned. The message identifies the rejected form and a valid repair. Do not add it to a specific diagnostic for the same rejection, including arm separation, matcher admission, arity lint, ordinary-class extraction, parameter-home bindings, outward async-match jumps, exhaustiveness or service patterns. Independent native lexical, type and name errors, including errors in valid embedded expressions, retain TypeScript's diagnostics; malformed native templates do not become `EK0707` merely by appearing in a match.

```vibe
const bad = match (s) { when `tag-${kind}`: 1; default: 0; } // EK0707
const good = match (s) { when let v and if (v === `tag-${kind}`): 1; default: 0; }
const nativeError = match (s) { when let v and if (missingName): 1; default: 0; } // TS2304
```

A primitive template pattern is a `NoSubstitutionTemplate`, such as `` `tag-A` ``. An interpolated template in pattern position is `EK0707`; ordinary interpolation remains valid in guards and arm expressions. This follows the pinned formal grammar where the explainer leaves interpolation unsettled. A no-substitution template uses general `SameValueZero`: equal strings match and every non-string subject fails without coercion, as for a string literal.

```vibe [VibeLang]
// compiler-gap: pending VIP-7
function templateLabel(s: unknown, kind: string) {
  return match (s) {
    when `tag-A`: "literal";
    when let v and if (v === `tag-${kind}`): "guard";
    default: "miss";
  }
}
// when `tag-${kind}`: is a syntax error; use the guard above.
```

```ts [Effect]
import { Effect } from "effect"

function templateLabel(s: unknown, kind: string) {
  if (s === "tag-A") return "literal"
  if (s === `tag-${kind}`) return "guard"
  return "miss"
}
const templateExit = Effect.runSyncExit(Effect.sync(() => [
  templateLabel("tag-A", "B"), templateLabel("tag-B", "B"), templateLabel(Symbol("tag-A"), "B"),
])) // Success(["literal", "guard", "miss"])
```

Synchronous `match` evaluates its subject once and tests arms in order. It introduces no function or Effect boundary: its ordered tests and selected arm stay in the enclosing activation, so an arm's `try` becomes `yield*` in the enclosing Effect generator, as above. Only the selected arm body runs; guards run during arm testing and may have side effects. When no arm matches and there is no `default`, it throws `new TypeError()`, with an empty message: the pinned snapshot says only "a newly created *TypeError*", and no user code runs. In effect code that throw is a defect, not a failure.

<a id="match-evaluation"></a>**Match cache.** One `CreateMatchCache` per `match` (and per `is` test) caches property presence, property reads, `Symbol.iterator` lookup, iterators and pulled values per subject across arms, as the pinned draft specifies. Later arms reuse them: a cached pattern getter runs at most once and an iterable subject is iterated once. Object-rest copying is separate: it follows ordinary `CopyDataProperties` and may read the same getter again. The short object and fixed-pattern counterparts in this chapter omit cache machinery for subjects with plain data properties; they are not general lowerings for getters or iterators.

The pinned matching operations obey these behavioral invariants, with the draft errata recorded in the snapshot. Ordinary expression reads use ECMAScript [GetValue](https://tc39.es/ecma262/#sec-getvalue); iterator lookup preserves [GetV](https://tc39.es/ecma262/#sec-getv) receivers, and object rest keeps [CopyDataProperties](https://tc39.es/ecma262/#sec-copydataproperties).

| Rule | Required behavior |
| --- | --- |
| Object properties | Test properties left to right in source order, stopping at the first failure. For each property retain key evaluation, presence check, cached value read, sub-pattern and binding initialization in order; copy rest afterward. |
| Guard and selected expressions | Read a guard expression's value once before Boolean conversion. Read every selected/default arm expression's value once before iterator finishing. Getter calls, TDZ errors and abrupt completions occur at that read, never on an internal Reference Record or after cleanup. |
| Object rest | Use ordinary own-key, enumerability and value reads outside the match-specific read cache. A rest copy can re-read a previously cached getter; do not freeze its keys or descriptors in an earlier arm. |
| Array-pattern admission | `null` and `undefined` fail. Other subjects use cached `Symbol.iterator` lookup with `GetV` semantics: retain the original subject as receiver for both an inherited getter and the iterator call, including primitive strings. Missing/noncallable methods fail the pattern. Throwing accessors/calls and malformed protocol results retain their implicit throws. |
| Iterator records | Array and successful extractor list matching, and cleanup, use the same private cached Iterator Records, not user iterables. Successful custom extractor results must be objects. Iterator registration/closing stays in insertion order and skips empty registry slots; bookkeeping never reads user properties named `Value` or `IteratorsToClose`. Native iterator acquisition, saved `next`, result-object checks, `done`/`value` reads and abrupt-completion handling are preserved; an iterator marked done by an iteration error is not closed again. |
| Elisions | Each `Elision` consumes its full number of commas, excluding a list-separator comma. Every skipped position must exist. Leading, internal and trailing elisions advance cached reads and list cardinality by that width. |
| Optional elements | An absent optional element consumes zero values, leaves the iterator done and the actual index unchanged, and does not run its sub-pattern or initialize its bindings. Repeated missing optionals remain absent. A present `undefined` is a value and must satisfy its sub-pattern; no absent-binding default is invented. |
| Inclusive relations | On the admitted string, number or bigint subject, `<= bound` and `>= bound` mean ordinary `subject <= bound` and `subject >= bound`, with once-only bound evaluation and native coercion order. Unordered/`NaN` comparisons fail both; other subject types fail before bound evaluation. The draft's reversed inclusive bounds are not adopted. |

<a id="leaving-a-match"></a>**Leaving a `match`.** However a `match` or an `is` test ends, `FinishMatch` closes every unfinished cached iterator, in draft order, before control goes on, as the end of a `for…of` body closes its iterator:

| The arm, guard or test ends with | What happens |
| --- | --- |
| a value | the iterators close, then the `match` gives the value |
| `return`, `break` or `continue`, through `do` or a generator's `return()` | the iterators close, then the jump goes on |
| a JavaScript throw, the no-match `TypeError` included | the iterators close, then the throw goes on |
| an error from closing | it replaces a value or a jump, as in `for…of`. With a pending throw, or a second closing error, the `match` throws an `AggregateError` whose `errors` lists the pending throw and then the closing errors, where `for…of` keeps the pending throw alone |
| in effect code, a `try` that fails, dies or is interrupted, or a `throw` | nothing closes: the generator is [abandoned](/spec/008-runtime#abandonment) |

The pinned draft's `FinishMatch` appends every abrupt completion to its errors, so read literally it turns `return 7` into `throw 7`. Its own notes intend otherwise, and VibeLang reads that step as "a throw completion" (the snapshot's reconciliations). The rule is the `for…of` rule because a jump out of an arm is the same completion as a jump out of a loop body:

```vibe [VibeLang]
// compiler-gap: pending VIP-7
function* numbers(log: string[]) { try { yield 1; yield 2 } finally { log.push("closed") } }
function first(log: string[]) {
  const v = match (numbers(log)) { when [let a, ...]: do { return a }; default: 0; }
  return -1
}
effect function answer() {
  const ignored = match (true) { default: do { return 7 }; }
  return 0
}
effect function typed(log: string[]) {
  return match (numbers(log)) { when [let a, ...]: do { throw "bad" }; default: 0; }
}
effect function implicit(log: string[], o: { value: number }) {
  return match (numbers(log)) { when [let a, ...]: o.value; default: 0; }
}
```

| Call | Exit | `log` |
| --- | --- | --- |
| `first(log)` | returns `1` | `["closed"]`, as `for (const a of numbers(log)) return a` |
| `answer()` | `Success(7)` | |
| `typed(log)` | `Failure("bad")` | `[]`: the generator is abandoned |
| `implicit(log, o)`, the getter `o.value` throws `"t"` | `Die("t")` | `["closed"]`: a JavaScript throw unwinds the generator |

```ts [Effect]
import { Effect, Exit } from "effect"

function* numbers(log: string[]) { try { yield 1; yield 2 } finally { log.push("closed") } }
function first(log: string[]) {
  for (const a of numbers(log)) return a
  return -1
}
function typed(log: string[]) {
  return Effect.gen(function* () {
    for (const a of numbers(log)) return yield* Effect.fail("bad")
    return 0
  })
}
function implicit(log: string[], o: { value: number }) {
  return Effect.gen(function* () {
    for (const a of numbers(log)) return o.value
    return 0
  })
}
const firstLog: string[] = []
if (first(firstLog) !== 1 || firstLog.join() !== "closed") throw new Error("return lost its close")
const typedLog: string[] = []
const typedExit = Effect.runSyncExit(typed(typedLog))
if (!Exit.isFailure(typedExit) || typedLog.length !== 0) throw new Error("a failure closed the iterator")
const implicitLog: string[] = []
const bad = { get value(): number { throw "t" } }
const implicitExit = Effect.runSyncExit(implicit(implicitLog, bad))
if (!Exit.isFailure(implicitExit) || implicitLog.join() !== "closed") throw new Error("a throw skipped the close")
```

- In an object pattern, a bare key such as `{ tracking }` only tests that the property exists. Binding it takes `let tracking`, shorthand for `tracking: let tracking` (VIP-16). Replacing `let tracking` with `tracking` above would return `"outer"`, not the field.
  VibeLang does not adopt the draft's disputed early error rejecting a `MatchProperty` name coverable by `BindingIdentifier`, either as a bare presence key or before `:`. Identifier keys such as `_tag:` remain valid; the separate `__proto__` pattern-key restriction and unrelated early errors remain.
- Prefix `not` wins whenever the same token sequence can also be a member/extractor rooted at an identifier `not`. Parsing never consults a local binding or its type, and does not retry that identifier parse to evade an early error. Thus `not(let x)` negates a parenthesized binding pattern and `not[0]` negates an array pattern; `helpers.not(let x)` remains a qualified extractor. `not` stays an ordinary name outside the prefix collision and in property/binding-name positions.
- Pattern bindings use `let` or `const`; `when var x:` is `EK0107`, as `var` is everywhere in `.vibe`.
- An arm's body may be `throw e`, as VIP-5's example writes it. It means what `throw` means where the arm stands ([Failures](/spec/003-failures#throw)): in effect code it fails the Effect, in an `async` function or an `async match` it rejects the Promise, and in any other `.vibe` code it is `EK0401`.
- No-match `TypeError`, implicit matcher reads/calls and protocol checks are implicit throws: never tracked, and defects in effect code. Written calls in subjects, guards, arms and call-only predicates are tracked normally ([Thrown types](/spec/003-failures#thrown-types)).

The empty array pattern uses [ArrayPattern](/spec/900-appendices#arraypattern) with its one nullable-list derivation. It matches an empty iterable, including an empty string, and is not a wildcard or an array-only test. Every array pattern and extractor list receives a cached Iterator Record; its finishing paths never receive the original subject instead of that record.

```vibe [VibeLang]
// compiler-gap: pending VIP-7

```

## `is` expressions

`subject is P` evaluates the subject once and returns the pattern's Boolean result, using the same cache and finishing rules as `match`. In an ordinary block expression or an `if` head, its `let` and `const` names belong to the nearest enclosing lexical home, as the pinned explainer's binding rule states for a block: a block, a match arm or one of the [other homes](/spec/004-match#pattern-bindings). They are in scope in both branches and after the `if` within that home, shadow outer names throughout it, and exist even when short-circuiting skips the expression or a preceding subpattern fails. Each cell stays in TDZ until its binding pattern executes. A failed overall test does not undo bindings already initialized; a skipped binding is still uninitialized. Source assignments keep ordinary `const` immutability. The pinned duplicate-initialization rules and their `or` replacement exception apply within one top-level pattern. Two top-level patterns that bind one name in the same lexical home are a redeclaration, as two `let` declarations are, and report what such a `let` reports: `TS2451` beside another lexical declaration, `TS2300` beside a parameter ([VIP-7](/vips/0007-match#binding-homes-and-redeclarations)). Separate blocks, match arms and the [other homes](/spec/004-match#pattern-bindings) are separate homes. The diagnostic offers to rename the later binding and its uses, and `vibelang --fix` applies that rename.

An `is` in a loop head uses the pinned loop-head/per-iteration scopes. Each complete `while` or `do…while` condition evaluation has fresh cells; the initial `do` body sees its uninitialized head cells. A match arm has its own lexical scope, so an `is` inside it does not export names to another arm.

These bindings take part in TypeScript's definite-assignment and use-before-declaration checks, as a `let` assigned where the pattern runs would. A read on a path where the binding may not have run, because short-circuiting skipped it or the pattern failed before reaching it, is `TS2454`; a read before the binding's position in its scope is `TS2448`. A read those checks can't see, such as one inside a closure, throws `ReferenceError` while the cell is uninitialized.

```vibe [VibeLang]
// compiler-gap: pending VIP-7
function nameOf(value: { name: string } | undefined) {
  if (value is { let name }) return name
  return "missing"
}
function failedGuard() {
  if (5 is let n and if (false)) return 0
  return n // 5: the binding ran before the guard failed
}
effect function skippedBinding() {
  // @ts-expect-error: TS2454, short-circuiting skipped the binding's initialization
  if (true || (1 is const n)) return n
  return 0
} // Die(ReferenceError)
function pick(a: unknown, b: unknown) {
  if (a is { id: let id }) return id
  // @ts-expect-error: TS2451, id is already declared in this block
  if (b is { id: let id }) return id
  return 0
}
function pickOk(a: unknown, b: unknown) {
  if (a is { id: let first }) return first
  if (b is { id: let second }) return second
  return 0 // pickOk({}, { id: 1 }) is 1
}
```

The object counterpart specializes its stated subject type. Native lexical-cell witnesses check initialization before a failed guard and TDZ after a skipped initialization:

## Typing

Patterns type as the TypeScript counterpart this chapter shows for them, under the project's compiler options; the table below illustrates `tsc --strict` ([VIP-7](/vips/0007-match#decision), amended).

- **Result.** A `match` expression has the union of its arm types; a `throw` arm contributes `never`. A `match` with no `default` whose subject passes `EK4701` ([Exhaustiveness](/spec/004-match#exhaustiveness)) adds nothing for the no-match path. For arm-type union `U`, `async match` has type `Promise<Awaited<U>>`, with TypeScript's async-return resolution and Promise-like/thenable checks: a returned Promise is adopted, not nested. `x is P` has type `boolean` and narrows `x` as a type predicate where `P` narrows.
- **Subject narrowing.** Inside an arm the subject narrows as the arm's test narrows in TypeScript; a `default` arm follows TypeScript control flow after every preceding ordered pattern and guard test has failed, including cached reads and source mutations. This is independent of exhaustiveness coverage: a predicate false branch may exclude a type even though the predicate covers no `EK4701` case; failure of a guard does not establish that its positive predicate failed. A guard `and if (c)` narrows further, as `if (c)` would.
- **Bindings.** A `let` binding has the type TypeScript gives the value it is bound to in the counterpart.

| Pattern | Narrows `s` to | Binding types |
| --- | --- | --- |
| literal `"a"`, `1`, `null`, `undefined`, enum member | `s === v` | none |
| object `{ _tag: "Sent", let tracking, id }` | `(typeof s === "object" \|\| typeof s === "function") && s !== null && "_tag" in s && s._tag === "Sent" && "tracking" in s && "id" in s` | `tracking`: the narrowed subject's property type |
| array `[let a, let b]` | members that are iterable | the element type of the subject's iterable (tuple element types for a tuple) |
| `error` / `schema error` class `NotFound`, `NotFound(let e)` | subject members with `_tag: "NotFound"`, if any; otherwise `NotFound` | `e`: those subject members; otherwise the declared `NotFound` |
| class `C` with an own matcher | only narrowing established by its matcher invocation; no implicit `instanceof` | elements of the declared extraction iterable, excluding `false` |
| ordinary class `C` without an own matcher | `s instanceof C` | bare test has no bindings; any extractor is `EK0704` ([Class patterns](/spec/004-match#class-patterns)) |
| built-in `Array(let n)`, typed-array extractor | `Array.isArray(s)`, `s instanceof C` respectively | elements of the subject array or typed array (`number` or `bigint`) |
| other built-in constructor extractor | its specified recognition test | elements of its actual draft extraction list; `Map` and `Set` return `[s]`, so bind the collection |
| primitive class `String(let t)`, `Number`, … | `typeof s === "string" \|\| s instanceof String`, … | `t`: `string`, … |
| fixed `Option.Some(let v)` | `Option.isOption(s) && Option.isSome(s)` | `v`: `A` for `Option<A>`; `unknown` for an `unknown` subject |

| relational `< 0` | none | none |
| `not P` | the false branch of the actual positive test: `!(s instanceof C)` only for an ordinary class using `instanceof`; an own matcher, generated error matcher or fixed guard complements its own invocation/test. A boolean-returning custom matcher establishes no narrowing | none |
| `P or Q` | the union of each side's narrowing | a name bound in every alternative gets the union of its types |
| `P and Q` | both narrowings in order | both sides' bindings |

## Pattern bindings

An `or` pattern shares one lexical cell for a name bound with the same keyword in its alternatives. A later alternative may replace a cell initialized by a failed earlier alternative of that `or`; closures saved by that earlier alternative observe the replacement. Ordinary TDZ before first initialization, user-facing `const` immutability, and duplicate-initialization restrictions outside that authorized replacement remain. Do not reset unrelated bindings or give alternatives disconnected cells.

Lexical `is` bindings in `while` and `do…while` have the pinned explainer's loop-head/per-iteration scope, rather than an enclosing block's scope. The loop head shadows outer names and does not leak outside the loop. Each complete condition evaluation starts with fresh uninitialized cells, including after `continue`; condition reads see TDZ until the matching pattern initializes them. A successful condition and its following body share those cells, so closures see that body's later `let` writes. Short-circuiting past a binding leaves it uninitialized even if the condition is true. Nested source blocks/functions retain their own scopes.

The first `do…while` body runs with the initial uninitialized head cells. Its direct reads precede the binding, so they are `TS2448`, and with the check suppressed they throw `ReferenceError`; closures captured there keep those cells permanently in TDZ. Each subsequent condition gets new cells; its true result shares them with the following body. `continue` reaches a fresh condition set, and false/`break` exits without exporting names. The initial closures are never rebound to a later condition. An `if` head belongs to the home that contains the `if` statement; the within-one-`or` replacement above is unchanged.

Every other home follows the pinned explainer's rule that the usual binding scopes apply, with ECMAScript's environments:

- In `for (init; test; update)`, a binding from `init` belongs to the loop head, as a name declared by a `let` or `const` declaration in `init` would, whether `init` is a declaration or an expression: CreatePerIterationEnvironment copies a `let` binding into each iteration, and a `const` binding stays in the loop scope. A binding from `test` or `update` is a fresh, uninitialized cell in each environment CreatePerIterationEnvironment creates, shared by the update, test and body that run there and never copied forward, as for a `while` condition.
- In `for…in`, `for…of`, `for await`, `for concurrent` and `for try`, a binding from the head expression, which runs once in the head's own environment, is copied into each iteration's binding environment; a skipped binding is copied uninitialized. A binding from a default inside the head declaration belongs to that iteration's fresh binding environment. A binding in a `for concurrent` limit belongs to the nearest home that encloses the loop, because the limit runs before the head environment exists ([VIP-7](/vips/0007-match#binding-homes-and-redeclarations)); it is one cell, not copied into items.
- In a concise arrow body, a binding belongs to the arrow body's scope, where the block-body form would declare it.
- In a class field or static field initializer, a binding belongs to that initializer's own scope, because ECMAScript evaluates each initializer as a separate method-like body. A `static` block is a block.
- An `enum` member initializer has no lexical home in ECMAScript or the pinned explainer, so a binding introduced there is `EK0705`, as for a formal parameter: `enum E { A = (1 is let one) ? 1 : 0 }` is `EK0705`.
- The statement body of `if`, `else`, `for`, `for…in`, `for…of`, `for await`, `for concurrent`, `for try`, `while`, `do…while` or a labeled statement, when it is not a Block, is the home of the bindings inside it, exactly as if it were wrapped in braces, and it is fresh each time the body runs, so braces around a body never change a result ([VIP-7](/vips/0007-match#binding-homes-and-redeclarations)). An `if` head is outside its own body: `if (!(x is { id: let id })) return; use(id)` in a block reads `id` after the `if`, and the head of an `else if` belongs to the `else` body's home.

Each home holds one name once. Two top-level patterns that bind one name in the same home are a redeclaration, TypeScript's `TS2451`, as two `let` declarations in one block are; so is a binding that collides with another lexical declaration of that home, and a collision with a parameter keeps the native diagnostic for that collision. Inside one top-level pattern the pinned duplicate-initialization rule and its `or` exception stay. Separate blocks and match arms are separate homes, so braces or distinct names are the repair.

## Exhaustiveness

VibeLang adds these checks to TC39's proposal; `EK4701` is the exhaustiveness check.

| Rule | Diagnostic |
| --- | --- |
| a `match` with no `default` over a finite union that misses a case | `EK4701` |
| invalid `match`/`is` grammar or a pattern-specific early error without a more specific diagnostic | `EK0707` |
| a missing `;` after a `match` arm, the last one included | `EK0701` |
| an `is` pattern binding in formal-parameter or catch-parameter initialization with no explicit block/arm as its lexical home ([Parameter initialization](/spec/004-match#is-bindings-in-parameter-initialization)) | `EK0705` |
| a class pattern naming a `data` declaration or variant, a `schema`, or a directly constructed `Context.Reference`; a call-only callee whose return type fails detail 94, or a callee with neither signature (services use `EK3004`; [Class patterns](/spec/004-match#class-patterns)) | `EK0702` |
| an ordinary-class extractor without an own matcher (detail 100) | `EK0704` |
| lint warning: an extractor whose argument count can never match its pattern's list ([Class patterns](/spec/004-match#class-patterns)) | `EK0703` |
| a `return`, `break` or `continue` that leaves an `async match` ([Async jumps](/spec/004-match#async-match-jumps)) | `EK0706` |

`EK4701` applies equally to `match` and `async match`, which have the same arms. The check only reports errors. It never changes what runs: a `match` that passes the check compiles to the same tests as one that doesn't need it.

One algorithm decides every subject (VIP-7, amended):

- **Subjects.** Start from TypeScript's type of the subject expression at that evaluation point, including its represented flow refinements. Resolve its effective base constraint when one exists; otherwise keep that type. Normalize the result into a union of members, expanding `boolean` to `true | false`, an enum to its members, a `data` type to its variants, `Option.Option<A>` to `None | Some`, and `Exit.Exit<A, E>` and `Result.Result<A, E>` to `Success | Failure`. `EK4701` applies when every member is a literal type, `true`, `false`, `null`, `undefined`, an enum member, a `data` variant, an `error` or `schema error` instance, one of those six `Option`, `Exit` and `Result` cases, a retained Effect error ([Retained fixed patterns](/spec/004-match#retained-fixed-patterns)), or a tagged member. Any other member (`string`, `number`, an untagged object or class instance, `unknown`, `any`) turns the check off for that `match`, which keeps TC39's run-time `TypeError`.
- **Generic constraints and flow.** A constrained type parameter uses its finite constraint as a conservative domain; an unconstrained parameter or a broad constraint stays open. A represented refinement such as `T & { _tag: "A" }` can reduce that domain to `"A"`. If TypeScript still exposes bare `T` after an equality or property guard, its whole constraint remains: the check does not invent extra narrowing from the guard's text. Ordinary literals keep their literal types, without apparent-type boxing to `Number`, `String` or `Boolean`. This coverage projection neither casts the subject nor changes arm or default-flow types.
- <a id="tagged-members"></a>**Tagged members.** Only `_tag` is a discriminant, Effect's convention, and `EK4701` counts the literal cases of `switch (s._tag)`. Coverage is per normalized member and tag case, even when TypeScript does not narrow the whole subject because every member has the same `_tag` type. A member is tagged when it is an object, interface or class instance and its `_tag` is what TypeScript calls a literal type: a string, number, bigint, boolean, enum, `null` or `undefined` literal, a `unique symbol`, or a union of those. Each of those literals is a case of the member, and an optional `_tag` has the case `undefined`. A `_tag` of any other type, such as `string` or a template type, is not tagged, because TypeScript checks no `switch` over it.
- **Coverage.** Only an unguarded arm covers anything. A literal, `null`, `undefined` or enum-member pattern covers that member. A signed Number literal whose value is zero (`+0`, `-0`, `-0.0`, `+0e0`, and equivalent spellings) covers no zero case: its `SameValue` test distinguishes signs, while TypeScript's `0` type admits both. Even both signed arms together give no whole-case proof; use unsigned zero or `default`. Unsigned zero uses `SameValueZero` and covers both signs. Valid signed nonzero literals retain singleton coverage; bigint zero has no distinct negative zero. The same rule applies to a checked zero-valued enum case. A bare binding (`let x` or `const x`) covers every member. `when NotFound:`, `when NotFound(let e):` and `when NotFound(const e):` cover each member's `"NotFound"` tag case, including a plain object with that tag; other tag cases on that member remain; `when NotFound():` and `when NotFound({ id: "x" }):` cover nothing. A fixed pattern (`Option.Some`, `Option.None`, `Exit.Success`, `Exit.Failure`, `Result.Success`, `Result.Failure`) or a retained error covers its case when it is bare, or when its argument list has the required length and every argument pattern is a bare `let` or `const` binding. A bare pattern has no argument list, which is not an empty list: `when Option.Some:` and `when Option.Some(let v):` cover `Some`; `when Option.Some():` and `when Option.Some(1):` do not. An object pattern with `_tag: "V"` covers case `V` of each `data` variant or tagged member when every other property it tests is a bare key or a `let` or `const` binding that the member declares as required: `"x" in s` removes a member from its false branch only where `x` is required. Members that share a tag are covered one at a time, and one left uncovered stays uncovered. The `undefined` case of an optional `_tag` is covered only by a bare binding, because `{ _tag: undefined }` tests `"_tag" in s` first and an absent tag fails that test. `or` covers the union of its alternatives. `and`, `not`, regex, relational, array, built-in matcher and user-matcher patterns cover nothing, so those arms need a `default`.

[AsyncMatchExpression](/spec/900-appendices#asyncmatchexpression) is a primary expression; no line terminator may separate `async` and `match`. `async match (s) { … }` has the async-function behavior `(async () => match (s) { … })()`: subject evaluation, tests and the selected arm run inside the async function. `await` is allowed there; a thrown exception, including the no-match `TypeError`, rejects the resulting `Promise`. The explicit VIP-7 reconciliation gives the subject, tests and arms `[~Yield, +Await, ~Return, ~Effect]` contexts, even inside a plain function. Under VIP-7, a `return` in it, and a `break` or `continue` whose target is outside it, are syntax errors. Nested source callables retain their own grammar contexts.

<a id="async-match-jumps"></a>`EK0706` reports a jump out of an `async match`: a `return` that belongs to the `async match`, or a `break` or `continue` whose target is outside it. The rule covers the subject, patterns, guards and arm expressions, including a `do` expression in them. A `return` in a nested function belongs to that function, and a `break` or `continue` whose target is inside the `async match` follows the ordinary rules. Ownership and targets come from the source, not from the generated async function; a `break` or `continue` with no target anywhere keeps TypeScript's own error. No quick fix rewrites the jump, because no jump can cross the `Promise` boundary.

## `is` bindings in parameter initialization

An `is` test in formal-parameter initialization is `EK0705` if a `let` or `const` pattern binding would need the parameter environment as its lexical home. This includes direct defaults, defaults nested in parameter destructuring, and evaluated computed binding keys. The same holds for a catch clause's parameter, whose environment is distinct from the catch Block ([VIP-7](/vips/0007-match#binding-homes-and-redeclarations)). The pinned explainer leaves that scope unfinished, so no parameter-home binding is invented or moved into the body.

A binding-free test remains allowed. A binding in an explicit source block within the initializer, including a `do` block or a match arm's scope, belongs to that block/arm and does not escape to other parameters or the body. Nested source callable bodies keep their own scopes and boundaries. Ordinary call arguments in a lexical block retain that block's binding rule; they are not formal parameters.

A repair preserves eager, left-to-right, once-only initialization, parameter/body environment separation, `length`, TDZ and closure identity. An explicit local block can return the needed result; a different explicit parameter is an option only when it preserves the intended API. There is no generic move-to-body quick fix. Execution and exception boundaries retain the [shared default rules](/spec/002-running#destructuring-and-parameter-defaults).

## Regular-expression patterns

A [RegularExpressionPattern](/spec/900-appendices#regularexpressionpattern) admits a bare `RegularExpressionLiteral` or its extractor suffix `(MatchList)`, including the nullable list `()`. It evaluates the literal once at its pattern position and matches as the same named `RegExp` value does. The runtime emulates the draft's `RegExp.prototype` matcher without patching the prototype: a bare pattern calls `test`; a non-global extractor returns `[regexp[Symbol.match](subject)]`, failing on `null`. A global extractor returns `Array.from(regexp[Symbol.matchAll](subject))` directly, failing when empty. Thus a non-global regex extracts one match array, not separate capture arguments; a global regex extracts one element per match. Calls preserve the regex receiver and the draft's observable property reads and `lastIndex` effects.

```vibe [VibeLang]
// compiler-gap: pending VIP-7

  return match (s) {
    when /(\d+)-(\d+)/(let m): m[1] + m[2];
    default: "none";
  }
}
```

## Class patterns

A class arm whose class has its own `Symbol.customMatcher` (an own property, `Object.hasOwn(C, Symbol.customMatcher)`) reads and calls that matcher when the pattern runs, as the draft says. A static matcher inherited from a superclass is not an own matcher: for `class B extends A {}`, `when B:` tests `s instanceof B`. Inherited lookup would make `class Sub extends NotFound {}` match every `NotFound` through its superclass’s tag matcher. VIP-7's retained fixed patterns below are recognized before this test. Any other class uses `instanceof`; the runtime never installs the draft's `Function.prototype` matcher.

- An `error` class ([Failures](/spec/003-failures#error-declarations)), including a `schema error`, gets a matcher that tests `_tag`. It returns `[subject]` on a match and `false` otherwise; `when NotFound(let e):` binds that subject. `when NotFound():` never matches: the matcher returns one element, but the extractor has zero argument patterns. Write `when NotFound:` for a bare test. Thus `when NotFound:` matches across copies of the same package. The TypeScript counterpart is in [Failures](/spec/003-failures#error-declarations).
- `data` variants get no custom matchers. Match them with object patterns on `_tag`: `when { _tag: "Sent", let tracking }: …` ([Data](/spec/006-data#data-declarations)). Only `error` and `schema error` declarations, and the retained Effect checks, have their own matcher.
- A class pattern whose expression resolves to a `data` declaration or variant constructor, a `schema` declaration or a directly constructed `Context.Reference` is `EK0702` (decided detail 67b): under the draft such a function would be called with the subject and match almost anything. The quick fix for a variant writes `when { _tag: "Sent" }:`; for a schema, test `Schema.is(Address)(x)` in a guard. Every `service` declaration, with or without `defaultValue`, reports `EK3004` instead ([Services](/spec/005-services#static-rules)).
- **No run-time patching of Effect.** The thirty-nine fixed patterns below are compiler intrinsics until Effect ships matchers. The names are pattern syntax, not values exported by Effect 4.1.1. Recognition follows the resolved module binding, including aliases: `import * as O from "effect/Option"` permits `when O.Some(let v):`. A local `Option` instead uses TC39's matcher lookup; spelling alone never selects an intrinsic.
- Thirty-three of the thirty-nine are Effect’s tagged errors, each tested with its module’s own guard (decided detail 53). The alias and shadowing rule above applies. Neither `instanceof`, a universal `_tag` test nor the subject’s static type replaces the guard.
- Built-in constructor patterns use `Array.isArray(subject)` for `Array`, and `subject instanceof C` for every other built-in, including native errors, `AggregateError`, `Date`, `RegExp`, collections, `Promise`, typed arrays and `ArrayBuffer` (decided detail 67a). A cross-realm array matches; other cross-realm built-ins may fail. Native-error matching follows the current prototype chain, not an inaccessible original native-error kind. `String`, `Number`, `Boolean`, `BigInt` and `Symbol` test the primitive or its boxed object, `typeof s === "string" || s instanceof String` and so on, and extract `[s]` for a primitive and `[s.valueOf()]` for a boxed object (decided detail 87). Extraction otherwise follows the draft; no methods are defined on globals. Ordinary classes without an explicit matcher, including classes imported from untouched `.ts` or `.js`, instead test `subject instanceof C`, then extract as the draft specifies (decided detail 67). No helper patches `Function.prototype` or records construction identity. This deliberately differs from the snapshot's `[[ConstructedBy]]` test: changing a genuine instance's prototype can make it stop matching, while forging a prototype can make an object match. A future switch to engine matchers requires a VIP. Where an engine lacks `Symbol.customMatcher`, the runtime defines the symbol ([Runtime guarantees](/spec/008-runtime)).

For an ordinary class without an own matcher, the draft’s successful test returns `true`, not `[s]`: using it as an extractor throws `TypeError`, rather than binding an instance. Built-in adapters retain their own extraction rules: `Array` and typed arrays return the subject as the list; `Map` and `Set` return `[subject]`.

After own matchers, fixed patterns, built-ins and declaration diagnostics, dispatch uses the callee’s static signatures: a construct signature selects `instanceof`, including ES5 constructors declared as constructable; call signatures only select `C(subject, { matchType })`, preserving a member receiver. A bare call-only pattern requires a return type assignable to `boolean`; an extractor requires `Iterable<unknown> | false`. Other return types, and callees with neither signature (`any`, `unknown`, `Function`, non-callable objects), are `EK0702`; quick fix: test the call in a guard. Type predicates narrow as ordinary TypeScript calls do. The global `Function` still reports `EK0107`; use a `typeof` guard.
