# Pattern matching

Source: [VIP-7](/vips/0007-match).

## Syntax and meaning

```vibe [VibeLang]
// compiler-gap: pending VIP-7
effect function label(d: { _tag: "Sent"; tracking: string } | { _tag: "Waiting" }) {
  const tracking = "outer"
  return match (d) {
    when { _tag: "Sent", let tracking }: try Effect.succeed(tracking);
    default: tracking;
  }
}
```

```ts [Effect]
import { Effect } from "effect"

function label(d: { _tag: "Sent"; tracking: string } | { _tag: "Waiting" }) {
  return Effect.gen(function* () {
    const tracking = "outer"
    const subject = d
    if (subject._tag === "Sent" && "tracking" in subject) {
      const tracking = subject.tracking
      return yield* Effect.succeed(tracking)
    }
    return tracking
  })
}
```

`match`, `when`, `is`, patterns, guards, `and`, `or`, `not` and `default` follow the vendored TC39 snapshot: commit `ba73ffe42f30f0cf56ece28bebdc28f955f2a52e`, dated `2025-10-03`, with the reconciliations listed there. VibeLang moves to a newer snapshot deliberately, never automatically. The full proposal is in the language, including regular-expression patterns, relational patterns and `async match`.

The arm grammar is [MatchBody](/spec/900-appendices#matchbody), [MatchArm](/spec/900-appendices#matcharm) and [ArmBody](/spec/900-appendices#armbody): the pinned draft with VIP-7's `when` prefix and VIP-5's `throw` arm body. `default` is last; guards belong to `MatchPattern` (`P and if (condition)`). Separate arms with `;`, including the final arm; a newline alone is not a separator. The reconciliations are: relational patterns use the draft specification; regex patterns accept both literals and `RegExp` values; `async match` uses the explainer's Promise-producing sketch; custom matchers receive `(subject, { matchType })`, with `matchType` either `"boolean"` or `"extractor"`; built-in matchers use the draft specification, emulated without modifying globals.

Synchronous `match` evaluates its subject once and tests arms in order. It introduces no function or Effect boundary: its ordered tests and selected arm stay in the enclosing activation, so an arm's `try` becomes `yield*` in the enclosing Effect generator, as above. Only the selected arm runs. When no arm matches and there is no `default`, it throws a `TypeError` with the host’s default message (the pinned snapshot specifies no message); in effect code that is a defect, not a failure.

- In an object pattern, a bare key such as `{ tracking }` only tests that the property exists. Binding it takes `let tracking`, shorthand for `tracking: let tracking` (VIP-16). Replacing `let tracking` with `tracking` above would return `"outer"`, not the field.
- An arm's body may be `throw e`, as VIP-5's example writes it. In effect code it fails the Effect ([Failures](/spec/003-failures#throw)); outside effect code it is JavaScript's `throw`.

A `match` inside a larger expression follows the shared [expression-lowering rule](/spec/002-running#do-expressions): call references, receivers and short-circuit evaluation are preserved, and `eval` and `arguments` are compile errors anywhere in `.vibe`, including subjects, guards and arms ([Legacy JavaScript](/spec/001-functions#direct-eval); VIP-1, amended).

## Exhaustiveness

VibeLang adds one check to TC39's proposal.

| Rule | Diagnostic |
| --- | --- |
| a `match` with no `default` over a finite union that misses a case | `EK4701` |

The check only reports errors. It never changes what runs: a `match` that passes the check compiles to the same tests as one that doesn't need it.

The check covers literal unions, `boolean`, `data` unions, `error` unions and enums ([VIP-7, amended](/vips/0007-match)). An arm covers a case only when its pattern matches every value of that case: for `error NotFound { id: string }`, `when NotFound:` and `when NotFound(let e):` cover `NotFound`; `when NotFound():`, `when NotFound({ id: "x" }):` and guarded arms cover nothing. The empty extractor never matches; the field-constrained extractor leaves other `id` values uncovered.

**Undecided (pending VIP):** which non-class pattern forms the exhaustiveness checker can prove cover a case. VIP-7 specifies the checked subject types and that guarded arms cover nothing, but neither it nor TC39 specifies this static algorithm. In particular, coverage for `data` object patterns, `or`, `and`, `not`, regex, relational and built-in matcher patterns is pending. Their run-time matching remains the pinned TC39 algorithm; use `default` when relying on these forms until coverage is decided.

```vibe [VibeLang]
// compiler-gap: pending VIP-7
effect function bit(b: boolean) {
  return match (b) { when true: 1; when false: 0; }
}
// Guarding the true arm requires another unguarded true arm or default.
```

```ts [Effect]
import { Effect } from "effect"

function bit(b: boolean) {
  return Effect.gen(function* () {
    const subject = b
    if (subject === true) return 1
    if (subject === false) return 0
    throw new TypeError()
  })
}
```

`async match (s) { … }` has the async-function behavior `(async () => match (s) { … })()`: subject evaluation, tests and the selected arm run inside the async function. `await` is allowed there; a thrown exception, including the no-match `TypeError`, rejects the resulting `Promise`.

```vibe [VibeLang]
// compiler-gap: pending VIP-7
function asyncLabel(s: Promise<string>) {
  return async match (await s) {
    when "sent": await Promise.resolve("sent");
  }
}
```

```ts [Effect]
function asyncLabel(s: Promise<string>) {
  return (async () => {
    const subject = await s
    if (subject === "sent") return await Promise.resolve("sent")
    throw new TypeError()
  })()
}
```

Inside effect code, a direct `async match` is a compile error under the [Promise-bridge rule](/spec/003-failures#calls-in-effect-code): like a Promise-returning call or `new` expression, it must run inside an explicit bridge's thunk. Its subject, tests and arms form a plain async boundary (`[~Effect, +Await]`): `await` is allowed there and effect `try` is not, as in a nested TypeScript async function. For example:

```vibe [VibeLang]
// compiler-gap: pending VIP-7
effect function asyncBit(b: boolean) {
  return try promise(() => async match (b) {
    when true: await Promise.resolve(1);
    default: 0;
  })
}
```

```ts [Effect]
import { Effect } from "effect"

function asyncBit(b: boolean) {
  return Effect.gen(function* () {
    return yield* Effect.promise(() => (async () => {
      const subject = b
      if (subject === true) return await Promise.resolve(1)
      return 0
    })())
  })
}
```

## Class patterns

Except for VIP-7's retained compiler intrinsics below, a class arm such as `when NotFound:` uses the class's `Symbol.customMatcher`, as TC39 says.

- An `error` class ([Failures](/spec/003-failures#error-declarations)), including a `schema error`, gets a matcher that tests `_tag`. It returns `[subject]` on a match and `false` otherwise; `when NotFound(let e):` binds that subject. `when NotFound():` never matches: the matcher returns one element, but the extractor has zero argument patterns. Write `when NotFound:` for a bare test. Thus `when NotFound:` matches across copies of the same package. The TypeScript counterpart is in [Failures](/spec/003-failures#error-declarations).
- `data` variants get no custom matchers. Match them with object patterns on `_tag`: `when { _tag: "Sent", let tracking }: …` ([Data](/spec/006-data#data-declarations)).
- **No run-time patching of Effect.** The six fixed patterns below are compiler intrinsics until Effect ships matchers. The names are pattern syntax, not values exported by Effect 4.1.0. Recognition follows the resolved module binding, including aliases: `import * as O from "effect/Option"` permits `when O.Some(let v):`. A local `Option` instead uses TC39's matcher lookup; spelling alone never selects an intrinsic.
- VIP-7 also retains the fixed checks for Effect’s tagged errors until Effect ships matchers; the inventory below uses each module’s own guard (decided detail 53, 2026-10-29). The alias/shadowing rule above applies. Neither `instanceof`, a universal `_tag` test nor the subject’s static type replaces the guard.
- Built-in constructor patterns, including `Array`, `Error`, `Map`, `Set`, `Date` and `Promise`, use the runtime's `$is`/`$extract` emulation of the snapshot's built-in matchers, without defining methods on globals. Outside the retained Effect tagged-error checks, the inherited `Function.prototype` matcher for other ordinary classes is also emulated, through `$is`, without modifying `Function.prototype`: use the pinned specification’s constructed-by test and non-class callable fallback, not a blanket `instanceof` rewrite. Where an engine lacks `Symbol.customMatcher`, the runtime defines the symbol ([Runtime guarantees](/spec/008-runtime)).

For the six specified intrinsics below, `s` is the subject, evaluated once; modules mean the resolved `effect/Option`, `effect/Exit` and `effect/Result` identities. A bare pattern only runs the test. An extractor matches the listed array against its argument patterns using the snapshot's list-matching rules: without rest, zero arguments match only `[]`, one matches a singleton, and extra arguments fail. Rest patterns follow the snapshot. Arity mismatch is a failed match, not a new compile-time error.

| Fixed pattern | Ordered test | Extracted list |
| --- | --- | --- |
| `Option.Some(P)` | `Option.isOption(s) && Option.isSome(s)` | `[s.value]` |
| `Option.None` / `Option.None()` | `Option.isOption(s) && Option.isNone(s)` | `[]` |
| `Exit.Success(P)` | `Exit.isExit(s) && Exit.isSuccess(s)` | `[s.value]` |
| `Exit.Failure(P)` | `Exit.isExit(s) && Exit.isFailure(s)` | `[s.cause]` |
| `Result.Success(P)` | `Result.isResult(s) && Result.isSuccess(s)` | `[s.success]` |
| `Result.Failure(P)` | `Result.isResult(s) && Result.isFailure(s)` | `[s.failure]` |

```vibe [VibeLang]
// compiler-gap: pending VIP-7
import * as O from "effect/Option"
effect function unwrap(s: unknown) {
  return match (s) {
    when O.Some(let v): v;
    when O.None: "none";
    when Exit.Success(let v): v;
    when Exit.Failure(let c): c;
    when Result.Success(let v): v;
    when Result.Failure(let e): e;
    default: "other";
  }
}
// A local Option uses Option.Some[Symbol.customMatcher] instead.
```

```ts [Effect]
import { Effect, Exit, Option as O, Result } from "effect"

function unwrap(s: unknown) {
  return Effect.gen(function* () {
    const subject = s
    if (O.isOption(subject) && O.isSome(subject)) return subject.value
    if (O.isOption(subject) && O.isNone(subject)) return "none"
    if (Exit.isExit(subject) && Exit.isSuccess(subject)) return subject.value
    if (Exit.isExit(subject) && Exit.isFailure(subject)) return subject.cause
    if (Result.isResult(subject) && Result.isSuccess(subject)) return subject.success
    if (Result.isResult(subject) && Result.isFailure(subject)) return subject.failure
    return "other"
  })
}
```

## Retained Effect tagged-error patterns

```vibe [VibeLang]
// compiler-gap: pending VIP-7
function errorLabel(e: unknown) {
  return match (e) {
    when Cause.TimeoutError(let t): t._tag;
    when Schema.SchemaError: "invalid";
    default: "other";
  }
}
```

```ts [Effect]
import { Cause, Schema } from "effect"

function errorLabel(e: unknown) {
  const subject = e
  if (Cause.isTimeoutError(subject)) {
    const t = subject
    return t._tag
  }
  if (Schema.isSchemaError(subject)) return "invalid"
  return "other"
}
```

This is the retained inventory for Effect `4.1.0` (VIP-7, D208; decided detail 53). Each constructor is recognized by its resolved module binding, including aliases and excluding shadowed names. A bare pattern runs the listed guard; an extractor matches `[s]` by the same list rules as above: `X(let e)` binds the subject, `X()` never matches, and arity mismatch is a failed match.

| Resolved constructor | Ordered test on `s` | Extracted list |
| --- | --- | --- |
| `Cause.NoSuchElementError` | `Cause.isNoSuchElementError(s)` | `[s]` |
| `Cause.TimeoutError` | `Cause.isTimeoutError(s)` | `[s]` |
| `Cause.IllegalArgumentError` | `Cause.isIllegalArgumentError(s)` | `[s]` |
| `Cause.ExceededCapacityError` | `Cause.isExceededCapacityError(s)` | `[s]` |
| `Cause.AsyncFiberError` | `Cause.isAsyncFiberError(s)` | `[s]` |
| `Cause.UnknownError` | `Cause.isUnknownError(s)` | `[s]` |
| `Schema.SchemaError` | `Schema.isSchemaError(s)` | `[s]` |
| `Cron.CronParseError` | `Cron.isCronParseError(s)` | `[s]` |
| `PlatformError.PlatformError` | `PlatformError.isPlatformError(s)` | `[s]` |
| `SemVer.SemVerError` | `SemVer.isSemVerError(s)` | `[s]` |
| `Terminal.QuitError` | `Terminal.isQuitError(s)` | `[s]` |
| `TextDiff.TextDiffError` | `TextDiff.isTextDiffError(s)` | `[s]` |

These guards recognize Effect’s brands across installed copies and reject an unbranded object with only the same `_tag`. Every other constructor, including `Config.ConfigError` (no guard), `PlatformError.BadArgument` and `PlatformError.SystemError`, uses ordinary TC39 matching. A VIP-32 Effect version bump updates this inventory.
