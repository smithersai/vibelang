# The VibeLang specification

This specification defines VibeLang as the accepted VibeLang Improvement Proposals (VIPs) and their public amendments define it, and nothing more. Each VIP lives in [`docs/design/vips/`](/vips/), with the reasons for the decision and its history. Where this text and an accepted VIP or its public amendment disagree, the VIP wins and this text is the bug. Authorized clarifications are recorded in public amendments to the relevant VIP and its affected chapter, with the applicable pinned references and explicit reconciliation notes. Where a VIP is silent, its TypeScript or pinned TC39 counterpart applies.

The previous specification and its decision log (`D1` to `D558`) are in `docs/design/history/`. They are historical and not normative: nothing in them is part of the language unless a VIP adds it.

## Principles

VibeLang is TypeScript with a small set of constructs for writing Effect programs. Four principles decide every rule.

1. **Syntax decides.** A keyword on a function, a block or an expression decides what it means. A function literal never becomes an Effect because a parameter expects one, and a type never decides whether a loop consumes a Stream (VIP-1, VIP-2, VIP-20). Class patterns follow their separate [dispatch rules](/spec/004-match#class-patterns), including static call and construct signatures (decided detail 94).
2. **Exact sugar for Effect.** Every construct means one specific piece of Effect TypeScript, shown beside it in this specification. Compiled code gives the same `Exit` as that Effect TypeScript, with finalizers in the same order (VIP-31). Failures, defects, interruption and `Cause` combination follow Effect. VIP-7 adds exhaustiveness checking and generated error matchers to TC39 matching, and retains compiler fixed checks for Effect's `Option`, `Exit`, `Result` and tagged errors until Effect ships custom matchers; none patches Effect at runtime. The retained tagged-error checks use resolved constructor bindings (aliases included, shadowing excluded) and each module's own guard (including subpath errors: `HttpClientError.HttpClientError` uses `HttpClientError.isHttpClientError`; decided detail 92), not `instanceof` or a bare `_tag` test, as listed in [Retained fixed patterns](/spec/004-match#retained-fixed-patterns).
3. **No ambiguity.** Every new keyword has exactly one reading. The new keywords are contextual, except `fork` and `join`, which are reserved words in effect code exactly as `await` is in an `async` function ([the grammar's Effect parameter](/spec/900-appendices#the-effect-parameter); VIP-17, amended). The expression forms of `try` and `catch` reuse words already reserved by JavaScript. "A little bit of ambiguity is unacceptable" (VIP-8). A proposal that can't meet that bar is denied (VIP-8, VIP-10, VIP-11, VIP-24).
4. **TypeScript's meaning outside Effect code.** Plain functions, `async` functions, `await`, `throw`, `using`, classes, `do` expressions and the pipe operator keep their TypeScript or pinned TC39 meaning. The [contextual-keyword rules](/spec/900-appendices#contextual-keywords) apply throughout `.vibe`, including plain code; a TypeScript statement beginning with one of those identifiers can therefore parse differently. The additional static checks still apply: [throw tracking and `@throws`](/spec/003-failures#thrown-types) apply only to non-effectful functions; functions returning an `Effect`, `Stream` or `Layer` cannot throw JavaScript exceptions; `throw` in an `effect` body means typed failure through `Effect.fail` (VIP-4, amended). [Legacy JavaScript restrictions](/spec/001-functions#direct-eval) also apply throughout `.vibe`, including plain functions (VIP-1, VIP-4, amended). [Platform restrictions](/spec/005-services#the-platform-standard-library) apply throughout `.vibe`, including plain functions and wrapper arrows (VIP-33).

## The language at a glance

| Construct | Means exactly | VIP | Chapter |
| --- | --- | --- | --- |
| `effect function f() { }`, `effect function (x) { }` (an expression), `effect () => …`, `effect m() { }` (a method) | a function returning `Effect.gen(function* () { … })` | 1 | [Functions](/spec/001-functions) |
| `A!E!R` | `Effect.Effect<A, E, R>` | 3 | [Functions](/spec/001-functions) |
| `try e` (unary, with the precedence of `await`) | `yield* e` | 5 | [Running Effects](/spec/002-running) |
| `e catch (err) => y`, `e catch effect (err) => …` | `yield* Effect.catch(e, …)` | 5 | [Running Effects](/spec/002-running) |
| `effect { … }` | `Effect.gen(function* () { … })` | 2 | [Running Effects](/spec/002-running) |
| `fork e`, `fork.in(s) e`, `fork.scoped e`, `fork.detached e`, `join f` | `Effect.forkChild`, `forkIn`, `forkScoped`, `forkDetach`, `Fiber.join` | 17 | [Running Effects](/spec/002-running) |
| `try.all [ … ]`, `try.race`, `try.any`, `try.allSettled` | `Effect.all(…, { concurrency: "unbounded" })`, `raceAllFirst`, `raceAll`, … | 18 | [Running Effects](/spec/002-running) |
| `for concurrent (const x of xs) { }` | `Effect.forEach(xs, …, { concurrency, discard: true })` | 19 | [Running Effects](/spec/002-running) |
| `for try (const x of stream) { }` | `Stream.runForEachWhile` | 20 | [Running Effects](/spec/002-running) |
| `effect function* p() { yield x }` | `Stream.callback` | 21 | [Running Effects](/spec/002-running) |
| `uninterruptible { restore { } }`, `interruptible { }` | `Effect.uninterruptibleMask`, `Effect.interruptible` | 22 | [Running Effects](/spec/002-running) |
| `throw e` in an `effect` function | `return yield* Effect.fail(e)` | 4 | [Failures](/spec/003-failures) |
| `error E { fields }` | `class E extends Data.TaggedError("E")<…> {}` | 13 | [Failures](/spec/003-failures) |
| `schema error E { fields }` | `class E extends Schema.TaggedError<E>()("E", { … }) {}` | 29 | [Failures](/spec/003-failures) |
| `match (x) { when P: …; }` | TC39 pattern matching, plus an exhaustiveness check, generated error matchers and fixed Effect pattern checks | 7 | [Pattern matching](/spec/004-match) |
| `service S { members }` | `class S extends Context.Service<S, { … }>()("key") {}` | 9 | [Services](/spec/005-services) |
| `provide L, K = v { … }` | `yield* Effect.provide(Effect.gen(…), [L, Layer.succeed(K, v)])` | 12 | [Services](/spec/005-services) |
| `retry`, `sleep`, `Schema`, `Layer`, … | Effect's exports and modules, in scope without an import | 6, 14, 33 | [Services](/spec/005-services) |
| `schema S { fields }` | `const S = Schema.Struct({ … }); type S = typeof S.Type` | 15 | [Data](/spec/006-data) |
| `data D { V; W { f: T } }` | `Data.TaggedEnum` and `Data.taggedEnum` | 16, 28 | [Data](/spec/006-data) |

The table abbreviates the full translations: preserve [source function bindings](/spec/001-functions#meaning), dispatch [outward jumps](/spec/002-running#region-bodies) after `provide` and interruption blocks, and add the [custom matcher](/spec/004-match#class-patterns) to error classes. All Effect TypeScript meanings use the [pinned `effect` 4.1.0](/spec/007-tooling#the-effect-version).

Classes without an own `Symbol.customMatcher` use `instanceof`, built-ins use `Array.isArray` or `instanceof`, and primitives test `typeof` too, because compiled JavaScript can't read the pinned draft's engine slots. [Class patterns](/spec/004-match#class-patterns) gives the full rule.

What VibeLang leaves out is just as deliberate. The [appendix](/spec/900-appendices#denied-vips) lists the denied VIPs: no Effect meaning for `using`, no `Users.find(id)` shorthand, no trailing blocks, no `wire`, no inline modules. The open VIPs (handlers, the declaration manifest, Effectify the universe) are not part of the language.

## How to read this specification

Constructs generally have four parts; the type shorthand keeps its static rule under **Meaning**:

- **Syntax**, as links to the productions of [Appendix A](/spec/900-appendices#appendix-a-grammar), the only place the grammar is written, with prose and examples.
- **Static rules**, with the diagnostic each rule reports and its code in [Appendix B](/spec/900-appendices#appendix-b-diagnostics). VIP-34 requires every diagnostic to have a code; each imported Effect language-service rule prints a stable `EK38xx` code (decided detail 77).
- **Meaning**, as the exact Effect TypeScript the construct equals, beside the VibeLang.
- **Examples.**

A detail that no accepted VIP, public amendment, or TypeScript or pinned TC39 counterpart decides is marked **Undecided (pending VIP)**. Such details are not part of the language until decided.

### Examples are pending

The compiler is being changed to match the VIPs. Until it does, every VibeLang example here starts with a `// compiler-gap: pending VIP-N` line, which the snippet checker (`docs/tools/check-snippets.ts`) reports as a known gap rather than a failure. An Effect TypeScript comparison that needs undeclared helpers is marked `// fragment`, for example when it calls `fetchUser` without declaring it. Complete comparisons omit that marker and can be checked as self-contained programs. [Appendix D](/spec/900-appendices#appendix-d-flipping-pending-examples) says how to flip an example once its VIP is implemented.
