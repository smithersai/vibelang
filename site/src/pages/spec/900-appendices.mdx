# Appendices

## Appendix A. Grammar

VibeLang's grammar is TypeScript's, with the TC39 proposals for do expressions, pattern matching and the Hack pipe operator, each pinned to a dated snapshot, plus the productions below. Names not defined here (`Block`, `Params`, `Type`, `Expression`, …) are TypeScript's. `"x"` is a token; `X?` is optional; `X*` repeats.

### Contextual keywords

Every VibeLang keyword is contextual: it is a keyword only in the positions below, and an ordinary identifier everywhere else. Each one and the token after it are on one line.

| Word | Keyword when followed by | Chapter |
| --- | --- | --- |
| `effect` | `function`, a name and `(`, `(` of an arrow's parameters, `{`, `*` (methods) | [Functions](/spec/001-functions) |
| `async` | a name and `(`, in the declaration shorthand (otherwise TypeScript's) | [Functions](/spec/001-functions) |
| `fork` | an expression, or `.in(…)`, `.scoped`, `.detached` | [Running Effects](/spec/002-running#fork-and-join) |
| `join` | an expression | [Running Effects](/spec/002-running#fork-and-join) |
| `concurrent` | after `for`, then `(` | [Running Effects](/spec/002-running#for-concurrent) |
| `uninterruptible`, `interruptible`, `restore` | `{` | [Running Effects](/spec/002-running#interruption-blocks) |
| `provide` | a provider list, then `{` | [Services](/spec/005-services#provide-blocks) |
| `service` | a name, then `{` | [Services](/spec/005-services#service-declarations) |
| `error` | a name | [Failures](/spec/003-failures#error-declarations) |
| `schema` | a name, or `error` and a name | [Data](/spec/006-data#schema-declarations) |
| `data` | a name | [Data](/spec/006-data#data-declarations) |
| `match`, `when`, `is`, `and`, `or`, `not` | as TC39's pattern-matching proposal says | [Pattern matching](/spec/004-match) |

`try` and `catch` are reserved words already; VibeLang gives them new expression forms in effect code.

### Productions

```text
EffectFunction    = "effect" "function" Name Params ReturnType? Block
                  | "effect" Name Params ReturnType? Block
EffectArrow       = "effect" ArrowParams ReturnType? "=>" ConciseBody
EffectMethod      = "effect" PropertyName Params ReturnType? Block
AsyncShorthand    = "async" Name Params ReturnType? Block
Producer          = "effect" "function" "*" Name Params ReturnType? Block
ProducerMethod    = "effect" "*" PropertyName Params ReturnType? Block

EffectType        = Type "!" Type "!" Type | Type "!" Type | Type "!" "!" Type | Type "!" "!"

TryExpression     = "try" UnaryExpression
CatchExpression   = (CatchExpression | Operand) "catch" (EffectArrow | "effect" Block | ArrowFunction | Expression)
EffectBlock       = "effect" Block
ForkExpression    = "fork" Expression
                  | "fork" "." "in" "(" Expression ")" Expression
                  | "fork" "." "scoped" Expression
                  | "fork" "." "detached" Expression
JoinExpression    = "join" Expression
TryAll            = "try" "." ("all" | "race" | "any" | "allSettled") Expression

ForConcurrent     = "for" "concurrent" ("(" Expression ")")? "(" ForBinding "of" Expression ")" Statement
ForTry            = "for" "try" "(" ForBinding "of" Expression ")" Statement
Uninterruptible   = "uninterruptible" Block
Restore           = "restore" Block
Interruptible     = "interruptible" Block
ProvideStatement  = "provide" Provider ("," Provider)* Block
Provider          = Expression | Expression "=" Expression

ServiceDecl       = "export"? "service" Name "{" ServiceMember* "}"
ErrorDecl         = "export"? "error" Name ("{" ClassMember* "}")?
SchemaErrorDecl   = "export"? "schema" "error" Name "{" ClassMember* "}"
SchemaDecl        = "export"? "schema" Name ("{" SchemaFields "}" | "=" Type)
DataDecl          = "export"? "data" Name TypeParameters? "{" Variant (";" Variant)* ";"? "}"
Variant           = Name ("{" Fields "}")?
```

`catch` has the precedence of `??` and is left-associative (VIP-5).

**Undecided (pending VIP):** the precedence of `try`, `fork` and `join` among TypeScript's operators, and of `!` among type operators. The productions above place `try` with `await`; no VIP states it.

## Appendix B. Diagnostics

Every diagnostic has an `EK` code and a message that says how to fix it (VIP-34). The VIPs assign these codes:

| Code | Rule | VIP |
| --- | --- | --- |
| EK3001 | two services with the same key | 9 |
| EK3002 | a class extends a service | 9 |
| EK3003 | `new` on a service | 9 |
| EK3004 | `instanceof` a service | 9 |
| EK3005 | a generic service | 9 |

**Undecided (pending VIP):** the codes of every other rule in this specification, each marked "code pending" where it is defined:

| Rule | Chapter |
| --- | --- |
| `try` outside effect code; `try` on a value that is not an Effect; `try x catch y`; a `try` statement in effect code | [Running Effects](/spec/002-running#try) |
| `await` in effect code; `await` on an Effect in an `async` function; `try` at the top level | [Functions](/spec/001-functions#static-rules) |
| `catch` outside effect code; `catch` mixed with `??`, `\|\|` or `&&` without parentheses | [Running Effects](/spec/002-running#catch) |
| `fork`, `join`, `for concurrent`, `for try`, interruption blocks or `provide` outside effect code | [Running Effects](/spec/002-running), [Services](/spec/005-services#provide-blocks) |
| a `try.all` operand that is not an array of Effects | [Running Effects](/spec/002-running#running-effects-concurrently) |
| `break` or `return` in `for concurrent`; `return` in `for try` | [Running Effects](/spec/002-running) |
| `return value` in a producer; `restore` outside `uninterruptible` | [Running Effects](/spec/002-running) |
| an unwrapped call that may throw, or an unwrapped Promise, in effect code | [Failures](/spec/003-failures#calls-that-may-throw) |
| a constructor, `_tag` or `extends` in an `error` or `schema error` declaration | [Failures](/spec/003-failures#error-declarations) |
| a `match` that is not exhaustive | [Pattern matching](/spec/004-match#exhaustiveness) |
| a `schema` field type outside the mapping; a `data` declaration with more than 4 type parameters | [Data](/spec/006-data) |
| a `node:*` value import or a Node global in a `.vibe` file | [Services](/spec/005-services#the-platform-standard-library) |

The compiler's current registry (`typescript/tsc/internal/vibelang/diagnostics.go`) still carries the old language's codes, documented in `docs/design/history/src/428-part4-ch28-tooling.md`. It is not normative.

## Appendix C. Denied and open VIPs

### Denied VIPs

A denied VIP is not part of the language. Each records what was proposed and why it was denied.

| VIP | Denied | Instead |
| --- | --- | --- |
| [8](/vips/0008-using-denied) | special syntax for Effect resources (`using` with Effect meaning, a `scoped` keyword) | `using` is TypeScript's; Effect resources use `scoped(effect { … })` |
| [10](/vips/0010-service-call-shorthand-denied) | the `Users.find(id)` shorthand | `try (try Users).find(id)` |
| [11](/vips/0011-trailing-blocks-denied) | trailing blocks, `f(x) { … }` | `f(x, () => { … })` or `f(x, effect { … })` |
| [24](/vips/0024-wire-denied) | `wire`, automatic layer composition | Effect's `Layer.provide` and `Layer.provideMerge` |
| [25](/vips/0025-inline-modules-denied) | inline `module` declarations as a TypeScript escape | a `.ts` file |

### Open VIPs

Listed for a future decision; not part of the language.

| VIP | Title |
| --- | --- |
| [35](/vips/0035-handlers-open) | Effect handlers (`control`, `handle`, `resume`, `abandon`) |

## Appendix D. Flipping pending examples

Every VibeLang example in this specification starts with `// compiler-gap: pending VIP-N`, and every Effect TypeScript example with `// fragment`. The snippet checker reports a `compiler-gap` block as a known gap, not a failure.

To check the specification's examples:

```sh
bun docs/tools/check-snippets.ts --root docs/design/src
```

When the compiler implements VIP-N:

1. Run the command above. A block whose marker is stale fails with "Stale compiler-gap marker; remove it": the compiler now accepts it.
2. Delete that block's `// compiler-gap: pending VIP-N` line. If the block only names functions it doesn't declare (`fetchUser`), declare them in the block or a page fixture, or mark it `// fragment`.
3. When a page has no `compiler-gap` markers left, add `docs/design/src` to the snippet step of the merge queue's gate (`//:snippets`), so the examples stay checked.
4. To make an Effect TypeScript example checked, replace `// fragment` with the declarations it needs; the checker compiles ```` ```ts effect ```` blocks as comparisons.
