# Running Effects

Sources: [VIP-5](/vips/0005-try-runs-effects), [VIP-2](/vips/0002-effect-blocks-and-do), [VIP-17](/vips/0017-fork), [VIP-18](/vips/0018-concurrent), [VIP-19](/vips/0019-for-concurrent), [VIP-20](/vips/0020-for-try), [VIP-21](/vips/0021-producers), [VIP-22](/vips/0022-interruption-blocks), [VIP-23](/vips/0023-pipe).

A call never runs anything. Calling an `effect` function, or any function that returns an Effect, gives the Effect unrun. An Effect runs only where one of these constructs runs it, in effect code (an `effect` function, a producer or an `effect` block):

| Construct | Runs |
| --- | --- |
| `try e` | one Effect, giving its success |
| `e catch (err) => y` | one Effect, handling its failure |
| `fork e` and its forms | one Effect, in a new fiber |
| `try.all`, `try.race`, `try.any`, `try.allSettled` | several Effects at once |
| `for concurrent` | one Effect per item, at once |
| `for try` | one Effect per Stream element, in order |
| `provide`, `uninterruptible`, `interruptible` | a block of statements ([Services](/spec/005-services#provide-blocks) for `provide`) |

"Effect code" means the body of an `effect` function, a producer or an `effect` block, not counting nested functions, class field initializers or `static` blocks, as `await` is not allowed there in an `async` function. A computed class key and an `extends` clause are effect code, as `await` is allowed there: in `effect function f() { class C { [try key()]() { } } }`, `try key()` runs. It is the code Appendix A parses with [the grammar's Effect parameter](/spec/900-appendices#the-effect-parameter), minus parameter lists, class field initializers and `static` blocks. Parentheses, `do` and `match` are not boundaries; an `async match` is one, as a nested `async` function is ([Pattern matching](/spec/004-match)), so `try` inside it is an error. Outside effect code a parser still parses these constructs, as TypeScript parses `await x` outside an `async` function, and reports the construct's "outside effect code" error; tokens that are also valid TypeScript, such as `fork(x)` or `join(x)`, keep their TypeScript meaning.

Every operand is evaluated once, left to right as written, with three exceptions: a `catch` handler is evaluated only on failure; the body of an `effect` block or function is evaluated on each run; and `fork.in(scope) e` evaluates `e` before `scope`, as VIP-17's `Effect.forkIn(e, scope)` does. Where Effect's argument order differs from the source order elsewhere (`for concurrent(n) (… of xs)`), the Effect TypeScript evaluates the operands into temporaries first, in source order: `const $n = n, $xs = xs` before `Effect.forEach($xs, …, { concurrency: $n })`.

## `try`

### Syntax

[TryExpression](/spec/900-appendices#tryexpression).

### Static rules

| Rule | Diagnostic |
| --- | --- |
| `try` outside effect code | `EK0501` |
| `try e` where `e` is not an Effect. A call that may throw, and a Promise, must first be wrapped with `Effect.try`, `tryPromise` or `promise` | `EK0502` |
| a `try` statement (`try { } catch { }`, `try { } finally { }`) anywhere in effect code. Handle failures with `catch` or `match`, and clean up with `ensuring` or `onExit`: `try ensuring(write(x), close())` | `EK0503` |

`e` is an Effect when its type is assignable to `Effect.Effect<any, any, any>`. In Effect 4.1.0 a `Context.Service` key, a `Context.Reference` and an `error` instance (`Data.TaggedError` or `Schema.TaggedError`) are, so `try new NotFound({ id })` fails like `throw`; `Option` and `Result` are not. An Effect that can't fail is still run with `try`. `never` passes this test, as the success of an Effect that only fails; it is the operand test, not [Failures](/spec/003-failures)' test of which callables are effectful.

`try` works like `await`: it is a unary operator with `await`'s precedence, so `try a.b()` runs `a.b()` and `try f() + 1` adds 1 to the success. As with `await`, the operand may start on the next line. At the start of a statement, `try` followed by `{`, on the same line or not, begins a `try` statement, as in JavaScript, and that is an error in effect code.

### Meaning

`try e` is `yield* e`. It runs `e` and gives its success value. A failure propagates to the enclosing Effect, as Zig's `try x` means `x catch |err| return err`.

```vibe [VibeLang]
// compiler-gap: pending VIP-5
effect function load(id: string) {
  const u = try fetchUser(id)
  try sleep("1 second")
  return u
}
```

```ts [Effect]
// fragment
function load(id: string) {
  return Effect.gen(function* () {
    const u = yield* fetchUser(id)
    yield* Effect.sleep("1 second")
    return u
  })
}
```

## `catch`

### Syntax

[CatchExpression](/spec/900-appendices#catchexpression) with a [CatchHandler](/spec/900-appendices#catchhandler). `catch` sits beside `??` in ECMAScript's precedence chain: it has the precedence of `??` and is left-associative, so `a catch (() => b) catch (() => c)` parses as `(a catch (() => b)) catch (() => c)`, which type-checks only when the inner `catch` gives an Effect (below), and `x = a catch () => b` assigns the result. As with `??`, mixing it with `??`, `||` or `&&` needs parentheses; without them it is a syntax error.

The handler is always a function literal, and its syntax alone decides its kind (VIP-5, amended 2026-10-29). Either kind may be parenthesized:

| Handler | Kind | On `fail("bad")` gives |
| --- | --- | --- |
| an `effect` arrow or `effect function` expression | effect function | what the function's Effect succeeds with; a `throw` in it fails again, typed |
| an arrow, `async` arrow, `function`, generator, `async function` or `async` generator expression | plain function | what the function returns |

Anything else after `catch` is a syntax error: a name, a call, any other value, an `effect { … }` block or a class expression. Its quick fix wraps it in a function literal, so the handler's kind stays visible in the source:

| Written | Kind | On `fail("bad")` gives |
| --- | --- | --- |
| `x catch (e) => 7`, `x catch ((e) => 7)` | plain function | `7` |
| `x catch () => guest` | plain function | `guest` |
| `x catch function (e) { return 7 }` | plain function | `7` |
| `x catch effect (e) => 7`, `x catch (effect function (e) { return 7 })` | effect function | `7` |
| `x catch async (e) => 7` | plain function | a Promise: an error, see Static rules |
| `x catch function* (e) { }` | plain function | the Generator object it returns, unrun, as any plain function's result |
| `x catch guest` | syntax error | quick fix: `x catch () => guest` |
| `x catch onErr` (`onErr` a function) | syntax error | quick fix: `x catch (e) => onErr(e)` |
| `x catch effect { return 7 }` | syntax error | quick fix: `x catch effect () => { return 7 }` |

An arrow handler's body is TypeScript's concise body, which extends as far as an assignment expression does, as in `(e) => a ?? b`: `a catch () => b ? c : d` means `a catch (() => (b ? c : d))`. So `a catch effect (e) => b catch () => c` means `a catch (effect (e) => (b catch (() => c)))`. With a plain arrow, `b catch () => c` is in a plain function, so `a catch (e) => b catch () => c` is the error "`catch` outside effect code". Parenthesizing the arrow, `a catch ((e) => b) catch ((e) => c)`, parses, but the outer `catch` then needs an Effect operand (below).

In `(a catch h) catch k`, the outer `catch` runs the value that `a catch h` gives, so `a`'s success (`never`, if `a` only fails, passes the operand test above) and `h`'s result must both be Effects. To try fallbacks in turn, nest them in an `effect` handler: `a catch effect () => b catch () => c`.

```ts [Effect]
// fragment
const chained = Effect.gen(function* () {
  // (a catch h) catch k, where a's success and h's result are both Effects
  return yield* Effect.catch(yield* Effect.catch(a, (e) => Effect.succeed(h(e))), (e) => Effect.succeed(k(e)))
})
const nested = Effect.gen(function* () {
  // a catch effect () => b catch () => c
  return yield* Effect.catch(a, () => Effect.gen(function* () { return yield* Effect.catch(b, () => Effect.succeed(c)) }))
})
```

After a parenthesized handler or a function expression handler, another `catch` or a lower-precedence operator may follow, but a member access or call can't attach to the handler, so `a catch function () { }.call(o)` is a syntax error. Parenthesize the whole `catch` expression first: `(a catch function () { }).pipe(f)`.

### Static rules

| Rule | Diagnostic |
| --- | --- |
| `catch` outside effect code | `EK0504` |
| `try x catch h`: write `try x` or `x catch h`, never both. It fires when the head's leftmost unparenthesized operand is a `try` or `try.all` expression: `try a + b catch h` is `((try a) + b) catch h`, so `EK0505`. `try.all x catch h` and the other three operations get this error too, not the one below. `(try x) catch h` is allowed: it catches the Effect that `x` succeeds with | `EK0505` |
| `e catch h` where `e` is not an Effect | `EK0506` |
| a handler whose result type is a Promise or thenable, `async` or not (`x catch async (e) => 7`, `x catch (e) => queryDb(e)`): the Promise is never run, as for an unwrapped Promise in effect code ([Failures](/spec/003-failures)) | `EK0507` |

### Meaning

`e catch h` runs `e`. On a failure in its error channel it calls `h` with the error, as Zig's `catch |err|` does. The handler's kind decides whether its result runs Effects, as for any function. `h` is evaluated only on failure:

| Written | Effect TypeScript |
| --- | --- |
| `x catch h`, `h` a plain function: `x catch (e) => f(e)` is `(e) => Effect.succeed(f(e))`, and `x catch () => guest` is `() => Effect.succeed(guest)`. A `throw` inside is a JavaScript exception, so a defect (VIP-5); write `catch effect (e) =>` to fail again, typed | `yield* Effect.catch(x, ($e) => Effect.succeed(h($e)))` |
| `x catch h`, `h` an effect function: it runs its Effects, and `throw` fails again, typed | `yield* Effect.catch(x, ($e) => h($e))`; for an arrow, `(e) => Effect.gen(…)` |
| `(try x) catch (e) => y`, `x` succeeding with an Effect | `yield* Effect.catch(yield* x, (e) => Effect.succeed(y))` |

```vibe [VibeLang]
// compiler-gap: pending VIP-5
effect function load(id: string) {
  const g = fetchUser(id) catch () => guest
  const h = fetchUser(id) catch effect (e) => match (e) {
    when NotFound: guest;
    when DbError: throw e;         // fails again, typed (VIP-4)
  }
  return [g, h]
}
```

```ts [Effect]
// fragment
function load(id: string) {
  return Effect.gen(function* () {
    const g = yield* Effect.catch(fetchUser(id), () => Effect.succeed(guest))
    const h = yield* Effect.catch(fetchUser(id), (e) => Effect.gen(function* () {
      if (e._tag === "NotFound") return guest              // NotFound's matcher tests _tag
      if (e._tag === "DbError") return yield* Effect.fail(e)
      throw new TypeError()                                // no arm matched (pinned snapshot): a defect
    }))
    return [g, h]
  })
}
```

A handler's parameter may have a type annotation, checked as for a TypeScript arrow parameter: the error type must be assignable to it, so `x catch (e: NotFound) => guest` is an error when `x` can also fail with `DbError` (VIP-5, amended).

A plain handler whose result type is an Effect gets a VIP-38 lint warning (`EK0508`), with the quick fix `catch effect (e) => try …`:

```vibe [VibeLang]
// compiler-gap: pending VIP-38
// fragment: inside an effect function
fetchUser(id) catch (e) => fetchUser("guest")              // warning: the fallback is an unrun Effect
fetchUser(id) catch effect (e) => try fetchUser("guest")   // the fix: Effect.catch(fetchUser(id), () => fetchUser("guest"))
```

## `await`

`await` keeps exactly JavaScript's meaning and belongs to `async` functions and the module top level. `await`, `for await` and `await using` inside effect code are errors, and so is `await` on an Effect inside an `async` function ([Functions](/spec/001-functions#static-rules)). `await fiber` and `await deferred` keep TypeScript's behavior and get a VIP-38 lint warning suggesting `join fiber` (`EK4609`) or `try Deferred.await(deferred)` (`EK4610`) (VIP-5, amended).

## `effect` blocks

### Syntax

[EffectBlock](/spec/900-appendices#effectblock), an expression.

### Meaning

`effect { … }` is an expression. It builds an Effect from the block without running it. Each time the Effect runs, the block runs again. It is `Effect.gen(function* () { … })`, and the same as `(effect () => { … })()`. Inside it, `try` runs Effects. Its `this`, `super` and `new.target` are the enclosing function's, passed in as for an `effect` arrow ([Functions](/spec/001-functions#meaning)).

```vibe [VibeLang]
// compiler-gap: pending VIP-2
effect function demo() {
  const p = effect { try Console.log("hi"); return 1 }   // an Effect, not yet run
  try p                                              // prints "hi", gives 1
  try p                                              // prints "hi" again
  return try retry(effect { try save(try fetchUser("1")) }, policy)
}
const UsersLive = Layer.effect(Users, effect { return makeUsers() })
```

```ts [Effect]
// fragment
function demo() {
  return Effect.gen(function* () {
    const p = Effect.gen(function* () { yield* Console.log("hi"); return 1 })
    yield* p
    yield* p
    return yield* Effect.retry(Effect.gen(function* () { yield* save(yield* fetchUser("1")) }), policy)
  })
}
const UsersLive = Layer.effect(Users, Effect.gen(function* () { return makeUsers() }))
```

An `effect { … }` statement builds an Effect and discards it, as a call statement `f()` does; the Effect language service's floating-Effect rule, run by VIP-38, reports it. Its code, an `EK` code or the language service's own rule name, is Undecided (pending VIP). Write `try effect { … }` to run it.

No other syntax builds an Effect. A function literal never becomes an Effect because the parameter it's passed to expects one.

## `do` expressions

`do { … }` is exactly TC39's do expression, pinned to a dated snapshot of the proposal, everywhere, with no exceptions. It runs now and gives its last statement's value. It is not a function: as TC39 specifies, `await` inside `do` belongs to the enclosing function, and so does `try`. Neither `do` nor `match` is lowered to a function, so a `try` inside one stays a `yield*` of the enclosing generator. **Expression lowering.** This paragraph is the one rule for every `do` or `match` inside a larger expression; [Pattern matching](/spec/004-match) and [Runtime guarantees](/spec/008-runtime) refer to it. Everything evaluated before the `do` or `match` goes into temporaries in source order, the callee and a method's receiver included; the `do` or `match` runs as statements that assign its value to a temporary; and the expression continues. `f(try a(), match (x) { … })` is `const $f = f, $t1 = yield* a(); let $t2; if (…) $t2 = …; $f($t1, $t2)`, and `o.m(…)` reads `o.m` before the arguments and calls it with `Reflect.apply`, keeping `this` as `o`. A `do` or `match` on one side of `&&`, `||`, `??`, `?:`, `&&=`, `||=`, `??=` or after `?.` (call, member or element) runs only when JavaScript would evaluate that side: its statements go inside the matching `if`. `eval` needs no lowering: it is a compile error anywhere in a `.vibe` file ([Legacy JavaScript](/spec/001-functions#direct-eval)).

```vibe [VibeLang]
// compiler-gap: pending VIP-2
const x = do { const a = 1; a + 1 }    // 2
effect function total(o: Calc) {
  return o.add(try a(), match (n()) { when 1: 10; default: 0; })
}
```

```ts [Effect]
// fragment
function total(o: Calc) {
  return Effect.gen(function* () {
    const $r = o, $f = $r.add, $t1 = yield* a()      // receiver, callee, then the first argument
    const $s = n()
    let $t2
    if ($s === 1) $t2 = 10
    else $t2 = 0
    return Reflect.apply($f, $r, [$t1, $t2])          // this is o
  })
}
```

The pinned snapshot is the vendored copy of `tc39/proposal-do-expressions` at commit `3ef6d463b8163cbf222846b40d17178cca36e9e1`, the head on 2026-10-28 (UTC), as pattern matching is pinned.

## `fork` and `join`

### Syntax

[ForkExpression](/spec/900-appendices#forkexpression) and [JoinExpression](/spec/900-appendices#joinexpression). In effect code, `fork` and `join` are reserved words, exactly as `await` is in an `async` function ([the grammar's Effect parameter](/spec/900-appendices#the-effect-parameter); VIP-17, amended): they can't name a variable, parameter or label there, and where an expression can start they begin a `fork` or `join` expression. As property names they stay names, as `await` does. Outside effect code they are ordinary identifiers. The owner forms `fork.in(…)`, `fork.scoped` and `fork.detached` are productions in JavaScript's `keyword.name` shape, like `new.target` and `import.meta`, not property reads. Their tokens may be separated as `new . target`'s may ([TryAll](/spec/900-appendices#tryall)). As with `await`, the operand may start on the next line. A [ForkOperand](/spec/900-appendices#forkoperand) never contains a top-level comma, so `const f = fork a(), g = fork b()` declares two fibers.

```vibe [VibeLang]
// compiler-gap: pending VIP-17
const sep = (xs: string[]) => xs.join("/")      // outside effect code: a method named join
effect function names(parts: Fiber.Fiber<string[]>) {
  const xs = join(parts)             // joins the fiber parts
  const s = xs.join(",")             // the method join
  const t = sep(xs)
  return [s, t]
}
effect function bad(join: number) { }  // syntax error: join is reserved here, as await is in async code
```

A line break after `fork` or `join` changes nothing, as after `await`: `join` then `f` on the next line joins `f`. After `join`, `/` begins a regular expression and `- 1` is a negation, as after `await` (VIP-17, amended).

### Static rules

| Rule | Diagnostic |
| --- | --- |
| `fork` or `join` outside effect code | `EK1701` |

### Meaning

`fork` starts a fiber and gives its `Fiber`. The form names the owner, which interrupts the fiber when it ends. A child is not awaited at the end of a scope, as Swift's and Kotlin's structured children are; it keeps Effect's meaning. A `fork` child whose parent ends first exits with an interruption; a `fork.detached` child runs to its own end.

| VibeLang | Effect TypeScript | Owner |
| --- | --- | --- |
| `fork worker()` | `yield* Effect.forkChild(worker())` | the current fiber |
| `fork.in(scope) worker()` | `yield* Effect.forkIn(worker(), scope)` | the given scope; `worker()` is evaluated before `scope` |
| `fork.scoped worker()` | `yield* Effect.forkScoped(worker())` | the current `Scope`; adds `Scope` to R |
| `fork.detached worker()` | `yield* Effect.forkDetach(worker())` | none |
| `join f` | `yield* Fiber.join(f)` | |

```vibe [VibeLang]
// compiler-gap: pending VIP-17
effect function both() {
  const f = fork worker()
  const mine = try other()
  return [mine, join f]
}
effect function owners(scope: Scope.Scope) {
  const a = fork.in(scope) worker()
  const b = fork.scoped worker()
  const c = fork.detached worker()
  return [a, b, c]
}
```

```ts [Effect]
// fragment
function both() {
  return Effect.gen(function* () {
    const f = yield* Effect.forkChild(worker())
    const mine = yield* other()
    return [mine, yield* Fiber.join(f)]
  })
}
function owners(scope: Scope.Scope) {
  return Effect.gen(function* () {
    const a = yield* Effect.forkIn(worker(), scope)
    const b = yield* Effect.forkScoped(worker())
    const c = yield* Effect.forkDetach(worker())
    return [a, b, c]
  })
}
```

`fork` and `join` have `await`'s precedence: [ForkOperand](/spec/900-appendices#forkoperand) is a `UnaryExpression`, as for `try` (VIP-17, amended: "exactly as `await`"). So `fork a() |> f(%)` forks `a()` and pipes the `Fiber`, and `join f + 1` adds 1 to the joined value.

## Running Effects concurrently

### Syntax

[TryAll](/spec/900-appendices#tryall). `try` is a reserved word, so `try.` can't start anything else. Its tokens may be separated as `new . target`'s may. The operand has `try`'s precedence, so `try.all [a(), b()]` and `try.all ids.map(load)` each have one reading. The operand is any expression whose type is an array, readonly array or tuple of Effects, not only an array literal (VIP-18, amended).

### Static rules

| Rule | Diagnostic |
| --- | --- |
| an operand that is not an array of Effects; an object of Effects uses the `all` global instead | `EK1801` |

### Meaning

These are TC39's await operations, run with `try` instead of `await`. The names keep JavaScript's choice of result: `try.all` runs everything at once, like `Promise.all`, even though `Effect.all` defaults to one at a time. Unlike Promises, the Effects that lose are interrupted, and an empty operand to `try.race` or `try.any` never completes, where `Promise.any([])` rejects.

| VibeLang | Effect TypeScript | Gives |
| --- | --- | --- |
| `try.all [a(), b()]` | `yield* Effect.all([a(), b()], { concurrency: "unbounded" })` | every success, in operand order; the first failure fails the whole and interrupts the rest |
| `try.race [a(), b()]` | `yield* Effect.raceAllFirst([a(), b()])` | the first to finish, success or failure; the losers are interrupted |
| `try.any [a(), b()]` | `yield* Effect.raceAll([a(), b()])` | the first to succeed; the losers are interrupted. If every operand fails, the whole fails with all their failures in its `Cause`, in the order they occurred, and `catch` receives the first to occur, not the first operand's |
| `try.allSettled [a(), b()]` | `yield* Effect.all([a(), b()].map(Effect.exit), { concurrency: "unbounded" })` | every element's `Exit` (success, failure, defect or interruption); the whole never fails, as `Promise.allSettled` never rejects; it can still be interrupted from outside |

```vibe [VibeLang]
// compiler-gap: pending VIP-18
effect function page(id: string) {
  const [u, o] = try.all [fetchUser(id), fetchOrders(id)]
  const both = try all({ u: fetchUser(id), o: fetchOrders(id) }, { concurrency: "unbounded" })   // an object: the all global
  const first = try.race [fetchUser(id), fetchUser("cache")]
  const ok = try.any [fetchUser(id), fetchUser("cache")]
  const exits = try.allSettled [fetchUser(id), fetchUser("cache")]
  return [u, o, both, first, ok, exits]
}
```

```ts [Effect]
// fragment
function page(id: string) {
  return Effect.gen(function* () {
    const [u, o] = yield* Effect.all([fetchUser(id), fetchOrders(id)], { concurrency: "unbounded" })
    const both = yield* Effect.all({ u: fetchUser(id), o: fetchOrders(id) }, { concurrency: "unbounded" })
    const first = yield* Effect.raceAllFirst([fetchUser(id), fetchUser("cache")])
    const ok = yield* Effect.raceAll([fetchUser(id), fetchUser("cache")])
    const exits = yield* Effect.all([fetchUser(id), fetchUser("cache")].map(Effect.exit), { concurrency: "unbounded" })
    return [u, o, both, first, ok, exits]
  })
}
```

## `for concurrent`

### Syntax

[ForConcurrent](/spec/900-appendices#forconcurrent). JavaScript's `for` can only be followed by `(` or `await`, so `for concurrent` has one reading, and Appendix A says when the first parenthesized group is the limit: `for concurrent (const x of xs) (try f(x));` has no limit.

### Static rules

| Rule | Diagnostic |
| --- | --- |
| `for concurrent` outside effect code | `EK1902` |
| `break` that would leave the body | `EK1903` |
| `return` in the body | `EK1904` |
| a labeled `continue` naming a statement that encloses the `for concurrent` | `EK1905` |
| an operand that is not an `Iterable`; a Stream uses `for try` | `EK1901` |

`continue`, and a labeled `continue` naming the `for concurrent` itself, end that one item: each is `return` from the item's generator, as the example shows. The others are errors because no loop runs on the body's fiber (VIP-19). A loop or `switch` nested in the body keeps its own `break` and `continue`.

### Meaning

Every item runs in its own fiber, all at once, or at most `n` at a time with `for concurrent(n)`. `n` is any Effect `Concurrency`, which in Effect 4.1.0 is a number or `"unbounded"`, passed straight to `concurrency` (VIP-19, amended). All items join before the loop ends, and one failure interrupts the rest. Results are discarded; `try.all ids.map(…)` keeps them.

```vibe [VibeLang]
// compiler-gap: pending VIP-19
effect function syncAll(ids: string[]) {
  for concurrent (const id of ids) { if (id === "") continue; try syncOne(id) }
  for concurrent(limit()) (const id of ids) { if (id === "") continue; try syncOne(id) }   // limit() first
  for concurrent("unbounded") (const id of ids) { try syncOne(id) }
}
```

```ts [Effect]
// fragment
function syncAll(ids: string[]) {
  return Effect.gen(function* () {
    yield* Effect.forEach(ids, ($item) => Effect.gen(function* () { const id = $item; { if (id === "") return; yield* syncOne(id) } }), { concurrency: "unbounded", discard: true })
    const $n = limit(), $xs = ids
    yield* Effect.forEach($xs, ($item) => Effect.gen(function* () { const id = $item; { if (id === "") return; yield* syncOne(id) } }), { concurrency: $n, discard: true })
    yield* Effect.forEach(ids, ($item) => Effect.gen(function* () { const id = $item; { yield* syncOne(id) } }), { concurrency: "unbounded", discard: true })
  })
}
```

The head is a `const` or `let` declaration, destructuring included: ECMAScript's `ForDeclaration`, `LetOrConst ForBinding` (VIP-19, amended). `var` and an assignment head, `for concurrent (x of xs)`, are syntax errors. The item arrives under a fresh parameter, and the head's declaration runs first in the item's generator, so a default or computed key in it may run Effects and a failure there fails that item. The body keeps its own block scope:

```vibe [VibeLang]
// compiler-gap: pending VIP-19
effect function saveAll(entries: Array<[string, number]>) {
  for concurrent (let [k, v] of entries) { try save(k, v) }
}
```

```ts [Effect]
// fragment
function saveAll(entries: Array<[string, number]>) {
  return Effect.gen(function* () {
    yield* Effect.forEach(entries, ($item) => Effect.gen(function* () {
      let [k, v] = $item
      { yield* save(k, v) }
    }), { concurrency: "unbounded", discard: true })
  })
}
```

## `for try`

### Syntax

[ForTry](/spec/900-appendices#fortry).

### Static rules

| Rule | Diagnostic |
| --- | --- |
| `for try` outside effect code | `EK2001` |
| `return` in the body | `EK2002` |
| a labeled `break` or `continue` naming a statement that encloses the `for try`: `outer: for (const s of streams) { for try (const x of s) { continue outer } }` | `EK2003` |
| an operand that is not a `Stream`; convert an AsyncIterable with `Stream.fromAsyncIterable` first | `EK2004` |

### Meaning

`for try (const x of stream)` consumes a Stream, pulling one element at a time, in order. It mirrors `for await` over AsyncIterables, which keeps its JavaScript meaning. `continue` skips one element, `break` stops consuming, and a failure in the body fails the loop.

```vibe [VibeLang]
// compiler-gap: pending VIP-20
effect function saveAll(rows: Stream.Stream<Row>) {
  for try (const row of rows) {
    if (row.skip) continue
    if (row.last) break
    try save(row)
  }
}
```

```ts [Effect]
// fragment
function saveAll(rows: Stream.Stream<Row>) {
  return Effect.gen(function* () {
    yield* Stream.runForEachWhile(rows, ($item) => Effect.gen(function* () {
      const row = $item
      {
        if (row.skip) return true
        if (row.last) return false
        yield* save(row)
      }
      return true
    }))
  })
}
```

A `break` or `continue` naming the `for try` itself means the unlabeled one, as in JavaScript and as `for concurrent` rules:

```vibe [VibeLang]
// compiler-gap: pending VIP-20
effect function first(rows: Stream.Stream<number>) {
  scan: for try (const row of rows) {
    if (row === 0) break scan   // return false
    continue scan               // return true
  }
}
```

The head and its lowering are as for `for concurrent` (VIP-20, amended): a `const` or `let` declaration, run first in the element's generator.

```vibe [VibeLang]
// compiler-gap: pending VIP-20
effect function first() {
  let out = 0
  for try (const [n = try succeed(7)] of Stream.make([undefined] as const)) { out = n }   // one element, the tuple [undefined]
  return out                                         // 7; a failing default fails the loop
}
```

```ts [Effect]
// fragment
function first() {
  return Effect.gen(function* () {
    let out = 0
    yield* Stream.runForEachWhile(Stream.make([undefined] as const), ($item) => Effect.gen(function* () {
      const [n = yield* Effect.succeed(7)] = $item
      { out = n }
      return true
    }))
    return out
  })
}
```

## Producers

### Syntax

[Producer](/spec/900-appendices#producer) and [ProducerMethod](/spec/900-appendices#producermethod), with TypeScript's class-member [Modifiers](/spec/900-appendices#modifiers), as for an `async` method. The shorthand `effect *name()` exists only for methods, as `async *gen()` does in TypeScript; at top level it could parse as multiplication. A plain `function*` stays a JavaScript generator.

### Static rules

| Rule | Diagnostic |
| --- | --- |
| `return value` in a producer (a bare `return` is allowed and ends the stream) | `EK2101` |
| a written return type that is not a `Stream.Stream<A, E, R>`, as TypeScript requires an `AsyncGenerator` type for `async function*` | `EK2102` |
| `yield*` in a producer, `effect function* p() { yield* other() }`: no VIP specifies delegation | `EK2103` |

### Meaning

`effect function*` returns a Stream, as `async function*` returns an AsyncIterable. Its body is effect code: `yield x` emits `x`, and `try` and the other constructs run Effects. `yield` belongs to the innermost producer, as in JavaScript, so `yield` in a nested `effect` block, an arrow or an `effect function` handler is a syntax error; in a `function*` or `async function*` handler it is that generator's. A `provide` block, an interruption block, a `for try` body and a `for concurrent` body are not producers: `yield x` there is `yield* Queue.offer(queue, x)` on the enclosing producer's queue, as `yield` in a nested block of an `async function*` yields from that function. In a `for concurrent` body, each item's fiber offers its own elements, so elements arrive in offer order. It compiles to `Stream.callback` with one element of buffer, so the producer may run up to two elements ahead of its consumer: one in the buffer and one waiting to be offered (VIP-21, corrected). Exact pull semantics are not provided. `yield x` evaluates to `undefined`, as in an `async function*` consumed by `for await`: it is `(yield* Queue.offer(queue, x), undefined)`. A failure run by `try` in the body fails the stream. The return type, when written, is `Stream.Stream<A, E, R>`. The generator gets the function's `this`, `super` and `new.target` as an `effect` function's does ([Functions](/spec/001-functions#meaning)), with `Effect.gen({ self: this }, …)` when the body reads `this`.

```vibe [VibeLang]
// compiler-gap: pending VIP-21
effect function* ticks() {
  yield 1
  try sleep("1 second")
  yield 2
}
effect function consume() { for try (const t of ticks()) { try log(t) } }
class Feed {
  effect *items(ids: string[]) {
    for concurrent (const id of ids) { yield try fetchUser(id) }
  }
}
```

```ts [Effect]
// fragment
function ticks() {
  return Stream.callback<number>((queue) => Effect.gen(function* () {
    yield* Queue.offer(queue, 1)
    yield* Effect.sleep("1 second")
    yield* Queue.offer(queue, 2)
  }).pipe(Effect.andThen(Queue.end(queue))), { bufferSize: 1, strategy: "suspend" })
}
function consume() {
  return Effect.gen(function* () {
    yield* Stream.runForEachWhile(ticks(), ($item) => Effect.gen(function* () { const t = $item; { yield* Effect.log(t) }; return true }))
  })
}
class Feed {
  items(ids: string[]) {
    return Stream.callback<User, NotFound>((queue) => Effect.gen(function* () {
      yield* Effect.forEach(ids, ($item) => Effect.gen(function* () {
        const id = $item
        { yield* Queue.offer(queue, yield* fetchUser(id)) }
      }), { concurrency: "unbounded", discard: true })
    }).pipe(Effect.andThen(Queue.end(queue))), { bufferSize: 1, strategy: "suspend" })
  }
}
```


## Interruption blocks

### Syntax

[Uninterruptible](/spec/900-appendices#uninterruptible), [Restore](/spec/900-appendices#restore) and [Interruptible](/spec/900-appendices#interruptible): contextual keywords followed by `{` on the same line, and statements in effect code.

`uninterruptible { }` is always `Effect.uninterruptibleMask(($restore) => Effect.gen(…))`, as VIP-22 writes it, whether or not a `restore` block is inside it. The callback's parameter has a fresh name, as `$c` does, so a user variable `restore` stays visible.

### Static rules

| Rule | Diagnostic |
| --- | --- |
| any of the three outside effect code | `EK2201` |
| `restore { }` outside an `uninterruptible` block; one inside an `interruptible` block nested in it is inside, as `$restore` is in scope there | `EK2111` |
| `restore { }` inside an `effect` arrow or `effect` block nested in the `uninterruptible` block, `uninterruptible { const e = effect { restore { try poll() } }; try e }`: `restore` is lexical, and the nested Effect can run after the mask ends | `EK2202` |

### Meaning

```vibe [VibeLang]
// compiler-gap: pending VIP-22
effect function pay(card: Card, user: User) {
  uninterruptible {
    const receipt = try charge(card)
    restore { try notify(user) }        // the interruptibility from before the mask
    try record(receipt)
  }
  interruptible { try poll() }
}
```

```ts [Effect]
// fragment
function pay(card: Card, user: User) {
  return Effect.gen(function* () {
    yield* Effect.uninterruptibleMask(($restore) => Effect.gen(function* () {
      const receipt = yield* charge(card)
      yield* $restore(Effect.gen(function* () { yield* notify(user) }))
      yield* record(receipt)
    }))
    yield* Effect.interruptible(Effect.gen(function* () { yield* poll() }))
  })
}
```

The keywords remove the globals of the same name ([VIP-6](/vips/0006-effect-globals)), so Effect's functions are written `Effect.uninterruptible` and `Effect.interruptible`.


## Region bodies

A *region body* is source code that the lowering moves into a generated callback: the block of `provide`, `uninterruptible`, `restore` and `interruptible`, and the body of `for try` and `for concurrent`. Its names and jumps mean what they mean in the source, as ECMAScript defines them: `provide` and interruption blocks are ordinary blocks, so `return`, `break` and `continue` inside them reach the enclosing function, loop, `switch` or label, as in any TypeScript block (VIP-12 and VIP-22, amended). This section is the one lowering rule for both; [Services](/spec/005-services#provide-blocks), [Functions](/spec/001-functions#meaning) and [Runtime guarantees](/spec/008-runtime) refer to it.

**Bindings.** Every name is resolved on the source before lowering. `var` is a compile error in `.vibe` ([Legacy JavaScript](/spec/001-functions#direct-eval)), so every declaration in a region body (`let`, `const`, `class`, a function declaration) is scoped to its block, as in strict module code, and stays in it; the callback closes over every outer binding, so an assignment to one is seen outside. `this`, `super` and `new.target` are the source function's, passed in as for an `effect` arrow ([Functions](/spec/001-functions#meaning)).

**Jumps.** In ECMAScript every statement completes with a Completion Record: normal, `return` with a value, or `break` or `continue` with a target label, empty when unlabeled. LabelledEvaluation decides which statement consumes a `break` or `continue`: an unlabeled `break` is consumed by the innermost iteration or `switch` statement, an unlabeled `continue` by the innermost iteration statement, and a labeled one by the statement whose label set holds the label (any statement for `break`, an iteration statement for `continue`). A `return` is consumed by the function. The lowering keeps that resolution:

- A completion consumed inside the region body stays as written.
- Any other completion ends the body's generator with a record: `{ _tag: "Return", value }`, `{ _tag: "Break", label }` or `{ _tag: "Continue", label }`, under fresh names, and `{ _tag: "Normal" }` when the body completes normally. `return e` evaluates `e` once, inside the body.
- Where the region stands, after `yield*` returns, the code re-issues the record: `return $c.value`, `break L` or `continue L`, where `L` is the consumer's label; the lowering gives an unlabeled consumer a fresh label. Inside an enclosing region body the re-issued jump is again a record, so it passes outward until it reaches its consumer.
- When the consumer is itself a callback, the record becomes that callback's own completion: a `for try` consumes `continue`, or a `continue` naming it, as `return true` and `break`, or a `break` naming it, as `return false` from the element's callback; a `for concurrent` consumes `continue`, or a `continue` naming it, as `return` from the item's callback.
- A `for concurrent` body can't produce a `break` it doesn't consume, a `return` or a `continue` naming an enclosing statement, and a `for try` body can't produce a `return` or a labeled `break` or `continue` naming a statement that encloses it: their static rules make these errors, because no loop or function runs on the body's fiber (VIP-19, VIP-20).
- Only a body that completes gives a record. A failure, defect or interruption stays in Effect's `Cause`. The region's own finalizers, such as releasing a `provide`'s layers, run before the jump, because `Effect.provide` and the masks complete before `yield*` returns.

```vibe [VibeLang]
// compiler-gap: pending VIP-12
effect function find(ids: string[]) {
  outer: for (const id of ids) {
    provide Users = testUsers {
      if (id === "skip") continue outer
      if (id === "stop") break outer
      if (try (try Users).has(id)) return id
    }
  }
  return "none"
}
```

## The pipe operator

`|>` is exactly TC39's Hack pipe operator, pinned to a dated snapshot of the proposal. `%` is the topic: the left side's value, evaluated once. The topic-versus-modulo grammar is TC39's, unchanged.

```vibe [VibeLang]
// compiler-gap: pending VIP-23
effect function run(id: string) {
  const n = fetchUser(id) |> retry(%, policy) |> timeout(%, "1 second")
  return try n
}
```

```ts [Effect]
// fragment
function run(id: string) {
  return Effect.gen(function* () {
    const t1 = fetchUser(id); const t2 = Effect.retry(t1, policy); const n = Effect.timeout(t2, "1 second")
    return yield* n
  })
}
```

Effect's `pipe(x, f, g)` function stays available ([VIP-14](/vips/0014-effect-modules-in-scope)).

The pinned snapshot is the vendored copy of `tc39/proposal-pipeline-operator` at commit `5ac4dfd624e68b649e6f947885bf5ef67bac19f4`, the head on 2026-10-28 (UTC), as pattern matching is pinned.
