# Failures

Sources: [VIP-4](/vips/0004-throw), [VIP-13](/vips/0013-error-declarations), [VIP-29](/vips/0029-schema-errors). Handling failures with `catch` is in [Running Effects](/spec/002-running#catch), and matching them is in [Pattern matching](/spec/004-match).

## `throw`

### Meaning

`throw` is allowed everywhere ([Thrown types](/spec/003-failures#thrown-types) says which calls may throw).

| Where | `throw e` means |
| --- | --- |
| a plain or `async` function, or the top level | JavaScript's `throw` |
| effect code | the Effect fails with `e`, a typed error: `return yield* Effect.fail(e)` |

```vibe [VibeLang]
// compiler-gap: pending VIP-4
effect function load(id: string) {
  const user = try findUser(id)
  if (!user) throw new NotFound({ id })
  return user
}
```

```ts [Effect]
// fragment
function load(id: string) {
  return Effect.gen(function* () {
    const user = yield* findUser(id)
    if (!user) return yield* Effect.fail(new NotFound({ id }))
    return user
  })
}
```

## Thrown types

This section is the one definition of throw tracking; every other chapter refers to it. Every call, `new` expression and tagged template has a *thrown type*: what it may throw synchronously, or `never`. Tracking applies only to non-effectful callables (VIP-4, amended: "an effectful function literally cannot throw").

### Effectful callables

A callable is *effectful* when its return type, written or inferred, is an Effect, a `Stream` or a `Layer`: an `effect` function or producer, Effect's own `sleep`, `sync`, `tryPromise` and `Effect.try`, a service member typed as an Effect, a `.ts` function whose return type is `Effect`. Except for `never` (below), ‘an Effect’ uses the [Running Effects](/spec/002-running#try) test: assignability to `Effect.Effect<any, any, any>`. In Effect 4.1.0 this includes `error` instances, service keys and references; a plain function returning one is effectful and may not throw. Its thrown type is `never`, and it never rethrows a callback: its failures are its Effect's error channel. This is a static contract, not a JavaScript runtime guarantee: a `.ts` implementation that throws before returning produces a defect when evaluated inside an Effect generator, but a JavaScript exception at the call when evaluated in a parameter default, before the Effect exists.

Because an effectful function can't throw, its own code that runs before the Effect exists may not throw either. In a plain `.vibe` function whose return type is an Effect, a `Stream` or a `Layer`, a `throw`, or a call whose thrown type is not `never`, is an error (`EK0401`): make it an `effect` function, or return `fail(e)`. This follows VIP-4's effectful-callable amendment; its later ‘`try` only in effect code’ amendment removes the old restriction on non-Effect return annotations. The same holds for code an `effect` function runs at the call ([Code outside the generator](/spec/003-failures#code-outside-the-generator)).

Only a return type other than `never`, wholly consisting of Effects, `Stream`s or `Layer`s, is effectful. `never`, `any`, `unknown` and unions containing a non-effectful member, such as `Effect.Effect<number> | undefined`, remain throw-tracked (decided detail 36).

```vibe [VibeLang]
// compiler-gap: pending VIP-4
error Missing
function missing() { return new Missing() } // effectful; no synchronous throw
const boom = () => { throw new Error("x") } // throws Error; never is not effectful
// function bad() { throw new Error(); return new Missing() } // error
```

```ts [Effect]
import { Data, Effect } from "effect"

class Missing extends Data.TaggedError("Missing") {}
function missing() { return new Missing() }
const boom = () => { throw new Error("x") }
const failure: Effect.Effect<never, Missing> = missing()
```

### Thrown type by kind of callable

```vibe [VibeLang]
// compiler-gap: pending VIP-4
/** @rethrows f */
function invoke(f: () => number) { return f() }
// lib.d.ts: /** @throws {never} @rethrows f */
// export declare function each(xs: string[], f: (s: string) => void): void
// lib.d.ts: export declare const parse: (s: string) => string

effect function checked() {
  // invoke(() => { throw "bad" })                 // EK0403
  // each(["x"], () => { throw "callback" })        // EK0403
  // parse("x")                                   // EK0403, from source or .d.ts
  return try Effect.try(() => invoke(() => { throw "bad" }))
}
```

```ts [Effect]
import { Effect } from "effect"

/** @rethrows f */
function invoke(f: () => number) { return f() }
/** @throws {never} @rethrows f */
function each(xs: string[], f: (s: string) => void) { xs.forEach(f) }
const checked = Effect.try(() => invoke(() => { throw "bad" }))
const checkedEach = Effect.try({
  try: () => each(["x"], () => { throw "callback" }),
  catch: (error) => error
})
```

Determine a call's synchronous thrown type in three steps (decided detail 66):

1. **Effectful callee:** its thrown type is `never`; neither `@throws` nor `@rethrows` adds synchronous throws.
2. **Own thrown type:** a written `@throws {T}` on the declaration or its declared call signature gives `T` (a checked upper bound in `.vibe`). Otherwise use the shipped annotation, installed on the signature before defaults apply ([Appendix E](/spec/900-appendices#appendix-e-shipped-throws-and-rethrows-annotations)). Otherwise infer a plain `.vibe` function's uncaught throws and unwrapped throwing calls, including field initializers for constructors. Otherwise a callable declared in `.ts`, `.d.ts` or JavaScript has `unknown`, whether its type is written or inferred: functions, callable constants, class or interface methods, and each overload. A function type in a `.vibe` type position (parameter, alias, interface member or annotation) instead defaults to `never`.
3. **Rethrows:** union the own thrown type with the thrown types of the actual callbacks passed for every named `@rethrows` parameter, whichever case in step 2 applied. The tag is written, never inferred. `@throws {never}` describes only the callee's own throws and does not erase `@rethrows f`. Argument-expression evaluation remains the caller's code.

Calling an `async` `.vibe` function throws `never`: body throws reject its Promise. Promise construction separately catches executor throws, as specified below. Getters and setters are not tracked calls. Constructing an `error` or `data` variant throws `never`; their generated constructors do not throw for well-typed input in Effect 4.1.0. Shipped annotations give `JSON.parse` `SyntaxError`, `Math.max` and `Option.some` `never`, and the decoder returned by `Schema.decodeUnknownSync` or `Schema.decodeSync` `SchemaError`; building either decoder throws `never`. Effect's `map`, `forEach`, `filter` and `reduce` are effectful; the shipped rethrowing array methods are `Array.prototype` methods and `Array.from`, not those Effect globals.

`@throws {T}` and `@rethrows p` attach to call signatures, not a `type` alias's declaration: write `type Reader = { /** @throws {Error} */ (): string }`. Contracts travel with signatures: `const g = f` preserves `f`'s thrown type. Declaration output tags exported non-effectful callables ([Declaration output](/spec/001-functions#declaration-output)). Implicit throws, such as reading a property of `undefined` or a stack overflow, are never tracked; they are defects, as in `Effect.sync`.

Contracts attach to each call signature, including each overload and a returned callable's own signature; declaration output preserves them (decided details 37–38). Calls through `any` or `Function` throw `unknown`; callable unions combine their alternatives' thrown types (detail 44). TypeScript still requires narrowing `unknown` before calling it.

```ts [Effect]
import { Effect } from "effect"

// A returned callable carries its own contract:
declare function decoder(): { /** @throws {Error} */ (s: string): string }
const dynamic: any = (s: string) => { if (!s) throw new Error("empty"); return s }
const wrapped = Effect.try(() => dynamic("ok"))
function uncertain(): Effect.Effect<number> | undefined { throw new Error("empty") }
const uncertainWrapped = Effect.try(() => uncertain()) // mixed return type remains tracked
```

A generated `schema error` constructor has thrown type `never`, a static contract (detail 42). Effect 4.1.0 validates its fields; invalid input can throw a plain `Error`, which becomes a defect inside `Effect.gen`.

```vibe [VibeLang]
// compiler-gap: pending VIP-29
schema error Invalid { name: Schema.NonEmptyString }
effect function invalid() { throw new Invalid({ name: "" }) } // defect, not typed failure
```

```ts [Effect]
import { Effect, Schema } from "effect"

class Invalid extends Schema.TaggedError<Invalid>()("Invalid", { name: Schema.NonEmptyString }) {}
const invalid = Effect.gen(function* () {
  return yield* Effect.fail(new Invalid({ name: "" }))
})
```

Recursive and mutually recursive plain functions infer the least fixed point of their thrown types, starting from `never` (detail 43): `fib` below throws `never`, `walk` throws `Error`. A written `@throws {T}` is a checked upper bound: the body may throw only subtypes of `T` (otherwise `EK0405`), callers see `T`, and declaration output copies the tag (detail 45).

```vibe [VibeLang]
// compiler-gap: pending VIP-4
function fib(n: number): number { return n < 2 ? n : fib(n - 1) + fib(n - 2) }
/** @throws {Error} */
function walk(n: number) { if (n) walk(n - 1); else throw new Error("end") }
// /** @throws {never} */ function bad() { throw new Error("end") } // error
```

```ts [Effect]
// fragment
function fib(n: number): number { return n < 2 ? n : fib(n - 1) + fib(n - 2) }
/** @throws {Error} */
function walk(n: number): void { if (n) walk(n - 1); else throw new Error("end") }
const direct = fib(5)
const walked = Effect.try(() => walk(1))
```

### Assignability

As for Swift's non-`throws` function type, a function whose thrown type is `T` is assignable to a function type only when that type admits `T`: a type without `@throws` admits only `never`, `@throws {U}` admits subtypes of `U`, and `@throws {unknown}` admits anything. A parameter named by `@rethrows` admits anything, because the call then throws what its argument throws. So `const r: () => string = parse` is an error (`EK0402`): wrap the function, or annotate the type `@throws`.

The rule applies member by member when assigning an object to an interface or object type with callable members, as TypeScript checks member assignability. The rule applies to arguments too. VIP-4's two wrappers declare their thunk parameter `@throws {unknown}` ([Appendix E](/spec/900-appendices#appendix-e-shipped-throws-and-rethrows-annotations)), in both overloads: the function argument or the options object's `try` property. Thus `Effect.try(() => parse(s))` and `tryPromise(() => queryDb(q))` are allowed, and the wrapper turns a throw into a failure. The options object's `catch` callback has the ordinary non-throwing function type; a tracked throw there is rejected, while an implicit throw is a defect. Effect's `LazyArg` and other callback parameter types are function types, including those in `.d.ts` files. Every other function parameter admits only what its type says: `sync(() => parse(s))` is an error, so wrap the call with `Effect.try`.

JavaScript's `Promise` constructor separately admits `@throws {unknown}` on its executor's call signature (detail 64). The constructor itself has `@throws {never}` and no `@rethrows`: executor throws reject the Promise. Evaluating the executor argument is still the caller's code. This does not change the Effect wrapper contracts above.

```vibe [VibeLang]
// compiler-gap: pending VIP-4
function rejected() { return new Promise<never>(() => { throw "executor" }) }
effect function checked() { return try tryPromise(() => rejected()) }
```

```ts [Effect]
import { Effect } from "effect"

interface PromiseExecutor<T> {
  /** @throws {unknown} */
  (resolve: (value: T | PromiseLike<T>) => void, reject: (reason?: any) => void): void
}
const executor: PromiseExecutor<never> = () => { throw "executor" }
/** @throws {never} */
function rejected() { return new Promise<never>(executor) }
const checked = Effect.tryPromise(() => rejected())
```

### Calls in effect code

| Rule | Diagnostic |
| --- | --- |
| In effect code or the body of a plain `catch` handler, a call, `new` expression or tagged template whose thrown type is not `never`. Wrap it: `try Effect.try(() => parse(s))` | `EK0403` |
| In effect code, a call, `new` expression or `async match` producing a Promise or thenable, even if assigned to a variable and never awaited. Move the expression into a `tryPromise` thunk, whether or not it can reject; `promise` also works when the thunk's thrown type is `never` | `EK0404` |

A plain function may propagate a JavaScript throw; an `async` function turns it into rejection. Effect code calls a function whose thrown type is `never` directly. Promise-producing calls inside wrapper thunks are ordinary JavaScript; wrapping never exempts a platform call from [VIP-33](/vips/0033-platform-stdlib). `Promise.reject(e)`, like every Promise-producing call, must be inside a wrapper thunk in effect code. An unannotated foreign `queryDb` may throw `unknown`, so use `tryPromise(() => queryDb(q))`; `promise` does not admit that throwing thunk under the wrapper annotations above.

A tracked throwing call in a plain `catch` handler is an error (`EK0403`, detail 39); use an effect handler and a wrapper. An explicit `throw` in the plain handler retains VIP-5's defect meaning.

```vibe [VibeLang]
// compiler-gap: pending VIP-4
// fragment: source: string!Error; parse(e: Error): string may throw
source catch (e) => parse(e) // error
source catch effect (e) => try Effect.try(() => parse(e))
```

```ts [Effect]
// fragment
const source = Effect.fail(new Error("input"))
function parse(e: Error): string { throw e }
const recovered = Effect.catch(source, (e) => Effect.try(() => parse(e)))
```

```vibe [VibeLang]
// compiler-gap: pending VIP-4
function parse(s: string) { if (!s) throw new Error("empty"); return s }   // throws Error (inferred)
function add(a: number, b: number) { return a + b }                         // throws never

effect function load(s: string, q: string) {
  add(1, 2)                                      // ok: throws never
  parse(s)                                       // error: may throw
  const p = try Effect.try(() => parse(s))       // ok: the thunk parameter admits any throw
  const r = try tryPromise(() => queryDb(q))     // a Promise is always wrapped; queryDb is from a .ts module
  return [p, r]
}
```

```vibe [VibeLang]
// compiler-gap: pending VIP-4
error BadInput
effect function parsed(s: string) {
  return try Effect.try({ try: () => parse(s), catch: () => new BadInput() })
}
```

```ts [Effect]
// fragment
class BadInput extends Data.TaggedError("BadInput") {}
function parsed(s: string) {
  return Effect.gen(function* () {
    return yield* Effect.try({ try: () => parse(s), catch: () => new BadInput() })
  })
}
```

An empty input fails with `BadInput`; the thunk-only form instead fails with Effect's `UnknownError`.

`Effect.try` keeps its module prefix because `try` is a reserved word ([VIP-6](/vips/0006-effect-globals)).

The annotations affect checking, not the JavaScript implementation:

```vibe [VibeLang]
// compiler-gap: pending VIP-4
/** @rethrows callback */

type Reader = () => string                       // throws never by default
function stream(text: string) { return Stream.succeed(text) }
function layer() { return Layer.empty }          // both effectful: never tracked
class Input {
  constructor(readonly text: string) { if (!text) throw new Error("empty") }
  get value() { return this.text }               // access is not throw-tracked
}
effect function checked(text: string) {
  const input = try Effect.try(() => new Input(text)) // the constructor throws Error
  const some = Option.some(input.value)                  // throws never

}
```

### Code outside the generator

Some code an `effect` function owns runs when the function is called or a class is constructed, not when its Effect runs. `try` works like `await` (VIP-5), so none of it is effect code ([Appendix A](/spec/900-appendices#the-effect-parameter)):

- **Parameter defaults and destructuring** run at the call, before the Effect exists. An effectful function can't throw, so a default whose thrown type is not `never` is an error (`EK0401`). A default that returns a Promise is a plain value, as in TypeScript. Destructuring a parameter can still throw a `TypeError`, an implicit throw: a JavaScript exception at the call, and a defect when the call is inside effect code.
- **Class field initializers** run in `new X()`, so their thrown types belong to the constructor's. **`static` blocks** run when the class is evaluated, as JavaScript's.
- **Arguments** are evaluated by the caller, so their thrown types are the caller's.
- **Wrapper thunks** run inside the Effect: their throws become what the wrapper makes of them.

```vibe [VibeLang]
// compiler-gap: pending VIP-4
// fragment: s: string and q: string are supplied by the enclosing scope
effect function a(p = parse(s)) { return p }          // error: a default that may throw
effect function b(p = queryDb(q)) { return p }        // error: unannotated foreign queryDb may throw unknown
async function resolved() { return 1 }              // calling an async function throws never
effect function b2(p = resolved()) { return p }      // allowed: p is a Promise
effect function c({ id }: User) { return id }         // c() from untyped JS throws TypeError at the call
```

## `error` declarations

### Syntax

[ErrorDeclaration](/spec/900-appendices#errordeclaration), with an [ErrorBody](/spec/900-appendices#errorbody) of [Field](/spec/900-appendices#field)s and methods: ECMAScript's `MethodDefinition` (plain, `async`, generator and `async` generator methods, getters and setters, private names included) with TypeScript's class-method modifiers, plus [effect methods](/spec/900-appendices#effectmethod) and [producer methods](/spec/900-appendices#producermethod), as any class can have (VIP-13). A setter parses as a `MethodDefinition` and the static rules below reject it. [Field](/spec/900-appendices#field) and [Separator](/spec/900-appendices#separator) are shared with `schema` and `data`, so adjacent fields on one line need a separator. The field type is parsed greedily as a TypeScript type member: a line break separates members only after the type is complete. An explicit `readonly` is allowed and redundant. Empty `;` class elements between members are ignored, as in TypeScript.

`error`, like `service`, `schema` and `data`, follows TypeScript's contextual keyword `type`: a declaration is the keyword, no line break, then the declaration's name (a `BindingIdentifier`), where a declaration can start; anything else is ordinary TypeScript, where `error` is an identifier ([Declaration keywords](/spec/900-appendices#declaration-keywords), the one rule for all four). So `const error = …`, `catch (error)`, `const e = error as Error` and `error instanceof NotFound` still work, and `error as T;` declares `as`, then fails; write `(error as T);`. The body is optional, as for TypeScript's `declare module "m"` ([ErrorDeclaration](/spec/900-appendices#errordeclaration)). As in ECMAScript's `ExportDeclaration`, `export error E` and `export schema error E` are named declarations; `export default error E` and `export default schema error E` are syntax errors. Write `export { E as default }` instead, as for a [service](/spec/005-services).

Each member has one classification ([Declarations](/spec/900-appendices#notes-on-the-productions)): `id: string`, `readonly id: string` and `id?: string` are always [Field](/spec/900-appendices#field)s, each complete method or accessor is classified once, including `effect` and producer methods, empty `;` class elements are ignored, and any other class element is a [RejectedElement](/spec/900-appendices#rejectedelement), which the static rules below reject. The parser also accepts type parameters and heritage clauses, only so their rules can report them.

Field keys follow TypeScript object types, as in [Schema declarations](/spec/006-data#schema-declarations): an identifier, a string or numeric literal, or a computed name, emitted as written. A computed key of non-literal type gives an index signature in the instance type; at runtime it supplies just the one key the expression evaluates to. In `schema error`, the decoder requires that runtime key and ignores other keys by default; an index signature does not make it validate arbitrary keys.

```ts [Effect]
import { Schema } from "effect"

const field: string = "actual"
class Dynamic extends Schema.TaggedError<Dynamic>()("Dynamic", { [field]: Schema.Number }) {}
const decode = Schema.decodeUnknownExit(Dynamic)
decode({ _tag: "Dynamic", other: 1 })             // Failure: actual is missing
decode({ _tag: "Dynamic", actual: 1, other: 2 })  // Success: other is stripped
```

```vibe [VibeLang]
// compiler-gap: pending VIP-13
error Access {
  role:
    | "admin"
    | "member"
  get message() { return this.role }; // empty class element is allowed
}
```

### Static rules

| Rule | Diagnostic |
| --- | --- |
| a constructor in an `error` or `schema error` body | `EK1301` |
| a `_tag` member in an `error` or `schema error` body | `EK2117` |
| an `extends` clause, `error UserNotFound extends NotFound { … }`, in either error form | `EK2117` |
| a user-written `static` member or setter, in either error form | `EK1302` |
| type parameters, such as `error Invalid<T> { value: T }`, in either error form | `EK1303` |
| any other member that is not a [Field](/spec/900-appendices#field), a method, a getter or an empty `;` class element, in either error form (for example `id = 1`, `private id: string`, `#id = 1`, `declare id: string`, `accessor id = 1`, or an index signature); an `implements` clause | `EK1304` |

A member rejected by [Functions](/spec/001-functions#static-rules) for `effect` on a getter, setter or constructor gets that diagnostic alone, including in either error form. Otherwise a member gets one diagnostic: the first row that names it. The last row applies only when no other row applies. For example, `_tag = 1` reports `EK2117`; `static x = 1` reports the static-member rule, not the general member rule.

### Meaning

`error Name { fields }` declares exactly Effect's `Data.TaggedError` class. The tag is always the name, and every field is readonly. Optional `id?: T` maps to `readonly id?: T`, as in a TypeScript type literal. Fields, methods and getters may be interleaved, as in a TypeScript class.

User-written `static` members and setters are forbidden in both forms. The compiler-supplied matcher below is the exception; its `Symbol.customMatcher` shim is described in [Pattern matching](/spec/004-match#class-patterns).

```vibe [VibeLang]
// compiler-gap: pending VIP-13
error NotFound {
  id: string
  get message() { return `no user ${this.id}` }
}
error Timeout
```

```ts [Effect]
// fragment
class NotFound extends Data.TaggedError("NotFound")<{ readonly id: string }> {
  get message() { return `no user ${this.id}` }
  static [Symbol.customMatcher](subject: unknown) {          // VIP-7: tests _tag
    return (subject as { _tag?: unknown } | null)?._tag === "NotFound" ? [subject] : false
  }
}
class Timeout extends Data.TaggedError("Timeout") {
  static [Symbol.customMatcher](subject: unknown) {
    return (subject as { _tag?: unknown } | null)?._tag === "Timeout" ? [subject] : false
  }
}
```

The matcher gives `[subject]` on a match, so `when NotFound(let e):` binds the error, and `false` otherwise. `when NotFound:` is a bare test; `when NotFound():` never matches because its zero patterns cannot match the singleton extraction list. An error is constructed with its fields as one object, `new NotFound({ id })`. Two packages that both declare `error NotFound` match each other in `match`, as with Effect's `catchTag`, because an `error` class's matcher tests `_tag` ([Pattern matching](/spec/004-match#class-patterns)).

VIP-7 retains module-guard checks for Effect's own tagged errors, without patching Effect (detail 53). For example, `when Cause.TimeoutError(let e):` tests `Cause.isTimeoutError(subject)` and binds `subject` as `e`. A bare `{ _tag: "TimeoutError" }` does not pass that guard. These checks use neither a universal `_tag` test nor inherited `Function.prototype` matching. The twelve resolved constructors, alias/shadowing rules and singleton extraction are listed in [Retained Effect tagged-error patterns](/spec/004-match#retained-effect-tagged-error-patterns).

```ts [Effect]
import { Cause } from "effect"

function timeoutPattern(subject: unknown) {
  return Cause.isTimeoutError(subject) ? [subject] : false
}
timeoutPattern(new Cause.TimeoutError()) // [subject]
timeoutPattern({ _tag: "TimeoutError" }) // false
```

An `error` always extends `Data.TaggedError`. Group errors with a union, `type LookupError = NotFound | Timeout`: tagged errors are matched by `_tag`, and a subclass would match two tags.

Neither form accepts type parameters. For example, `error Invalid<T> { value: T }` and `schema error Invalid<T> { value: T }` are compile errors.

## `schema error` declarations

### Syntax

[SchemaErrorDeclaration](/spec/900-appendices#schemaerrordeclaration). Its [ErrorBody](/spec/900-appendices#errorbody) is shared with `error`. Each field's type is mapped as in a `schema` declaration, optional properties included. Every field is readonly, as in `error`, so no field gets `Schema.mutableKey`. Omitting the body means no fields, as for `error Timeout`, and the body boundary is the same as for `error`.

`schema error NotFound {` and a schema named `error` (`schema error = …`) differ at the next token. `schema error { id: string }` is a schema named `error`: `{` is not the name required after `schema error`.

### Meaning

`schema error Name { fields }` combines `error` and the field mapping of `schema` declarations ([Data](/spec/006-data#schema-declarations)). Fields are written as TypeScript types and mapped to Schemas, so the error can be decoded from JSON and crosses workers and RPC. The body rules, and their diagnostics, are those of `error` declarations.

```vibe [VibeLang]
// compiler-gap: pending VIP-29
schema error NotFound { id: string }
schema error Timeout
```

```ts [Effect]
// fragment
class NotFound extends Schema.TaggedError<NotFound>()("NotFound", { id: Schema.String }) {
  static [Symbol.customMatcher](subject: unknown) {          // as for error
    return (subject as { _tag?: unknown } | null)?._tag === "NotFound" ? [subject] : false
  }
}
class Timeout extends Schema.TaggedError<Timeout>()("Timeout", {}) {
  static [Symbol.customMatcher](subject: unknown) {
    return (subject as { _tag?: unknown } | null)?._tag === "Timeout" ? [subject] : false
  }
}
```
