Browser apps and strict TypeScript consumers importing `vibelang-runtime` had to contend with explicit `any` annotations across `packages/runtime/src/` and an over-broad `sideEffects` manifest that pulled optional runtime helpers into core bundles, while standalone Smithers flow runners in `.smithers/flows/` duplicated in-memory `FlowEngine.layerMemory` hosts instead of persisting runs to the workspace SQLite store. Explicit `any` annotations have been replaced with strict types across `packages/runtime/src/`, `vibelang-runtime` now exports a lean `vibelang-runtime/core` subpath with a minimal four-file `sideEffects` list and zero static imports from `experimental/` or `kernel/`, and `.smithers/flows/host.ts` provides one shared durable SQLite host on `@smthrs/platform-node` and `@smthrs/control` (with `--memory` opt-in for isolated tests) so standalone flow executions are tracked by `smthrs runs list`.
