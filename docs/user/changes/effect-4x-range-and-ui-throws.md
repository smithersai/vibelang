Projects using Effect `4.1.2+` (including `@effect/ui` apps requiring `effect@^4.1.4`) previously failed with `EK3201` or a runtime version-guard error unless every Effect package and transitive `@effect/platform-node-shared` dependency was pinned to exact `4.1.1`, and pure constructors and builders from `@effect/ui` packages triggered `EK0403` inside `effect` functions because their declarations carry no `@throws {never}` tags. Core runtime helpers (`$catch`, `$catchExpression`, `$catchCause`, `$settle`/`$fast`, `uninterruptible`, `restore`) now use public Effect 4 APIs without `FiberImpl` internals, `vibelang` and `vibelang-runtime` accept any stable `effect` version matching `^4.1.0` (`>=4.1.0 <5.0.0`, tested on `4.1.6`) while still rejecting `3.x`, `4.0.x`, `5.x`, and prereleases, and non-throwing constructors and builders from `@effect/ui`, `@effect/ui-kit`, `@effect/ui-devtools`, and `@effect/ui-opentui` are treated as `@throws {never}` while throwing helpers (`*Unsafe`, `*OrThrow`, `decode*Sync`, `encode*Sync`, `asserts`) still report `EK0403`.
