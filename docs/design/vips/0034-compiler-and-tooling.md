# VIP-34: compiler and tooling requirements

**Status:** accepted, 2026-10-29, under Will's standing approval of recommendations ("assume I accept now. I will interrupt you if I need to").

## Decision

1. **Diagnostics.** Every VibeLang diagnostic has a code (`EKxxxx`) and a message in the user's words that says what is wrong and how to fix it, with a quick fix wherever the fix is mechanical. TypeScript's own lexical, syntax and static errors on ordinary native syntax keep their `TS` codes, including independent errors in embedded expressions and types. A rejection that depends on a VibeLang production, placement rule, proposal-specific early error or explicitly adopted reconciliation uses its owning VIP's `EK` code, even when a TypeScript parser helper implements it. Use an already assigned specific diagnostic for the same rejection; preserve independent native errors.
2. **Codemods.** Every breaking change ships a `vibelang --fix` codemod, so code that compiled under the previous release migrates mechanically.
3. **One formatter.** VibeLang's formatter is the only formatter. Prettier, dprint and Oxfmt reach it through plugins, so a repo's existing formatter command covers `.vibe` files. Under the same compiler/options, formatting preserves parsed program meaning: bindings and scopes, operator and control-flow targets, evaluation order, receivers and call syntax, ordinary runtime values and effects, coldness, failures, interruption and finalizers. It preserves inferred and declared public types, declarations and throws contracts, and diagnostic codes, categories and occurrences; diagnostic locations and quoted source follow the formatted file. Comments and their code associations survive, including JSDoc, compiler/linter/tool directives and directive-prologue meaning. An unparsable file is reported and left unchanged; formatting is idempotent. Semantic migrations and diagnostic repairs belong to `vibelang --fix` or editor actions.

   Ordinary layout and lexical-spelling normalization may change emitted JavaScript bytes. `Function.prototype.toString`, generated source text, source offsets, line/column and stack presentation may reflect the formatted text. This source-text boundary never permits changes to ordinary strings/data, tagged-template raw or cooked values, regex meaning, function names or lengths, property names or directive semantics. For example, changing an escaped string into an actual `use strict` directive changes meaning. Regenerate compiler-generated source-map and declaration-map provenance, including `sourcesContent`, for the formatted file; never retain stale maps. Preservation tests compare parsed source/emit structure, runtime behavior, types/declarations, diagnostics, comments/directives and maps; arbitrary regex stripping is unsound, and a finite structural oracle is not a proof of all program equivalence. Exact-byte tests remain useful where equality is expected, without restricting advertised native formatter style settings.
4. **Existing tools work.** Type checkers work through `.d.vibe.ts` (VIP-27), and linters, Knip, bundlers and test runners each read `.vibe`. Every tool is tested against the dogfood repositories.
5. **Severities.** Warning severities can be adjusted in the config's `"vibe"` section (VIP-30). Errors can't be turned off.

Any forbidden write is refused with the not-fixed explanation.

Its identity-safe shorthand or qualified-type rewrite precedes coordinated alias removal; user-defined and imported types are unchanged.

- **Amended 2026-11-01: declaration import spelling.** Runtime JavaScript rewrites `./x.vibe` to `./x.js`. Package declarations use VIP-27/VIP-30's `vibelang.declarationImportStyle`: `".js"` (default), `"extensionless"` or `".ts"`. 67a. **Built-in class patterns** (resolves Astra round-16 M1; extends detail 67). The TC39 draft's matchers for built-in classes check engine internal slots (`[[ErrorData]]`, `[[DateValue]]`, `[[RegExpMatcher]]`, `[[MapData]]`, …) that compiled JavaScript cannot read portably. So a class pattern naming a built-in uses:
   - `Array`: `Array.isArray(subject)`, which is the draft's own brand check and available everywhere;
   - every other built-in (`Error` and its subclasses `TypeError`, `RangeError`, …, `AggregateError`, `Date`, `RegExp`, `Map`, `Set`, `WeakMap`, `WeakSet`, `Promise`, typed arrays, `ArrayBuffer`): `subject instanceof C`, as detail 67 does for ordinary classes. `Error.isError` is not in Node 22, which VibeLang supports, so errors use `instanceof` too.
   - Divergence, stated beside detail 67's: a cross-realm built-in (from another `vm` context or iframe) fails `instanceof`, except arrays. When the supported Node versions all have `Error.isError`, errors switch to it in a VIP.
   Effect TS: `Array.isArray(x)` and `x instanceof C`. Decided by the agent from detail 67, principle 1 and implementability, 2026-10-30.

67b. **A class pattern naming a VibeLang value that is not a class is a compile error** (audit-x 004 D1). A class pattern whose expression resolves to a `data` declaration or variant constructor, a `schema` declaration, a `service` or a `Context.Reference` is `EK0702`, with a quick fix: for a variant, "write `when { _tag: "Sent" }:`"; for a schema, test with `Schema.is(Address)(x)` in a guard; for a service, extend `EK3004`. Under the pinned draft such a function would be *called* with the subject and match almost everything, silently. Correction to detail 67's aside: only `error` declarations (and the Effect matchers of detail 53) have their own `Symbol.customMatcher`; `data` variant constructors and `schema` constants do not (chapter 006 is right). Decided by the agent from principle 8 (an error can be relaxed later) and VIP-7's no-patching condition, 2026-10-30.

67c. **Declaration output carries the generated matcher** (audit-x 001 D1). A `.d.vibe.ts` that declares an `error` or `schema error` keeps its static `[Symbol.customMatcher]` member, `vibelang-runtime` ships the `Symbol.customMatcher` type (`declare global { interface SymbolConstructor { readonly customMatcher: unique symbol } }`), and each such declaration file begins with `/// <reference types="vibelang-runtime" />`, so plain `tsc` type-checks it and cross-package matching dispatches at run time as the draft says. Decided by the agent from VIP-27 (declarations are what idiomatic Effect TypeScript would declare), 2026-10-30.

51a. **`restore` in any `for concurrent` body is `EK2202`** (audit-x 002 D1; extends detail 51). `restore` is lexical, and a `for concurrent` body's items run as separate Effects that the enclosing `uninterruptible` mask does not govern, whatever the limit. A body that needs it masks per item with `Effect.uninterruptibleMask` inside the body, or uses a plain `for` instead of `for concurrent(1)`. Decided by the agent from detail 51's rule, 2026-10-30.
