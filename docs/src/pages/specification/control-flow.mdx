# Control Flow [Normative model for statements, cleanup, and the one grammar addition]

Status: **Locked**.

## Existing TypeScript Forms

Valid TypeScript statement forms MUST retain their TypeScript behavior on the TypeScript target.

Smithers MUST NOT reinterpret an existing TypeScript statement in a way that changes observable behavior.

## No Expression-Form Grammar

Blocks, `if`, `switch`, `while`, and `for` are statements. None MUST be usable as an expression.

A value-position conditional is a conditional expression (`c ? a : b`). A value-position multi-way choice is a function call, an object lookup, or a conditional chain. TypeScript expresses both today, so neither justifies new grammar.

Smithers MUST NOT add:

- `if` or `switch` in expression position, braced or braceless
- a block in expression position
- a value-carrying labeled `break`
- a loop `else` completion value
- a labeled block or loop value
- an arrow-arm switch grammar
- a throw-expression grammar

## Switch

`switch` MUST retain TypeScript's `case`, `default`, colon-delimited clauses, fallthrough, and `break` behavior, unchanged.

Exhaustiveness over a closed union is a type-level concern and MUST NOT be expressed through new syntax.

## Throw Statements

Smithers MUST retain ordinary statement-form `throw`. Inside a fallible function, throwing an `Error` produces the function's Result error variant according to [Failure Semantics](/specification/failures).

Expression-form `throw` MAY be reconsidered when the TC39 proposal reaches TypeScript.

## Declarations in Conditions

This is the only grammar Smithers adds.

```ts
if (const user = cache.get(id); user !== undefined) {
  render(user)
}
```

The binding MUST be visible in the then branch and in every `else` branch, and MUST be out of scope after the construct.

Smithers adopts this early from the TC39 **Declarations in Conditionals** proposal (Stage 1). It is accepted because it is standards-track: upstream adoption would eventually make the fork patch unnecessary, which is true of no invented form.

## Cleanup

Smithers MUST NOT add `defer` or `errdefer`. Scope-exit cleanup uses TC39 explicit resource management (`using` and `await using`), which TypeScript already supports and which Smithers inherits unchanged.

Cleanup that must run only on a Result error exit MUST be written explicitly in the failure path — through `mapError`, `recover`, `match`, or an ordinary JavaScript `try`/`catch` at an interop boundary.

Interaction between `using` disposal and a compiler-generated failure exit from `!` requires further normative specification.

That specification MUST additionally cover **abandonment**: when a handler declines to resume a suspended computation, every live `using` and `await using` scope in the abandoned computation MUST be disposed, in reverse acquisition order, and every `finally` block MUST run. `catch` clauses MUST NOT run. A runtime MUST NOT allow an abandoned computation to leave a resource undisposed. Whether a disposal error raised during abandonment can be observed by the handler is **open**. See [Effects](/specification/effects) §Abandonment.

## Grammar Additions in General

A new source form MUST correspond to an active TC39 proposal. Value semantics that TypeScript can already express belong in the type system, the standard library, or a compiler-recognized imported intrinsic.
