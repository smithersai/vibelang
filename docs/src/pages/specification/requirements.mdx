# Requirements [Normative model for capabilities and provider layers]

Status: **Locked** for capability identity, context access, inference, lean layer provision, and lifetime boundaries. Declaration encoding and lowering are **open**.

## Capability Identity

A capability MUST be represented by an abstract class extending `Context` from `vibelang/context`.

Two structurally identical context subclasses MUST remain different requirements unless the program defines an explicit identity relationship.

The abstract class MUST act as both the service contract and its nominal context key:

```ts
import { Context } from "vibelang/context"

abstract class Clock extends Context {
  abstract now(): number
}
```

This declaration uses ordinary class syntax. VibeLang MUST NOT add a separate capability declaration form.

## Context Access

A function accesses a service with a library-shaped call:

```ts
function timestamp(message: string): Entry {
  const clock = Clock.context()
  return { message, recordedAt: clock.now() }
}
```

`Capability.context()` MUST be an inherited, compiler-recognized call on subclasses of `Context`. It MUST return the receiving capability's instance type and add that class's nominal identity to the enclosing function's inferred `R` row.

The call is intentionally library-shaped: it uses ordinary static method-call syntax and has ordinary runtime behavior after lowering, while the compiler gives it additional static meaning. The receiver MUST identify a `Context` subclass strongly enough for the compiler to record its nominal key.

A reference to a capability's `context` member that is not an immediate call on a statically determined `Context` subclass MUST be rejected. The compiler MUST be able to identify, at every access site, exactly one nominal capability key and one runtime constructor value. This is a precondition of the lowering, not a stylistic restriction: it is what makes rewriting `Capability.context()` into a handler-answered effect request sound.

The context row MUST be part of the function's static type even though it is not written with dedicated function-declaration syntax. Callers MUST NOT pass a context argument by hand.

Lookup MUST remain fully typed. The implementation MUST NOT expose an untyped service locator.

## Inference

Calling a function with unsatisfied requirements MUST add those capabilities to the caller's `R` row. The source call MUST remain an ordinary call with only the function's declared value arguments.

Requirement inference MUST be transitive through ordinary calls. Duplicate nominal requirements MUST collapse.

This includes calls performed by ordinary resource management: `using` selects
`Symbol.dispose`, and `await using` selects `Symbol.asyncDispose` when present,
otherwise `Symbol.dispose`. The selected getter and callable contribute their
requirements. An optional or nullish async disposer retains the possible
synchronous fallback; a definite async disposer does not invoke the sync method.
The fallback's return value is discarded by native resource management, not
awaited, so an async `Symbol.dispose` does not satisfy Promise ownership. A
discarded Result from either disposal protocol likewise does not satisfy
must-consume. This method selection does not decide cleanup-error precedence.

Public declarations MUST preserve the inferred row. Its exact TypeScript declaration encoding is open; a phantom `Context.Function<Fn, R>` representation is a candidate.

This obligation includes implicit calls through imported accessors and native
protocols. Publishing a getter as a data property MUST NOT erase the getter's
requirements. Read and write contracts remain distinct, including the rows of
returned and accepted function values. Enumeration must preserve the distinction
between an own enumerable getter and a class accessor that it does not invoke.

The same rule applies to structural object views: assignments, assertions,
arguments, return contracts, containers and index signatures MUST NOT erase the
requirements of reading or writing an accessor. An enumerable getter's row MUST
also survive a view that can subsequently be spread, even when that view omits
the getter's name. Generic instantiation MUST NOT authorize an implicit call
which the generic body's checked parameter contract omits. A pure identity can
transfer the original type without invoking its members. Spreading a value
invokes its own getters once and produces data properties; those resulting
properties MUST NOT be published or charged as getters again.

## Platform Requirements

Platform-sensitive functionality MUST use requirements. This includes filesystem, network, environment, clock, randomness, process, browser document, and comparable host facilities.

Clock and randomness are not merely hygiene. Because a Flow body re-executes on every resumption, routing them through capabilities is the precondition that makes replay correct at all; see [Durable Execution](/specification/durable-execution) §Flow Determinism.

A capability MAY have multiple host implementations. For example, `FileSystem` MAY be implemented by Node, Bun, Deno, or a test provider.

Host suitability MUST be determined from the satisfied dependency closure, not merely the source module's import path.

## Layer Algebra

Provider composition MUST be expressed by a library imported from `vibelang/provider`. The accepted design MUST NOT rely on a dedicated source-language `provide {}` statement.

A base layer conceptually has the type:

```ts
Layer<Provides>
```

Layer composition MUST track:

- the nominal capabilities produced

A layer MUST associate each capability's nominal context key with a compatible service instance. Layer APIs are library-shaped; the compiler recognizes their effect on `R` without introducing special provider grammar.

Resource acquisition and finalization MUST remain explicit ordinary code, initially through `using`. A base Layer receives an already acquired service and MUST NOT own that service's lifetime. A future resource-building convenience MAY carry construction failures and requirements without changing the base Layer rule.

## Satisfaction

Providing a layer to a computation MUST remove matching capabilities from the computation's unsatisfied requirement row. The provider library MUST establish the runtime scope in which `Capability.context()` resolves those instances.

When the compiler knows the complete closure, an unsatisfied capability MUST be a compile error.

## Scoping

Provided implementations MUST be scoped to the provided computation. `Layer.provide(layer, body)` MUST keep its environment active through `body` and the Promise returned by `body`, then revoke it. Nested scopes MAY override implementations according to a future explicit precedence rule.

A provided environment MUST NOT be observable outside the dynamic extent of the computation it scopes. Because the handler holds the environment on its own stack rather than in ambient storage, and a completed or abandoned computation cannot issue a further request, revocation is structural. A runtime MUST NOT require a host promise-settlement hook, MUST NOT restrict which Promise a provider body returns, and MUST NOT refuse an async provider scope on a host that cannot observe Promise settlement synchronously.

A base Layer MUST NOT discover, register, cancel, or join child work. Fire-and-forget and detached work are initially unavailable in authored `.vibe`; every started Promise MUST be consumed directly by `await` or by a recognized combinator whose resulting Promise is consumed before scope exit. Under replay this is a correctness rule rather than lifetime hygiene: an unconsumed Promise is an unjournaled, unreproducible interleaving.

Imported JavaScript or TypeScript that starts hidden background work owns that work. Caller-controlled background APIs MUST expose explicit completion or disposal handles through their adapters.

## Lowering

The TypeScript backend MAY lower requirements through hidden environment parameters, scoped ambient context, handler-answered effect requests, or another mechanism that preserves semantics and ordinary source-level call syntax.

Ambient runtime context is not a locked implementation choice. The lowering MUST preserve async scope, nesting, failure cleanup, and nominal lookup behavior.

The accepted mechanism is the one defined by [Effects](/specification/effects): `Capability.context()` issues a `get` request and `Layer.provide` installs the handler that answers it. That page is normative for the mechanism; the four preservation obligations above are normative for what any mechanism must not break.

## Amendment Record — one-shot delimited continuations, 2026-08-27

**Withdrawn — promise-settlement revocation** (previously §Scoping):

> "Promise revocation MUST occur at settlement before queued Promise reactions
> run. A runtime MAY require the Promise to be created by the provider body, and
> MUST reject an unverifiable pre-existing Promise or a host that cannot observe
> settlement synchronously. Authors can establish an unaliased boundary with
> `async () => await existingPromise`; this adapts the lifetime without making
> the Layer own the underlying work."

The guarantee it protected — an environment MUST NOT outlive the computation it
scopes — is unchanged and now holds structurally. Three obligations it imposed
are withdrawn as unnecessary rather than relaxed: the Promise-provenance rule,
the fail-closed refusal on a host without a synchronous settlement hook, and the
author-written `async () => await existingPromise` adapter. Hosts previously
refused for lacking that hook are now fully supported.

**(SA-6), re-measured 2026-09-05.** The V8 promise-hook machinery,
Promise-provenance refusal and required pre-existing-Promise adapter are removed.
Compiled provider scopes install lexical handlers, including across async body
steps and durable replay. The old note claiming the handler substrate was
unwired no longer describes the implementation.

`AsyncLocalStorage` remains a compatibility bridge for ordinary eager calls,
accessors and native callbacks. Removing the old guards does not itself prove
every lifetime case; shared path-sensitive ownership checks and lexical-handler
tests cover the current accepted path, while full opaque callback/container
coverage remains open. The retained lifetime guarantee and withdrawn obligations
above are unchanged.

`Layer.provide(layer, body)` keeping its environment active through `body` and
the Promise returned by `body` is retained verbatim. Layer merging and nested
override precedence remain **open** and still fail closed.

**Execution follow-up, 2026-09-06.** The Go eager-call runtime previously lost
its environment at the first async suspension. It now uses the reference's
async-environment model, including sibling isolation and revocation. Reference
emit also preserves the scope of a non-`async` callback that returns a Promise,
and an eager nested provider can read its still-live outer environment. The
shared Layer-scope execution tests cover these cases; this does not establish a
shared Go/reference request ABI. Both current environment bridges require
Node-compatible host modules; browser/edge linking remains unimplemented. These
are implementation-status facts, not changes to the host-independent rules above.
