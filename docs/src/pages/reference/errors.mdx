# Results and Errors [Reference for expected failure values]

## Types

```ts
Result<A, E extends Error>
Promise<Result<A, E>>
```

`A` is the success type and `E` is the union of expected errors. Async fallible functions wrap the whole Result in an ordinary Promise.

## Error Declaration

```ts
class HttpError extends Error {
  constructor(
    readonly status: number,
    readonly url: string,
  ) {
    super(`HTTP ${status}: ${url}`)
  }
}
```

No special error declaration or tagged-error base is used. The compiler attaches stable nominal identity and transport metadata to ordinary `Error` subclasses.

## Function Authoring

```ts
function operation(): Result<Output, ErrorA | ErrorB> {
  if (conditionA) throw new ErrorA()
  if (conditionB) return otherOperation()
  return new Output()
}
```

Within a Result-returning function:

- `return value` creates the success variant.
- `throw error` creates the error variant.
- returning a compatible Result forwards it without nesting.
- `result!` produces the success value or propagates its error.

There is no failure annotation, prefix propagation expression, postfix catch expression, or public `Result.ok`/`Result.err` constructor.

## Result Methods

The API is modelled on [better-result](https://github.com/dmmulroy/better-result).

This table is the **complete** set of members an authored `.sm` program may call
on a Result. It is not a subset of a larger library surface: a member that is not
listed here does not discharge the must-use obligation, so calling one is
reported as `SMITHERS1301` ("Result value is not consumed") rather than as an
unknown property.

| Method | Meaning |
| --- | --- |
| `isOk()`, `isError()` | inspect and narrow the variant |
| `match({ ok, error })` | exhaustively produce a value from either variant |
| `map`, `mapError` | transform one side |
| `andThen` | sequence success-dependent work |
| `recover` | replace an error with a value or a Result |
| `tap`, `tapError` | observe without changing the Result |
| `expr!` | compiler propagation point |
| `unwrapOr`, `expect` | extract with fallback or invariant message |
| `Result.all` | collect Results, returning the first error |
| `Result.try`, `Result.tryPromise` | adapt a foreign throwing/rejecting operation |

Not provided, because Smithers supplies them another way: `Result.ok` and `Result.err` (use `return` and `throw`), `TaggedError` (use `class ... extends Error`), and `Result.gen`/`yield*` (use `!`).

Serialization is not a Result member. The boundary codecs are module-level
functions on `smthrs/result` — `encodeResult`, `decodeResult`, `encodeError`,
`decodeError`, `registerErrorCodec` — because a codec is a property of the
transport, not of one value. See §Transport.

Results are must-use.

### Deliberately absent

An asynchronous mirror of the combinator set (`andThenAsync`, `tapAsync`,
`tapErrorAsync`, `tapBothAsync`, `Result.allAsync`, `Result.partitionAsync`) is
**not** provided. The blocker is not the runtime half; it is that a callback
returning `Promise<Result<…>>` is a new shape for the must-use ownership walk,
and an order-sensitive `allAsync` collides with
[Actions & Flows](/reference/actions-and-flows) §Flow Determinism, which requires
every arrival-order-dependent combinator to be dispatched through the runtime
scheduler. Write the `await` explicitly instead: `await` unwraps the Promise and
leaves an ordinary Result, which the synchronous combinators then handle.

`tryRecover`/`tryRecoverAsync` are absent because `recover` already accepts both
a plain value and a Result, and it deliberately does **not** recover `panic`. A
separate "try" recovery would first have to answer whether it enters the
distinguished panic channel, which §Foreign Exceptions and Defects reserves.

`Result.partition` is absent for the same reason: emitting the failures as a
plain array erases the panic/domain distinction that recovery is required to
preserve.

`flatten` and `tapBoth` are the two members whose absence is only half true:
the runtime implements and tests both, and foreign TypeScript importing
`smthrs/result` can call them today. They are not listed in the table above
because the checker's Result surface does not yet declare them, so an authored
`.sm` calling one is refused by `SMITHERS1301`. They join the table when it does.

## Error Methods

All Errors expose:

```ts
error.is(NotFound)
error.matches(NotFound, Timeout)
error.match({ NotFound: onMissing, Timeout: onTimeout })
error.matchPartial({ NotFound: onMissing }, onOther)
error.rootCause()
```

The compiler checks `match` exhaustiveness against the known `E` union and narrows each handler. Runtime dispatch uses stable nominal identity. `matchPartial` accepts an explicit fallback. `rootCause` follows standard `Error.cause` links.

## Async

```ts
async function load(): Promise<Result<Output, Timeout>> {
  const response = (await request())!
  return response.decode()!
}
```

`await` unwraps the Promise and leaves the Result. Promise instance `.then()`, `.catch()`, and `.finally()` are compile errors in authored Smithers.

## Foreign Exceptions and Defects

Every unannotated foreign runtime call adds the distinguished checked `panic` case, including unexpected throws, rejections, and declaration violations. `@throws {never}` is a trusted opt-out; `@throws {T}` declares a more precise foreign failure channel. `Result.try` and `Result.tryPromise` are adapter helpers: without a trusted translation they preserve panic, while a trusted adapter may catch and map it to a declared Error subtype. `Reflect.panic(...)` and compiler/runtime invariant failures enter the same explicitly catchable panic channel. Ordinary Result recovery does not swallow panic implicitly.

## Transport

Worker and durable boundaries serialize a declared Error's stable identity, fields, message, cause, and codec version. Panic transport and explicit recovery must preserve the distinguished channel rather than silently relabeling it as a domain Error.
