# Capabilities [Reference for requirements and layer composition]

## Declaration and Access

```ts
import { Context } from "smthrs/context"

abstract class Service extends Context {
  abstract operation(input: Input): Result<Output, ServiceError>
}

function run(): Result<Output, ServiceError> {
  const service = Service.context()
  return service.operation(input)
}
```

The abstract class is both the service contract and nominal capability identity. `Service.context()` returns its instance and adds `Service` to the enclosing function's inferred requirement channel.

## Multiple Requirements

```ts
function run() {
  const db = Database.context()
  const clock = Clock.context()
  const log = Logger.context()
}
```

The requirement set is `Database | Clock | Logger`; duplicate nominal identities collapse.

## Layer Type

```ts
Layer<Provides>
```

| Parameter | Meaning |
| --- | --- |
| `Provides` | capabilities made available by the Layer |

## Constructors

```ts
Layer.succeed(Service, implementation)
Layer.merge(left, right, ...rest)
Layer.provide(layer, callback)
```

These names are API direction, not a stable published surface.

## Composition Rules

- `merge` unions provided capabilities.
- `provide` removes satisfied requirements from the callback's requirement set.
- a missing capability is a compile error when the closure is statically known.

Provider composition is a library API from `smthrs/provider`; there is no special provider statement syntax.

Base Layers receive already acquired service instances. Acquisition and cleanup are explicit ordinary code, initially with `using`; the Layer owns neither the resource nor its finalizer.

## Platform Services

Planned standard capabilities include `FileSystem`, `HttpClient`, `Clock`, `Random`, `Environment`, and `Console`. Targets provide live implementations; tests supply deterministic ones.

## Scope and Open Semantics

`Layer.provide(layer, body)` keeps the environment active through `body` and the Promise returned by `body`, then revokes it. A Layer does not supervise or join other work, and authored `.sm` has no detached Promise path.

The Node runtime observes the exact Promise state transition. The asynchronous body must create its returned Promise during the invocation; adapt a pre-existing Promise with `async () => await promise`. Unsupported hosts and unverifiable Promise provenance fail closed.

Merge and nested-override precedence, cycle diagnostics, and requirement-environment lowering remain to be specified.
