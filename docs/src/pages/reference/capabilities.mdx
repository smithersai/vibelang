# Capabilities [Reference for requirements and layer composition]

## Declaration and Access

```ts
import { Context } from "smthrs/context"

abstract class Service extends Context {
  abstract operation(input: Input): Result<Output, ServiceError>
}

function run(): Result<Output, ServiceError> {
  const service = Service.context()
  return service.operation(input)
}
```

The abstract class is both the service contract and nominal capability identity. `Service.context()` returns its instance and adds `Service` to the enclosing function's inferred requirement channel.

## Multiple Requirements

```ts
function run() {
  const db = Database.context()
  const clock = Clock.context()
  const log = Logger.context()
}
```

The requirement set is `Database | Clock | Logger`; duplicate nominal identities collapse.

## Layer Type

```ts
Layer<Provides>
```

| Parameter | Meaning |
| --- | --- |
| `Provides` | capabilities made available by the Layer |

## Constructors

```ts
Layer.succeed(Service, implementation)
Layer.merge(left, right, ...rest)
Layer.provide(layer, callback)
```

These names are API direction, not a stable published surface.

## Composition Rules

- `merge` unions provided capabilities.
- `provide` removes satisfied requirements from the callback's requirement set.
- a missing capability is a compile error when the closure is statically known.

:::note Open — subclass substitution at a capability receiver
That build-time guarantee has a known hole. A concrete `typeof Db` annotation is
accepted and records the key `Db`, but a **subclass** is assignable to
`typeof Db` and carries a different nominal key, so a program can check clean
against a satisfied layer and panic at run time. Both backends behave identically.
The residual is bounded — a *bound* of `typeof Db` is refused at both receiver
sites, and a subclass used directly records the subclass — and the unpinned case
is the middle one. Two of the three candidate fixes would refuse forms the
language deliberately accepts. Recorded in `DECISIONS.md` §Requirements and
dependency injection; not resolved here.
:::

Provider composition is a library API from `smthrs/provider`; there is no special provider statement syntax.

Base Layers receive already acquired service instances. Acquisition and cleanup are explicit ordinary code, initially with `using`; the Layer owns neither the resource nor its finalizer.

## Platform Services

Standard capabilities include `FileSystem`, `HttpClient`, `Clock`, `Random`,
`Environment`, and `Console`. JavaScript hosts provide live implementations;
tests supply deterministic ones.

## Scope and Open Semantics

`Layer.provide(layer, body)` keeps the environment active through `body` and the Promise returned by `body`, then revokes it. A Layer does not supervise or join other work, and authored `.sm` has no detached Promise path.

Revocation is **structural**, not a settlement hook. `Layer.provide` installs a
handler that answers the capability keys the layer provides; the handler holds
the environment on its own stack rather than in ambient storage, and a computation
that has completed or been abandoned cannot issue a further request. A runtime
therefore must not require a host promise-settlement hook, must not restrict which
Promise a provider body returns, and must not refuse an async provider scope on a
host that cannot observe settlement synchronously. See
[Effects](/specification/effects) §Extent Is Structural.

Every started Promise must still be consumed by `await` or a recognized
combinator whose result is itself consumed. Under replay that is a correctness
rule rather than lifetime hygiene: an unconsumed Promise is an unjournaled,
unreproducible interleaving.

Merge and nested-override precedence, cycle diagnostics, and requirement-environment lowering remain to be specified and fail closed.

### Withdrawn — promise-settlement revocation, 2026-08-27

This section previously required that "the asynchronous body must create or
explicitly await that Promise inside the invocation; adapt a pre-existing Promise
with `async () => await promise`" and that "a host that cannot preserve this scope
MUST fail closed."

Those three obligations — the Promise-provenance rule, the author-written adapter,
and the fail-closed host refusal — are withdrawn as **unnecessary rather than
relaxed**. The guarantee they protected is unchanged and now holds structurally.
Hosts previously refused for lacking a synchronous settlement hook are now fully
supported. See
[Requirements](/specification/requirements) §Amendment Record.

:::danger Not yet implemented — (SA-6), measured 2026-08-28
The runtime on this branch still enforces all three withdrawn obligations, so
this section describes the decision and not the behaviour. `Layer.provide` is
implemented with `v8.promiseHooks.createHook` and `AsyncLocalStorage`
(`poc/src/runtime/layer.ts`) — a settlement hook and ambient storage, which is
what "structural, not a settlement hook" above says was removed. Reproduce:

```js
await Layer.provide(layer, () => preExistingPromise)
// TypeError: Layer.provide async body must return a Promise created by that
// body; wrap an existing Promise with `async () => await promise`
```

The refusal quotes the withdrawn adapter verbatim as the required remedy, and a
