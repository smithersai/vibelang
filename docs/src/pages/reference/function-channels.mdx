# Function Channels [Reference for values, errors, and requirements]

Every VibeLang function is analyzed across three conceptual channels, but all runtime values use ordinary types:

| Parameter | Meaning | Runtime representation |
| --- | --- | --- |
| `A` | success value | the success variant of `Result<A, E>` |
| `E` | expected errors | the error variant of `Result<A, E>` |
| `R` | required capabilities | compiler-tracked context, provided by Layers |

For an infallible function, the return type remains `A`. For a fallible function it is `Result<A, E>`; for a fallible async function it is `Promise<Result<A, E>>`.

## Example

```ts
function getUser(
  id: string,
): Result<User, DatabaseError | NotFound> {
  const db = Database.context()
  const log = Logger.context()
  const row = db.find(id)!
  if (row === null) throw new NotFound(id)
  log.info(`user:${id}`)
  return User.from(row)
}
```

The compiler sees:

```text
A = User
E = DatabaseError | NotFound
R = Database | Logger
```

## Composition

| Operation | Effect on `E` | Effect on `R` |
| --- | --- | --- |
| return a Result | union returned errors | union called requirements |
| `!` | propagate the Result error | replaces `!` |
| `result.match(…)` / `result.recover(…)` | remove or transform handled errors | unchanged |
| `throw ErrorSubclass` | add that Error type | unchanged |
| `Layer.provide` | unchanged | remove provided capabilities |
| `await` | unwrap Promise only; leave Result | unchanged |

Duplicate Error members collapse in unions.

## Rows on Function Values

A function's **effect row** is the pair `(E, R)`. It is part of the function's
static type, is preserved in exported declarations, and is carried by a function
**value**, not only by a function declaration:

- assigning a function with a non-empty row where a function with a smaller row is expected is a type error;
- an unannotated function type carries the empty row;
- a call whose callee the compiler cannot resolve, and whose callee type carries no row, is rejected rather than compiled with an assumed calling convention;
- a function whose row is empty is never emitted in the resumable calling convention — an infallible function is not wrapped.

:::note Implementation checkpoint, 2026-09-06
Both backends now reject requirement-row erasure at callable assignment and
argument boundaries, including aliases, members, containers and higher-order
variance. Shared tests also reject hiding an owned Result or Promise behind a
`() => void` or widened return type.

A parameter typed `() => number` has the locked empty row, so calling it is
decidable and remains legal; `VIBE1807` is retired. The assignment that
would put a capability-dependent function into that parameter is refused.

JS declaration artifacts now carry explicit calling conventions and nominal
requirement tables. Source-free tests cover aliases, members, overloads,
returned closures and forwarded package calls. Cross-backend declaration/runtime
linking and complete opaque-container coverage are not yet certified.

The Go compiler now publishes and consumes eager callable contracts through
ordinary declaration emission. Source-free execution tests cover methods,
constructors, returned closures, aliases, re-exports, forwarded private
capability identities, Result channels and async calls. Requirement tables
preserve the original constructors; a same-spelled class cannot replace one.

Source-free coverage now also includes native accessor, coercion, iterator and
disposal calls. Object accessors retain separate `get`/`set` signatures, including
the rows of returned versus accepted callables. The compiler-owned
`@vibelangAccessor {"version":1,"enumerable":false}` record preserves class
accessor provenance when TypeScript publishes an anonymous instance as a type
literal; object-literal accessors use `true`. This keeps object spread and rest
from charging prototype getters they never invoke. Malformed records and
authored claims are refused. Native disposal still cannot discard a Result or
an unowned Promise, including across a declaration-only boundary. A published
resumable callable cannot be invoked by an ordinary native protocol driver.

Structural object views are checked too: getter reads, setter writes and own
getter enumeration have distinct requirement rows. An annotation or index
signature cannot replace those contracts with plain data, and generic readers
cannot hide them behind a weaker parameter bound. Inferred aliases, `typeof`,
mapped accessor views and pure generic identity functions preserve the row.
Actual object-spread results are plain data; the declaration publisher no
longer mistakes their retained source-location information for getter identity.

Callable metadata remains version 2. Go-produced module envelopes use version 3
to identify their runtime ABI explicitly. These tests link producer and consumer
to the same Go prelude instance. The JS frontend refuses that module envelope,
and Go refuses unlinked runtime locations or ABIs, with `VIBE1810`. General
shared-runtime linking and resumable declaration calls remain open; this is not
cross-backend package certification. An escaping function-local capability that
cannot be represented by the current declaration table is refused at publication.
:::

The last point is what keeps the row from becoming a tax on ordinary code. See
[Effects](/specification/effects) §Effect Rows.

## Public Signatures

```ts
export declare function boundary(): Result<A, E>
export declare function asyncBoundary(): Promise<Result<A, E>>
```

These are ordinary generic return types, not failure annotations. Context requirements are inferred from `Capability.context()` and retained in VibeLang analysis metadata. The declaration-file representation for `R` remains compiler-owned.

Declaration artifacts preserve failure and requirement rows for downstream
VibeLang compilation and tooling. Compiler-generated success and Error unions
are represented as one `Result<A, E>`, and each exported callable retains its
own channel metadata.

:::note Direction
The declaration-file encoding, overload behavior, and generic row encoding
remain compiler-owned and are not yet specified.
:::

## Inference and Lifting

An unannotated implementation may infer both `A` and `E` from its body. Once a function is fallible, plain returns and throws are lowered into Result variants. Returning an existing compatible Result does not produce `Result<Result<A, E>, E>`.

No marker opts a function into inference. Public API authors should spell `Result<A, E>` explicitly for stability.

## TypeScript Boundaries

Every imported TypeScript or JavaScript runtime call adds the distinguished checked `panic` case unless trusted `@throws {never}` metadata opts out or `@throws {T}` declares a more precise channel. The caller must propagate panic, explicitly catch it, or call through a trusted adapter that catches and translates it. 

## Async Boundary

VibeLang does not add an error generic to Promise. It wraps an ordinary Result:

```ts
Promise<Result<A, E>>
```

Authored VibeLang uses only `await` for Promise consumption. The compiler rejects `.then`, `.catch`, and `.finally` calls.
