# Standard Library [Target modules and design contract]

The Smithers standard library is a product direction. Module names and
signatures on this page are illustrative unless a linked specification locks
them.

## Design Contract

The standard library should:

- operate on ordinary Smithers values and functions
- return `Result<A, E>` for recoverable errors
- define platform services as abstract classes extending `Context`
- work across JavaScript hosts where applicable
- derive schemas and codecs from ordinary types
- include structured concurrency without a fiber runtime

## Core Data

Designed areas include:

```text
Array  Chunk  HashMap  HashSet  Result  Data  Match
```

TypeScript-compatible built-ins remain available. Alternatives should not require wrapper values merely for effect tracking.

Collection misses use `T | undefined`. Maps and sets preserve insertion order
and use explicit `Equivalence` and `Hash` instances where JavaScript identity is
not the desired key relation. Persistent representation is an internal choice
and does not change value semantics.

## Schema and Encoding

```text
Schema  Codec  Json  JsonSchema  Equivalence  Hash
```

These artifacts are derived at comptime where possible. Parsing failures return Results.

The compiler and library share one type descriptor model for Schema, Codec,
JSON Schema, Equivalence, and Hash derivation.

## Configuration and Time

```text
Config  Duration  Instant  Schedule
```

Reading environment variables or the wall clock requires a capability. Pure duration arithmetic does not.

`Duration`, `Instant`, and `Schedule` are pure values. Waiting is explicit
through a `Sleeper` capability. Configuration reads use `Environment`; they do
not read ambient process state.

## Platform Services

```text
FileSystem  HttpClient  Clock  Random  Environment  Console
Path  Process  Socket  Terminal
```

Each service can have Node, Bun, Deno, browser, edge, and test implementations where the host supports it.

Each capability includes deterministic test implementations. `Path` is a pure
POSIX or Windows namespace selected explicitly rather than an ambient host
read. Platform Layers bundle compatible implementations for a host.

Services use the same library-shaped declaration and access model as application capabilities:

```ts
import { Context } from "smthrs/context"

abstract class Clock extends Context {
  abstract now(): Instant
}

function timestamp(): Instant {
  const clock = Clock.context()
  return clock.now()
}
```

The inherited `Clock.context()` method is compiler-aware: it adds `Clock` to `timestamp`'s inferred context channel, while callers continue to use `timestamp()` with no explicit context argument. Layers from `smthrs/provider` supply the target-specific implementation.

## Concurrency and Streams

```text
Stream  Queue  Semaphore  Channel
```

The library uses static concurrency combinators, cancellation, and workers rather than introducing Effect-style fibers or parser-level Promise syntax. TC39 concurrency governors may provide a future limit for async-iterator fan-out.

The concurrency library includes typed cancellation, keyed joins, FIFO
governors, bounded Queue, fair Semaphore, Channel, lazy Stream, and typed worker
contracts. Helpers contain and join work they start. Queue and Stream runners
preserve typed cancellation and failure Results.

## Durable Runtime

```text
Action  Flow  Artifact  Signal  Journal  Deployment
```

These APIs connect compiler-emitted Flow bodies and their Effect Manifests to coordinator and worker runtimes.

## Agent Library

The agent library provides MDX prompt rendering, model adapters, TypeScript
compilation, sandbox execution, and optional Action and Flow durability
adapters. Exact packaging remains directional.

## Implementation Strategy

Compute-heavy components may call into Wasm modules, including implementations written in Zig, imported through the asset loaders. JavaScript/Wasm boundaries should be chosen by measurement. Host-specific implementations remain behind capabilities.
