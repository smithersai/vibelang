# Language Syntax [Quick reference for Smithers source forms]

Smithers keeps additions TypeScript-shaped where possible. Compiler-recognized behavior is exposed through imported functions and ordinary generic types instead of new keywords.

## Source Files

| Form | Status | Meaning |
| --- | --- | --- |
| `.sm` | Locked | Smithers source file |
| `.ts` | Locked | imported TypeScript with TypeScript behavior |
| `.smx` | Open | candidate JSX-capable Smithers extension |

## Results and Errors

```ts
class Name extends Error {
  constructor(readonly field: Type) {
    super("failure message")
  }
}

function operation(): Result<Value, Name> {
  if (failed) throw new Name(value)
  return value
}
```

Plain returns and throws are compiler-lifted in a Result-returning function. Propagate a Result with postfix `!` — TypeScript's non-null assertion is removed in `.sm`, and `!` takes the role Zig gives `try foo()`. Recover with `match`, `recover`, or `error.match`:

```ts
const value = operation()!

const label = operation().match({
  ok: value => render(value),
  error: error => error.match({ Name: describe }),
})
```

An async fallible function returns `Promise<Result<A, E>>`. `await` unwraps only the Promise. Promise `.then`, `.catch`, and `.finally` are banned in authored Smithers.

## Absence

```ts
function lookup(id: string): User | undefined {
  if (missing) return undefined
  return user
}

const name = lookup(id)?.name ?? "guest"
```

Absence is an ordinary TypeScript union. There is no `Optional<T>` and no optional sigil.

`!` is the error axis and `?.`/`??` are the absence axis, so both can appear in one expression:

```ts
const nickname = findUser(id)!?.nickname ?? "anonymous"
```

`arr[2]` is `T | undefined` — [Compatibility](/specification/compatibility)
§Mandatory makes `noUncheckedIndexedAccess` a required option, and the compiler
enforces it: `const v: number = arr[2]` is a `TS2322`. Your own `tsconfig.json`
MUST state it, along with the rest of §Mandatory; `smithers check -p
tsconfig.json` reports `SMITHERS6001` for one that is missing.

The one place the widening does not bite is the operator that would otherwise
contradict it. `arr[i]!` compiles when `arr` holds Results: the `| undefined` an
index read adds is the option widening the access, not the author declaring the
element optional, so `!` sees through it. An element type the author really did
declare optional — `(Result<A, E> | undefined)[]` — is not a `!` operand, because
`!` is the error axis and `?.`/`??` are the absence axis.
## Requirements

```ts
import { Context } from "smthrs/context"

const store = Store.context()
const log = Logger.context()
```

`context()` returns a capability instance and adds its nominal identity to the enclosing function's inferred requirement channel. There is no requirement keyword.

## Control Flow

Control flow is TypeScript's, unchanged. The one addition is declarations in conditionals, adopted early from the TC39 Stage 1 proposal:

```ts
if (const user = cache.get(id); user !== undefined) {
  render(user)
}
```

The binding is visible in every branch and out of scope after the construct.

## Cleanup

```ts
using file = fs.open(path, "write")!
```

Cleanup uses TC39 explicit resource management, inherited from TypeScript. Error-path rollback is written in the failure path.

## Comptime

```ts
import { comptime } from "smithers:comptime"

const value = comptime(expression)
const generatedFunction = comptime(functionValue)
comptime.target
```

Passing a value requests deterministic compile-time evaluation. Passing a function marks and returns a compile-time function without invoking it. `comptime` is an imported intrinsic, not a keyword.

## Durable Functions

```ts
import { durable } from "smithers:flows"

const workflow = durable(function workflow(
  input: Input,
): Result<Output, BuildError> {
  return Build.run(input)
})
```

The compiler emits a statically resolvable durable function's body and derives its Effect Manifest without ever invoking the body. The function stays an ordinary function: `durable(...)` changes only which handler answers its Action calls. `durable` is an imported intrinsic, not a keyword.

## Import Attributes

All non-code and foreign-source imports use standard import attributes:

```ts
import config from "./config.json" with { type: "json" }
import frozen from "./config.json" with { type: "json", mode: "const" }
import prompt from "./prompt.md" with { type: "text" }
import readme from "./readme.md" with { type: "markdown" }
import page from "./page.mdx" with { type: "mdx" }
import blob from "./icon.png" with { type: "bytes" }
```

Attribute values are strings. Ordinary `.sm`, `.ts`, and `.js` code imports do not need a `type` attribute.

The built-in loader types are exactly `json`, `text`, `bytes`, `markdown`, and
`mdx`. Any other value — including the foreign-source types `zig`, `rust`, and
`wasm` that earlier drafts of this page showed — is refused with `SMITHERS5213`,
"no comptime loader registered for import type '…'", unless a project registers
its own loader for that type through `comptime.loader`.

## Deliberately Absent Syntax

The initial language has no failure clause, prefix propagation syntax, postfix catch expression, special Error declaration, optional type sigil, optional fallback operator, `Optional<T>`, non-null assertion, comptime keyword, durable keyword, separate const-import grammar, expression-form `if` or `switch`, block expression, labeled break value, loop `else`, labeled block or loop value, arrow-arm switch, throw expression, `defer`, or `errdefer`.
