# Concurrency [Use async functions and typed workers without a fiber runtime]

Smithers keeps ordinary async functions. Expected async failure is `Promise<Result<A, E>>`, and `await` unwraps only the Promise.

Concurrency helpers are ordinary TypeScript library APIs. Smithers adds no
fiber runtime or Promise-specific parser syntax.

## Promise Discipline

Authored `.sm` code cannot call Promise instance `.then()`, `.catch()`, or `.finally()`. Use `await`, then inspect or propagate the Result:

```ts
const userResult = await loadUser(id)
const user = userResult!
```

Imported TypeScript and JavaScript libraries may use Promise chaining internally. Every unannotated foreign call contributes the checked `panic` case, including rejection; `@throws {never}` opts out and `@throws {T}` declares a more precise channel.

## Typed Workers

```ts
const analytics = spawn module {
  export function summarize(
    values: Float64Array,
  ): Result<Summary, InvalidSample> {
    return Statistics.summarize(values)
  }
}
```

Calls across a worker boundary retain Result types. Values and Errors crossing realms must satisfy the derived transport codec.

:::note Direction
`spawn module { … }` communicates the target worker model; its exact syntax is
not locked. A library form may expose the same contract as
`TypedWorker.spawn<Contract>(moduleUrl, options)`. The compiler derives the
export allowlist and transport codecs. The boundary enforces bounded active
calls, timeouts, message limits, canonical Result envelopes, replay protection,
and idempotent termination. A worker realm is not by itself a security sandbox.
:::

## Join Concurrent Operations

Start work with a static or library combinator and consume the Promise with `await`:

```ts
const results = await Promise.all([
  loadProfile(id),
  loadActivity(id),
])

const [profile, activity] = Result.all(results)!
```

`Promise.all` handles Promise scheduling. `Result.all` collects the successful values or returns the first Error. This uses standard call syntax and introduces no special `await.all` grammar.

The Promise returned by a call or combinator owns that task lifetime from the caller's perspective. Every started Promise must ultimately be consumed with `await` before its enclosing scope exits. Authored `.sm` has no fire-and-forget or detach operation.

Keyed joins preserve names as well as tuple-style joins preserve positions:

```ts
const values = await allKeyed({
  profile: loadProfile(id),
  activity: loadActivity(id),
})

const settled = await allSettledKeyed({ profile, activity })
```

Both return null-prototype records with the same own enumerable string and
symbol keys. `allKeyed` rejects on the first Promise-style rejection;
`allSettledKeyed` records each settlement. Fallible operations compose
explicitly with `Result.all(Object.values(values))` rather than changing the
Promise combinators' semantics.

## Cancellation

Cancellation is an expected Error and its source is a capability:

```ts
async function index(
  records: AsyncIterable<Record>,
): Promise<Result<void, Cancelled>> {
  const cancellation = Cancellation.context()
  for await (const record of records) {
    cancellation.checkpoint()!
    indexRecord(record)
  }
}
```

Callers can distinguish cancellation from timeout or domain failure.

`CancellationSource` creates manual and `AbortSignal`-linked cancellation with
parent/child linkage. Registrations are idempotent disposables. Adapters expose
an `AbortSignal`, a typed cancellation Error, checkpoints, and listener
registration. Listener exceptions are contained, but JavaScript cannot forcibly
abort an iterator that ignores both cancellation and `return()`.

## Streams and Coordination Primitives

:::warning Not importable from `.sm` yet — measured 2026-08-28
Everything in this section is real and works under plain `node` from
`smthrs/concurrency`. It is **not** reachable from an authored `.sm` file:
`import { Queue } from "smthrs/concurrency"` is refused with `SMITHERS1510`,
because only six specifiers are compiler-owned and `smthrs/concurrency` is not
one of them. `allKeyed` and `allSettledKeyed` have a second, separate barrier —
the frontend recognizes those names only as members of the ambient `Promise`
namespace, a spelling no `lib.es*.d.ts` supplies, so the free-function form is
reported as `SMITHERS1402`, "started Promise is not consumed".
:::

The standard library supplies:

- `new Queue<T>(capacity)` / `Queue.bounded<T>(capacity)` implement a bounded
  FIFO MPMC queue. `offer` and `take` suspend with typed
  `Result<…, QueueClosed | Cancelled>` outcomes; `tryOffer` and `tryTake`
  use tagged states to distinguish temporary backpressure from permanent closure;
  `shutdown` lets accepted buffered values drain.
- `new Semaphore(size)` / `Semaphore.withPermits(size)` provide fair
  `acquire`, `tryAcquire`, and `withPermit`. Permits release idempotently.
- `new Channel<T>(capacity = 1)` / `Channel.buffered<T>(capacity)` layer
  `send`, `receive`, try operations, closing, and draining async iteration over
  a Queue. This is a small-buffer channel, not a zero-capacity rendezvous
  channel.
- `Stream.fromIterable`, `Stream.fromAsyncIterable`, and `Stream.of` build
  reusable lazy streams. `map`, `filter`, `take`, `drop`, and `scan` are lazy;
  `mapConcurrent` is completion-ordered and governor-aware; `buffer` retains
  source order through a bounded Queue; `interrupt` adds cancellation; and
  `runCollect`, `runForEach`, and `runFold` return typed Results.

Nonblocking operations return a tagged result so `null` and `undefined` remain
valid element values. Internally started Promises contain rejections, and early
Stream or iterator exit joins the cleanup the helper owns.

## Shared Data

Shared structs over `SharedArrayBuffer` provide an explicit path for
high-throughput worker communication. Ordinary mutable objects are not silently
shared between realms. The compiler checks cross-realm layout and Error
transport.

:::note Direction
Shared-struct declaration syntax, memory layout, synchronization primitives,
and host support remain open.
:::

## Limiting Fan-Out

Concurrency governors limit how much work may run simultaneously; they do not define child ownership or Error composition. A structured library combinator may own, cancel, and join the work it starts, but a Layer never does. Smithers intends to follow viable JavaScript proposals or standard-library APIs instead of adding parser syntax for throttling.

The library spells this `Governor.withLimit(limit)`. `acquire()`
returns an idempotently releasable permit and `run(operation)` releases in
`finally`; admission is FIFO. A `Governor` can be shared by independent helper
instances. `mapUnordered`, `filterUnordered`, and `bufferedUnordered` accept a
positive numeric bound or a shared Governor, yield in completion order, cancel
only their own child token on early exit/failure, and join admitted work before
closing. `bufferedUnordered` governs concurrent source pulls as well as output.

## Open Semantics

:::note Direction
Language-wide sibling cancellation, aggregate-error policy, worker ownership,
shared-struct layout, and custom thenable handling remain specification work.
The library primitives above use FIFO admission, first-observed helper failure,
child cancellation, and cleanup joining. A Flow's durable scheduler is a
separate opt-in runtime, not the execution model for ordinary async code.
:::

## Inside a Flow Body

These combinators behave the same way inside a `durable(...)` body, with one
addition: the durable runtime owns the dispatch order. Every concurrent effect
request gets a deterministic submission index before dispatch, the runtime
journals the completion order it observed, and resumption delivers completions in
that journaled order. `Promise.race` and `Promise.any` — whose *result* depends on
arrival order — are reachable only through that scheduler. The scheduler has no
source-language surface.

:::note Open
`Promise.all` and its keyed and settled variants are order-independent in their
result, yet they still start concurrent requests that must acquire submission
indices deterministically. How an order-independent combinator reaches the
scheduler is unspecified, and two locked obligations are in tension until it is
settled. See
[Durable Execution](/specification/durable-execution) §Deterministic Scheduling.

Separately: what happens to the requests still in flight when one arm of a
combinator fails — cancelled, awaited, or abandoned, and what is journaled for
them — is stated by no page. Nothing here should be read as deciding it.
:::
