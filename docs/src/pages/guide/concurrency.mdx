# Concurrency [Use typed workers and structured joins without a fiber runtime]

VibeLang builds structured concurrency around ordinary async functions and typed join expressions. It does not reinterpret every function as a fiber.

:::warning Design direction
Structured joins are VibeLang design direction, not implemented syntax. Concurrency governors are a separate TC39 Stage 1 direction whose API and semantics may change.
:::

## Typed Workers

Module expressions define a statically visible worker surface:

```ts
const analytics = spawn module {
  export function summarize(
    values: Float64Array,
  ): Summary throws InvalidSample {
    return try Statistics.summarize(values)
  }
}
```

Calls across the worker boundary retain their success and failure types. Values crossing realms need an appropriate structured or shared representation.

## Structured Joins

Pass async operations directly to a typed join:

```ts
const [profile, activity] = try await.all(
  loadProfile(id),
  loadActivity(id),
)
```

The join does not produce its value until both operations complete according to its join policy. This is VibeLang's structured child-task direction; exact cancellation and sibling-failure semantics are still being designed. It does not require a separate scope object or wrapper around each call.

## Typed Joins

Join operations combine success values and failure sets:

```ts
const [stats, metadata] = try await.all(
  analytics.summarize(samples),
  fetchMetadata(datasetId),
)
```

If the first operation fails with `InvalidSample` and the second with `Timeout`, the join fails with `InvalidSample | Timeout | Cancelled`.

The same approach extends to `await.race`, `await.any`, `await.allSettled`, and keyed joins.

## Cancellation

Cancellation is visible as a typed failure. A cancellation capability is supplied through the requirement system rather than threaded through every call by hand:

```ts
async function index(records: AsyncIterable<Record>) {
  const cancellation = Cancellation.context()
  for await (const record of records) {
    try cancellation.checkpoint()
    // ...
  }
}
```

Callers can distinguish cancellation from timeout or domain failure and decide whether to recover, retry, or propagate it.

## Shared Data

Shared structs over `SharedArrayBuffer` provide an explicit path for high-throughput worker communication. Ordinary mutable objects are not silently shared between realms.

The compiler can check the cross-realm layout and failure transport protocol while each backend chooses its most appropriate implementation.

## Limiting Fan-Out

TC39's Stage 1 concurrency-control proposal explores governors for limiting concurrent access to a resource or consuming an async iterator with bounded fan-out. Its current API direction includes `CountingGovernor`:

```ts
const governor = new CountingGovernor(16)

try await AsyncIterator.from(urls)
  .map(fetchPage)
  .forEach(index, governor)
```

A governor limits how much work may run concurrently. It does not define structured child-task ownership, join failure composition, or task lifetimes. VibeLang intends to track the JavaScript proposal rather than invent a competing governor API.

## Promises and Native Output

Standard async functions remain the basic abstraction. Promise behaviors that cannot be implemented efficiently or soundly on native targets may add the `TypeScript` requirement. The exact supported subset, including custom thenables and Promise subclassing, is still open.
