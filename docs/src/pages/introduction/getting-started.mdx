# Getting Started [Start with TypeScript-shaped code, then add Results and requirements]

## Overview

Smithers uses a TypeScript-derived frontend. A `.sm` file opts into Smithers semantics; imported `.ts` and `.js` files retain their normal behavior.

The language focuses on:

- expected failures as `Result<A, E>` values
- capability-based dependency injection
- deterministic compile-time execution
- opt-in durable and distributed execution

Compiler intrinsics such as `comptime(...)` and `durable(...)` are imported functions rather than keywords.

## Create a Project

```bash
npm install --save-dev smthrs
```

Create `answer.sm`:

```ts
class InvalidAnswer extends Error {}

function answer(valid: boolean): Result<number, InvalidAnswer> {
  if (!valid) throw new InvalidAnswer("invalid")
  return 42
}

answer(true).match({
  ok: value => `answer=${value}`,
  error: () => "failed",
})
```

Check and run it:

```bash
npx smithers check answer.sm
npx smithers run answer.sm
```

`check` validates the complete project graph without emitting artifacts. `run`
checks the graph and executes the selected entry module. See the [CLI
reference](/reference/cli) for the target command contract.

## Your First Fallible Function

```ts
import { Context } from "smthrs/context"

class NotFound extends Error {
  constructor(readonly id: string) {
    super(`User not found: ${id}`)
  }
}

abstract class Users extends Context {
  abstract find(id: string): User | undefined
}

function getUser(id: string): Result<User, NotFound> {
  const users = Users.context()
  return users.find(id).toResult(() => new NotFound(id))
}
```

The ordinary return type tells the whole story:

- `User` is the success value.
- `NotFound` is the expected Error.
- `Users.context()` adds `Users` to the compiler-inferred requirement channel.
- `User | undefined` models a successful lookup with no value.

## Handle or Propagate

Handle both Result variants with `match`, then use `error.match` for a known Error union:

```ts
const user = getUser("42").match({
  ok: user => user,
  error: error => error.match({
    NotFound: () => User.guest(),
  }),
})
```

Use `!` when the enclosing function returns a compatible Result:

```ts
function displayName(id: string): Result<string, NotFound> {
  const user = getUser(id)!
  return user.name
}
```

Inside a Result-returning body, a plain return is lifted to success and a thrown Error is lifted to error. No explicit success/error constructor is needed.

## Provide a Capability

```ts
import { Layer } from "smthrs/provider"

const App = Layer.succeed(Users, new PostgresUsers(databaseUrl))

const name = Layer.provide(App, () => displayName("42")!)
```

Removing the `Users` provider is intended to be a compile error. Tests can provide an in-memory implementation without changing application code. A Layer only supplies the environment; resources are acquired and finalized explicitly outside it.

## Async Results

```ts
async function loadUser(
  id: string,
): Promise<Result<User, Timeout | NotFound>> {
  const response = (await HttpClient.context().get(`/users/${id}`))!
  return (await response.json(User))!
}
```

`await` unwraps the Promise but leaves the Result. Authored Smithers does not use Promise instance `.then`, `.catch`, or `.finally`.
